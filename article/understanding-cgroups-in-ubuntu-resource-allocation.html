Understanding cgroups in Ubuntu Resource Allocation

Control groups, commonly known as cgroups, are a Linux kernel feature that allows administrators to organize processes into hierarchical groups to monitor, meter, and restrict their system resource usage. In Ubuntu, cgroups serve as the foundational mechanism for resource allocation, ensuring that critical system services, user applications, and containers receive balanced access to finite hardware resources like CPU, memory, disk I/O, and network bandwidth. By preventing individual processes from exhausting system capacity, cgroups guarantee stability, multi-tenant fairness, and predictable performance across the operating system.

Core Functions of cgroups

The implementation of cgroups in Ubuntu revolves around four distinct functional pillars:

1. Resource Limiting

cgroups enforce hard and soft boundaries on how much of a specific hardware resource a collection of processes can consume.

  • Memory: Administrators can set limits on physical RAM and swap space. If a group exceeds its allotted memory, the kernel can throttle it or trigger an Out-Of-Memory (OOM) killer targeted specifically at that group rather than terminating critical system-wide processes.
  • CPU: Using the Completely Fair Scheduler (CFS) bandwidth control, cgroups limit the quota of CPU time a group can consume during a given period.
  • Block I/O: Limits can be placed on read and write throughput or input/output operations per second (IOPS) for specific storage devices.

2. Prioritization and Share Allocation

Instead of rigid ceilings, cgroups can assign proportional weights to different tasks. When resource contention occurs:

  • A high-priority group (such as a database service) can be configured with higher CPU shares than background tasks (such as log indexing).
  • The kernel dynamically distributes resources based on these relative weights, ensuring mission-critical processes operate smoothly under heavy load.

3. Accounting and Monitoring

cgroups provide real-time metrics detailing resource consumption at the group level. Ubuntu administrators can track:

  • Total CPU time consumed across all threads in a group.
  • Current and peak memory usage, including cache and swap utilization.
  • Total I/O operations executed on block devices.

These metrics enable continuous performance analysis, capacity planning, and usage-based billing in multi-user environments.

4. Process Control

cgroups allow actions to be executed across an entire tree of processes simultaneously. For example, using the freezer subsystem, an administrator can suspend (freeze) an entire application stack and its child processes, create a snapshot or backup, and resume it without altering the internal state of individual processes. Similarly, all child processes of an application can be safely terminated at once, eliminating orphaned "zombie" processes.

Role in systemd and Containers

In modern Ubuntu releases, cgroups are integrated directly with systemd and default to the unified cgroups v2 architecture. Every systemd unit (services, scopes, and slices) automatically runs inside its own control group. This enables administrators to define resource constraints directly inside systemd service files using directives like MemoryMax=, CPUQuota=, and IOReadBandwidthMax=.

Furthermore, cgroups are the enabling technology behind containerization platforms on Ubuntu, including Docker, containerd, and LXD. While Linux namespaces isolate what a container can see (such as filesystems and network interfaces), cgroups enforce what a container can use, preventing containerized workloads from compromising the host operating system.
