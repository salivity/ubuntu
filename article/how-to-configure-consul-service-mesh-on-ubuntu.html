How to Configure Consul Service Mesh on Ubuntu

This article provides a practical, step-by-step walkthrough for configuring HashiCorp Consul service mesh between microservices hosted on Ubuntu systems. It covers the complete workflow: repository setup, package installation, Consul server and client initialization, sidecar proxy injection using Envoy, and defining access control intentions to establish secure mutual TLS (mTLS) communication across services.

Step 1: Install Consul and Envoy on Ubuntu

Run these commands on all Ubuntu nodes (both the Consul server node and the microservice client nodes) to add HashiCorp's official repository and install the required packages.

# Update system and install dependencies
sudo apt-get update && sudo apt-get install -y wget gpg coreutils lsb-release

# Add HashiCorp GPG key
wget -O- https://apt.releases.hashicorp.com/gpg | sudo gpg --dearmor -o /usr/share/keyrings/hashicorp-archive-keyring.gpg

# Add HashiCorp repository
echo "deb [signed-by=/usr/share/keyrings/hashicorp-archive-keyring.gpg] https://apt.releases.hashicorp.com $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/hashicorp.list

# Install Consul and Envoy
sudo apt-get update
sudo apt-get install -y consul envoy

Step 2: Configure and Start the Consul Server

On the dedicated Consul server node, create a base configuration to initialize the cluster and enable the Connect service mesh features.

  1. Create or edit /etc/consul.d/consul.hcl:
datacenter = "dc1"
data_dir   = "/opt/consul"
bind_addr  = "0.0.0.0"
client_addr = "0.0.0.0"

server           = true
bootstrap_expect = 1

connect {
  enabled = true
}

ui_config {
  enabled = true
}
  1. Start and enable the Consul service:
sudo systemctl enable consul
sudo systemctl start consul

Step 3: Configure the Consul Client Node

On the Ubuntu node hosting your microservices, configure the Consul client to join the Consul server.

  1. Create or edit /etc/consul.d/consul.hcl on the client machine:
datacenter = "dc1"
data_dir   = "/opt/consul"
bind_addr  = "0.0.0.0"

# Replace with the actual IP address of your Consul Server
retry_join = ["<CONSUL_SERVER_IP>"]

connect {
  enabled = true
}
  1. Start the Consul client:
sudo systemctl enable consul
sudo systemctl start consul

Step 4: Register Microservices with Connect Sidecars

Assume you have two microservices: Service A (client, e.g., web frontend) running on port 8080 and Service B (upstream, e.g., backend API) running on port 9090.

Register the Upstream (Backend API)

On the backend service host, create /etc/consul.d/backend.hcl:

service {
  name = "backend"
  port = 9090

  connect {
    sidecar_service {}
  }

  check {
    id       = "backend-check"
    name     = "Backend Health Check"
    tcp      = "localhost:9090"
    interval = "10s"
    timeout  = "1s"
  }
}

Register the Downstream (Web Frontend)

On the frontend service host, create /etc/consul.d/web.hcl:

service {
  name = "web"
  port = 8080

  connect {
    sidecar_service {
      proxy {
        upstreams = [
          {
            destination_name = "backend"
            local_bind_port  = 5000
          }
        ]
      }
    }
  }
}

Reload the Consul configuration on both nodes:

consul reload

Step 5: Start Envoy Sidecar Proxies

Each service requires an Envoy sidecar proxy process to intercept and route encrypted traffic.

  1. Start the proxy for the backend service:
consul connect envoy -sidecar-for backend > /var/log/envoy-backend.log 2>&1 &
  1. Start the proxy for the web service:
consul connect envoy -sidecar-for web > /var/log/envoy-web.log 2>&1 &

Once started, the web service can communicate with the backend service locally via localhost:5000. The Envoy proxy encrypts outbound traffic over mTLS and delivers it to the backend's Envoy proxy, which decrypts it and forwards it to port 9090.

Step 6: Control Traffic with Intentions

Consul Service Mesh uses Intentions to define authorization rules between services.

  1. Deny all traffic by default across the mesh:
consul intention create -deny "*" "*"
  1. Explicitly allow the web microservice to communicate with the backend microservice:
consul intention create -allow web backend
  1. Verify active intentions:
consul intention list

Any unauthorized service attempting to connect to the backend sidecar proxy will now receive a connection drop or reset at the TLS layer.
