How to Remove Old Kernels in Ubuntu /boot

A full /boot partition is a common issue in Ubuntu that can prevent system updates and cause package manager errors. Over time, system updates install newer Linux kernels while retaining older versions as fallbacks, gradually exhausting the limited space allocated to /boot. This guide explains how to identify your active kernel, safely remove outdated kernel images using Ubuntu’s built-in package tools, and manually purge packages if your disk is already at 100% capacity.

Step 1: Check Your Current Kernel

Before removing any files, you must identify which kernel is currently running so you do not accidentally remove it.

Run the following command:

uname -r

Take note of this version string (e.g., 5.15.0-88-generic). You must keep this kernel and ideally the one immediately preceding it for emergency recovery.

Step 2: Check Available Space in /boot

Verify the current disk usage of the /boot mount:

df -h /boot

Step 3: Remove Kernels Automatically

In modern Ubuntu versions, the APT package manager can automatically identify and remove residual, superseded kernels.

Run:

sudo apt autoremove --purge

The --purge flag ensures that configuration files associated with old kernels are also deleted, maximizing reclaimed space. If this command completes successfully and frees enough space, skip to Step 5.

Step 4: Manually Remove Old Kernels (If /boot is 100% Full)

If your /boot partition is completely full, apt commands may fail with write errors. You will need to remove packages manually.

  1. List all installed kernel packages:

    dpkg --list | grep -E 'linux-image|linux-headers|linux-modules'

  2. Identify packages to delete: Look for versions older than your running kernel marked with status ii (installed).

  3. Purge the old kernel packages using APT: Replace X.X.X-XX with the specific version you wish to remove:

    sudo apt purge linux-image-X.X.X-XX-generic linux-headers-X.X.X-XX-generic linux-modules-X.X.X-XX-generic

  4. Force removal with DPKG (Emergency Only): If APT refuses to run due to broken dependencies caused by zero disk space, use dpkg directly to remove a single old kernel package and free immediate working room:

    sudo dpkg --purge linux-image-X.X.X-XX-generic

    Once space is cleared, run sudo apt -f install to fix any interrupted package installations.

Step 5: Update the GRUB Bootloader

After old kernels have been deleted, update your bootloader configuration to ensure the boot menu reflects the changes:

sudo update-grub
