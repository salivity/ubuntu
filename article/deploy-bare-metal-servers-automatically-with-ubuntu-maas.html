Deploy Bare-Metal Servers Automatically with Ubuntu MAAS

Ubuntu MAAS (Metal as a Service) transforms physical servers into a flexible, cloud-like resource by automating bare-metal provisioning, configuration, and deployment. This guide provides a direct, step-by-step overview of setting up MAAS, enlisting hardware via PXE booting, commissioning inventory, and automatically deploying operating systems to physical machines using both the web interface and automated scripts.

Step 1: Install and Initialize MAAS

To begin, install MAAS on a dedicated control node running Ubuntu Server. MAAS operates using a Region Controller (manages the database and web UI) and a Rack Controller (handles DHCP, DNS, and PXE booting).

  1. Install the MAAS snap package:

    sudo snap install maas

  2. Initialize MAAS as a standalone setup (combining Region and Rack controllers):

    sudo maas init mode=region-rack

  3. Create an administrative user account:

    sudo maas createadmin

Log in to the web interface at http://<your-controller-ip>:5240/MAAS to complete the initial setup wizard, select default OS images (such as Ubuntu LTS), and import SSH keys.

Step 2: Configure Network Services (DHCP and PXE)

Automated bare-metal deployment relies on Preboot Execution Environment (PXE) booting over the local network.

  1. In the MAAS Web UI, navigate to Subnets.
  2. Select the VLAN connected to your target physical servers.
  3. Enable DHCP managed by MAAS on the primary Rack Controller.
  4. Ensure target servers are connected to this isolated deployment network and configured in their BIOS/UEFI to prioritize PXE/Network booting.

Step 3: Server Enlistment and Commissioning

Once network booting is enabled, target machines can be discovered and cataloged automatically.

  1. Enlistment: Power on the target servers. They boot via PXE, contact MAAS, register their MAC addresses, and automatically shut down. The machines now appear in the MAAS UI under the Machines tab in an “In Use” or “New” state.
  2. Commissioning: Select the enlisted servers and trigger Commissioning. MAAS turns on the physical machines via IPMI/BMC (or Wake-on-LAN), runs diagnostic scripts, catalogs hardware details (CPU, RAM, storage layout, network interfaces), and powers them off again.

Note: Configure IPMI/BMC power credentials in the machine details panel so MAAS can automatically manage machine power states.

Step 4: Automated Server Deployment

With machines commissioned and in the “Ready” state, you can provision them manually through the UI or automatically via the MAAS API and CLI.

Option A: Deployment via Web Interface

  1. Select one or more “Ready” machines.
  2. Click Take Action and select Release/Acquire, then click Deploy.
  3. Choose the desired operating system (e.g., Ubuntu 22.04 LTS), kernel, and storage layout configuration.
  4. Click Deploy Machine. MAAS turns on the physical server, formats drives, installs the OS, injects your SSH keys, and configures networking.

Option B: Fully Automated Deployment via CLI/API

For complete automation within CI/CD pipelines or infrastructure-as-code workflows, interact with MAAS using its CLI tool:

  1. Authenticate to the API:

    maas login admin http://<your-controller-ip>:5240/MAAS/api/2.0/ <your-api-key>

  2. Allocate a ready machine:

    maas admin machines allocate

  3. Deploy an OS to the allocated machine (using its System ID):

    maas admin machine deploy <system-id> distro_series=jammy

MAAS powers on the machine and executes the automated deployment without manual intervention. Once completed, the server transitions to the “Deployed” state and is fully accessible via SSH.
