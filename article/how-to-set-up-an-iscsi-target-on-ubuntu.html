How to Set Up an iSCSI Target on Ubuntu

Setting up an iSCSI target on Ubuntu allows you to share local block storage devices, such as physical disks, partitions, or file images, over a network to remote client machines known as initiators. This guide covers the complete step-by-step process to install the required package, configure storage backstores, define the iSCSI target IQN, set up access control lists, and allow firewall traffic for seamless network storage sharing.

Prerequisites

  • An Ubuntu server (20.04 LTS or later recommended) with root or sudo privileges.
  • A secondary dedicated block device, partition, or sufficient disk space to create a storage file image.
  • The static IP address of the Ubuntu server and the IQN (iSCSI Qualified Name) of the client machine (initiator).

Step 1: Install targetcli-fb

Ubuntu uses the targetcli-fb administration tool to manage the Linux kernel target framework.

Run the following commands to update package lists and install the administration shell:

sudo apt update
sudo apt install targetcli-fb -y

Verify that the service is active and running:

sudo systemctl status targetctl

Step 2: Open the targetcli Management Interface

Launch the interactive configuration interface:

sudo targetcli

You will see a navigation prompt (/>).

Step 3: Create the Storage Backstore

You must define the storage you want to share. You can use a raw block device (like /dev/sdb) or a file-based storage image.

Option A: Block Device (Physical Disk/Partition)

If you have an unused drive or partition (e.g., /dev/sdb):

cd /backstores/block
create name=storage_block dev=/dev/sdb

Option B: File-Based Backstore

If you want to use a file created on your existing filesystem:

cd /backstores/fileio
create name=storage_file file_or_dev=/var/iscsi_storage.img size=20G

Step 4: Create the iSCSI Target IQN

Navigate to the iSCSI directory and create a Target Qualified Name (IQN). The standard format is iqn.yyyy-mm.reverse-domain:identifier.

cd /iscsi
create iqn.2023-10.com.example:ubuntu.target

This command automatically creates a Target Portal Group (tpg1).

Step 5: Map the Storage to a LUN

Bind the backstore storage created in Step 3 to the Target Portal Group as a Logical Unit Number (LUN):

cd /iscsi/iqn.2023-10.com.example:ubuntu.target/tpg1/luns
create /backstores/fileio/storage_file

(Replace /backstores/fileio/storage_file with /backstores/block/storage_block if you chose Option A).

Step 6: Configure Access Control Lists (ACLs)

To restrict access so that only authorized initiators can mount the storage, create an ACL entry using the client's IQN (found in /etc/iscsi/initiatorname.iscsi on the client machine):

cd /iscsi/iqn.2023-10.com.example:ubuntu.target/tpg1/acls
create iqn.2023-10.com.example:client.initiator

Step 7: Save Configuration and Exit

Save the changes to make them persistent across system reboots, then exit the interface:

saveconfig
exit

Step 8: Configure the Firewall

iSCSI traffic communicates over TCP port 3260. Allow this port through Ubuntu's Uncomplicated Firewall (UFW):

sudo ufw allow 3260/tcp
sudo ufw reload

Testing and Client Connection

From the remote client (initiator) machine, discover and connect to your newly exposed Ubuntu target:

  1. Discover targets: 
    sudo iscsiadm -m discovery -t sendtargets -p <UBUNTU_SERVER_IP>
  2. Log in to the target: 
    sudo iscsiadm -m node -T iqn.2023-10.com.example:ubuntu.target -p <UBUNTU_SERVER_IP> --login

Once connected, the remote block device will appear on the initiator machine as a local raw disk (e.g., /dev/sdb or /dev/sdc), ready to be formatted and mounted.
