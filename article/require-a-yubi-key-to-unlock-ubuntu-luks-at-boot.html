Require a YubiKey to Unlock Ubuntu LUKS at Boot

Securing an Ubuntu system with Full Disk Encryption (LUKS) traditionally relies on a passphrase entered at boot. By pairing LUKS with a physical YubiKey, you can require hardware token authentication—either alongside or in place of a password—to decrypt the root partition. This guide details how to leverage modern systemd tools and FIDO2 capabilities to configure your Ubuntu bootloader to require a physical YubiKey during startup.

Prerequisites

  • An existing installation of Ubuntu (22.04 LTS or newer) configured with LUKS Full Disk Encryption.
  • A YubiKey that supports FIDO2 (YubiKey 5 Series or Security Key Series).
  • Administrative (sudo) access.

Step 1: Identify the Encrypted LUKS Partition

Plug in your YubiKey and open a terminal. Identify the block device that hosts your LUKS container by running:

lsblk -f

Look for the partition labeled crypto_LUKS (for example, /dev/nvme0n1p3 or /dev/sda3). Note this device path, as it will be referenced throughout the configuration.

Step 2: Enroll the YubiKey Using systemd-cryptenroll

Modern versions of Ubuntu use systemd-cryptenroll to bind hardware security keys directly to a free LUKS keyslot using the FIDO2 standard.

Run the following command to register your YubiKey to the LUKS partition (replace /dev/nvme0n1p3 with your actual partition):

sudo systemd-cryptenroll --fido2-device=auto /dev/nvme0n1p3

To require both user presence (touching the key) and user verification (entering the YubiKey's FIDO2 PIN), add the --fido2-with-user-verification=true flag:

sudo systemd-cryptenroll --fido2-device=auto --fido2-with-user-verification=true /dev/nvme0n1p3

You will be prompted to enter your existing disk encryption passphrase to authorize the addition of the new keyslot, followed by a prompt to touch your YubiKey.

Step 3: Configure crypttab

The /etc/crypttab file controls how encrypted block devices are unlocked during the early boot process.

Open the file in a text editor:

sudo nano /etc/crypttab

Locate the entry corresponding to your root partition. It will resemble the following:

dm_crypt-0 UUID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx none luks

Modify the options column (the fourth field) to append fido2-device=auto. If you set up a PIN in Step 2, ensure the option is present:

dm_crypt-0 UUID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx none luks,fido2-device=auto

Save the changes and exit the editor.

Step 4: Update the Initial RAM Filesystem (initramfs)

For the bootloader and the kernel to utilize FIDO2 drivers prior to mounting the root filesystem, the initial RAM disk must be rebuilt.

Execute:

sudo update-initramfs -u -k all

This ensures that the necessary FIDO2 libraries, cryptographic modules, and the updated crypttab rules are integrated into the boot image.

Step 5: Verify and Test the Configuration

Reboot the system to test the setup:

sudo reboot

During startup, the system will detect the YubiKey and prompt you to touch the physical sensor (and enter the PIN if configured) to decrypt the drive. If the YubiKey is not inserted, the system will fall back to prompting for your original recovery passphrase after a brief timeout.
