How to Set Up a Pacemaker HA Cluster on Ubuntu

Setting up a highly available (HA) cluster on Ubuntu using Pacemaker and Corosync ensures that critical applications remain online even if an individual server fails. This guide covers the essential step-by-step process, from preparing your network and installing the necessary packages to authenticating nodes, initializing the cluster, configuring virtual IP resources, and verifying failover capability.

Prerequisites and System Preparation

Ensure you have at least two Ubuntu servers configured with static IP addresses.

  1. Update Host Files: Edit /etc/hosts on all nodes so every server can resolve all cluster members by their hostnames.
  2. Synchronize Time: Ensure precise time synchronization across all nodes using chrony or systemd-timesyncd.

Step 1: Install Pacemaker, Corosync, and PCS

Run the following commands on all nodes to install the package suite:

sudo apt update
sudo apt install -y pacemaker corosync pcs

Start and enable the Pacemaker Configuration System (pcsd) daemon on all nodes:

sudo systemctl enable --now pcsd

Step 2: Authenticate Cluster Nodes

The package installation automatically creates a default system user named hacluster. Set a password for this user on all nodes:

sudo passwd hacluster

On one node only, run the authentication command to connect the nodes together (replace node1 and node2 with your actual hostnames):

sudo pcs cluster auth node1 node2 -u hacluster

Step 3: Create and Start the Cluster

From the same node where you ran the authentication, generate the cluster configuration and enable all services across the network:

sudo pcs cluster setup my_cluster node1 node2
sudo pcs cluster start --all
sudo pcs cluster enable --all

Check the operational status of your cluster:

sudo pcs status

Step 4: Configure Cluster Properties

For standard two-node setups or testing environments where dedicated fencing devices are unavailable, disable STONITH (Shoot The Other Node In The Head) and set the quorum policy to ignore lost quorums:

sudo pcs property set stonith-enabled=false
sudo pcs property set no-quorum-policy=ignore

Note: In production environments, STONITH should remain enabled with proper fencing devices configured to prevent data corruption.

Step 5: Add Cluster Resources

Create a floating Virtual IP (VIP) address that automatically migrates to an active node if the primary node goes offline:

sudo pcs resource create Virtual_IP ocf:heartbeat:IPaddr2 ip=192.168.1.200 cidr_netmask=24 op monitor interval=30s

Replace 192.168.1.200 with an unassigned IP address on your local network.

Step 6: Test Cluster Failover

Verify that the cluster handles node failures correctly by putting the primary node into standby mode:

sudo pcs node standby node1

Run sudo pcs status on node2 to verify that the Virtual_IP resource successfully migrated to node2. Once verified, restore the first node back to the active cluster state:

sudo pcs node unstandby node1
