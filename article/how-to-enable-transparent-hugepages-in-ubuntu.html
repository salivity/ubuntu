How to Enable Transparent Hugepages in Ubuntu

Transparent HugePages (THP) is a Linux memory management system that reduces Translation Lookaside Buffer (TLB) misses by automatically managing larger chunks of memory (typically 2MB instead of the standard 4KB). For memory-intensive database applications that benefit from large contiguous memory blocks, properly enabling THP can significantly reduce CPU overhead and improve throughput. This guide walks directly through checking your current configuration, enabling THP at runtime, and persisting the settings across system reboots on Ubuntu.

1. Check the Current THP Status

To verify whether Transparent HugePages is currently active, read the state from the sysfs virtual file system:

cat /sys/kernel/mm/transparent_hugepage/enabled

The output will display the available options with the currently active mode wrapped in brackets:

  • [always] madvise never: THP is fully enabled for all processes.
  • always [madvise] never: THP is only enabled for processes explicitly requesting it using the madvise() system call.
  • always madvise [never]: THP is completely disabled.

2. Enable THP Temporarily (Runtime)

You can activate THP immediately without rebooting the server. Run the following command with root privileges:

echo always | sudo tee /sys/kernel/mm/transparent_hugepage/enabled

To configure how aggressively the kernel defragments memory to allocate huge pages, adjust the defragmentation setting. For high-throughput database workloads, setting this to madvise prevents latency spikes caused by synchronous runtime defragmentation:

echo madvise | sudo tee /sys/kernel/mm/transparent_hugepage/defrag

3. Make THP Persistent Across Reboots

Changes made directly to /sys are lost when the system restarts. To ensure THP remains enabled permanently, apply the configuration through the GRUB bootloader.

Open the GRUB configuration file:

sudo nano /etc/default/grub

Locate the GRUB_CMDLINE_LINUX_DEFAULT directive and append transparent_hugepage=always. For example:

GRUB_CMDLINE_LINUX_DEFAULT="quiet splash transparent_hugepage=always"

Save the file and exit the editor. Update GRUB to apply the changes to the boot sequence:

sudo update-grub

4. Alternative: Persist via a Systemd Service

If you also want to persist specific defrag policies alongside the main THP setting, a dedicated systemd service provides granular control.

Create a new service file:

sudo nano /etc/systemd/system/thp-configuration.service

Add the following content:

[Unit]
Description=Configure Transparent HugePages
DefaultDependencies=no
After=sysinit.target local-fs.target
Before=mongod.service mysql.service postgresql.service

[Service]
Type=oneshot
ExecStart=/bin/sh -c 'echo always > /sys/kernel/mm/transparent_hugepage/enabled && echo madvise > /sys/kernel/mm/transparent_hugepage/defrag'

[Install]
WantedBy=basic.target

Reload systemd and enable the service:

sudo systemctl daemon-reload
sudo systemctl enable thp-configuration.service

5. Verify the Active Configuration

After rebooting or executing the commands, confirm that [always] is selected:

cat /sys/kernel/mm/transparent_hugepage/enabled

To monitor whether your database is actively allocating huge pages, check the active anonymous huge page memory count:

grep AnonHugePages /proc/meminfo

A non-zero value in AnonHugePages confirms that the kernel is actively provisioning 2MB pages to running processes.
