Query Ubuntu Audit Logs Using Ausearch

The ausearch utility is a dedicated command-line tool used on Ubuntu to search, filter, and parse audit records generated by the Linux Audit Daemon (auditd). Because raw audit logs stored in /var/log/audit/audit.log are verbose and difficult to process manually, ausearch streamlines log analysis by grouping related messages into complete events and filtering them based on specific parameters. This article explains the primary role of ausearch, its core features, and how system administrators use it to simplify security auditing and incident response.

Understanding the Role of ausearch

The primary function of ausearch is to query the audit daemon logs for specific events, system calls, user actions, or file access attempts. Rather than relying on standard text-processing tools like grep, which treat each line independently, ausearch understands the internal structure of auditd logs and combines multi-line audit events that share the same event ID.

Key capabilities include:

  • Event Correlation: Reconstructs multi-record audit events into a single, cohesive view.
  • Targeted Filtering: Narrows down thousands of log entries based on specific criteria such as user ID, timestamp, process ID, or system call.
  • Human-Readable Parsing: Translates raw numerical data (such as UIDs, GIDs, and system call numbers) into human-readable names when invoked with the interpretation flag.

Common Filtering Options

ausearch provides several flags to query audit logs precisely:

  • By Time (-ts, -te): Filters logs starting from a specific time (-ts for start time) or ending at a specific time (-te for end time). Keywords like today, yesterday, recent, or explicit timestamps (mm/dd/yyyy hh:mm:ss) are supported.
  • By User ID (-ui): Searches for actions performed by a specific real user ID.
  • By Process ID (-p): Finds all audit records associated with a specific process ID.
  • By Audit Key (-k): Queries events tagged with a custom key defined in your /etc/audit/rules.d/ rule files (such as tracking modifications to /etc/passwd).
  • By Message Type (-m): Isolates specific event types, such as USER_LOGIN, SYSCALL, or CONFIG_CHANGE.
  • By Success Status (-sv): Filters logs based on whether an operation succeeded (yes) or failed (no).

Translating Numeric Values to Human-Readable Format

Raw audit logs store system calls, user IDs, and architecture types as numeric values. Adding the -i (or --interpret) flag to an ausearch command automatically converts these numeric identifiers into names (for example, converting UID 1000 to the account username, or syscall 59 to execve).

Example Usage

To query all failed login attempts from today and display the results in a human-readable format, run:

sudo ausearch -m USER_LOGIN -sv no -ts today -i

This command filters logs for login event types, selects only failed attempts, constrains the search to today, and translates IDs into readable names.

Conclusion

On Ubuntu, ausearch is an indispensable tool for system administrators and security analysts. By parsing raw auditd log files into structured events, it allows for fast, accurate troubleshooting, security auditing, and forensic analysis.
