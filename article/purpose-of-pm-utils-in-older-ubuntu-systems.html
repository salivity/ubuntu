Purpose of pm-utils in Older Ubuntu Systems

The pm-utils (Power Management Utilities) package was the foundational framework used in older Ubuntu releases to control power state transitions, specifically suspending, hibernating, and resuming the operating system. Before the widespread adoption of modern init systems like systemd, pm-utils provided the command-line binaries and modular scripting structure necessary to safely pause system operations, preserve hardware state, and reliably restore the computer when awakened.

Core Functions and Binaries

At its core, pm-utils offered straightforward commands that bridged the gap between user space and the Linux kernel's power management interfaces (such as /sys/power/state). The package provided three primary commands:

  • pm-suspend: Saved the system state to RAM and put the machine into a low-power sleep mode.
  • pm-hibernate: Wrote the contents of RAM to swap space on disk and powered down the machine completely.
  • pm-suspend-hybrid: Wrote system state to disk while keeping RAM powered, ensuring data was preserved even if battery power failed during suspend.

The Hook Architecture

The primary value of pm-utils was not merely signaling the kernel to sleep, but coordinating the software and hardware environments before and after the sleep state. It achieved this through an extensible hook directory system located in /etc/pm/sleep.d/ (for user-defined scripts) and /usr/lib/pm-utils/sleep.d/ (for distribution-provided scripts).

These hooks were numbered sequentially (e.g., 00powersave, 50unload_alpm, 99video) to determine their execution order. When a sleep command was triggered, pm-utils ran these scripts in numerical order with arguments like suspend or hibernate. Upon resume, the scripts ran in reverse order with arguments like resume or thaw.

Common Tasks Managed by pm-utils Scripts

Older hardware and drivers frequently struggled with power transitions. The script hooks within pm-utils resolved these issues by executing essential pre-sleep and post-wake maintenance tasks:

  • Kernel Module Management: Unloading problematic device drivers (such as legacy Wi-Fi or graphics drivers) before sleep and reloading them upon waking to prevent kernel panics.
  • Network and Service Handling: Disconnecting NetworkManager connections or stopping specific background daemons cleanly to avoid hanging sockets.
  • Hardware Re-initialization: Resetting the video card state using utilities like vbetool, restoring audio mixer settings via ALSA, or resetting USB controller states.
  • Screen Locking: Invoking desktop environment lock screens before the system entered suspend to maintain user security.

Obsolescence and Replacement

As Ubuntu transitioned to systemd (fully realized in Ubuntu 15.04 and 16.04 LTS), the responsibilities of pm-utils were superseded. Modern Ubuntu systems utilize systemd-logind and systemd-suspend.service to control power states. While systemd supports its own drop-in script directory (/lib/systemd/system-sleep/), modern Linux kernel drivers manage their own sleep and resume lifecycles far more reliably, largely eliminating the need for the extensive userspace workarounds that pm-utils previously handled.
