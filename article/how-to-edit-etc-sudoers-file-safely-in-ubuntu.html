How to Edit /etc/sudoers File Safely in Ubuntu

The /etc/sudoers file in Ubuntu is a critical system file that controls which users and groups are granted administrative privileges via the sudo command. Because a syntax error in this file can completely lock you out of administrative access, it must never be edited directly with standard text editors. This guide explains the purpose of the /etc/sudoers file, why manual edits are risky, and how to safely modify it using the built-in visudo utility.

Purpose of the /etc/sudoers File

The /etc/sudoers file defines the security policy for the sudo (Superuser Do) command. It specifies:

  • Which users or user groups can run administrative commands.
  • Which commands specific users are allowed to execute.
  • Whether a user needs to enter their password to execute a command.
  • Which hosts the rules apply to.

By default, Ubuntu uses this file to grant full root access to members of the sudo group.

Why You Should Never Edit /etc/sudoers Directly

Editing /etc/sudoers with standard text editors like nano or vim directly (e.g., sudo nano /etc/sudoers) is dangerous. If you introduce a typo, missing space, or invalid syntax, the system will fail to parse the file. As a result, the sudo command will stop working entirely, preventing all users from gaining root privileges to fix the mistake.

How to Edit /etc/sudoers Safely with visudo

To safely modify the sudoers configuration, always use the visudo command.

visudo locks the /etc/sudoers file against simultaneous edits, opens it in a text editor, and performs a strict syntax check before saving your changes. If it detects an error, it alerts you and prevents the bad configuration from taking effect.

Step 1: Open visudo

Run the following command in your terminal:

sudo visudo

Step 2: Change the Default Editor (Optional)

By default, visudo opens using nano or vim. If you prefer to use nano explicitly, you can set the environment variable before running the command:

sudo EDITOR=nano visudo

Step 3: Add or Modify Rules

Navigate through the file and add your custom rules. Common examples include:

  • Grant full sudo access to a user:

    username ALL=(ALL:ALL) ALL

  • Allow a user to run sudo without a password prompt:

    username ALL=(ALL:ALL) NOPASSWD: ALL

  • Allow a user to run a specific command without a password:

    username ALL=(ALL:ALL) NOPASSWD: /usr/sbin/service apache2 restart

Step 4: Save and Exit

  • In Nano: Press Ctrl + O then Enter to write the changes, and Ctrl + X to exit.
  • In Vim: Press Esc, type :wq, and press Enter.

Step 5: Handling Syntax Errors

If you made a syntax error, visudo will display a message such as parse error in /etc/sudoers near line X and prompt you with options:

  • Press e to re-edit the file and fix the mistake.
  • Press x to exit without saving the changes (preserving your working system).
  • Press Q to force save (not recommended, as this can break sudo).

Always choose e to correct the issue or x to discard invalid changes.

Best Practice: Using the /etc/sudoers.d/ Directory

Instead of modifying the main /etc/sudoers file, the safest approach is to create separate configuration files inside the /etc/sudoers.d/ directory.

To create or edit a file in this directory safely, use visudo with the -f flag:

sudo visudo -f /etc/sudoers.d/custom_rules

This keeps your custom configurations modular, easier to manage, and safe from being overwritten during system updates.
