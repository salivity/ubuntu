Fix Bufferbloat on Ubuntu Router Using fq_codel

Bufferbloat introduces crippling latency and jitter during high-bandwidth network usage by causing packets to queue up excessively in network hardware buffers. Implementing the Fair Queuing Controlled Delay (fq_codel) active queue management algorithm on an Ubuntu-based home router prioritizes interactive traffic (such as gaming, VoIP, and DNS lookups) over bulk transfers (like large file downloads or system updates). This guide provides the exact steps to identify your network interfaces, apply fq_codel with bandwidth shaping using Linux traffic control (tc), verify packet handling, and make the configuration persistent across reboots.

Step 1: Identify Your WAN Interface

To apply queue management to outbound traffic, determine the exact logical name of your WAN (Internet-facing) interface:

ip link show

Locate the interface connected to your modem or upstream optical network terminal (ONT). Common names include eth0, enp3s0, or a virtual interface like ppp0 if using PPPoE.

Step 2: Configure Traffic Shaping and fq_codel

Applying fq_codel directly to an interface only mitigates bufferbloat if the router's physical port is the true bottleneck. Because your WAN port typically negotiates at 1 Gbps or 2.5 Gbps while your ISP plan provides less bandwidth, you must shape traffic slightly below your provisioned upload speed.

Use the tc (traffic control) tool to create a Hierarchical Token Bucket (HTB) and attach fq_codel to it.

Run the following commands, replacing eth0 with your WAN interface and 95mbit with approximately 90–95% of your measured upload bandwidth:

# 1. Clear any existing queuing disciplines on the interface
sudo tc qdisc del dev eth0 root 2>/dev/null

# 2. Create the root HTB qdisc
sudo tc qdisc add dev eth0 root handle 1: htb default 10

# 3. Create a rate-limiting class set to your usable upload speed
sudo tc class add dev eth0 parent 1: classid 1:10 htb rate 95mbit ceil 95mbit

# 4. Attach fq_codel as the leaf queue under the shaped class
sudo tc qdisc add dev eth0 parent 1:10 handle 100: fq_codel

Step 3: Verify the Configuration

Verify that fq_codel is actively attached to your interface:

tc -s qdisc show dev eth0

The output will confirm the presence of both the htb root qdisc and the fq_codel leaf. You will see active statistics such as flows, dropped, and marks updating as traffic flows through the router.

Step 4: Make the Configuration Persistent

Commands executed directly via tc do not persist across reboots. To ensure the rules are applied on system startup, create a dedicated systemd service.

Create a new service file:

sudo nano /etc/systemd/system/bufferbloat-fqcodel.service

Add the following configuration, adjusting the interface name (eth0) and upload rate (95mbit) to match your network:

[Unit]
Description=Apply fq_codel and Traffic Shaping to WAN
After=network-online.target
Wants=network-online.target

[Service]
Type=oneshot
RemainAfterExit=yes
ExecStart=/sbin/tc qdisc del dev eth0 root 2>/dev/null || true
ExecStart=/sbin/tc qdisc add dev eth0 root handle 1: htb default 10
ExecStart=/sbin/tc class add dev eth0 parent 1: classid 1:10 htb rate 95mbit ceil 95mbit
ExecStart=/sbin/tc qdisc add dev eth0 parent 1:10 handle 100: fq_codel
ExecStop=/sbin/tc qdisc del dev eth0 root

[Install]
WantedBy=multi-user.target

Reload the systemd daemon, enable the service, and start it:

sudo systemctl daemon-reload
sudo systemctl enable bufferbloat-fqcodel.service
sudo systemctl start bufferbloat-fqcodel.service

Check the status to ensure the service executed without errors:

sudo systemctl status bufferbloat-fqcodel.service

Your Ubuntu router will now automatically apply fq_codel on every boot, keeping round-trip latency consistently low even during peak upload saturation.
