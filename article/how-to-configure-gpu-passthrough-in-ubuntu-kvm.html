How to Configure GPU Passthrough in Ubuntu KVM

Configuring GPU PCI passthrough on an Ubuntu KVM (Kernel-based Virtual Machine) host grants a virtual machine direct access to a physical graphics card, achieving near-native graphical and compute performance. This process involves enabling hardware virtualization extensions in the system BIOS, configuring the IOMMU controller in Linux, isolating the target GPU using VFIO drivers, and attaching the device to your guest virtual machine using Virt-Manager or virsh.

Prerequisites

  • An Intel CPU with VT-x and VT-d enabled, or an AMD CPU with AMD-V and AMD-Vi enabled in the BIOS/UEFI.
  • A dedicated secondary GPU for passthrough (recommended, as the host needs a primary display adapter).
  • An Ubuntu host system running KVM, QEMU, and libvirt.

Step 1: Enable IOMMU in the Bootloader

To allow the host system to isolate PCI devices, you must enable Input-Output Memory Management Unit (IOMMU) support in GRUB.

  1. Open the GRUB configuration file for editing:

    sudo nano /etc/default/grub

  2. Locate the line beginning with GRUB_CMDLINE_LINUX_DEFAULT and append the appropriate IOMMU flags:

    • For Intel CPUs: 
      GRUB_CMDLINE_LINUX_DEFAULT="quiet splash intel_iommu=on iommu=pt"
    • For AMD CPUs: 
      GRUB_CMDLINE_LINUX_DEFAULT="quiet splash amd_iommu=on iommu=pt"

  3. Update GRUB and restart your system:

    sudo update-grub
sudo reboot

  4. Verify that IOMMU is enabled after rebooting:

    dmesg | grep -i -E "dmar|iommu"

    Look for logs indicating "DMAR: IOMMU enabled" or "AMD-Vi: Initialized".

Step 2: Identify the GPU and Audio PCI IDs

You must identify the specific Vendor and Device IDs for the GPU and its integrated audio controller.

  1. List all PCI devices and filter for your graphics card:

    lspci -nn | grep -i -E "vga|3d|audio"

  2. Note the hexadecimal IDs inside the square brackets at the end of the line for both the video and audio devices. Example output:

    01:00.0 VGA compatible controller [0300]: NVIDIA Corporation [10de:1b80] (rev a1)
01:00.1 Audio device [0403]: NVIDIA Corporation [10de:10f0] (rev a1)

    In this example, the device IDs are 10de:1b80 and 10de:10f0.

Step 3: Configure VFIO Drivers

Isolate the GPU from the host operating system by assigning it to the vfio-pci driver upon boot.

  1. Create a VFIO configuration file:

    sudo nano /etc/modprobe.d/vfio.conf

  2. Add your hardware IDs (replace 10de:1b80,10de:10f0 with your actual IDs):

    options vfio-pci ids=10de:1b80,10de:10f0

  3. Ensure VFIO modules load before host GPU drivers. Edit /etc/modules:

    sudo nano /etc/modules

    Add the following lines:

    vfio
vfio_iommu_type1
vfio_pci
vfio_virqfd

  4. Blacklist default GPU drivers to prevent the host from claiming the card (optional for dedicated secondary GPUs, required for single-GPU setups):

    sudo nano /etc/modprobe.d/blacklist.conf

    Add the relevant driver (e.g., nouveau, nvidia, amdgpu, or radeon):

    blacklist nouveau
blacklist nvidia

  5. Update initramfs and reboot:

    sudo update-initramfs -u -k all
sudo reboot

Step 4: Confirm Driver Binding

After rebooting, verify that the GPU is using the vfio-pci kernel driver:

lspci -nnk -d 10de:

Check the Kernel driver in use: output line. It should display vfio-pci for both the VGA and Audio devices.

Step 5: Attach the GPU to the Guest VM

Method A: Using Virt-Manager (GUI)

  1. Open Virtual Machine Manager (virt-manager).
  2. Open the Target VM details (Lightbulb icon).
  3. Click Add Hardware > PCI Host Device.
  4. Select the GPU's main PCI entry (e.g., 0000:01:00.0) and click Finish.
  5. Click Add Hardware > PCI Host Device again, and select the GPU's companion audio device (e.g., 0000:01:00.1).
  6. Start the virtual machine and install the official graphics drivers inside the guest operating system.

Method B: Using Virsh (CLI)

  1. Find the host device XML name format:

    virsh nodedev-list --tree | grep pci

  2. Attach the devices to your guest XML configuration using virsh edit <vm-name> under the <devices> section:

    <hostdev mode='subsystem' type='pci' managed='yes'>
  <source>
    <address domain='0x0000' bus='0x01' slot='0x00' function='0x0'/>
  </source>
</hostdev>
<hostdev mode='subsystem' type='pci' managed='yes'>
  <source>
    <address domain='0x0000' bus='0x01' slot='0x00' function='0x1'/>
  </source>
</hostdev>
