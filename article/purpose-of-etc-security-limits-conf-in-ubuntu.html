Purpose of /etc/security/limits.conf in Ubuntu

The /etc/security/limits.conf file in Ubuntu is a core configuration file used by the Pluggable Authentication Modules (PAM) framework to control system resource consumption on a per-user or per-group basis. This article explains the primary function of the file, how soft and hard resource limits operate, the syntax used to define rule parameters, common configuration examples, and how to verify that your limit settings are applied correctly.

Core Function of limits.conf

In Ubuntu and other Linux distributions, system stability relies on preventing any single user or process from consuming all available system resources. The /etc/security/limits.conf file acts as the configuration interface for the pam_limits.so module. When a user logs in or starts a session authenticated via PAM, this module reads the file and enforces resource boundaries on the user’s shell and spawned processes.

Controlling resources through this file helps prevent: * Denial of Service (DoS): Uncontrolled loops or fork bombs exhausting process IDs or CPU time. * Resource Starvation: Single applications consuming all open file descriptors, blocking other critical system services. * Memory Exhaustion: Unrestricted memory allocations causing system-wide slowdowns or triggering the kernel Out-Of-Memory (OOM) killer.

Soft vs. Hard Limits

Resource constraints defined in limits.conf fall into two distinct categories:

  • Soft Limits: The default limit enforced for a user or session. Users can increase their soft limit up to the value of the hard limit using shell commands like ulimit.
  • Hard Limits: The absolute ceiling set by the system administrator. Non-root users cannot increase a hard limit beyond this value, nor can they raise their soft limit higher than the hard limit.

File Syntax and Structure

Each non-comment line in /etc/security/limits.conf consists of four fields separated by spaces or tabs:

<domain>    <type>    <item>    <value>
  1. Domain: Specifies who the limit applies to. This can be:
    • A user name (e.g., john).
    • A group name, prefixed with @ (e.g., @developers).
    • The wildcard *, which applies to all non-root users.
  2. Type: Specifies the limit type:
    • soft
    • hard
    • - (enforces both soft and hard limits simultaneously).
  3. Item: The specific resource to limit. Common items include:
    • nofile: Maximum number of open file descriptors.
    • nproc: Maximum number of processes allowed for the user.
    • memlock: Maximum locked-in-memory space (KB).
    • cpu: Maximum CPU time in minutes.
    • fsize: Maximum file size created by the user (KB).
    • as: Address space limit / virtual memory limit (KB).
  4. Value: The numerical limit assigned to the item (or unlimited).

Practical Usage Examples

Increasing Open File Limits for Databases or Web Servers

High-performance services like MySQL, Nginx, or Elasticsearch often require opening thousands of network connections and files simultaneously. To allow the www-data user to handle heavy loads:

www-data    soft    nofile    65536
www-data    hard    nofile    65536

Preventing Process Flooding

To prevent users in the students group from launching too many background processes:

@students    hard    nproc    100

Setting Global Defaults

To set a baseline for all regular users while preventing extreme system resource abuse:

*    soft    nofile    4096
*    hard    nofile    10240
*    hard    nproc     2048

Applying and Verifying Changes

Changes made to /etc/security/limits.conf do not apply to currently active sessions. For the limits to take effect:

  1. The affected user must log out and establish a new session.

  2. Ensure that /etc/pam.d/common-session includes the PAM limits line:

    session required pam_limits.so

To verify active limits inside a user session, run the shell built-in command:

  • View current soft limits: ulimit -a
  • View current hard limits: ulimit -Ha
  • Check specific open file limit: ulimit -n
