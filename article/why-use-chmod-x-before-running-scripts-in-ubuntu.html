Why Use chmod +x Before Running Scripts in Ubuntu

The chmod +x command in Ubuntu grants execution permissions to a file, transforming a plain text file into a runnable program. By default, Linux systems restrict newly created files from executing to protect the operating system from malicious or accidental execution. This article explains how Linux permissions work, why the "Permission denied" error occurs when launching new scripts, and how chmod +x allows you to execute custom scripts directly from the terminal.

Understanding File Permissions in Ubuntu

Ubuntu, like all Linux distributions, relies on a strict file permission model based on three access levels:

  • Read (r): Allows viewing the file's contents.
  • Write (w): Allows modifying or deleting the file.
  • Execute (x): Allows running the file as a program or script.

These permissions are assigned across three distinct scopes: the user (owner), the group, and others (everyone else).

When you create a script using a text editor like nano or vim, Ubuntu typically assigns default read and write permissions (often rw-r--r--). Notice that the execute flag (x) is missing. Because the kernel treats the file strictly as text, it will actively refuse to run it as code.

The Purpose of the chmod +x Command

The name chmod stands for change mode, which refers to modifying the permission mode of a file or directory.

Breaking down the syntax:

  • chmod: The system utility used to modify file system flags.
  • +: Instructs the system to grant (add) the designated permission.
  • x: Specifies the execute permission.

Running chmod +x filename.sh marks the file as executable for the user, the group, and all other users on the system. If you only want to grant execution permissions to yourself (the file owner), you can alternatively use chmod u+x filename.sh.

What Happens Without chmod +x?

If you try to run a custom script directly without setting execution permissions:

./myscript.sh

The terminal will return an error:

bash: ./myscript.sh: Permission denied

While you can bypass this error by explicitly passing the file to an interpreter (for example, bash myscript.sh), doing so requires you to specify the runtime manually every time.

Adding the execute permission allows the operating system to inspect the first line of the file—known as the shebang (e.g., #!/bin/bash or #!/usr/bin/env python3)—and automatically call the correct interpreter.

How to Apply and Verify the Execute Permission

To properly prepare and run a custom script in Ubuntu:

  1. Add execute permissions:

    chmod +x myscript.sh

  2. Verify the change: Run ls -l myscript.sh to inspect the permissions. You will see an x appear in the output flags (e.g., -rwxr-xr-x), and the filename will often change color in the terminal:

    -rwxr-xr-x 1 user user 120 May 10 10:00 myscript.sh

  3. Run your script: Now you can execute the script directly from its relative path:

    ./myscript.sh

Using chmod +x ensures that Ubuntu handles your script as a standalone command while maintaining the system's security architecture by requiring explicit permission before any code can run.
