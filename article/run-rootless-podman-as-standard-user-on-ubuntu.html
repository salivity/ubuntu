Run Rootless Podman as Standard User on Ubuntu

Running Podman in rootless mode allows standard users to create, run, and manage containers without requiring root privileges or a background daemon. This guide covers how to set up user namespaces, install Podman on Ubuntu, configure sub-UIDs and sub-GIDs, and run your first isolated container entirely within the context of an unprivileged standard user account.

Step 1: Install Podman and Dependencies

Log in to Ubuntu and install Podman alongside the uidmap package, which provides the tools needed for managing user namespace mappings:

sudo apt update
sudo apt install -y podman uidmap

Step 2: Configure Subordinate UIDs and GIDs

Rootless containers rely on user namespaces to map a range of user IDs (UIDs) and group IDs (GIDs) on the host to IDs inside the container.

Check if your user already has sub-UID and sub-GID ranges allocated:

grep $USER /etc/subuid
grep $USER /etc/subgid

If these commands return a line similar to username:100000:65536, your ranges are already active. If no output appears, allocate a range by running:

sudo usermod --add-subuids 100000-165535 $USER
sudo usermod --add-subgids 100000-165535 $USER

After modifying these files, apply the new user namespace settings by running:

podman system migrate

Step 3: Enable Lingering (Optional)

If you plan to run long-lived containers or services via systemd that persist after logging out, enable user lingering for your account:

loginctl enable-linger $USER

Step 4: Verify Rootless Operation

Make sure you are logged in as the standard user (not using sudo). Run a quick diagnostic to confirm Podman recognizes rootless mode:

podman info

Look for rootless: true in the output under the host section.

Step 5: Run a Test Container

You can now launch and test a container without root permissions:

podman run --rm -it alpine whoami

This command pulls the Alpine image and runs whoami, returning root. Inside the container's isolated namespace, the user appears as root, but on the host system, the process is mapped strictly to your standard unprivileged UID.

To test port mapping without root permissions, use ports above 1024:

podman run -d --name web -p 8080:80 nginx

Verify the running container:

podman ps
curl http://localhost:8080

To stop and remove the container:

podman stop web
podman rm web
