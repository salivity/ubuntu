Purpose of /proc/sys/kernel/sysrq in Ubuntu

The /proc/sys/kernel/sysrq file in Ubuntu controls the activation and functional permissions of the Magic SysRq key, a low-level key combination built into the Linux kernel. This article explains what the file does, how its numerical values alter kernel responsiveness during system freezes, and how to configure it to safely perform emergency recoveries like the REISUB sequence.

Understanding /proc/sys/kernel/sysrq

In Ubuntu and other Linux distributions, /proc/sys/ provides an interface to view and modify kernel parameters at runtime. The /proc/sys/kernel/sysrq file specifically manages the Magic SysRq feature.

When a system completely freezes and the graphical interface or terminal stops responding, the standard user space is blocked. However, as long as the Linux kernel is still running, it can listen to lower-level input via the SysRq key (usually Alt + Print Screen). Reading from or writing to /proc/sys/kernel/sysrq controls which emergency commands the kernel is allowed to accept via these key combinations.

Values and Bitmask Settings

The contents of /proc/sys/kernel/sysrq dictate which SysRq functions are available. The file accepts a single integer value:

  • 0: Disables SysRq completely. The kernel ignores all emergency keyboard commands.
  • 1: Enables all SysRq functions. The kernel processes every supported emergency command.

Values greater than 1 act as a bitmask to enable specific subsets of SysRq functions:

  • 2: Enable control of console log level.
  • 4: Enable keyboard control (SAK).
  • 8: Enable debugging dumps of processes.
  • 16: Enable the sync command (s).
  • 32: Enable remounting filesystems as read-only (u).
  • 64: Enable signaling processes (term/kill: e, i).
  • 128: Enable reboot/poweroff (b, o).
  • 256: Enable setting nice real-time priority for tasks.

Ubuntu often sets a default bitmask value (such as 176, which is a combination of 16 + 32 + 128), allowing users to sync disks, remount filesystems as read-only, and reboot the machine without enabling potentially hazardous debugging features.

Managing the SysRq Configuration

Changing Values Temporarily

To enable all SysRq commands for the current session, write 1 to the file with root privileges:

echo "1" | sudo tee /proc/sys/kernel/sysrq

This change takes effect immediately but resets upon reboot.

Changing Values Permanently

To ensure all emergency functions remain enabled permanently across system reboots, edit the sysctl configuration.

  1. Open or create a configuration file in /etc/sysctl.d/:
sudo nano /etc/sysctl.d/99-sysrq.conf
  1. Add the following line to enable all commands:
kernel.sysrq = 1
  1. Apply the changes immediately:
sudo sysctl -p /etc/sysctl.d/99-sysrq.conf

Practical Emergency Application: The REISUB Sequence

With SysRq enabled via /proc/sys/kernel/sysrq, you can safely recover a frozen Ubuntu system without forcing a hard power-off. Holding down Alt + Print Screen while typing the following sequence in order performs a safe restart:

  1. r (unRaw): Takes control of the keyboard back from the X server.
  2. e (tErminate): Sends SIGTERM to all processes except init.
  3. i (kIll): Sends SIGKILL to any processes that refused to terminate.
  4. s (Sync): Flushes cached data to the hard drive to prevent corruption.
  5. u (Unmount): Remounts all filesystems as read-only to protect data.
  6. b (reBoot): Immediately reboots the computer.
