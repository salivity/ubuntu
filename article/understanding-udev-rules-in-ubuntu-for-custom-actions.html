Understanding udev Rules in Ubuntu for Custom Actions

In Ubuntu, udev is the Linux kernel's dynamic device manager responsible for handling device nodes in the /dev directory. The primary purpose of udev rules is to give system administrators and users fine-grained control over how the operating system responds to hardware events, such as plugging in or removing a USB drive, network card, or serial device. By writing custom udev rules, you can automate task execution, enforce consistent device naming, modify access permissions, and seamlessly integrate new hardware into system workflows.

Core Purposes of udev Rules

When a new device is connected to an Ubuntu system, the kernel detects it and generates a uevent. The udev daemon processes this event by evaluating defined rules against the device's attributes. Its main functions include:

1. Assigning Persistent Device Names

By default, Ubuntu assigns names to connected devices dynamically (such as /dev/sdb1 or /dev/ttyUSB0). These names can change across reboots depending on the order devices are plugged in. Custom udev rules allow you to create fixed symbolic links (symlinks) based on unique hardware attributes like vendor IDs, product IDs, or serial numbers. This guarantees that your scripts always reference the correct hardware.

2. Automating Custom Scripts and Commands

udev rules can trigger external scripts or commands immediately upon device detection or removal using the RUN key. For example, plugging in an external backup drive can automatically launch a backup script, or attaching a specific peripheral can start a background daemon.

3. Managing Access Permissions and Ownership

Certain hardware devices (such as microcontrollers, specialized USB tools, or custom peripherals) require root privileges to access by default. Using udev rules, you can set custom file permissions (MODE), user ownership (OWNER), or group access (GROUP) so that unprivileged users can interact with specific hardware without using sudo.

4. Setting Custom Device Attributes and Environment Variables

Rules can set environment variables for system service managers like systemd. This allows plugged-in devices to trigger systemd services, enable power management settings, or alter kernel parameters specifically for that hardware.

How udev Rules Function in Ubuntu

Rule files are stored in designated directories, evaluated in lexical order:

  • /etc/udev/rules.d/ (User-defined custom rules, prioritized highest)
  • /run/udev/rules.d/ (Runtime-generated rules)
  • /lib/udev/rules.d/ (System default rules)

Basic Rule Structure

A udev rule consists of match keys (to identify the device) and assignment keys (to specify actions):

  • Match Keys: Attributes like SUBSYSTEM, ATTRS{idVendor}, ATTRS{idProduct}, or KERNEL.
  • Assignment Keys: Directives like SYMLINK, MODE, OWNER, GROUP, or RUN.

Example Scenario

To automatically assign a persistent symlink named /dev/my_sensor and execute a script when a specific USB-to-Serial adapter is plugged in, a rule inside /etc/udev/rules.d/99-custom-sensor.rules would look like this:

SUBSYSTEM=="tty", ATTRS{idVendor}=="0403", ATTRS{idProduct}=="6001", SYMLINK+="my_sensor", RUN+="/usr/local/bin/notify_plugin.sh"

Whenever the device matching vendor ID 0403 and product ID 6001 connects:

  1. udev verifies the match conditions.
  2. A symbolic link pointing to the device node is created at /dev/my_sensor.
  3. The script /usr/local/bin/notify_plugin.sh runs automatically in the background.
