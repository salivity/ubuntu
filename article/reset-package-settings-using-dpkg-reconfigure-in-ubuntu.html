Reset Package Settings Using dpkg-reconfigure in Ubuntu

The dpkg-reconfigure command is a core utility in Ubuntu and Debian-based systems designed to re-open the initial configuration interface of already installed packages. Instead of requiring administrators to remove and reinstall software to fix misconfigurations, this tool accesses the debconf database to prompt users with the package setup questions again and regenerate configuration files. This article explains how dpkg-reconfigure works, its role in resetting system settings, and how to use it effectively with different configuration priorities and frontends.

What is dpkg-reconfigure?

In Ubuntu, many packages rely on debconf, a backend configuration management system. When you first install a service or system tool, debconf asks questions regarding basic setup—such as setting the system timezone, defining default locales, or configuring an display manager.

Once installation finishes, those questions are typically not shown again during updates. The dpkg-reconfigure tool exposes these configuration stages on demand, allowing you to alter or reset existing settings without altering the underlying package binaries.

How dpkg-reconfigure Resets Settings

When you run dpkg-reconfigure, the following steps occur:

  1. Loads the debconf Database: It queries the package's configuration script and template files to identify which settings can be adjusted.
  2. Prompts the Administrator: It launches an interactive menu presenting the original configuration prompts, often prepopulated with current or default choices.
  3. Executes Post-Installation Scripts: Once choices are submitted, the command runs the package's postinst (post-installation) script.
  4. Regenerates Configuration Files: The script writes the new values into the appropriate configuration files in /etc/ and restarts relevant system services if necessary.

This method is faster and safer than running apt purge followed by apt install, as it preserves package dependencies and binary files while targeting only configuration parameters.

Basic Syntax and Common Examples

The standard syntax requires administrative privileges:

sudo dpkg-reconfigure [options] package-name

Common system packages frequently managed with this command include:

  • Timezone configuration:

    sudo dpkg-reconfigure tzdata

    Opens the interactive menu to select your geographic area and time zone, immediately updating /etc/timezone and /etc/localtime.

  • System locales:

    sudo dpkg-reconfigure locales

    Allows you to generate new character sets and choose the primary system language.

  • Keyboard mapping:

    sudo dpkg-reconfigure keyboard-configuration

    Guides you through selecting keyboard models, layouts, and key combinations.

Adjusting Priority and Interface

By default, dpkg-reconfigure only shows questions categorized with a priority level equal to or higher than the system default (usually high). If you need to access every hidden setting or perform a complete, granular reset, use the -p (priority) flag:

  • low: Displays all questions, offering the most comprehensive configuration reset.
  • medium: Displays normal questions.
  • high: Displays questions with non-reasonable defaults.
  • critical: Displays only questions that could break the system if unanswered.

To see all available options for a package:

sudo dpkg-reconfigure -p low package-name

You can also specify the frontend interface with the -f flag. Options include dialog (default terminal menu), readline (plain text for basic terminals), and noninteractive (applies defaults without prompts):

sudo dpkg-reconfigure -f readline package-name

Limitations

While dpkg-reconfigure is effective, it only resets files and settings managed directly by debconf. If a user manually edits a configuration file in a way that diverges from the template generated by debconf, the package script may preserve the custom edits rather than overwriting them. For complete resets of manually altered files, inspecting /etc/ or consulting the package's default templates in /usr/share/ may still be necessary.
