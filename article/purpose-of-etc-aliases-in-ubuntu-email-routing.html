Purpose of /etc/aliases in Ubuntu Email Routing

The /etc/aliases file in Ubuntu serves as a system-wide configuration table used by Mail Transfer Agents (MTAs) like Postfix, Sendmail, or Exim to redirect local email messages to different local user accounts, external email addresses, files, or executable scripts. This article explains the primary function of the /etc/aliases file, details its syntax, outlines common use cases, and demonstrates how to apply changes effectively within your server's mail system.

Primary Functions of /etc/aliases

When a system process, cron job, or local user sends an email on an Ubuntu server, the local MTA consults the /etc/aliases file to determine the actual destination for the message. Its main roles include:

  1. Forwarding System Alerts: By default, system daemons send critical alerts and logs to local accounts such as root, postmaster, or webmaster. Since administrators rarely log in as root to check local mail directly, /etc/aliases redirects these emails to a real user account or an external inbox.
  2. Creating Local Email Groups: It allows administrators to create a single alias that redistributes incoming mail to multiple recipients.
  3. Piping Mail to Commands: Emails sent to a specific local address can be passed directly to a script or application for processing, which is common in automated ticketing or logging systems.
  4. Appending Mail to Files: Incoming emails can be routed directly to append to a specified text file on disk.

File Syntax and Structure

The syntax of the /etc/aliases file is straightforward. Each entry consists of a key (the local alias name) followed by a colon and one or more comma-separated destinations.

# Basic format
name: destination1, destination2, ...

Common Configuration Examples

  • Forwarding to a Local User: Redirects email intended for postmaster to a local system account named sysadmin.

    postmaster: sysadmin

  • Forwarding to an External Email Address: Routes all system emails sent to root to an off-server corporate email address.

    root: admin@example.com

  • Routing to Multiple Destinations: Sends messages directed to alerts to both a local user and an external address.

    alerts: sysadmin, primary-tech@example.com

  • Piping to an Executable Script: Passes incoming emails for support as standard input to a custom script.

    support: "|/usr/local/bin/process_ticket.py"

Applying Changes with the newaliases Command

MTAs do not directly read the plain text /etc/aliases file for every email lookup due to performance considerations. Instead, they read a binary database file (typically /etc/aliases.db) built from /etc/aliases.

After editing the /etc/aliases file, you must run the following command to compile your changes into the indexed database:

sudo newaliases

If you do not execute sudo newaliases after modifying the file, the MTA will continue using the old configuration, and your updated email routing rules will not take effect.
