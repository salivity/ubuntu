What Is /etc/apt/apt.conf.d in Ubuntu?

The /etc/apt/apt.conf.d directory is a crucial component of Ubuntu’s Advanced Package Tool (APT) system, used to store modular configuration snippets that dictate how package management behaves. This article explains the purpose of /etc/apt/apt.conf.d, how APT processes its configuration files, and practical examples of how system administrators use this directory to customize package installations, updates, and repository settings.

Understanding the Modular APT Configuration

Ubuntu and Debian-based systems use APT to install, update, and remove software. Historically, APT configuration was stored in a single file located at /etc/apt/apt.conf.

Modern Ubuntu systems favor a modular approach. Instead of editing a single main configuration file—which can easily be overwritten or broken during system upgrades—APT scans the /etc/apt/apt.conf.d/ directory and merges all the individual configuration files found inside it into a single runtime configuration.

How APT Reads Configuration Fragments

APT loads the files in /etc/apt/apt.conf.d in a specific order based on their filenames:

  1. Numerical Sorting: Files are read in numerical and lexicographical (alphabetical) order.
  2. Precedence: Settings parsed later in the sequence overwrite conflicting settings defined in earlier files.
  3. Naming Convention: Most files use a two-digit prefix (such as 01, 20, or 50) followed by a descriptive name (e.g., 50unattended-upgrades). Lower numbers are processed first, and higher numbers are processed last.

For example, a directive set in 99mysettings will override a conflicting directive defined in 01autoremove.

Purpose and Key Use Cases

The primary purpose of /etc/apt/apt.conf.d is to allow package maintainers, automated scripts, and system administrators to modify APT’s behavior without interfering with each other’s configuration files.

1. Application-Specific Settings

When you install specific system utilities, they often drop their own configuration files into this directory. For example: * 50unattended-upgrades manages automatic security updates. * 01autoremove defines rules for clearing out unused dependencies.

2. Customizing Network and Proxy Settings

If your Ubuntu machine operates behind a corporate proxy, you can create a custom file (e.g., 90proxy) inside /etc/apt/apt.conf.d to define network routes for APT:

Acquire::http::Proxy "http://proxy.example.com:8080/";
Acquire::https::Proxy "https://proxy.example.com:8080/";

3. Modifying Package Installation Behavior

Administrators can control default installation parameters, such as disabling recommended packages to save disk space. Creating a file named 99norecommends with the following content achieves this:

APT::Install-Recommends "false";
APT::Install-Suggests "false";

4. Tuning Update Check Intervals

You can control how often APT refreshes package lists or checks for updates automatically by adding periodic configuration directives:

APT::Periodic::Update-Package-Lists "1";
APT::Periodic::Unattended-Upgrade "1";

Syntax Rules for Files in /etc/apt/apt.conf.d

When adding or modifying files in this directory, keep the following rules in mind:

  • End with Semicolons: Every configuration line must end with a semicolon ;.
  • Grouped Block Structure: Options can use tree notation (APT::Get::Assume-Yes "true";) or block notation.
  • No File Extensions Required: Files do not need a .conf extension; APT reads any valid file inside the directory unless the filename contains invalid characters (such as period extensions like .bak or .disabled, which APT ignores).

Verifying the Final Configuration

Because APT merges multiple files from /etc/apt/apt.conf.d, you can view the complete, active APT configuration by running:

apt-config dump

To check a specific configuration key (e.g., proxy settings), filter the output:

apt-config dump | grep -i proxy
