Advertise BGP Routes from Ubuntu to Cloud

Advertising a BGP prefix from an Ubuntu instance to a cloud provider involves establishing an external Border Gateway Protocol (eBGP) peering session using a routing daemon such as FRRouting (FRR) or BIRD. By configuring the local Autonomous System Number (ASN), defining peering parameters for the cloud gateway (such as AWS Direct Connect, Azure ExpressRoute, or Google Cloud Router), and originating the network route, you can dynamically announce private or public IP ranges to your cloud infrastructure.

1. Prerequisites and Network Setup

Before beginning the configuration, ensure you have the following information from your cloud provider:

  • Peer IP Address: The IP assigned to the cloud provider's BGP router.
  • Local IP Address: The IP assigned to your Ubuntu instance for peering (often via a tunnel interface or dedicated virtual network interface).
  • Cloud ASN: The Autonomous System Number used by the cloud provider (e.g., 64512).
  • Local ASN: Your assigned public or private ASN.
  • Prefix to Advertise: The network block (e.g., 192.168.100.0/24) you intend to announce.

2. Install FRRouting (FRR)

FRR is a robust, production-grade routing suite natively supported on Ubuntu.

Update your package index and install FRR:

sudo apt update
sudo apt install frr -y

3. Enable the BGP Daemon

By default, the BGP daemon is disabled in FRR. Enable it by modifying the daemons configuration file:

sudo nano /etc/frr/daemons

Locate the line bgpd=no and change it to:

bgpd=yes

Save and exit the file, then restart the FRR service:

sudo systemctl restart frr

4. Ensure Prefix Presence in Kernel Routing

BGP will only advertise a route if that exact prefix exists in the host's kernel routing table. If the subnet is not assigned to a physical interface, add a blackhole route or bind it to a dummy/loopback interface:

sudo ip route add 192.168.100.0/24 dev lo

To make this persistent across reboots, add the route to your /etc/netplan/*.yaml file under the loopback or primary interface definition.

5. Configure BGP Peering and Prefix Advertisement

Access the FRR integrated shell using vtysh:

sudo vtysh

Enter configuration mode and define your BGP instance, neighbor relationship, and network advertisement:

configure terminal

router bgp 65001
 neighbor 169.254.10.1 remote-as 64512
 neighbor 169.254.10.1 description Cloud-Peer

 address-family ipv4 unicast
  network 192.168.100.0/24
  neighbor 169.254.10.1 activate
  neighbor 169.254.10.1 soft-reconfiguration inbound
 exit-address-family
exit

write memory
exit

Replace 65001 with your Local ASN, 169.254.10.1 with the Cloud Peer IP, 64512 with the Cloud ASN, and 192.168.100.0/24 with your target prefix.

6. Verify the BGP Session and Advertised Routes

To verify that the peering session is operational and the prefix is being transmitted:

Check BGP session state:

sudo vtysh -c "show ip bgp summary"

The state should transition to Established, showing a positive counter under PfxRcd or State/PfxRcd.

Check prefixes advertised to the cloud peer:

sudo vtysh -c "show ip bgp neighbors 169.254.10.1 advertised-routes"

The output should list your designated prefix (192.168.100.0/24) with the local interface IP set as the next hop. Verify via your cloud provider's console or CLI that the prefix is successfully received in the cloud routing table.
