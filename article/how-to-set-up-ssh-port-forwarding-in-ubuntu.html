How to Set Up SSH Port Forwarding in Ubuntu

SSH port forwarding, or SSH tunneling, is a powerful technique used to route network traffic through an encrypted SSH connection to bypass restrictive firewalls and secure unencrypted communications on Ubuntu. This guide covers the three main types of SSH port forwarding—Local, Remote, and Dynamic—providing straightforward commands and clear examples so you can quickly access restricted services or secure your internet traffic.

Prerequisites

Before getting started, ensure you have:

  • An Ubuntu system with a terminal open.
  • An SSH user account and IP address (or domain) for a remote server.
  • SSH client installed (pre-installed on most Ubuntu versions).

1. Local Port Forwarding

Local port forwarding redirects traffic from your local machine to a destination server through the SSH server. This is ideal for accessing a service on a remote network (like a database or web dashboard) that is blocked by a firewall.

Syntax:

ssh -L [local_port]:[destination_ip]:[destination_port] [user]@[ssh_server]

Example: To access a web server running on 192.168.1.50:80 inside a private network via your remote SSH server (remote-server.com), run:

ssh -L 8080:192.168.1.50:80 user@remote-server.com

Now, open your local web browser and navigate to http://localhost:8080 to access the remote web server.

2. Remote Port Forwarding

Remote port forwarding allows a remote server to access a service running on your local Ubuntu machine. This is useful for exposing a local web application under development to an external server.

Syntax:

ssh -R [remote_port]:[destination_ip]:[destination_port] [user]@[ssh_server]

Example: To share a web application running on your local machine at port 3000 so that users on the remote SSH server can access it on port 9090:

ssh -R 9090:localhost:3000 user@remote-server.com

Anyone connected to the remote server can now access your local service at http://localhost:9090.

3. Dynamic Port Forwarding (SOCKS Proxy)

Dynamic port forwarding turns your SSH connection into a SOCKS proxy server. This routes all traffic from specific applications (like a web browser) through the SSH server, effectively bypassing local firewalls and encrypting your general web browsing.

Syntax:

ssh -D [local_port] [user]@[ssh_server]

Example: To create a SOCKS proxy on local port 1080:

ssh -D 1080 user@remote-server.com

Configure Your Application:

  1. Open your browser settings (e.g., Firefox or Chrome).
  2. Go to Network Settings > Manual Proxy Configuration.
  3. Set the SOCKS Host to 127.0.0.1 and the Port to 1080.
  4. Select SOCKS v5.

All browser traffic will now route through the remote SSH server.

Useful SSH Flags for Tunneling

Combine these flags with your SSH commands to optimize background tunnels:

  • -N: Tells SSH not to execute a remote command (useful just for forwarding ports).
  • -f: Requests SSH to go to the background just before command execution.
  • -C: Enables compression to speed up data transfer.

Example of a background tunnel:

ssh -f -N -L 8080:192.168.1.50:80 user@remote-server.com

To close a background SSH tunnel, find its Process ID (PID) using pgrep ssh or ps aux | grep ssh, and terminate it using kill [PID].
