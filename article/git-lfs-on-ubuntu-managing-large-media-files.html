Git LFS on Ubuntu: Managing Large Media Files

Git Large File Storage (Git LFS) is an open-source Git extension designed to manage large media assets and binary files efficiently within version control repositories on Ubuntu. By substituting heavy files—such as high-resolution video, audio, graphics, and datasets—with lightweight text pointers inside the Git repository, Git LFS stores the actual binary payloads on a separate remote server. This approach prevents repository bloat, accelerates clone and fetch speeds, and ensures consistent development workflows without degrading Git's core performance.

The Problem with Native Git and Large Files

Git is inherently distributed, meaning every user who clones a repository downloads its entire version history. When large media files—such as .mp4, .psd, .wav, or 3D assets—are added and modified, Git stores a complete copy of every new version in the .git folder. Over time, this causes the repository size to grow exponentially. On an Ubuntu workstation or server, this leads to:

  • Excessively slow git clone, git fetch, and git pull operations.
  • Wasted local disk space, as every historical version of a massive binary file remains stored locally.
  • Exceeded file size limits enforced by popular hosting platforms like GitHub, GitLab, and Bitbucket.

How Git LFS Solves the Problem

Git LFS addresses these limitations by altering how Git tracks binary data. Instead of writing the full content of large media files directly into the Git object database, Git LFS does the following:

  1. Pointers Replace Binaries: Git commits only a small text file (a pointer) containing the file's cryptographic hash, size, and version metadata.
  2. External Storage: The actual media payload is uploaded to dedicated LFS object storage (typically backed by cloud storage on services like GitHub or self-hosted GitLab servers).
  3. On-Demand Downloads: When switching branches or checking out a commit on Ubuntu, Git LFS downloads only the specific binary versions required for your current working tree, rather than downloading the entire historical timeline of those files.

Key Benefits on Ubuntu

  • Faster Clones and Bandwidth Efficiency: Ubuntu developers and CI/CD pipelines can clone repositories in seconds rather than hours, as they only download the pointer data until the current commit's binaries are requested.
  • Transparent Workflow: Git LFS hooks directly into standard Git operations. After initial configuration, commands like git add, git commit, and git push work identically to standard Git.
  • Reduced Local Disk Footprint: Developers only keep the active versions of large assets on their Ubuntu machine, saving valuable local drive space.

Core Usage on Ubuntu

To set up Git LFS on an Ubuntu system, install the package via the official package manager:

sudo apt update
sudo apt install git-lfs
git lfs install

Once installed, specify the types of media files Git LFS should track:

git lfs track "*.mp4"
git lfs track "*.zip"

This generates or updates a .gitattributes file in the repository root. When this file is committed, Git automatically routes the specified media formats through Git LFS, keeping the main repository lightweight and fast.
