Install Certbot DNS Route53 on Ubuntu

Securing your domain with wildcard Let's Encrypt SSL/TLS certificates requires automated DNS-01 challenge validation, and for Amazon Web Services users, the certbot-dns-route53 plugin streamlines this workflow. This guide provides the exact installation commands to set up the plugin on Ubuntu, configure the required AWS credentials, and issue your wildcard certificate quickly and securely.

Primary Installation Command

The recommended method by the Electronic Frontier Foundation (EFF) to install Certbot and its plugins on Ubuntu is via Snap. To install the certbot-dns-route53 plugin, execute:

sudo snap install certbot-dns-route53

After installing the plugin via Snap, connect it to Certbot and grant the necessary permissions by running:

sudo snap set certbot trust-dns-plugins=true
sudo snap connect certbot:plugin certbot-dns-route53

Alternative Installation via APT

If you are using the standard Ubuntu repository packages rather than Snap, install the Python 3 APT package using:

sudo apt update
sudo apt install python3-certbot-dns-route53

Configuring AWS Credentials

The plugin requires programmatic access to update DNS TXT records in your Route 53 hosted zone. You must provide an IAM user or role with permissions for route53:ListHostedZones, route53:GetChange, and route53:ChangeResourceRecordSets.

Configure the credentials on your Ubuntu system using the AWS CLI or by manually creating an AWS credentials file:

sudo mkdir -p /root/.aws
sudo nano /root/.aws/credentials

Add your AWS access keys:

[default]
aws_access_key_id = YOUR_AWS_ACCESS_KEY_ID
aws_secret_access_key = YOUR_AWS_SECRET_ACCESS_KEY

Restrict file permissions so only root can access the keys:

sudo chmod 600 /root/.aws/credentials

Generating the Wildcard Certificate

Once installed and configured, request your wildcard certificate by running:

sudo certbot certonly --dns-route53 -d example.com -d "*.example.com"

Certbot will automatically verify ownership by creating the necessary _acme-challenge DNS records in Route 53, generate the certificate, and delete the temporary DNS records upon successful verification.
