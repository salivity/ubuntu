How to Setup a Restricted SFTP User in Ubuntu

Setting up a restricted SFTP-only user in Ubuntu allows administrators to grant secure file transfer access while preventing unauthorized SSH shell access and confining users to a designated directory. This configuration leverages OpenSSH's built-in internal-sftp subsystem and chroot jail mechanisms, ensuring that users can only upload and download files within their specific storage folder without navigating the rest of the server's filesystem.

Step 1: Create an SFTP User Group

Creating a dedicated group helps manage all restricted SFTP users consistently:

sudo groupadd sftpusers

Step 2: Create the SFTP User

Create the new user, assign them to the sftpusers group, and set their default shell to /bin/false or /usr/sbin/nologin to block interactive terminal access:

sudo adduser --ingroup sftpusers --shell /usr/sbin/nologin sftpuser

Set a strong password when prompted.

Step 3: Configure the Directory Structure and Permissions

OpenSSH's ChrootDirectory requires strict ownership rules: every directory component in the path leading up to the chroot folder must be owned by root and cannot be writable by any other user or group.

  1. Create a root directory for the user and an inner directory where the user can actually write files:
sudo mkdir -p /var/sftp/sftpuser/files
  1. Assign root ownership and standard read-and-execute permissions to the chroot parent directory:
sudo chown root:root /var/sftp/sftpuser
sudo chmod 755 /var/sftp/sftpuser
  1. Assign ownership of the inner files directory to the SFTP user:
sudo chown sftpuser:sftpusers /var/sftp/sftpuser/files
sudo chmod 755 /var/sftp/sftpuser/files

Step 4: Configure the SSH Daemon

Modify the OpenSSH server configuration to isolate the sftpusers group. Open the configuration file in a text editor:

sudo nano /etc/ssh/sshd_config

Scroll to the bottom of the file and append the following directives:

Match Group sftpusers
    ChrootDirectory /var/sftp/%u
    ForceCommand internal-sftp
    AllowTcpForwarding no
    X11Forwarding no
  • Match Group sftpusers applies these rules strictly to members of this group.
  • ChrootDirectory /var/sftp/%u replaces %u with the username, isolating them inside their folder.
  • ForceCommand internal-sftp requires SFTP usage and blocks shell execution.
  • AllowTcpForwarding no and X11Forwarding no eliminate network tunneling and GUI forwarding risks.

Save the file and exit the editor.

Step 5: Test and Restart the SSH Service

Verify that the configuration contains no syntax errors:

sudo sshd -t

If the command returns no errors, restart the SSH service to apply the changes:

sudo systemctl restart ssh

Step 6: Verify the Setup

Test the connection from a remote machine using standard SFTP:

sftp sftpuser@server_ip

Once connected, navigate to the files directory and confirm upload permissions. Finally, attempt an interactive SSH login:

ssh sftpuser@server_ip

The server should refuse the shell connection immediately while keeping SFTP functionality fully operational.
