How to List Open File Descriptors in Ubuntu

In Ubuntu Linux, managing system resources and troubleshooting stuck processes often requires identifying which files, network sockets, and file descriptors are currently in use. The standard and most powerful command used for this purpose is lsof (List Open Files). This article covers how to use lsof and the /proc filesystem to inspect open file descriptors and resolve system bottlenecks effectively.

The Primary Tool: lsof

In Unix-like systems, almost everything is treated as a file, including regular files, directories, block devices, network sockets, and pipes. The lsof utility reads system information to display a detailed list of all open files and the processes utilizing them.

Because viewing processes owned by other users or the system kernel requires elevated permissions, always run lsof with sudo.

Basic lsof Commands for Troubleshooting

  • List all open files on the system:

    sudo lsof

  • List open file descriptors for a specific process ID (PID):

    sudo lsof -p <PID>

  • Count total open file descriptors for a specific process:

    sudo lsof -p <PID> | wc -l

  • List open files for a specific user:

    sudo lsof -u <username>

  • Find which process is using a specific file or directory:

    sudo lsof /path/to/file_or_directory

  • List open network files and active ports:

    sudo lsof -i

  • Find the process listening on a specific port (e.g., port 80):

    sudo lsof -i :80

Alternative Method: Inspecting the /proc Filesystem

If lsof is not installed or you need a lightweight programmatic check, you can directly inspect the Linux kernel’s virtual /proc directory. Every running process has a subfolder named after its PID containing an fd (file descriptor) directory.

To view all open file descriptors for a process with PID 1234:

sudo ls -l /proc/1234/fd

This lists all numerical file descriptors (0 for stdin, 1 for stdout, 2 for stderr, 3+ for other files/sockets) and points symbolically to the actual target file or network socket.

To count the open descriptors for that process:

sudo ls /proc/1234/fd | wc -l

Practical Troubleshooting Workflow

  1. Identify High Resource Usage or “Too many open files” Errors: Check system-wide open file limits using ulimit -n or cat /proc/sys/fs/file-nr.

  2. Locate the Problematic Process: Identify the application process ID using pgrep <process_name> or top.

  3. Inspect the Process Descriptors: Run sudo lsof -p <PID> to check for leaking file descriptors, unclosed network connections, or locked files preventing system unmounts.
