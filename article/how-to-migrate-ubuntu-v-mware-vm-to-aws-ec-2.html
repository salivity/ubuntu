How to Migrate Ubuntu VMware VM to AWS EC2

Migrating an on-premises Ubuntu VMware virtual machine to AWS EC2 allows organizations to leverage the scalability and reliability of the cloud without re-architecting their existing workloads. This guide outlines the two primary methods for migration: using the automated AWS Application Migration Service (AWS MGN) for minimal downtime, and using the manual AWS VM Import/Export tool for file-based transfers. Following these structured steps will ensure system compatibility, data integrity, and a seamless cutover to the AWS environment.

Method 1: Using AWS Application Migration Service (Recommended)

AWS Application Migration Service (AWS MGN) is the primary service recommended by AWS for lift-and-shift migrations. It continuously replicates block-level data from the source server to AWS, minimizing cutover downtime.

Step 1: Prepare the Ubuntu Source VM

  1. Ensure the VM has internet access to communicate with AWS MGN service endpoints.
  2. Verify outbound TCP port 443 (HTTPS to AWS endpoints) and TCP port 1500 (data replication to the replication server) are open.
  3. Install Python 3 on the Ubuntu machine: 
    sudo apt update
sudo apt install -y python3

Step 2: Configure AWS MGN

  1. Log in to the AWS Management Console and navigate to AWS Application Migration Service.
  2. Click Get Started to initialize the service and create the required IAM roles.
  3. Define the Replication Settings, specifying the target VPC, subnet, and staging area disk types.

Step 3: Install the AWS Replication Agent

  1. In the MGN console, select Add servers to generate the installation command.
  2. Download the installer onto your Ubuntu VM: 
    wget -O ./aws-replication-installer-init.py https://aws-application-migration-service-<region>.s3.amazonaws.com/latest/linux/aws-replication-installer-init.py
  3. Run the installer using an AWS IAM user's credentials with AWSApplicationMigrationAgentPolicy attached: 
    sudo python3 aws-replication-installer-init.py --region <region> --aws-access-key-id <ACCESS_KEY> --aws-secret-access-key <SECRET_KEY>

Step 4: Replicate, Test, and Cutover

  1. Initial Sync: Once installed, the agent begins replicating your Ubuntu VM disks to AWS. Monitor progress in the MGN console until the status reads Ready for testing.
  2. Launch Test Instance: Select the server and choose Launch test instances. Verify that the instance boots correctly, applications run as expected, and network settings are functional.
  3. Cutover: When ready for final migration, shut down non-essential services on the source VM, choose Launch cutover instances, and finalize the cutover in the console.

Method 2: Using AWS VM Import/Export

If automated agent-based replication is not suitable, you can export the VM from VMware vSphere as an image file and import it directly as an Amazon Machine Image (AMI).

Step 1: Prepare the Ubuntu VM for Export

  1. Enable the SSH service and ensure password or key-based access is configured.
  2. Install cloud-init to handle EC2 initialization: 
    sudo apt update
sudo apt install -y cloud-init
  3. Verify that GRUB is configured to use legacy naming or predictable network interface names, and remove any static IP configurations.

Step 2: Export from VMware

  1. In vSphere Client, shut down the Ubuntu VM.
  2. Right-click the VM, navigate to Template, and select Export OVF Template.
  3. Select OVA format or export raw VMDK files.

Step 3: Upload Image to Amazon S3

  1. Create an Amazon S3 bucket in your target region.
  2. Upload the exported .ova or .vmdk file using the AWS CLI: 
    aws s3 cp /path/to/exported-vm.ova s3://your-migration-bucket/

Step 4: Configure the vmimport Service Role

  1. Create a file named trust-policy.json: 
    {
   "Version": "2012-10-17",
   "Statement": [
      {
         "Effect": "Allow",
         "Principal": { "Service": "vmie.amazonaws.com" },
         "Action": "sts:AssumeRole",
         "Condition": {
            "StringEquals":{
               "sts:ExternalId": "vmimport"
            }
         }
      }
   ]
}
  2. Create the IAM role: 
    aws iam create-role --role-name vmimport --assume-role-policy-document file://trust-policy.json
  3. Attach a role policy granting access to read from your S3 bucket and convert the image.

Step 5: Execute the Import Task

  1. Create a containers.json file defining the source image: 
    [
  {
    "Description": "Ubuntu VM Import",
    "Format": "ova",
    "UserBucket": {
        "S3Bucket": "your-migration-bucket",
        "S3Key": "exported-vm.ova"
    }
  }
]
  2. Start the import process: 
    aws ec2 import-image --description "Ubuntu VMware Migration" --disk-containers file://containers.json
  3. Track the task status using the ImportTaskId returned: 
    aws ec2 describe-import-image-tasks --import-image-task-ids <task-id>

Step 6: Launch the EC2 Instance

Once the task status changes to completed, an AMI ID is generated. Navigate to the EC2 AMIs console, select the imported AMI, and launch your new EC2 instance with your chosen instance type, VPC, and security group.

Post-Migration Steps

  1. Install AWS Systems Manager (SSM) Agent: Ensures remote management capabilities without requiring open SSH ports.
  2. Remove VMware Tools: Uninstall the legacy hypervisor integration tools from the Ubuntu system: 
    sudo apt purge -y open-vm-tools
  3. Verify Networking and DNS: Assign Elastic IPs if needed and update external DNS records to point to the new EC2 instance.
