Dynamic Fan Speed Control in Ubuntu with Fancontrol

The fancontrol script in Ubuntu serves as a lightweight, automated daemon that dynamically regulates chassis fan speeds based on real-time hardware temperatures. By interfacing with the Linux hardware monitoring framework (hwmon), the script bridges thermal readings from components like the CPU and motherboard with Pulse Width Modulation (PWM) fan headers. This dynamic regulation ensures a balance between thermal efficiency and acoustic noise, accelerating fans during heavy computational loads and throttling them down when the system is idle.

Integration with the Hardware Monitoring Subsystem

In Ubuntu, fancontrol is part of the lm-sensors package. It does not read temperatures directly from physical hardware via low-level bus calls during runtime. Instead, it relies on kernel drivers that expose thermal sensors and fan controllers as virtual files within the /sys/class/hwmon/ directory.

The script reads temperature values from specific input files (such as temp1_input) and writes duty-cycle commands to corresponding PWM attributes (such as pwm1). Because it works directly with the standard Linux sysfs interface, it operates independently of proprietary desktop utilities or desktop environments, consuming minimal system resources.

The Role of Configuration: /etc/fancontrol

The behavior of the fancontrol script is governed entirely by the /etc/fancontrol configuration file, which is typically created using the interactive wizard pwmconfig. This file establishes the relationship between thermal zones and specific chassis fan headers using several key parameters:

  • INTERVAL: Specifies how frequently (in seconds) the script reads temperatures and recalculates fan speeds.
  • FCTEMPS: Maps a specific fan's PWM output to its corresponding temperature sensor input.
  • MINTEMP: Sets the temperature threshold below which the fan runs at its minimum defined speed or shuts off entirely.
  • MAXTEMP: Sets the temperature ceiling at which the fan is driven to its maximum speed (100% duty cycle).
  • MINSTART / MINSTOP: Defines the minimum PWM values required to overcome static friction to spin up a stopped fan (MINSTART) and the lowest PWM value at which the fan will continue to spin (MINSTOP).

The Dynamic Adjustment Cycle

Once the fancontrol service starts via systemd, it executes an ongoing loop:

  1. Polling: The script queries the configured temperature inputs at the interval specified in the configuration.
  2. Calculation: It calculates a linear progression between MINTEMP and MAXTEMP. If the current temperature is between these thresholds, fancontrol scales the PWM value linearly between MINPWM and MAXPWM (values ranging from 0 to 255).
  3. Application: The calculated PWM value is written directly to the fan’s control file in sysfs, causing the motherboard’s fan controller to adjust the voltage or PWM duty cycle sent to the chassis fan.
  4. Hysteresis and Safety: If a temperature sensor reports readings above MAXTEMP, the script automatically sets the PWM value to 255 (maximum speed) to prevent thermal throttling or hardware damage.

Through this cycle, fancontrol acts as an autonomous feedback loop, maintaining chassis airflow without requiring user intervention or complex graphical utilities.
