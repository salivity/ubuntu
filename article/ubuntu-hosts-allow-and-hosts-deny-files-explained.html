Ubuntu hosts.allow and hosts.deny Files Explained

The /etc/hosts.allow and /etc/hosts.deny files in Ubuntu serve as a host-based network access control system managed by TCP Wrappers (tcpd). They allow system administrators to restrict which IP addresses, subnets, or hostnames can connect to specific network services running on the server. By defining rules in these files, you can grant or deny access to network daemons like SSH or FTP before the service processes the connection.

Understanding TCP Wrappers

TCP Wrappers act as a simple security layer at the application level. When an incoming network request arrives for a network service compiled with libwrap support, the system checks /etc/hosts.allow and /etc/hosts.deny to determine whether to accept or drop the connection.

Purpose of /etc/hosts.allow

The /etc/hosts.allow file is used to specify which clients are explicitly permitted to access particular services. If a client's IP address, hostname, or network matches a rule in this file, the connection is immediately accepted.

Rules defined in /etc/hosts.allow always take precedence over rules defined in /etc/hosts.deny.

Purpose of /etc/hosts.deny

The /etc/hosts.deny file is used to specify which clients are explicitly blocked from accessing specific services. If an incoming connection request does not match any rule in /etc/hosts.allow, the system evaluates /etc/hosts.deny. If a match is found here, the connection is refused.

If a client request matches neither file, access is granted by default.

Rule Processing Order

Ubuntu processes host access rules in a strict top-down sequence:

  1. /etc/hosts.allow is checked first: If a rule matches the client and service, access is granted, and processing stops.
  2. /etc/hosts.deny is checked second: If no match was found in hosts.allow, but a rule matches in hosts.deny, access is blocked, and processing stops.
  3. Default Allow: If the request matches no rules in either file, access is permitted.

Syntax and Formatting

Both files share the exact same configuration format:

daemon_list : client_list
  • daemon_list: The name of the process/service binary (such as sshd) or the keyword ALL.
  • client_list: A list of hostnames, IP addresses, IP ranges, or keywords (such as ALL or LOCAL).

Configuration Examples

To allow SSH connections from a single IP address (192.168.1.50), add the following line to /etc/hosts.allow:

sshd : 192.168.1.50

To block all other SSH connections, add this line to /etc/hosts.deny:

sshd : ALL

To block a specific bad actor IP across all wrapped services, add this line to /etc/hosts.deny:

ALL : 203.0.113.45

Current Status in Modern Ubuntu

While TCP Wrappers using /etc/hosts.allow and /etc/hosts.deny were historically standard across Linux systems, many modern network services and Linux distributions (including newer Ubuntu releases) have deprecated libwrap support. For system-wide packet filtering and modern network access control, UFW (Uncomplicated Firewall) or iptables/nftables should be used alongside or in place of these files.
