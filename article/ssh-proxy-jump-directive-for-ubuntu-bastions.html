SSH ProxyJump Directive for Ubuntu Bastions

The ProxyJump directive in the ~/.ssh/config file simplifies and secures the process of connecting to private network servers through an intermediary gateway, commonly known as a bastion host or jump box. Instead of manually establishing multiple SSH sessions or configuring complex port-forwarding scripts, ProxyJump automates the traversal of an Ubuntu bastion host in the background. This article explains the role of ProxyJump, its operational and security advantages, and how to configure it for seamless routing to internal infrastructure.

Understanding the Role of an Ubuntu Bastion

In secure cloud and enterprise environments, internal servers hosting databases, application backends, and internal services rarely have public IP addresses. To manage these machines, administrators place a hardened, publicly accessible server—the bastion host—at the network perimeter.

Traditionally, accessing an internal server required logging into the Ubuntu bastion first, storing private keys on that bastion, and then running a second SSH command to reach the target machine. Alternatively, users had to write verbose ProxyCommand strings using utilities like netcat (nc). The ProxyJump directive replaces both workflows with a clean, native SSH mechanism.

How ProxyJump Functions

Introduced natively in OpenSSH 7.3, ProxyJump instructs your local SSH client to establish an encrypted transport-layer tunnel through the bastion to the target destination using OpenSSH’s standard -W (stdio forwarding) flag.

When you initiate an SSH connection using ProxyJump:

  1. Your local client connects and authenticates with the Ubuntu bastion host.
  2. The bastion opens an unauthenticated TCP channel directly to the private target server's SSH port (typically port 22).
  3. Your local client establishes an end-to-end encrypted SSH session with the internal server through this channel.

The Ubuntu bastion merely acts as a dumb packet forwarder at the transport layer; it never decrypts or inspects the traffic between your local machine and the destination host.

Advantages of Using ProxyJump

  • End-to-End Encryption: The SSH session to the target host is fully encrypted locally. The intermediate Ubuntu bastion cannot view commands, transmitted data, or credentials.
  • No Keys on the Bastion: Because the connection to the internal host originates cryptographically from your local machine, your private keys remain exclusively on your local workstation.
  • Avoids SSH Agent Forwarding Risks: Unlike agent forwarding (ForwardAgent yes), which can expose your authentication agent to compromise if the bastion host is hijacked, ProxyJump eliminates the need to expose your agent socket.
  • Simplified Commands: Once configured in ~/.ssh/config, connecting to an internal node behind a firewall requires nothing more than running ssh target-server.

Example ~/.ssh/config Configuration

To configure transparent routing through an Ubuntu bastion, open or create your ~/.ssh/config file and define both the bastion and the target instances:

# The Ubuntu Bastion Host (Gateway)
Host bastion
    HostName 203.0.113.10
    User ubuntu
    IdentityFile ~/.ssh/bastion_key.pem

# Internal Target Server
Host internal-db
    HostName 10.0.1.50
    User ubuntu
    IdentityFile ~/.ssh/internal_key.pem
    ProxyJump bastion

With this configuration in place, running:

ssh internal-db

automatically connects through the Ubuntu bastion at 203.0.113.10 and establishes the session with 10.0.1.50 without requiring any manual hopping or dual authentication commands.
