Configure ArgoCD to Sync Manifests on Ubuntu

This guide provides a direct walkthrough for setting up an ArgoCD controller to sync Kubernetes manifests to an Ubuntu-based Kubernetes cluster. By leveraging GitOps principles, you will install ArgoCD on your Ubuntu environment, connect your Git repository containing Kubernetes manifests, and configure an ArgoCD Application resource to automatically reconcile and deploy your workloads.

Prerequisites

Before beginning, ensure you have:

  • An active Ubuntu server (20.04 or 22.04 LTS recommended).
  • A running Kubernetes cluster (such as kubeadm, k3s, or microk8s) with administrative access.
  • kubectl installed and configured to communicate with your cluster.
  • A Git repository containing your Kubernetes deployment manifests (plain YAML, Kustomize, or Helm).

Step 1: Install ArgoCD on the Cluster

Create a dedicated namespace for ArgoCD and apply the official installation manifests:

kubectl create namespace argocd
kubectl apply -n argocd -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml

Wait until all pods in the argocd namespace are running:

kubectl wait --for=condition=available deployment -l "app.kubernetes.io/part-of=argocd" -n argocd --timeout=300s

Step 2: Install the ArgoCD CLI on Ubuntu

Download and install the latest ArgoCD CLI binary to interact with the controller directly from your Ubuntu terminal:

curl -sSL -o argocd-linux-amd64 https://github.com/argoproj/argo-cd/releases/latest/download/argocd-linux-amd64
sudo install -m 555 argocd-linux-amd64 /usr/local/bin/argocd
rm argocd-linux-amd64

Step 3: Access the ArgoCD API Server

By default, the argocd-server service is exposed as ClusterIP. For local access, use kubectl port-forward:

kubectl port-forward svc/argocd-server -n argocd 8080:443 &

Retrieve the default admin password generated during installation:

kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath="{.data.password}" | base64 -d; echo

Log in using the CLI:

argocd login localhost:8080 --username admin --insecure

Step 4: Configure Cluster Target

If ArgoCD is deploying manifests to the same Ubuntu Kubernetes cluster it is installed on, the target cluster is already registered as the default in-cluster address: https://kubernetes.default.svc.

If you are deploying to an external cluster context on the Ubuntu host, list your contexts and register the cluster:

kubectl config get-contexts -o name
argocd cluster add <CONTEXT_NAME>

Step 5: Create and Sync the Application Manifest

Create an ArgoCD Application Custom Resource (CR) to define the Git source repository and the destination cluster. Save the following configuration as application.yaml:

apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: ubuntu-app-sync
  namespace: argocd
spec:
  project: default
  source:
    repoURL: 'https://github.com/<your-org>/<your-repo>.git'
    targetRevision: HEAD
    path: 'manifests'
  destination:
    server: 'https://kubernetes.default.svc'
    namespace: default
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
    syncOptions:
      - CreateNamespace=true

Apply the application manifest to the cluster:

kubectl apply -f application.yaml

Alternatively, create the application using the CLI:

argocd app create ubuntu-app-sync \
  --repo https://github.com/<your-org>/<your-repo>.git \
  --path manifests \
  --dest-server https://kubernetes.default.svc \
  --dest-namespace default \
  --sync-policy automated \
  --auto-prune \
  --self-heal

Step 6: Verify the Synchronization

Check the synchronization status of the application:

argocd app get ubuntu-app-sync

If automated sync was not enabled, trigger a manual synchronization:

argocd app sync ubuntu-app-sync

Verify that the workloads specified in your Git repository have been successfully created on your Ubuntu cluster:

kubectl get all -n default
