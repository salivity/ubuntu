Deploy Authelia SSO Portal on Ubuntu

This guide provides a comprehensive walkthrough for deploying the Authelia open-source single sign-on (SSO) and multi-factor authentication (MFA) portal on an Ubuntu server. By using Docker and Docker Compose alongside an Nginx reverse proxy, you will learn how to configure the necessary configuration files, define user authentication rules, and protect your internal web applications behind a centralized authentication gate.

Prerequisites

  • An Ubuntu 22.04 or 24.04 server with a non-root sudo-enabled user.
  • A registered domain name with DNS A records pointing to your server's IP address (e.g., auth.example.com for Authelia and app.example.com for your protected service).
  • Ports 80 and 443 open on your firewall.

Step 1: Install Docker and Docker Compose

Update your package index and install Docker and the Docker Compose plugin:

sudo apt update
sudo apt install -y ca-certificates curl gnupg lsb-release
sudo mkdir -p /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg

echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
sudo usermod -aG docker $USER

Log out and back in to apply the group changes.

Step 2: Set Up Directory Structure

Create a dedicated directory to store the Authelia configuration and persistent data:

mkdir -p ~/authelia/config
cd ~/authelia

Step 3: Configure Authelia

Authelia requires a main configuration file, configuration.yml. Create this file inside ~/authelia/config/:

nano ~/authelia/config/configuration.yml

Insert the following configuration, adjusting the domain names and secret keys:

theme: light
default_redirection_url: https://app.example.com

server:
  host: 0.0.0.0
  port: 9091

log:
  level: info

jwt_secret: a_very_long_random_string_for_jwt_secret
session:
  name: authelia_session
  secret: another_very_long_random_string_for_session
  expiration: 3600
  inactivity: 300
  domain: example.com

regulation:
  max_retries: 3
  find_time: 120
  ban_time: 300

storage:
  local:
    path: /config/db.sqlite3

notifier:
  filesystem:
    filename: /config/notification.txt

authentication_backend:
  file:
    path: /config/users_database.yml

access_control:
  default_policy: deny
  rules:
    - domain: "app.example.com"
      policy: two_factor

Next, generate a password hash for your first user:

docker run --rm authelia/authelia:latest authelia crypto hash generate argon2 --password "YourStrongPassword"

Copy the generated digest, then create the users_database.yml file:

nano ~/authelia/config/users_database.yml

Add your user configuration:

users:
  john:
    disabled: false
    displayname: "John Doe"
    password: "$argon2id$v=19$m=65536,t=3,p=4$..." # Paste hash here
    email: john@example.com
    groups:
      - admins
      - users

Step 4: Create Docker Compose File

Create a docker-compose.yml file in the ~/authelia directory to run the Authelia container:

nano ~/authelia/docker-compose.yml

Add the following configuration:

version: '3.8'

services:
  authelia:
    image: authelia/authelia:latest
    container_name: authelia
    restart: unless-stopped
    volumes:
      - ./config:/config
    ports:
      - "127.0.0.1:9091:9091"
    environment:
      - TZ=UTC

Start the Authelia service:

docker compose up -d

Verify that the container is running:

docker compose ps

Step 5: Configure Reverse Proxy (Nginx)

Install Nginx and Certbot for SSL termination:

sudo apt install -y nginx certbot python3-certbot-nginx

Obtain SSL certificates for your domains:

sudo certbot certonly --nginx -d auth.example.com -d app.example.com

Create an Nginx configuration file for Authelia and your protected application:

sudo nano /etc/nginx/sites-available/authelia.conf

Insert the following server blocks:

# Authelia Portal
server {
    listen 443 ssl http2;
    server_name auth.example.com;

    ssl_certificate /etc/letsencrypt/live/auth.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/auth.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:9091;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

# Protected Application
server {
    listen 443 ssl http2;
    server_name app.example.com;

    ssl_certificate /etc/letsencrypt/live/auth.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/auth.example.com/privkey.pem;

    # Authelia Authentication Endpoint
    location /authelia {
        internal;
        proxy_pass http://127.0.0.1:9091/api/verify;
        proxy_pass_request_body off;
        proxy_set_header Content-Length "";
        proxy_set_header X-Original-URL $scheme://$http_host$request_uri;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        auth_request /authelia;
        auth_request_set $target_url $scheme://$http_host$request_uri;
        auth_request_set $user $upstream_http_remote_user;
        auth_request_set $groups $upstream_http_remote_groups;

        proxy_set_header Remote-User $user;
        proxy_set_header Remote-Groups $groups;

        error_page 401 =302 https://auth.example.com/?rd=$target_url;

        # Forward to your backend application (e.g., port 8080)
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

Enable the configuration and reload Nginx:

sudo ln -s /etc/nginx/sites-available/authelia.conf /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx

Step 6: Verify the Installation

  1. Navigate to https://app.example.com in a web browser.
  2. Nginx intercepts the request and redirects you to https://auth.example.com.
  3. Enter the username and password defined in users_database.yml.
  4. Because the rule requires two-factor authentication, check ~/authelia/config/notification.txt to retrieve the one-time registration link for setting up TOTP (e.g., Google Authenticator).
  5. Complete the two-factor authentication setup to gain access to the backend application.
