Diagnose Ubuntu Boot Issues with dmesg Command

The dmesg command is a vital diagnostic tool in Ubuntu used to examine the kernel ring buffer, providing detailed logs of the boot process and hardware initialization. This article explains how dmesg functions during boot diagnostics, how to analyze its output, and how to identify common boot failures such as driver errors, hardware detection issues, and kernel panics.

What is dmesg and How It Works During Boot

The term dmesg stands for "display message." When an Ubuntu system boots up, the Linux kernel loads first and begins detecting system hardware, loading necessary device drivers, and mounting root filesystems.

Because storage services and standard logging daemons (like systemd-journald or rsyslog) are not yet running during early boot phases, the kernel stores all system events in a temporary memory space called the kernel ring buffer. The dmesg command prints the contents of this buffer to the terminal, allowing administrators to review every action the kernel took from the exact moment power was applied.

Key Diagnostic Functions of dmesg

dmesg serves several critical functions when troubleshooting an Ubuntu machine that fails to boot cleanly, hangs during startup, or boots into a emergency shell:

  • Hardware Recognition Failures: It logs whether the kernel successfully detects components like RAM, CPUs, storage drives (NVMe/SATA), and network cards.
  • Missing Drivers and Firmware: If a device requires proprietary firmware or missing kernel modules (such as NVIDIA GPU drivers or Wi-Fi chipsets), dmesg explicitly reports the missing file errors.
  • Filesystem and Storage Errors: Read/write failures, corrupted drive sectors, or failures to mount the root filesystem (/) appear prominently in the logs.
  • Kernel Panics and Crash Dumps: If the boot process halts completely, dmesg captures the call trace showing which driver or function caused the crash.

Essential dmesg Commands for Troubleshooting

To use dmesg effectively when diagnosing boot problems, run the command in a terminal or recovery console using these common flags:

1. View Logs with Human-Readable Timestamps

By default, dmesg shows timestamps in seconds since the kernel started. Use the -T flag to convert these into readable date and time formats:

dmesg -T

2. Filter Output by Error Severity

Instead of scrolling through thousands of lines, filter the logs to display only errors, critical events, or alerts:

dmesg -l err,crit,alert,emerg

3. Search for Specific Hardware or Drivers

Pipe the output into grep to isolate issues related to specific components, such as hard drives (sda, nvme), memory, or graphics:

dmesg | grep -i "error"
dmesg | grep -i "sda"
dmesg | grep -i "failed"

4. Page Through Logs

Combine dmesg with less to scroll step-by-step through the startup sequence:

dmesg -T | less

Common Boot Issues Identified by dmesg

  • I/O Errors: Messages containing Buffer I/O error or descriptor error indicate failing hard drives or solid-state drives.
  • Firmware Missing: Messages like firmware: failed to load show that connected hardware cannot initialize properly without additional driver packages.
  • Initramfs / Mount Failures: Lines showing Cannot open root device or Kernel panic - not syncing: VFS: Unable to mount root fs indicate GRUB misconfigurations or corrupted initial RAM disk images.
