Run Ubuntu Scripts in Background After SSH Disconnect

Running long scripts over an SSH connection can be risky because closing the terminal or losing the network connection sends a SIGHUP (hangup) signal that terminates your running process. Ubuntu provides several powerful built-in utilities—primarily nohup, tmux, and cron—that allow you to execute or schedule scripts to run persistently in the background, ensuring they continue execution entirely unaffected by SSH disconnections.

1. The nohup Command (Best for Immediate Execution)

The most direct command to run a script continuously in the background is nohup (no hang up), combined with the background operator &.

To run your script, use the following syntax:

nohup /path/to/script.sh > output.log 2>&1 &
  • nohup: Prevents the process from receiving the SIGHUP signal when the SSH session ends.
  • > output.log 2>&1: Redirects both standard output (stdout) and standard error (stderr) to a file named output.log. If omitted, output defaults to nohup.out.
  • &: Sends the command to the background immediately, returning control of the terminal prompt to you.

Once executed, you can safely log out of your SSH session using the exit command without interrupting the script.

2. The cron Utility (Best for Scheduled Tasks)

If you need to schedule a script to run automatically at a specific time or on a recurring basis, use cron. Because cron runs as a system daemon, it executes independently of any active user login session.

  1. Open your user's crontab editor:

    crontab -e

  2. Add a line defining the schedule and the script:

    # Run every day at 02:00 AM
0 2 * * * /bin/bash /path/to/script.sh > /path/to/cron.log 2>&1

3. The at Command (Best for One-Time Scheduled Execution)

For scheduling a script to execute once at a future time in the background, use at.

  1. Install at if not already present:

    sudo apt update && sudo apt install at
sudo systemctl enable --now atd

  2. Schedule the execution time (for example, at 3:30 PM):

    echo "/bin/bash /path/to/script.sh" | at 15:30

4. tmux or screen (Best for Interactive Background Sessions)

Terminal multiplexers like tmux allow you to detach from an active session and let processes run inside an isolated shell environment.

  1. Start a new session: 
    tmux new -s mysession
  2. Execute your script inside the session: 
    ./script.sh
  3. Detach from the session by pressing Ctrl + B, then D.

You can now disconnect from SSH. To reattach to the running session later, log back in and run:

tmux attach -t mysession

Managing Running Background Jobs

To monitor or manage your background scripts:

  • Check active background processes: 
    ps aux | grep script.sh
  • Terminate a background process using its Process ID (PID): 
    kill <PID>
