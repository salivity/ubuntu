Configure Autofs to Mount Remote Shares on Ubuntu

This guide demonstrates how to configure the autofs daemon on Ubuntu to automatically mount remote file systems on demand and unmount them after a period of inactivity. By following these steps, you will install the necessary packages, configure the master and mapping files for a remote network share (such as NFS), and verify that directories mount dynamically upon access, conserving system resources and network bandwidth.

Step 1: Install Autofs and Support Utilities

Update your package index and install the autofs package. If you plan to mount NFS shares, install nfs-common. If you are mounting SMB/CIFS shares, install cifs-utils.

sudo apt update
sudo apt install autofs nfs-common -y

Step 2: Configure the Master Map File

The master map file, /etc/auto.master, tells autofs where the root mount point is located and which map file defines the specific shares.

  1. Open /etc/auto.master in a text editor:

    sudo nano /etc/auto.master

  2. Add a line at the end of the file specifying your base mount directory, the path to the custom map file, and an optional timeout (in seconds) to automatically unmount inactive shares:

    /mnt/remote /etc/auto.remote --timeout=60

  3. Save and close the file.

Step 3: Create the Map File

Create the map file referenced in the master configuration. This file maps the subdirectory name to the remote source and specifies mount options.

  1. Create and open the file defined in the master map:

    sudo nano /etc/auto.remote

  2. Add the configuration for your remote share. The syntax follows: [subdirectory] [options] [server:/path]

    For an NFS share:

    nfs_share -fstype=nfs4,rw,soft,intr 192.168.1.100:/srv/nfs/share

    For an SMB/CIFS share:

    smb_share -fstype=cifs,rw,credentials=/etc/auto.smb.credentials ://192.168.1.100/share

  3. Save and close the file.

Step 4: Secure Map Files and Credentials (Optional)

If your mapping files contain sensitive information or authentication credentials, restrict read and write permissions to the root user:

sudo chmod 600 /etc/auto.remote

Step 5: Start and Enable the Autofs Service

Apply the changes by restarting the autofs daemon and enabling it to start at boot:

sudo systemctl restart autofs
sudo systemctl enable autofs

Step 6: Test the On-Demand Mount

The base directory (/mnt/remote) will appear empty until the designated share subdirectory is directly requested.

  1. Trigger the mount by accessing the path:

    cd /mnt/remote/nfs_share
ls -la

  2. Verify that the file system is mounted:

    df -h /mnt/remote/nfs_share

After 60 seconds (or the timeout value configured in /etc/auto.master) of zero active processes accessing /mnt/remote/nfs_share, autofs will unmount the file system automatically.
