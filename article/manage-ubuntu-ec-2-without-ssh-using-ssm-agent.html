Manage Ubuntu EC2 Without SSH Using SSM Agent

The amazon-ssm-agent is the core software component that enables secure, centralized administration of Ubuntu EC2 instances via AWS Systems Manager, entirely eliminating the need for open inbound SSH ports or bastion hosts. By shifting management from traditional key-based SSH access to an identity-driven model governed by AWS Identity and Access Management (IAM), the agent facilitates interactive terminal sessions, automated patching, script execution, and continuous inventory tracking directly through the AWS Console or AWS CLI.

Outbound-Only Communication Architecture

Traditional EC2 management requires opening inbound port 22 in your security groups, creating an attack vector exposed to network scans and brute-force attempts. The amazon-ssm-agent fundamentally changes this security model by initiating only outbound HTTPS (port 443) traffic to AWS Systems Manager endpoints.

Because the instance makes outbound calls to poll the Systems Manager service for tasks, your Ubuntu instance requires zero inbound rules in its Security Group. Network connectivity can be established through an Internet Gateway, a NAT Gateway, or private AWS VPC Endpoints (PrivateLink) for fully isolated environments.

Core Capabilities Replicating and Replacing SSH

Once active, the amazon-ssm-agent on an Ubuntu instance enables several critical Systems Manager capabilities:

  • Session Manager (Interactive Shell Access): Serves as a full replacement for SSH. Users can launch a standard interactive bash shell inside the Ubuntu instance through the AWS Management Console or the AWS CLI using the Session Manager plugin. Access is granted through IAM permissions rather than static .pem SSH key pairs.
  • Run Command (Remote Execution at Scale): Allows administrators to run ad-hoc shell commands or scripts on one or thousands of Ubuntu instances simultaneously without establishing interactive sessions. Output is captured, logged, and reviewed centrally.
  • Patch Manager and Inventory: Automates tracking of installed software, packages, and OS configurations. It coordinates with Ubuntu's apt package manager to detect vulnerabilities and apply critical security patches automatically during defined maintenance windows.
  • State Manager: Enforces desired configurations, such as ensuring specific services are running, monitoring configurations are present, or antivirus definitions are up to date.

Security and Governance Advantages

Relying on the SSM Agent provides distinct operational and security benefits over conventional SSH workflows:

  1. Elimination of Key Management: There is no need to generate, rotate, distribute, or revoke private SSH keys when team members join or leave.
  2. Centralized Access Control: Access to instances is defined strictly via IAM policies, allowing fine-grained controls such as multi-factor authentication (MFA) enforcement, time-based access, and tag-based permissions.
  3. Comprehensive Audit Trails: Every user connection is tracked in AWS CloudTrail. Furthermore, Session Manager can record entire terminal input and output logs and stream them encrypted to Amazon S3 buckets or Amazon CloudWatch Logs for compliance and forensics.

Prerequisites for Ubuntu Instances

The amazon-ssm-agent is installed by default as a snap package on modern official Ubuntu Server AMIs (such as Ubuntu 20.04, 22.04, and 24.04 LTS). For the agent to function, the instance requires:

  1. An Attached IAM Role: The instance must have an attached IAM instance profile containing the AmazonSSMManagedInstanceCore managed policy (or equivalent permissions).
  2. Endpoint Reachability: The instance must have network routing and DNS resolution to reach the regional Systems Manager API endpoints over outbound port 443.
