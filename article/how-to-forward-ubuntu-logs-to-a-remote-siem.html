How to Forward Ubuntu Logs to a Remote SIEM

This article provides a step-by-step guide to configuring an Ubuntu server to forward its security logs to a remote Security Information and Event Management (SIEM) system. You will learn how to leverage Ubuntu's native rsyslog service to filter authentication events, configure reliable network transport using TCP or UDP, implement disk-assisted queuing to prevent data loss, and verify that your logs arrive securely at your centralized collector.

Step 1: Install and Verify Rsyslog

Ubuntu uses rsyslog as its default system logger. Ensure it is installed and running on your system by executing:

sudo apt update
sudo apt install rsyslog -y
sudo systemctl enable rsyslog
sudo systemctl status rsyslog

Step 2: Create a SIEM Forwarding Configuration

Rather than modifying the primary /etc/rsyslog.conf file directly, create a dedicated configuration file inside the /etc/rsyslog.d/ directory. This ensures clean configuration management and persists across system updates.

Create a new file named /etc/rsyslog.d/60-siem.conf:

sudo nano /etc/rsyslog.d/60-siem.conf

Add the following configuration to forward authentication and security-related logs (auth and authpriv facilities) to your remote SIEM:

# Setup in-memory and disk buffering for network resilience
$ActionQueueType LinkedList
$ActionQueueFileName siem_fwd_queue
$ActionResumeRetryCount -1
$ActionQueueSaveOnShutdown on

# Forward security and authentication logs via TCP
auth,authpriv.* @@siem.example.com:514
  • Replace siem.example.com with your SIEM collector’s IP address or hostname.
  • Replace 514 with the port designated by your SIEM.
  • The @@ prefix specifies transmission over reliable TCP. If your SIEM collector only accepts UDP, change @@ to a single @.
  • If you want to forward all system logs rather than strictly security logs, replace auth,authpriv.* with *.*.

Step 3: Validate and Restart Rsyslog

Before applying the changes, validate the configuration syntax to prevent service interruption:

sudo rsyslogd -N1

If the command returns no errors, restart the rsyslog service to apply the configuration:

sudo systemctl restart rsyslog

Step 4: Configure UFW (Firewall) Rules

If your Ubuntu server enforces outbound firewall rules using UFW (Uncomplicated Firewall), allow outbound traffic to your SIEM port:

sudo ufw allow out 514/tcp

Step 5: Verify Log Delivery

To confirm that your server successfully sends events to the SIEM:

  1. Generate a manual authentication log entry: 
    logger -p auth.notice "TEST: Security log forwarding configured on $(hostname)"
  2. Trigger an actual authentication event by attempting an SSH login or running a command using sudo.
  3. Check the ingestion dashboard or event stream inside your SIEM interface to verify the arrival of the test log.
  4. If logs are missing, check the local system journal on the Ubuntu server for transmission errors: 
    journalctl -u rsyslog --no-pager -n 50
