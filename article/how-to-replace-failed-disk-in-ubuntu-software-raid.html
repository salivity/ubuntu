How to Replace Failed Disk in Ubuntu Software RAID

Replacing a failed disk in an Ubuntu software RAID array managed by mdadm involves a straightforward process: identifying the faulty drive, removing it logically from the array, physically swapping the hardware, mirroring the partition structure, adding the new disk to the array, and updating the bootloader. This step-by-step guide walks you through each stage to ensure your system recovers completely without data loss.

Step 1: Identify the Failed Disk

Check the status of your RAID array using the command:

cat /proc/mdstat

Look for missing or degraded indicators, such as [U_] instead of [UU].

To get detailed information about a specific array (e.g., /dev/md0), run:

sudo mdadm --detail /dev/md0

Note the device name of the failed disk or partition (e.g., /dev/sdb1).

Step 2: Mark and Remove the Failed Disk

If mdadm has not automatically marked the drive as failed, manually set its status to failed:

sudo mdadm --manage /dev/md0 --fail /dev/sdb1

Next, remove the failed partition from the RAID array:

sudo mdadm --manage /dev/md0 --remove /dev/sdb1

Repeat this step for any other RAID partitions on that same physical disk.

Step 3: Replace the Physical Drive

Power down the machine (unless your hardware supports hot-swapping), disconnect the failed hard drive, and insert the new drive. Power the machine back on once the hardware is installed.

Identify the device name assigned to the new drive using:

lsblk

For this guide, assume the working drive is /dev/sda and the new drive is /dev/sdb.

Step 4: Copy the Partition Table

To ensure the new drive matches the existing disk, copy the partition layout from the healthy drive (/dev/sda) to the new drive (/dev/sdb).

For GPT Partitions:

sudo sgdisk -R /dev/sdb /dev/sda
sudo sgdisk -G /dev/sdb

The second command generates unique GUIDs for the new disk.

For MBR Partitions:

sudo sfdisk -d /dev/sda | sudo sfdisk /dev/sdb

Step 5: Add the New Disk to the RAID Array

Add the newly created partition back into the software RAID array:

sudo mdadm --manage /dev/md0 --add /dev/sdb1

If your disk contains multiple RAID partitions (such as separate partitions for root and swap), add each partition to its respective array.

Step 6: Monitor the Resynchronization

The RAID array will automatically start rebuilding data onto the new disk. You can monitor the recovery progress in real time with:

watch cat /proc/mdstat

Step 7: Reinstall GRUB Bootloader (Bootable Drives Only)

If the replaced disk is part of a bootable RAID array, install GRUB onto the new drive to ensure the system remains bootable if another drive fails:

sudo grub-install /dev/sdb
sudo update-grub
