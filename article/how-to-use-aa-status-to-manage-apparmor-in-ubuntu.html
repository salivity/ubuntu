How to Use aa-status to Manage AppArmor in Ubuntu

AppArmor is a Linux Security Module that restricts system capabilities for individual applications using security profiles. The aa-status command is the primary utility for checking the real-time operational status of AppArmor on Ubuntu, displaying loaded profiles, active modes (enforce or complain), and process confinement details. This guide covers how to inspect AppArmor profiles using aa-status, interpret its output, filter results, and take effective management actions based on its findings.

Checking the Status of AppArmor

To view the current state of AppArmor profiles and processes, execute the command with administrator privileges:

sudo aa-status

The output is divided into three primary sections: * Profiles loaded: The total count and names of profiles loaded into memory. * Profiles in enforce/complain mode: The specific operational mode assigned to each profile. * Processes defined: Active system processes currently restricted by AppArmor profiles.

Understanding Profile Modes in aa-status

AppArmor profiles operate in one of two main modes shown by aa-status:

  • Enforce Mode: The policy is actively enforced. Violations are blocked and logged to system audits (/var/log/syslog or dmesg).
  • Complain Mode: Policies are not enforced. Violations are permitted but still logged. This mode is typically used for testing and developing new profiles.

If a profile is listed as loaded but no processes are shown under it, the associated application is currently not running.

Using aa-status Command Line Flags

You can use specific options with aa-status to query precise information or use the output in automated scripts:

  • Check if AppArmor is enabled:

    sudo aa-status --enabled

    Returns an exit code of 0 if active, or 1 if inactive.

  • Display total count of loaded profiles:

    sudo aa-status --profiled

  • Display the number of profiles in enforce mode:

    sudo aa-status --enforced

  • Display the number of profiles in complain mode:

    sudo aa-status --complaining

  • Display the number of running processes under confinement:

    sudo aa-status --confining

Managing Profiles Based on aa-status Output

While aa-status reports the state of your security policies, changing profile states requires companion commands from the apparmor-utils package.

Switching Profiles Between Enforce and Complain Mode

If aa-status reveals a profile in complain mode that you want to restrict, switch it to enforce mode:

sudo aa-enforce /etc/apparmor.d/bin.ping

To move a profile causing issues back to complain mode for troubleshooting:

sudo aa-complain /etc/apparmor.d/bin.ping

Reloading and Unloading Profiles

After modifying a profile file located in /etc/apparmor.d/, reload it using the parser and verify the update with aa-status:

sudo apparmor_parser -r /etc/apparmor.d/profile_name

To remove a profile from kernel memory completely:

sudo apparmor_parser -R /etc/apparmor.d/profile_name

Running sudo aa-status immediately after these operations confirms that profile states and confined processes reflect your latest changes.
