How to Set Up Apache ModSecurity on Ubuntu

This guide provides a straightforward walkthrough for installing and configuring the ModSecurity Web Application Firewall (WAF) with the Apache HTTP server on an Ubuntu system. You will learn how to install the required packages, activate the ModSecurity engine, integrate the industry-standard OWASP Core Rule Set (CRS) to protect your server from common web attacks, and verify that the firewall is actively blocking malicious traffic.

Step 1: Update System Packages

Ensure your package index is updated before installing new software:

sudo apt update && sudo apt upgrade -y

Step 2: Install Apache and ModSecurity

Install the Apache web server (if not already installed) along with the ModSecurity Apache module:

sudo apt install apache2 libapache2-mod-security2 -y

Verify that the module has been enabled:

sudo apache2ctl -M | grep security2

If the output displays security2_module (shared), the module is successfully loaded.

Step 3: Configure the ModSecurity Engine

Ubuntu provides a default configuration file template that needs to be renamed and edited.

  1. Rename the template configuration file:
sudo cp /etc/modsecurity/modsecurity.conf-recommended /etc/modsecurity/modsecurity.conf
  1. Open the configuration file in a text editor:
sudo nano /etc/modsecurity/modsecurity.conf
  1. Locate the SecRuleEngine directive. By default, it is set to DetectionOnly, which logs attacks without blocking them. Change it to active enforcement:
SecRuleEngine On

Save and exit the file (press CTRL+O, Enter, then CTRL+X).

Step 4: Install the OWASP Core Rule Set (CRS)

The base ModSecurity installation provides the firewall engine, but it requires rules to identify malicious patterns such as SQL Injection (SQLi) and Cross-Site Scripting (XSS). The OWASP ModSecurity Core Rule Set is the standard choice.

  1. Remove the default minimal rule file:
sudo rm -rf /usr/share/modsecurity-crs
  1. Clone the latest OWASP CRS repository from GitHub:
sudo git clone https://github.com/coreruleset/coreruleset /usr/share/modsecurity-crs
  1. Create the configuration file from the provided example:
sudo cp /usr/share/modsecurity-crs/crs-setup.conf.example /usr/share/modsecurity-crs/crs-setup.conf

Step 5: Configure Apache to Load the Rules

Link the OWASP rules into the Apache ModSecurity configuration.

  1. Open the Apache ModSecurity configuration file:
sudo nano /etc/apache2/mods-available/security2.conf
  1. Verify that the file includes the core rule set by adjusting the configuration to match the following structure:
<IfModule security2_module>
    SecDataDir /var/cache/modsecurity
    IncludeOptional /etc/modsecurity/*.conf
    Include /usr/share/modsecurity-crs/crs-setup.conf
    Include /usr/share/modsecurity-crs/rules/*.conf
</IfModule>
  1. Test the Apache configuration for syntax errors:
sudo apache2ctl configtest

If you see Syntax OK, restart Apache to apply the changes:

sudo systemctl restart apache2

Step 6: Test ModSecurity

Verify that the firewall is actively blocking malicious requests by sending a basic attack pattern using curl.

Run a simulated Local File Inclusion (LFI) request against your server:

curl -i http://localhost/?exec=/bin/bash

If ModSecurity is working correctly, the server will block the request and return an HTTP 403 Forbidden status code.

You can view the detailed block event in the ModSecurity audit log:

sudo tail -f /var/log/apache2/modsec_audit.log
