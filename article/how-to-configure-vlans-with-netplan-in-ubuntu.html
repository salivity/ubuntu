How to Configure VLANs with Netplan in Ubuntu

Configuring Virtual Local Area Networks (VLANs) in Ubuntu using Netplan provides an efficient way to isolate network traffic and segment broadcast domains on a single physical network interface. Netplan uses YAML files to define network configurations, making setup straightforward and version-controllable. This article walks you through the step-by-step process of identifying your physical network interface, defining VLANs within a Netplan YAML file, testing the configuration, and verifying active VLAN connections.

Prerequisites

Before configuring VLANs, ensure you have:

  • Administrative access (sudo privileges) on an Ubuntu machine running Netplan (Ubuntu 18.04 LTS or newer).
  • The 8021q kernel module loaded (enabled by default in most Ubuntu installations).
  • Knowledge of your network details, including the physical interface name, VLAN IDs, IP addresses, and gateway details.

Step 1: Identify the Physical Network Interface

Open a terminal and run the following command to list all available network interfaces:

ip link show

Note the name of the physical interface on which you want to configure the VLAN (e.g., enp3s0, eth0, or eth1).

Step 2: Locate and Backup the Netplan Configuration File

Netplan configuration files are stored in the /etc/netplan/ directory. List the files in this directory to find your current configuration file:

ls /etc/netplan/

Common configuration filenames include 01-netcfg.yaml, 50-cloud-init.yaml, or 00-installer-config.yaml.

Before making changes, create a backup of your existing file:

sudo cp /etc/netplan/01-netcfg.yaml /etc/netplan/01-netcfg.yaml.bak

Step 3: Edit the Netplan Configuration File

Open the Netplan YAML configuration file in a text editor:

sudo nano /etc/netplan/01-netcfg.yaml

Add your VLAN configuration under the vlans block. YAML relies strictly on proper indentation (use spaces, not tabs).

Example Configuration (Static IP):

network:
  version: 2
  renderer: networkd
  ethernets:
    enp3s0:
      dhcp4: no
  vlans:
    vlan10:
      id: 10
      link: enp3s0
      addresses:
        - 192.168.10.50/24
      routes:
        - to: default
          via: 192.168.10.1
      nameservers:
        addresses:
          - 8.8.8.8
          - 1.1.1.1

Example Configuration (DHCP):

If your VLAN assigns IP addresses automatically via DHCP:

network:
  version: 2
  renderer: networkd
  ethernets:
    enp3s0:
      dhcp4: no
  vlans:
    vlan20:
      id: 20
      link: enp3s0
      dhcp4: yes

Key Configuration Fields:

  • vlans: The top-level block defining virtual interfaces.
  • vlan10: The logical name assigned to the VLAN interface.
  • id: The actual VLAN tag number (e.g., 10 or 20) assigned by your network switch.
  • link: The physical network interface tied to this VLAN.

Step 4: Test and Apply the Netplan Configuration

To prevent losing connectivity due to syntax errors or improper settings, test the configuration first:

sudo netplan try

If the settings are valid, press Enter to accept them. If an error occurs, Netplan will automatically revert to the previous configuration after a 120-second timeout.

Once confirmed, apply the changes permanently:

sudo netplan apply

Step 5: Verify the VLAN Interface

Check that the new VLAN interface is active and has received the correct IP address:

ip addr show vlan10

Verify routing settings to ensure traffic routes correctly over the VLAN:

ip route

Finally, test network connectivity by pinging your default gateway:

ping -c 4 192.168.10.1
