How to Configure Anycast IP on Ubuntu Server

Configuring an Anycast IP address on an Ubuntu server involves assigning a shared IP address to a local loopback interface and using a Border Gateway Protocol (BGP) routing daemon to advertise that address to your upstream network provider. This guide outlines the essential steps to prepare your Ubuntu system, configure a dummy interface for the Anycast IP, install and set up FRRouting (FRR) for BGP peering, and verify that traffic routes correctly to your server.

Prerequisites

Before starting, ensure you have: * An Ubuntu server (20.04 LTS or newer recommended) with root or sudo access. * A public IP address block designated for Anycast routing. * BGP session details from your data center or ISP (your ASN, neighbor IP, and neighbor ASN).

Step 1: Create a Dummy Interface for the Anycast IP

To prevent network conflicts, the Anycast IP address must be bound to a virtual loopback or dummy interface rather than your primary physical interface.

  1. Load the dummy kernel module:

    sudo modprobe dummy

  2. Ensure the module loads automatically on boot:

    echo "dummy" | sudo tee -a /etc/modules

  3. Configure Netplan to persist the dummy interface and assign the Anycast IP. Open your Netplan configuration file (typically located in /etc/netplan/):

    sudo nano /etc/netplan/01-netcfg.yaml

  4. Add the dummy0 interface definition:

    network:
  version: 2
  ethernets:
    eth0:
      # Your standard primary interface config remains here
      dhcp4: true
  dummies:
    dummy0:
      addresses:
        - YOUR_ANYCAST_IP/32

  5. Apply the configuration:

    sudo netplan apply

Step 2: Install FRRouting (FRR)

FRR is a high-performance routing protocol suite that handles BGP peerings on Linux.

  1. Update package lists and install FRR:

    sudo apt update
sudo apt install -y frr frr-pythontools

  2. Enable the BGP daemon by editing /etc/frr/daemons:

    sudo nano /etc/frr/daemons

    Change bgpd=no to bgpd=yes.

  3. Restart the FRR service:

    sudo systemctl restart frr

Step 3: Configure BGP to Advertise the Anycast IP

Use vtysh, the integrated shell for FRR, to configure BGP peering with your upstream provider.

  1. Enter the FRR shell:

    sudo vtysh

  2. Enter configuration mode:

    configure terminal

  3. Set up the BGP process using your Autonomous System Number (ASN):

    router bgp YOUR_LOCAL_ASN
  bgp router-id YOUR_PRIMARY_SERVER_IP
  neighbor UPSTREAM_NEIGHBOR_IP remote-as UPSTREAM_NEIGHBOR_ASN

  address-family ipv4 unicast
    network YOUR_ANYCAST_IP/32
    neighbor UPSTREAM_NEIGHBOR_IP activate
  exit-address-family
exit

  4. Save the configuration and exit:

    write memory
exit

Step 4: Enable IP Forwarding

Ensure the Linux kernel is configured to forward packets properly:

  1. Open /etc/sysctl.conf:

    sudo nano /etc/sysctl.conf

  2. Uncomment or add the following line:

    net.ipv4.ip_forward=1

  3. Apply changes:

    sudo sysctl -p

Step 5: Verify the Anycast Configuration

  1. Check Interface Status: Verify that dummy0 is active and holds the Anycast IP:

    ip addr show dummy0

  2. Check BGP Neighbor Status: Open vtysh and check if the BGP session with your ISP is established:

    sudo vtysh -c "show bgp summary"

    The state for your neighbor should show a number under MsgRcvd/MsgSent rather than Active or Idle.

  3. Check Advertised Routes: Confirm that your Anycast IP is actively being announced:

    sudo vtysh -c "show bgp ipv4 unicast neighbors UPSTREAM_NEIGHBOR_IP advertised-routes"

Once established, traffic sent to your Anycast IP address will automatically route to the nearest active server running this configuration.
