Managing Persistent Shell Sessions with Screen on Ubuntu

The GNU screen command is a terminal multiplexer that enables system administrators to manage persistent shell sessions on Ubuntu servers. By decoupling running processes from the active terminal window, screen ensures that tasks continue executing in the background even if your SSH connection drops or is closed. This article covers the fundamental role of the screen utility, how it prevents workflow disruption, and the basic commands needed to manage detached sessions effectively.

The Core Functions of the Screen Command

When managing a remote Ubuntu server over SSH, any interruption in your network connection typically terminates your active shell and kills all running child processes. The screen command eliminates this risk by acting as a wrapper between your terminal and the server's operating system.

1. Process Persistence and Network Independence

The primary role of screen is session persistence. When you launch a command inside a screen session, the process runs independently of your actual terminal connection. If your network drops, your laptop battery dies, or you manually close the SSH client, the processes inside screen continue to run uninterrupted on the Ubuntu server.

2. Terminal Multiplexing

screen allows you to create multiple virtual consoles within a single terminal session. You can open several shell prompts, switch between them, and monitor different server logs or run separate commands without opening multiple SSH connections.

3. Session Sharing and Collaboration

screen supports multi-user mode, allowing different users connected to the same server to join the same active session. This feature is particularly useful for troubleshooting issues collaboratively or demonstrating administrative tasks in real time.

Basic Workflow and Commands

screen is available directly from the default Ubuntu repositories.

Installation

To install screen on Ubuntu, run:

sudo apt update
sudo apt install screen

Starting a Named Session

While you can start screen by simply typing screen, naming your session makes it easier to manage multiple background tasks:

screen -S long_job

Detaching from a Session

To leave a session running in the background while returning to your standard SSH terminal:

  1. Press Ctrl + A.
  2. Press D.

Your commands inside the session will continue executing.

Listing Active Sessions

To see all active screen sessions running on the server:

screen -ls

Reattaching to a Session

To resume work on a detached session, use the -r flag followed by the session name or ID:

screen -r long_job

If a session is still marked as attached elsewhere, you can forcibly detach and reattach to it using:

screen -d -r long_job

Closing a Session

To permanently terminate a screen session, simply type exit inside the virtual console, or press Ctrl + D when all tasks in the session are complete.

When to Use Screen on Ubuntu Servers

Using screen is recommended for high-risk or long-running administrative tasks on remote servers, including:

  • System Updates and Upgrades: Running sudo apt upgrade or full OS upgrades where a dropped connection could leave the package manager in a broken state.
  • Large File Transfers: Performing long rsync or scp transfers across remote locations.
  • Database Backups: Executing lengthy database dumps or imports.
  • Compiling Software: Building applications from source code that require extended processing time.
