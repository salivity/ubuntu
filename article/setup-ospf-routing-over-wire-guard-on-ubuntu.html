Setup OSPF Routing Over WireGuard on Ubuntu

This guide provides a step-by-step walkthrough for configuring dynamic routing using the Open Shortest Path First (OSPF) protocol across a secure WireGuard tunnel on Ubuntu. By combining WireGuard's modern encryption with the FRRouting (FRR) suite, you can build a resilient, self-healing network that automatically routes traffic around outages without manually updating static routing tables.

Prerequisites

  • Two Ubuntu servers (referred to as Node A and Node B) with public IP addresses.
  • Sudo or root privileges on both machines.
  • Basic understanding of CIDR networking.

Step 1: Install WireGuard and FRR

Run the following commands on both Node A and Node B to install WireGuard and FRRouting:

sudo apt update
sudo apt install -y wireguard frr

Step 2: Configure WireGuard

Generate private and public key pairs on both nodes.

wg genkey | tee privatekey | wg pubkey > publickey

Node A Configuration (/etc/wireguard/wg0.conf)

Create the WireGuard configuration file on Node A:

[Interface]
Address = 10.10.10.1/30
ListenPort = 51820
PrivateKey = <Node_A_Private_Key>

[Peer]
PublicKey = <Node_B_Public_Key>
Endpoint = <Node_B_Public_IP>:51820
# Allow the tunnel subnet and OSPF multicast addresses (224.0.0.5, 224.0.0.6)
AllowedIPs = 10.10.10.0/30, 224.0.0.0/24
PersistentKeepalive = 25

Node B Configuration (/etc/wireguard/wg0.conf)

Create the WireGuard configuration file on Node B:

[Interface]
Address = 10.10.10.2/30
ListenPort = 51820
PrivateKey = <Node_B_Private_Key>

[Peer]
PublicKey = <Node_A_Public_Key>
Endpoint = <Node_A_Public_IP>:51820
AllowedIPs = 10.10.10.0/30, 224.0.0.0/24
PersistentKeepalive = 25

Start WireGuard

Enable and start the tunnel on both nodes:

sudo systemctl enable --now wg-quick@wg0

Verify connectivity by pinging across the tunnel:

# On Node A
ping 10.10.10.2

# On Node B
ping 10.10.10.1

Step 3: Enable Packet Forwarding

Enable IPv4 forwarding on both servers so they can route traffic between networks.

echo "net.ipv4.ip_forward = 1" | sudo tee -a /etc/sysctl.d/99-ipforward.conf
sudo sysctl -p /etc/sysctl.d/99-ipforward.conf

Step 4: Configure FRR for OSPF

1. Enable the OSPF Daemon

Edit /etc/frr/daemons on both servers and enable ospfd:

ospfd=yes

Restart FRR to load the daemon:

sudo systemctl restart frr

2. Configure OSPF on Node A

Open the integrated FRR shell on Node A:

sudo vtysh

Run the following configuration commands:

configure terminal
!
interface wg0
 ip ospf network point-to-point
 ip ospf area 0.0.0.0
!
router ospf
 ospf router-id 10.10.10.1
 network 10.10.10.0/30 area 0.0.0.0
 network 192.168.10.0/24 area 0.0.0.0
!
end
write memory
exit

(Replace 192.168.10.0/24 with the local subnet Node A should advertise).

3. Configure OSPF on Node B

Open the integrated FRR shell on Node B:

sudo vtysh

Run the following configuration commands:

configure terminal
!
interface wg0
 ip ospf network point-to-point
 ip ospf area 0.0.0.0
!
router ospf
 ospf router-id 10.10.10.2
 network 10.10.10.0/30 area 0.0.0.0
 network 192.168.20.0/24 area 0.0.0.0
!
end
write memory
exit

(Replace 192.168.20.0/24 with the local subnet Node B should advertise).

Step 5: Verification

Verify that the OSPF neighbor adjacency has formed.

Inside vtysh on either node, execute:

show ip ospf neighbor

The output should display the peer's router ID with a state of Full:

Neighbor ID     Pri State           Dead Time Address         Interface
10.10.10.2        1 Full/ -         00:00:34 10.10.10.2      wg0:10.10.10.1

Next, view the discovered routes:

show ip route ospf

You should see routes to the opposing node's local networks learned through the wg0 interface. The Linux kernel routing table will also reflect these additions, enabling full end-to-end dynamic communication.
