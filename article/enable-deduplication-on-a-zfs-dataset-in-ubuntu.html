Enable Deduplication on a ZFS Dataset in Ubuntu

ZFS deduplication allows you to save disk space by identifying and eliminating duplicate blocks of data within your storage pool. This guide demonstrates how to enable deduplication on a specific ZFS dataset on Ubuntu, check the configuration, and monitor the deduplication ratio. Because deduplication is set at the dataset level, you can apply it granularly to target specific data without incurring the heavy memory overhead across your entire storage pool.

Memory Requirements and Considerations

Before enabling deduplication, ensure your system has sufficient physical memory. ZFS keeps the deduplication table (DDT) in RAM to maintain read/write performance. As a general rule, plan for at least 5 GB of RAM per 1 TB of deduplicated storage. If the DDT exceeds available RAM and spills over to disk, system performance will degrade significantly. Additionally, deduplication only applies to new data written after the feature is enabled; it does not retroactively deduplicate existing data.

Step 1: Identify Your ZFS Dataset

Open your terminal and list your existing storage pools and datasets to find the exact target path:

zfs list

Identify the pool and dataset name you want to modify (for example, tank/backups).

Step 2: Enable Deduplication on the Dataset

Run the zfs set command with root privileges to turn on deduplication for the specified dataset:

sudo zfs set dedup=on pool_name/dataset_name

Replace pool_name/dataset_name with your actual pool and dataset path. By default, setting dedup=on uses the SHA-256 hash algorithm to calculate and match checksums for duplicate data blocks.

Step 3: Verify the Dataset Configuration

Confirm that deduplication is active on your target dataset by querying the dedup property:

zfs get dedup pool_name/dataset_name

The output should show VALUE as on and SOURCE as local:

NAME                     PROPERTY  VALUE  SOURCE
pool_name/dataset_name   dedup     on     local

Step 4: Monitor Deduplication Efficiency

To check how effectively deduplication is saving space, view the deduplication ratio of the parent pool:

zpool list

Look at the DEDUP column in the output. A ratio of 1.00x means no duplicate blocks exist. A ratio greater than 1.00x (such as 1.25x or 2.00x) indicates the space saved by pointing duplicate blocks to existing data.

Disabling Deduplication

If you observe excessive memory usage or degraded write speeds, you can disable deduplication for future writes at any time:

sudo zfs set dedup=off pool_name/dataset_name

Disabling deduplication will not undeduplicate data that has already been written; those blocks will remain deduplicated until they are overwritten or deleted.
