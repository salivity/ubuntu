Mitigate DDoS on Ubuntu with Apache mod_evasive

The libapache2-mod-evasive module is an essential security tool designed to protect Apache web servers running on Ubuntu from application-layer Denial of Service (DoS) and Distributed Denial of Service (DDoS) attacks. This article explains the role of mod_evasive, detailing how it detects abusive traffic patterns, enforces automated blocking mechanisms, integrates with system-level firewalls, and fits into a comprehensive Linux server security strategy.

Understanding libapache2-mod-evasive

libapache2-mod-evasive is an Apache HTTP server module that provides evasive action against HTTP flood attacks, brute-force attempts, and rapid-fire requests. When attackers attempt to overwhelm a web server by flooding it with high volumes of HTTP GET or POST requests, mod_evasive monitors the incoming traffic per IP address and intervenes before the server's resources are exhausted.

How mod_evasive Detects and Mitigates Threats

The module maintains an internal hash table of IP addresses and request URIs to track client activity across predefined intervals. It detects malicious activity using several key thresholds configured in /etc/apache2/mods-available/evasive.conf:

  • Single-Page Request Floods (DOSPageCount & DOSPageInterval): Tracks how many times an IP requests the same URI within a specific time window (e.g., 2 requests per second). If the threshold is exceeded, the module flags the IP.
  • Site-Wide Request Floods (DOSSiteCount & DOSSiteInterval): Monitors overall requests from an IP across the entire website within a short interval (e.g., 50 requests per second) to prevent aggressive scrapers or multi-page crawling attacks.
  • Temporary Blacklisting (DOSBlockingPeriod): Once a client violates a threshold, mod_evasive automatically blocks the IP address for a configured duration (e.g., 10 seconds). Any new requests sent during this blocking period reset the timer, keeping persistent attackers blocked indefinitely.
  • HTTP 403 Forbidden Response: While blocked, the server immediately rejects requests from the abusive IP with a 403 Forbidden status code. This minimal response consumes negligible memory and CPU, shielding backend scripts (like PHP) and databases from saturation.

Key Roles in an Ubuntu Security Stack

  1. Layer 7 Application Defense: Standard firewalls like UFW or iptables monitor network-layer metrics (packets and ports) but cannot inherently inspect HTTP request rates. mod_evasive operates at the application layer, recognizing patterns that appear legitimate to low-level firewalls.
  2. Automated Firewall Integration: Through its DOSSystemCommand directive, mod_evasive can execute shell scripts upon triggering a block. Administrators on Ubuntu often configure this to automatically push offending IPs directly to iptables, fail2ban, or ufw, effectively elevating the block to the network layer to save even more web server overhead.
  3. Admin Alerting: The module supports native email alerts via the DOSEmailNotify directive, enabling system administrators to quickly identify ongoing attack campaigns.

Limitations in Large-Scale DDoS Attacks

While libapache2-mod-evasive is highly effective against single-source floods, scripted brute-force attacks, and small-to-moderate botnet surges, it cannot counter massive, high-bandwidth volumetric DDoS attacks. If an attack distributes requests across hundreds of thousands of distinct IP addresses, or if the incoming traffic exceeds the network interface's bandwidth, the server will still become unresponsive. In such scenarios, mod_evasive serves as an internal line of defense that complements external edge-layer mitigation services and Content Delivery Networks (CDNs).
