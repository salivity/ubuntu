Mount EBS Volume Persistently in Ubuntu fstab

Configuring a persistent mount point for an Amazon EBS volume ensures that your storage remains attached and accessible across system reboots. This guide covers how to identify your attached EBS volume, format it if necessary, locate its Universally Unique Identifier (UUID), and configure the /etc/fstab file using the nofail option to prevent boot failures if the volume becomes detached.

Step 1: Identify the Attached Volume

Connect to your Ubuntu instance via SSH and list the block devices to find your attached EBS volume:

lsblk

Locate your EBS volume from the output. In AWS Nitro-based instances, volumes typically appear as /dev/nvmeXn1, while older instances use /dev/xvdf through /dev/xvdz.

Step 2: Check for an Existing File System

Before formatting, verify whether the volume already contains data or a filesystem:

sudo file -s /dev/xvdf

(Replace /dev/xvdf with your actual device name.)

  • If the output shows data, the volume is raw and needs to be formatted.
  • If the output shows filesystem details (such as Linux rev 1.0 ext4 filesystem data), do not format it, as formatting will erase existing data.

If the volume is empty, format it using the ext4 filesystem:

sudo mkfs -t ext4 /dev/xvdf

Step 3: Create a Mount Directory

Create a directory where the volume will be mounted:

sudo mkdir -p /mnt/ebs-data

Step 4: Get the Volume UUID

Device names can change between reboots in AWS. Using the volume's UUID guarantees the correct device is mounted every time.

Find the UUID of your formatted partition or disk:

sudo blkid

Locate your device line and copy the UUID value (e.g., UUID="1234abcd-56ef-78gh-90ij-1234567890kl").

Step 5: Back Up and Edit /etc/fstab

Create a backup of /etc/fstab to safeguard your system configuration:

sudo cp /etc/fstab /etc/fstab.orig

Open the /etc/fstab file in a text editor:

sudo nano /etc/fstab

Add a new line at the end of the file using the following structure:

UUID=your-uuid-here /mnt/ebs-data ext4 defaults,nofail 0 2
  • UUID=...: Identifies the specific EBS volume.
  • /mnt/ebs-data: The target mount point.
  • ext4: The filesystem type used on the volume.
  • defaults,nofail: The nofail option is critical; it allows the operating system to boot normally even if the EBS volume is detached or unvailable.
  • 0: Prevents the filesystem from being dumped by the dump utility.
  • 2: Sets the filesystem check order during boot.

Save and exit the file.

Step 6: Test the Mount Configuration

Test your /etc/fstab configuration immediately without rebooting. First, unmount the volume if it is currently mounted, then execute:

sudo mount -a

If the command executes without displaying errors, your configuration is correct. Verify the volume is mounted:

lsblk -f

The mount point column should now display /mnt/ebs-data alongside your device. The volume will now automatically remount whenever the instance boots.
