Set Up Local DNS Cache with systemd-resolved in Ubuntu

Setting up a local DNS cache using systemd-resolved in Ubuntu speeds up domain name resolution and reduces external network requests by storing IP addresses locally. This guide covers how to enable and configure the systemd-resolved service, update your system's resolv.conf file to route queries through the local stub resolver, and verify that your local DNS cache is actively functioning.

Step 1: Enable and Start systemd-resolved

Most modern Ubuntu releases come with systemd-resolved pre-installed. Start the service and enable it to run at system boot:

sudo systemctl enable systemd-resolved
sudo systemctl start systemd-resolved

Verify that the service is running correctly:

sudo systemctl status systemd-resolved

Step 2: Configure DNS Cache Settings

Edit the main configuration file for systemd-resolved to configure upstream DNS servers and enable caching.

Open the configuration file in a text editor:

sudo nano /etc/systemd/resolved.conf

Uncomment and update the following lines in the [Resolve] section:

[Resolve]
DNS=1.1.1.1 8.8.8.8
FallbackDNS=1.0.0.1 8.8.4.4
Cache=yes
CacheFromLocalhost=yes
  • DNS: Defines the primary upstream DNS servers (such as Cloudflare or Google).
  • FallbackDNS: Specifies backup DNS servers if the primary ones fail.
  • Cache: Enables DNS caching (yes is the default behavior, but explicitly setting it ensures it remains active).

Save the file and exit the text editor.

Step 3: Link /etc/resolv.conf to systemd-resolved

For system applications to use the local DNS cache, /etc/resolv.conf must point to the systemd-resolved stub file, which listens on local IP 127.0.0.53.

Create a symbolic link replacing the existing configuration file:

sudo ln -sf /run/systemd/resolve/stub-resolv.conf /etc/resolv.conf

Step 4: Restart the Service

Apply your new configuration changes by restarting systemd-resolved:

sudo systemctl restart systemd-resolved

Step 5: Verify Local DNS Caching

Check the status of your DNS servers and configuration:

resolvectl status

To test if DNS caching is actively recording hits and misses, view the real-time cache statistics:

resolvectl statistics

Look at the Cache section in the command output. Perform a query using dig or ping, then re-run resolvectl statistics to observe the Current Cache Size and Cache Hits increase.
