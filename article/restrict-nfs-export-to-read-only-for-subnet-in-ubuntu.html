Restrict NFS Export to Read-Only for Subnet in Ubuntu

Configuring Network File System (NFS) exports with granular permissions ensures data integrity across your local network. This guide explains how to restrict an NFS share to read-only access for a specific subnet on an Ubuntu server by editing the /etc/exports file, applying the updated configuration, and verifying the export status.

Step 1: Edit the NFS Exports File

NFS shares and their associated host permissions are defined in /etc/exports. Open this file in your preferred text editor using root privileges:

sudo nano /etc/exports

Step 2: Define the Subnet and Read-Only Permissions

Locate or add the line defining the directory you want to share. Specify the target subnet using CIDR notation, followed immediately by the access options in parentheses. Ensure there is no space between the subnet and the opening parenthesis.

Use the ro option to enforce read-only access:

/mnt/shared_data 192.168.1.0/24(ro,sync,no_subtree_check)

Option Breakdown:

  • /mnt/shared_data: The absolute path to the directory being exported.
  • 192.168.1.0/24: The allowed subnet. Only clients with IP addresses in this range can access the share.
  • ro: Restricts clients to read-only operations, preventing file creation, modification, or deletion.
  • sync: Forces the server to write changes to disk before responding to requests, ensuring data consistency.
  • no_subtree_check: Improves reliability by preventing the server from checking if a file is in a specific subdirectory of the exported tree.

Save the file and exit the editor (in nano, press CTRL+O, Enter, then CTRL+X).

Step 3: Apply the Changes

To update the NFS server with the new export rules without restarting the entire service, run:

sudo exportfs -ra
  • -r: Re-exports all directories listed in /etc/exports.
  • -a: Applies the action across all exports.

Step 4: Verify the Configuration

Confirm that the directory is correctly exported with read-only permissions for the specified subnet:

sudo exportfs -v

The output will display the active export path, the permitted subnet, and the applied flags, including ro.

Step 5: Configure the Firewall (Optional)

If Ubuntu's Uncomplicated Firewall (UFW) is active, ensure traffic from the specified subnet is permitted on the NFS port:

sudo ufw allow from 192.168.1.0/24 to any port nfs
sudo ufw reload
