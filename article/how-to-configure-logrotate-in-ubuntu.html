How to Configure Logrotate in Ubuntu

Managing log file sizes is essential for system stability and disk management on Ubuntu servers. This guide explains how to configure logrotate, a built-in utility in Ubuntu that automatically rotates, compresses, and archives system log files to prevent storage drives from filling up. You will learn the structure of logrotate configuration files, common directives, and how to test your custom setup.

Understanding the Logrotate Configuration Structure

Ubuntu manages logrotate through two main configuration locations: * /etc/logrotate.conf: The main global configuration file that sets default settings for all rotated logs. * /etc/logrotate.d/: A directory containing individual configuration files for specific applications (e.g., Nginx, Apache, or custom microservices).

The standard practice is to leave /etc/logrotate.conf intact and create a new configuration file inside /etc/logrotate.d/ for your specific application.

Step 1: Create a Custom Logrotate File

To create a custom rotation policy for an application, generate a new configuration file inside /etc/logrotate.d/:

sudo nano /etc/logrotate.d/myapp

Step 2: Define Rotation Rules

Inside your new file, specify the target log file path, followed by a block of configuration directives inside curly braces {}.

Here is a standard configuration example:

/var/log/myapp/*.log {
    daily
    missingok
    rotate 7
    compress
    delaycompress
    notifempty
    create 0640 www-data www-data
    sharedscripts
    postrotate
        systemctl reload myapp > /dev/null 2>&1 || true
    endscript
}

Essential Directives Explained

  • daily / weekly / monthly: Sets the rotation frequency.
  • rotate 7: Keeps 7 rotated log files before automatically deleting the oldest.
  • missingok: Prevents errors if the log file is missing.
  • notifempty: Skips rotation if the log file is empty.
  • compress: Compresses old rotated files using gzip.
  • delaycompress: Postpones compression until the next rotation cycle, keeping the most recently rotated log uncompressed.
  • create 0640 www-data www-data: Recreates a new log file immediately after rotation with specified file permissions, owner, and group.
  • postrotate / endscript: Executes a command or script after the logs are rotated (typically used to instruct applications to start writing to the newly created log file).

Step 3: Test the Configuration

Always verify your configuration syntax to ensure that automated rotation will execute smoothly.

To perform a dry run without making actual changes:

sudo logrotate -d /etc/logrotate.d/myapp

To force logrotate to run immediately for testing purposes:

sudo logrotate -f /etc/logrotate.d/myapp

Step 4: Verification and Automatic Execution

Ubuntu runs logrotate automatically once per day using a systemd timer (logrotate.timer) or a cron job located at /etc/cron.daily/logrotate. Once your configuration file is placed in /etc/logrotate.d/ and tested, no additional scheduling setup is required.
