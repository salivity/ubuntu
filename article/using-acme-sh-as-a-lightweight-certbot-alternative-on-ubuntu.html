Using acme.sh as a Lightweight Certbot Alternative on Ubuntu

This article explores the role of acme.sh as an efficient, lightweight ACME client for issuing and managing free SSL/TLS certificates on Ubuntu. While Certbot remains the standard tool recommended by Let's Encrypt, it often introduces significant overhead due to its Python runtime and modern packaging via Snap. In contrast, acme.sh provides a zero-dependency, pure POSIX shell alternative that reduces resource consumption while maintaining complete automation for certificate issuance and renewals.

The Problem with Certbot on Minimal Ubuntu Systems

Certbot is a robust ACME client, but on modern Ubuntu distributions, its officially supported installation method requires snapd. Running Snap packages introduces background daemons, mount namespaces, and additional system memory overhead. For small virtual private servers (VPS), embedded devices, or minimal cloud instances with 512MB to 1GB of RAM, this overhead can degrade performance or trigger out-of-memory (OOM) errors during certificate renewals.

What is acme.sh?

acme.sh is an open-source ACME protocol client written entirely in POSIX shell script. Because it does not rely on Python, Snap, or heavy system libraries, it runs natively on Ubuntu using standard system tools like curl or wget, openssl, and cron. It supports both ACME v1 and ACME v2 specifications, allowing users to obtain free certificates from certificate authorities such as Let's Encrypt, ZeroSSL, and BuyPass.

Key Advantages of acme.sh over Certbot

  1. Zero External Dependencies: The entire client consists of shell scripts. It does not require a runtime environment or package manager overhead, making it ideal for bare-metal installs, minimal containers, and low-spec VPS environments.
  2. Extensive DNS API Support: While Certbot requires separate plugins for DNS-01 verification (many of which are maintained by third parties), acme.sh natively supports over 100 DNS provider APIs out of the box, simplifying wildcard certificate management.
  3. Flexible CA Support: Unlike Certbot, which is primarily configured for Let's Encrypt, acme.sh defaults to ZeroSSL and allows seamless switching between different ACME certificate authorities without modifying system dependencies.
  4. Standard Cron Integration: Instead of relying on systemd timers wrapped in Snap containers, acme.sh uses a simple entry in the native Ubuntu user or root crontab to handle renewals.

Common Implementation Workflow on Ubuntu

Getting started with acme.sh on Ubuntu involves downloading the script, which automatically configures an alias and a renewal cron job:

curl https://get.acme.sh | sh -s email=admin@example.com
source ~/.bashrc

Issuing a certificate can be done using multiple validation modes:

  • Webroot Mode: Utilizes an existing web server (like Nginx or Apache) to serve verification files: 
    acme.sh --issue -d example.com -d www.example.com -w /var/www/html
  • Standalone Mode: Temporarily binds to port 80 if no web server is currently active.
  • DNS-01 Mode: Uses exported API credentials to automatically create and remove DNS TXT records for domain verification and wildcard certificate generation.

Once issued, the certificate must be installed to the target directory rather than linked directly from the .acme.sh internal folder. The --install-cert command handles this step and includes a reload hook to restart Nginx or Apache automatically:

acme.sh --install-cert -d example.com \
--key-file       /etc/ssl/private/example.com.key \
--fullchain-file /etc/ssl/certs/example.com.fullchain.cer \
--reloadcmd     "systemctl reload nginx"

When to Choose acme.sh

Choosing acme.sh over Certbot is recommended when deploying to resource-constrained Ubuntu servers, building stripped-down Docker images, or managing environments where installing snapd is prohibited or discouraged. It provides full control, security, and automation without sacrificing system resources.
