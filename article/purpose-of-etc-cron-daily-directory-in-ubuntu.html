Purpose of /etc/cron.daily Directory in Ubuntu

The /etc/cron.daily directory in Ubuntu is a system directory designed to store scripts that need to run automatically once per day. Instead of editing individual user crontables, system administrators and applications can place executable shell scripts directly into this folder to ensure routine maintenance, such as log rotation, system cleanup, and software updates, occurs daily. This guide explains how /etc/cron.daily functions, how tasks are executed, and how to create your own daily automated scripts.

How /etc/cron.daily Works

In Ubuntu, the cron daemon handles time-based job scheduling. The system configures cron to periodically check key directories, including /etc/cron.daily, /etc/cron.hourly, /etc/cron.weekly, and /etc/cron.monthly.

Rather than executing files directly through standard crontab syntax, the system uses a tool named run-parts. The main system configuration file (/etc/crontab) or the Anacron service triggers run-parts /etc/cron.daily, which sequentially runs every valid script inside the directory.

Execution Timing and Anacron Integration

On standard Ubuntu installations (especially Desktop and non-24/7 Server setups), daily jobs are managed by Anacron rather than traditional cron alone.

  • Traditional Cron: Executes jobs at a fixed, predefined time (historically around 06:25 AM). If the computer is powered off at that exact minute, the job is missed entirely until the next day.
  • Anacron: Checks whether a daily job was missed while the system was off. When the machine boots up, Anacron waits a short delay (usually 5 to 10 minutes) and then executes the scripts in /etc/cron.daily.

This ensures critical tasks run daily regardless of system downtime or irregular operating hours.

Common Uses for /etc/cron.daily

Ubuntu uses this directory out of the box for crucial background upkeep: * Log Rotation (logrotate): Compresses, archives, and deletes old system logs to prevent disk space exhaustion. * Database Updates (locate / apt): Updates the file indexing database for locate searches and refreshes APT package lists. * Security & Cleanup (man-db): Updates manual page databases and removes temporary files. * Custom Backups: Storing scripts for daily file or database backups.

How to Add a Custom Script to /etc/cron.daily

To add a custom task, follow these straightforward steps:

1. Create the Script File

Create a new file inside /etc/cron.daily without a file extension (such as .sh), as run-parts may ignore filenames containing dots depending on system configuration.

sudo nano /etc/cron.daily/custom-daily-backup

2. Add the Code

Start the script with a proper shebang line (#!/bin/sh or #!/bin/bash):

#!/bin/bin/bash
# Script to perform daily file backups
tar -czf /var/backups/system_backup_$(date +%F).tar.gz /var/www/html

3. Make the Script Executable

Cron will only execute files that have execution permissions enabled. Run:

sudo chmod +x /etc/cron.daily/custom-daily-backup

4. Test Execution

You can manually test if your script runs cleanly via run-parts before waiting for the scheduled trigger:

sudo run-parts --test /etc/cron.daily

Summary of Benefits

Using /etc/cron.daily simplifies system administration on Ubuntu by removing the need to manage complex cron syntax (0 0 * * *). It provides a clean, modular way to manage daily tasks, guarantees execution on systems that are powered off periodically, and keeps system automated scripts organized in a single location.
