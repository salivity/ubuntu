How to Configure QoS on an Ubuntu Router

Configuring Quality of Service (QoS) on an Ubuntu router allows network administrators to prioritize critical network traffic, manage bandwidth allocation, and reduce latency during peak usage. This article provides a clear, step-by-step guide on setting up QoS using Linux’s native tc (Traffic Control) utility within the iproute2 package. You will learn how to define queuing disciplines, set bandwidth limits for specific traffic types, apply filters for prioritization, and ensure your settings remain persistent across system reboots.

Step 1: Identify Network Interfaces

Identify the internal and external network interfaces on your Ubuntu router using the following command:

ip link show

Note the interface handling outgoing internet traffic (e.g., eth0 or enp3s0). QoS policies are applied to egress (outgoing) traffic on this interface.

Step 2: Install Required Utilities

Ubuntu includes the tc command by default via the iproute2 package. Ensure your system tools are updated:

sudo apt update && sudo apt install iproute2 -y

Step 3: Create a Root Queueing Discipline (qdisc)

To manage bandwidth dynamically, use the Hierarchical Token Bucket (HTB) qdisc. HTB allows you to create a hierarchy of traffic classes with specific bandwidth limits.

  1. Remove any existing default rules on the target interface:

    sudo tc qdisc del dev eth0 root

  2. Attach an HTB root qdisc to the interface:

    sudo tc qdisc add dev eth0 root handle 1: htb default 30

    (Unclassified traffic will automatically route to default class 1:30.)

Step 4: Define Traffic Classes and Bandwidth Limits

Set up parent and child classes to assign guaranteed and maximum bandwidth rates. Assuming a total upload capacity of 100 Mbps:

  1. Create the primary parent class matching the total upload capacity:

    sudo tc class add dev eth0 parent 1: classid 1:1 htb rate 100mbit

  2. Create a high-priority class (e.g., for VoIP or DNS traffic):

    sudo tc class add dev eth0 parent 1:1 classid 1:10 htb rate 30mbit ceil 100mbit prio 1

  3. Create a standard-priority class (e.g., for general web browsing):

    sudo tc class add dev eth0 parent 1:1 classid 1:20 htb rate 50mbit ceil 90mbit prio 2

  4. Create a low-priority default class (e.g., for bulk file downloads):

    sudo tc class add dev eth0 parent 1:1 classid 1:30 htb rate 20mbit ceil 50mbit prio 3

Step 5: Apply Traffic Filters

Direct specific network traffic into the defined classes using tc filters based on port numbers.

  1. Direct SSH traffic (port 22) to the high-priority class (1:10):

    sudo tc filter add dev eth0 protocol ip parent 1:0 prio 1 u32 match ip dport 22 0xffff flowid 1:10

  2. Direct HTTP (port 80) and HTTPS (port 443) traffic to the standard-priority class (1:20):

    sudo tc filter add dev eth0 protocol ip parent 1:0 prio 2 u32 match ip dport 80 0xffff flowid 1:20
sudo tc filter add dev eth0 protocol ip parent 1:0 prio 2 u32 match ip dport 443 0xffff flowid 1:20

Step 6: Verify Active QoS Settings

Check that the queuing disciplines, classes, and traffic filters are actively processing packets:

  • View active qdiscs:

    tc qdisc show dev eth0

  • View class statistics and bandwidth usage:

    tc -s class show dev eth0

  • View applied filters:

    tc filter show dev eth0

Step 7: Make the Configuration Persistent

Traffic control settings configured via the terminal are lost when the system restarts. To make them permanent:

  1. Create a script containing your configuration commands:

    sudo nano /usr/local/bin/setup-qos.sh

  2. Add #!/bin/bash at the top of the file followed by your exact tc commands, then save and exit.

  3. Grant execute permissions to the script:

    sudo chmod +x /usr/local/bin/setup-qos.sh

  4. Configure the script to execute automatically at startup using a systemd service or network interface startup hooks.
