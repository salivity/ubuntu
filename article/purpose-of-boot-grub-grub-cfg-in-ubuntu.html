Purpose of /boot/grub/grub.cfg in Ubuntu

The /boot/grub/grub.cfg file is the main runtime configuration file used by the GRUB (GRand Unified Bootloader) bootloader in Ubuntu to control how the operating system boots. It dictates which operating systems appear in the boot menu, sets default boot selections, configures kernel parameters, and manages boot timeouts. However, users should never edit this file directly because it is automatically generated by the system, meaning any manual modifications will be permanently overwritten whenever a kernel update or bootloader regeneration occurs.

The Purpose of /boot/grub/grub.cfg

When an Ubuntu computer starts up, the BIOS/UEFI initializes the hardware and passes control to GRUB. GRUB then reads the /boot/grub/grub.cfg file to determine how to present the boot menu and load the operating system.

Key functions of this file include: * Boot Menu Generation: Defines the list of available operating systems, recovery modes, and memory testing tools available at startup. * Kernel Parameters: Specifies the exact Linux kernel images, initial RAM disk files (initrd), and boot flags (such as quiet splash) passed to the kernel during startup. * System Settings: Controls default menu options, display resolutions, background images, and menu timeout durations.

Why You Should Not Edit /boot/grub/grub.cfg Directly

Although /boot/grub/grub.cfg is a plain text file, modifying it directly is unsafe and ineffective for several reasons:

  1. Automatic Overwrites: The file is dynamically generated by the update-grub tool (which calls grub-mkconfig). Whenever Ubuntu updates its Linux kernel, installs software that interacts with the bootloader, or runs automated maintenance scripts, grub.cfg is completely regenerated, deleting any custom edits you made manually.
  2. Risk of Boot Failures: The syntax used inside grub.cfg is a specialized scripting language. A single missing quote, incorrect variable, or syntax mistake can render the system unbootable, leaving you unable to load the operating system without recovery tools.
  3. Read-Only Intent: By default, the file permissions are set to read-only even for the root user to serve as a warning against direct modification.

The Correct Way to Modify GRUB Settings

Instead of editing /boot/grub/grub.cfg, Ubuntu provides a modular, safe system for customizing GRUB settings:

  1. Edit /etc/default/grub: This file contains primary user-configurable options, such as GRUB_TIMEOUT, GRUB_DEFAULT, and GRUB_CMDLINE_LINUX_DEFAULT.

  2. Use /etc/grub.d/ for Advanced Scripts: This directory contains executable scripts (like 10_linux or 40_custom) that build specific sections of the final configuration file. Custom boot entries should be added to /etc/grub.d/40_custom.

  3. Apply Changes: After saving modifications in /etc/default/grub or /etc/grub.d/, apply them by running:

    sudo update-grub

    This command safely parses your source configuration files, builds a new /boot/grub/grub.cfg, and ensures your changes persist across future updates.
