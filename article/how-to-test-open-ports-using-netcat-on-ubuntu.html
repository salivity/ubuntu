How to Test Open Ports Using Netcat on Ubuntu

Testing network connectivity to specific remote ports is a critical troubleshooting step for systems administrators and developers. This guide demonstrates how to use the Netcat (nc) utility on Ubuntu to check TCP and UDP port reachability, implement timeouts, scan port ranges, and interpret the command output to diagnose firewall and service availability issues.

1. Install Netcat on Ubuntu

While most Ubuntu distributions include Netcat by default, you can ensure the OpenBSD variant is installed by running:

sudo apt update
sudo apt install netcat-openbsd -y

2. Basic Syntax

The standard syntax for checking a port with Netcat is:

nc [options] <host> <port>

When probing ports, the two most common options are:

  • -z: Sets Netcat to zero-I/O mode, which scans for listening daemons without sending any payload data.
  • -v: Enables verbose output, providing details about whether the connection succeeded or failed.

3. Test a Single TCP Port

To check whether a specific TCP port is open and listening on a target host, run:

nc -zv 192.168.1.50 22

You can also use domain names instead of IP addresses:

nc -zv example.com 443

Interpreting the Results

  • Success: If the port is open, the output will display a confirmation: 
    Connection to example.com 443 port [tcp/https] succeeded!
  • Closed Port: If the host is reachable but no service is listening on that port, you will see: 
    nc: connect to example.com port 443 (tcp) failed: Connection refused
  • Filtered/Blocked: If a firewall is dropping packets, the command will hang indefinitely until it times out.

4. Set a Connection Timeout

To prevent Netcat from hanging when a firewall silently drops incoming packets, use the -w flag followed by the desired timeout duration in seconds:

nc -zvw 3 192.168.1.50 80

If the connection is not established within 3 seconds, Netcat terminates the attempt and reports a timeout.

5. Test a UDP Port

By default, Netcat operates over TCP. To test a UDP port (such as DNS on port 53 or NTP on port 123), add the -u flag:

nc -zvu 8.8.8.8 53

Note: Because UDP is a connectionless protocol, Netcat considers the port open unless the target system explicitly responds with an ICMP "Port Unreachable" packet. Firewalls configured to silently drop UDP packets may cause Netcat to report a false positive.

6. Scan a Range of Ports

Netcat allows you to test multiple sequential ports or lists of ports in a single command.

To test a continuous range:

nc -zv 192.168.1.50 20-25

To test non-sequential ports, list them separated by spaces:

nc -zv 192.168.1.50 80 443 8080
