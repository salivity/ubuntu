Configure Keepalived VIP on Two Ubuntu Load Balancers

Configuring a high-availability Virtual IP (VIP) between two Ubuntu load balancers ensures that incoming network traffic automatically reroutes if the primary load balancer fails. This guide covers the installation of Keepalived on Ubuntu, setting up the Virtual Router Redundancy Protocol (VRRP) on both a primary (MASTER) and secondary (BACKUP) node, and verifying seamless failover using a shared floating IP address.

Prerequisites

  • Two Ubuntu servers (Node 1 and Node 2) deployed on the same subnet.
    • Node 1 (Master): 192.168.1.11
    • Node 2 (Backup): 192.168.1.12
  • A free static IP address to serve as the Virtual IP (VIP): 192.168.1.100
  • Sudo or root privileges on both machines.

Step 1: Enable Non-Local IP Binding

By default, the Linux kernel does not allow services to bind to an IP address that is not currently assigned to a local network interface. Enable non-local binding on both Node 1 and Node 2 so services can bind to the VIP.

Run the following command on both servers:

echo "net.ipv4.ip_nonlocal_bind=1" | sudo tee -a /etc/sysctl.conf
sudo sysctl -p

Step 2: Install Keepalived

Update package repositories and install Keepalived on both servers:

sudo apt update
sudo apt install keepalived -y

Step 3: Configure the Master Node (Node 1)

Create the Keepalived configuration file on Node 1:

sudo nano /etc/keepalived/keepalived.conf

Add the following configuration. Replace eth0 with the actual name of your network interface (verify via ip a):

vrrp_instance VI_1 {
    state MASTER
    interface eth0
    virtual_router_id 51
    priority 101
    advert_int 1

    authentication {
        auth_type PASS
        auth_pass SecureSecret123
    }

    virtual_ipaddress {
        192.168.1.100/24
    }
}
  • state MASTER: Designates this node as the primary holder of the VIP.
  • virtual_router_id: Must be identical on both nodes to form a VRRP pair.
  • priority: Higher value wins the VIP election (101 vs 100).
  • auth_pass: A shared password used by both nodes to communicate.
  • virtual_ipaddress: The VIP and subnet mask.

Save and close the file.

Step 4: Configure the Backup Node (Node 2)

Create the Keepalived configuration file on Node 2:

sudo nano /etc/keepalived/keepalived.conf

Add the following configuration, ensuring the interface matches Node 2's network interface:

vrrp_instance VI_1 {
    state BACKUP
    interface eth0
    virtual_router_id 51
    priority 100
    advert_int 1

    authentication {
        auth_type PASS
        auth_pass SecureSecret123
    }

    virtual_ipaddress {
        192.168.1.100/24
    }
}

Save and close the file.

Step 5: Start and Enable Keepalived

Start and enable the Keepalived service on both nodes to ensure it runs on boot.

On Node 1 and Node 2:

sudo systemctl enable --now keepalived

Check the service status:

sudo systemctl status keepalived

Step 6: Verify and Test Failover

  1. Verify the VIP on Master: Run ip a show eth0 on Node 1. The output should list 192.168.1.100/24 under the interface addresses. Run ip a show eth0 on Node 2. The VIP should not appear here while the master is healthy.

  2. Simulate Master Failure: Stop the Keepalived daemon on Node 1:

    sudo systemctl stop keepalived

  3. Verify Failover on Backup: Run ip a show eth0 on Node 2. The VIP 192.168.1.100/24 should now be attached to Node 2's interface.

  4. Restore Master: Restart Keepalived on Node 1:

    sudo systemctl start keepalived

    Because Node 1 has a higher priority (101), it will preempt Node 2 and reclaim the VIP automatically.
