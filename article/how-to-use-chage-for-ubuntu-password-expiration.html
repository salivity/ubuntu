How to Use chage for Ubuntu Password Expiration

The chage (change age) command in Ubuntu is a dedicated administrative tool used to view, configure, and enforce user password aging and account expiration policies. By manipulating parameters stored in the /etc/shadow file, chage enables system administrators to implement organizational security standards, prevent credential stagnation, and control account lifespans. This article covers how chage works, its key options, and how to apply practical password expiration rules on an Ubuntu system.

Understanding the Role of chage

In Linux environments, password policies can be configured globally (via /etc/login.defs or PAM configurations) or on a per-user basis. The chage command provides granular, per-user control over password lifespans. It directly determines when a user must change their password, how early they receive warning notices, and when an account becomes inactive or disabled due to non-compliance.

Viewing Account Expiration Details

Before modifying an account's aging policy, administrators can inspect the current parameters using the -l (list) flag.

sudo chage -l username

This output displays the date of the last password change, the minimum and maximum days between changes, the warning period, account inactivity intervals, and overall account expiration dates.

Key Command Flags

The chage command provides specific flags to control every aspect of password aging:

  • -M, --maxdays MAX_DAYS: Sets the maximum number of days a password remains valid. Once this threshold is reached, the user must update their password.
  • -m, --mindays MIN_DAYS: Sets the minimum number of days required between password changes, preventing users from immediately changing their password back to a previous one.
  • -W, --warndays WARN_DAYS: Defines how many days in advance a user is warned that their password is due to expire.
  • -I, --inactive INACTIVE: Sets the number of days of inactivity after a password expires before the entire account is locked.
  • -E, --expiredate EXPIRE_DATE: Sets a fixed calendar date (in YYYY-MM-DD format) on which the account is disabled, useful for temporary workers or contractors.
  • -d, --lastday LAST_DAY: Sets the date of the last password change. Setting this to 0 forces the user to change their password upon their next login.

Practical Configuration Examples

1. Enforcing a Standard 90-Day Rotation

To enforce a policy where a password must be rotated every 90 days, with a 7-day warning period and a minimum wait time of 1 day between changes:

sudo chage -m 1 -M 90 -W 7 username

2. Forcing an Immediate Password Change

When onboarding new users or responding to a suspected credential leak, administrators can force an immediate change at next login by resetting the last change date to zero:

sudo chage -d 0 username

3. Setting Account Inactivity and Fixed Expiration

To configure an account to lock if the password remains expired for more than 14 days, and completely terminate access on December 31, 2026:

sudo chage -I 14 -E 2026-12-31 username

4. Disabling Password Expiration

To remove expiration limits for service accounts or specific users:

sudo chage -M -1 -E -1 username

Interactive Mode

Administrators who prefer a guided setup can run chage without flags alongside the target username:

sudo chage username

This launches an interactive prompt that steps through each parameter sequentially, allowing the administrator to accept default values or input new constraints.

Conclusion

The chage utility is a critical component of access management in Ubuntu. Applying proactive password aging schedules minimizes the window of opportunity for compromised credentials, ensures regulatory compliance, and maintains control over user account lifecycles across the system.
