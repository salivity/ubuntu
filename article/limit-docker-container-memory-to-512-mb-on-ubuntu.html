Limit Docker Container Memory to 512MB on Ubuntu

Controlling memory allocation for Docker containers on Ubuntu ensures single processes do not exhaust host resources and destabilize the operating system. This guide outlines how to enforce a 512MB memory limit when launching a Docker container using CLI flags, configure swap limits, verify memory usage, and apply equivalent configurations using Docker Compose.

Limiting Memory with the Docker CLI

To limit a container to 512MB of RAM upon launch, pass the -m or --memory flag to the docker run command.

Run the following command:

docker run -d --name my_container -m 512m nginx

In this command:

  • -d runs the container in detached mode.
  • --name my_container assigns a name to the container.
  • -m 512m (or --memory 512m) sets the maximum limit of user memory to 512 megabytes.
  • nginx is the example image being launched.

Managing Swap Memory Limits

By default, Docker allocates an equal amount of swap memory in addition to the specified RAM limit. If you restrict memory to 512m, the container can access up to 512MB of RAM and 512MB of swap, totaling 1GB of combined memory.

To completely prevent the container from using swap memory beyond the 512MB RAM allocation, set the --memory-swap flag to the same value as --memory:

docker run -d --name my_container -m 512m --memory-swap 512m nginx

Note: If Ubuntu displays a warning stating WARNING: No swap limit support, enable memory cgroups in your GRUB configuration by adding cgroup_enable=memory swapaccount=1 to /etc/default/grub and running sudo update-grub followed by a reboot.

Limiting Memory Using Docker Compose

If you use Docker Compose to manage containers, define the 512MB limit in your docker-compose.yml file under the resource deployment limits:

version: '3.8'

services:
  web:
    image: nginx
    deploy:
      resources:
        limits:
          memory: 512M

For Compose specification versions that do not use the deploy key, use the direct attribute:

version: '2.4'

services:
  web:
    image: nginx
    mem_limit: 512m
    memswap_limit: 512m

Apply the configuration with:

docker compose up -d

Verifying the Memory Limit

To confirm that the 512MB limit is actively enforced on the running container, inspect its real-time metrics with docker stats:

docker stats my_container

The output displays the MEM USAGE / LIMIT column, which will show the container's current usage alongside 512MiB, confirming the restriction is active.
