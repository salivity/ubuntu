How to Generate a CSR with OpenSSL on Ubuntu

Securing a web server with an SSL/TLS certificate begins with creating a Certificate Signing Request (CSR) and a corresponding private key. This guide walks you through using the OpenSSL utility on Ubuntu to generate these files, explain the required domain information, verify the request details, and prepare the CSR for submission to a Certificate Authority (CA).

Step 1: Install OpenSSL

OpenSSL is typically installed by default on Ubuntu. Update your package list and ensure OpenSSL is present:

sudo apt update
sudo apt install openssl

Step 2: Generate the Private Key and CSR

You can generate both the private key and the CSR in a single command. Replace yourdomain with your actual domain name:

openssl req -new -newkey rsa:2048 -nodes -keyout yourdomain.key -out yourdomain.csr
  • -new: Creates a new certificate signing request.
  • -newkey rsa:2048: Generates a 2048-bit RSA private key (the standard security requirement).
  • -nodes: "No DES"—keeps the private key unencrypted so the web server can read it upon restart without requiring a password.
  • -keyout: Specifies the output filename for the private key.
  • -out: Specifies the output filename for the CSR.

Step 3: Enter Certificate Information

After running the command, you will be prompted to enter the details for your certificate. Enter the following information:

  • Country Name (2 letter code): Your two-letter ISO country code (e.g., US).
  • State or Province Name: The full name of your state or province (e.g., California).
  • Locality Name: The city or town (e.g., San Francisco).
  • Organization Name: The legal name of your business or organization (e.g., Example LLC).
  • Organizational Unit Name: Your department or division (optional; press Enter to skip).
  • Common Name: The fully qualified domain name (FQDN) you want to secure (e.g., example.com or *.example.com for a wildcard certificate). This field is critical.
  • Email Address: An administrative email address for the domain.
  • A challenge password / Optional company name: Leave these blank by pressing Enter.

Step 4: Verify the CSR Contents

Before submitting the CSR to your CA, inspect it to confirm all details are accurate:

openssl req -text -noout -verify -in yourdomain.csr

Look at the Subject: line in the output to confirm your Common Name and organization details are correct.

Step 5: Secure the Private Key

Restrict access to your private key so only the root user can read it:

sudo chmod 600 yourdomain.key

Next Steps

To submit your request, view the raw CSR contents using:

cat yourdomain.csr

Copy the entire output, including the -----BEGIN CERTIFICATE REQUEST----- and -----END CERTIFICATE REQUEST----- lines, and paste it into your CA’s web portal to complete the issuance process. Keep the yourdomain.key file in a secure location on your server; you will need it to configure your web server once the CA issues your certificate.
