Cloud-Init Metadata for Ubuntu on Google Cloud

When deploying an Ubuntu virtual machine on Google Cloud Platform (GCE), the cloud-init metadata source serves as the critical communication bridge between Google's infrastructure and the instance's operating system. It queries the Google Compute Engine metadata server during early boot to retrieve instance-specific configurations, such as SSH keys, networking details, hostname, and user-provided provisioning scripts. By processing this data automatically, cloud-init ensures the Ubuntu instance transitions from a generic base image into a fully configured, secure, and operational workload without requiring manual intervention.

The Role of the GCE Data Source

Cloud-init relies on specialized modules called datasources to discover and consume platform-specific information. In Google Cloud, the relevant module is DataSourceGCE.

During the initialization sequence, DataSourceGCE contacts the internal Google Cloud metadata server at the well-known, non-routable IP address 169.254.169.254 (or metadata.google.internal). The metadata server provides a RESTful interface containing environment-specific attributes associated with the VM and its parent project.

Core Responsibilities During Bootstrapping

The metadata source orchestrates several fundamental bootstrapping tasks:

1. SSH Key and Access Management

Security configurations are prioritized during initialization. The metadata source reads project-level and instance-level SSH keys stored in Google Cloud and injects them into the designated user accounts (such as the default OS Login user or specified admin accounts). This provides immediate, secure administrative access via SSH upon boot completion.

2. Hostname and Network Configuration

Cloud-init sets the system hostname and domain based on metadata retrieved from GCP. It works in tandem with systemd-networkd or Netplan to configure network interfaces, ensuring internal and external IP addresses, default routes, and DNS resolvers are properly integrated into the operating system.

3. User Data and Cloud-Config Processing

Administrators frequently pass custom setup instructions via the user-data metadata key. This can be a shell script or a declarative cloud-config YAML file. The metadata source pulls this information and executes tasks such as:

  • Installing software packages and system dependencies.
  • Creating non-root system users and managing groups.
  • Writing configuration files to specific filesystem locations.
  • Managing storage, such as mounting attached persistent disks.

4. Startup Script Execution

Google Cloud allows users to define custom startup scripts via the startup-script metadata key. Cloud-init coordinates the execution order, allowing base system configurations to finalize before application-level initialization scripts run.

The Bootstrapping Lifecycle

Cloud-init executes in distinct phases during the Ubuntu boot process:

  1. Generator Phase: Systemd generators identify cloud-init targets.
  2. Local Phase (cloud-init-local): Minimal network configuration is applied, and the system prepares to identify the datasource.
  3. Network Phase (cloud-init): Once local networking is established, DataSourceGCE queries the metadata server, processes the network configuration, sets the hostname, and creates system accounts.
  4. Config Phase: Cloud-init runs modules to apply user configuration, such as package installations and file generation.
  5. Final Phase (cloud-init-final): Executes any defined runcmd directives, user scripts, and startup scripts, signaling that the instance is ready for production traffic.

By utilizing the native Google Cloud metadata source, Ubuntu instances achieve true zero-touch provisioning, enabling consistent automation across scalable cloud environments.
