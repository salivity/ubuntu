How to View ZFS Disk IO Statistics on Ubuntu

Monitoring individual disk input/output (I/O) performance in a ZFS storage pool is essential for diagnosing bottlenecks and detecting failing drives on Ubuntu. The native command used to retrieve real-time, detailed I/O statistics for each underlying disk in a pool is zpool iostat -v. This article covers how to execute this command, configure interval polling, and interpret the disk-level output.

The Primary Command: zpool iostat -v

Running zpool iostat without flags only outputs aggregated metrics for the entire storage pool. Appending the -v (verbose) flag forces ZFS to print statistics for every top-level virtual device (vdev) and each individual physical disk within those vdevs.

Run the following command in your terminal:

zpool iostat -v

Continuous Real-Time Monitoring

By default, zpool iostat -v displays the cumulative statistics since the system booted. To view current, real-time activity, append an interval (in seconds) to the command:

zpool iostat -v 1

This updates the console every second. The first printed block still reflects cumulative stats since boot, but every subsequent block shows the delta metrics for the preceding interval. To limit the number of updates, specify a count after the interval:

zpool iostat -v 1 5

Useful Command Flags

You can customize the output to gather deeper performance data:

  • Specify a Pool Name: Restrict output to a single pool: 
    zpool iostat -v mypool 2
  • Full Device Paths (-P): Display complete device paths (such as /dev/sdb or /dev/disk/by-id/...) instead of truncated device names: 
    zpool iostat -vP 1
  • Latency Statistics (-l): Display read, write, and disk management latency times alongside standard operations: 
    zpool iostat -vl 1
  • Latency Histograms (-w): Provide a visual latency breakdown across access times: 
    zpool iostat -v -w

Understanding the Output Columns

The output generated by zpool iostat -v organizes metrics into three primary sections:

  1. Capacity (alloc / free): Displays the amount of physical space currently allocated versus the remaining usable space for the pool and each underlying drive.
  2. Operations (operations - read / write): Measures IOPS (I/O operations per second). A single drive showing significantly higher read or write operations compared to other drives in the same mirror or RAID-Z group can indicate an uneven workload or a drive struggling to fulfill requests.
  3. Bandwidth (bandwidth - read / write): Measures the throughput (bytes transferred per second). This helps identify whether throughput limits on specific storage controllers or individual disks are being reached.
