How to Set Up an Internal CA with step-ca on Ubuntu

Setting up an internal Certificate Authority (CA) allows you to issue, manage, and automate private TLS/SSL certificates across your local network and development environments. This guide walks you through installing Smallstep's step-ca and the step CLI tool on an Ubuntu server, initializing your root and intermediate certificates, configuring step-ca to run as a reliable background service using systemd, and testing certificate generation.

Step 1: Install the Step CLI and Step-CA

First, update your local package lists and download the official Debian packages for both the step command-line utility and the step-ca server from Smallstep's releases.

sudo apt update && sudo apt install -y curl wget libpcsclite1

# Fetch the latest version tags and download the .deb packages
STEP_VERSION=$(curl -s https://api.github.com/repos/smallstep/cli/releases/latest | grep tag_name | cut -d '"' -f 4 | sed 's/v//')
STEP_CA_VERSION=$(curl -s https://api.github.com/repos/smallstep/certificates/releases/latest | grep tag_name | cut -d '"' -f 4 | sed 's/v//')

wget https://github.com/smallstep/cli/releases/download/v${STEP_VERSION}/step-cli_${STEP_VERSION}_amd64.deb
wget https://github.com/smallstep/certificates/releases/download/v${STEP_CA_VERSION}/step-ca_${STEP_CA_VERSION}_amd64.deb

# Install both packages
sudo dpkg -i step-cli_${STEP_VERSION}_amd64.deb
sudo dpkg -i step-ca_${STEP_CA_VERSION}_amd64.deb

Step 2: Initialize the Certificate Authority

Initialize the CA configuration. This command creates the root key, root certificate, intermediate key, intermediate certificate, and default configurations.

step ca init

During initialization, provide the following prompts:

  • Deployment Type: Select Standalone.
  • CA Name: Enter a recognizable name (e.g., Internal Corporate CA).
  • DNS Names/IP Addresses: Enter the local IP address or fully qualified domain name (FQDN) that clients will use to reach this CA (e.g., ca.internal.local or 192.168.1.10).
  • Address to Listen On: Enter :443 or :8443 (e.g., :8443).
  • Provisioner: Provide an administrative email or name to create the default JWK provisioner.
  • Password: Choose a strong password to protect the root and intermediate private keys. Save this password securely.

Step 3: Configure a Dedicated System User and Files

Running the service under a dedicated, unprivileged system user improves security.

Create the user and move the configuration files to /etc/step-ca:

# Create step user
sudo useradd --system --home /etc/step-ca --shell /bin/false step

# Move generated configuration to /etc/step-ca
sudo mv ~/.step /etc/step-ca/
sudo chown -R step:step /etc/step-ca

# Allow step-ca binary to bind to privileged ports (like 443) if needed
sudo setcap CAP_NET_BIND_SERVICE=+eip $(which step-ca)

Create a password file to allow the systemd service to start without manual password entry:

echo "YOUR_CHOSEN_CA_PASSWORD" | sudo tee /etc/step-ca/password.txt
sudo chmod 600 /etc/step-ca/password.txt
sudo chown step:step /etc/step-ca/password.txt

Step 4: Create and Start the Systemd Service

Create a systemd unit file to manage the step-ca lifecycle:

sudo tee /etc/systemd/system/step-ca.service > /dev/null <<EOF
[Unit]
Description=step-ca service
After=network.target
StartLimitIntervalSec=0

[Service]
Type=simple
User=step
Group=step
Environment=STEPPATH=/etc/step-ca/.step
ExecStart=/usr/bin/step-ca /etc/step-ca/.step/config/ca.json --password-file=/etc/step-ca/password.txt
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

Reload systemd, enable the service at boot, and start it:

sudo systemctl daemon-reload
sudo systemctl enable --now step-ca

Verify that the service is running:

sudo systemctl status step-ca

Step 5: Test Certificate Issuance

To test the installation, bootstrap a client or your local machine to trust the CA, and request a certificate.

Bootstrap the trust store on the host machine:

step ca bootstrap --ca-url https://localhost:8443 --fingerprint $(step certificate fingerprint /etc/step-ca/.step/certs/root_ca.crt)

Generate a test certificate and private key for a service:

step ca certificate test.internal.local test.crt test.key

Enter your provisioner password when prompted. The utility will issue test.crt signed by your intermediate CA, ready to be deployed to your internal web servers and services.
