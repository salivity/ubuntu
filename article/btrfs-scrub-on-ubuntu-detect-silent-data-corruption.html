Btrfs Scrub on Ubuntu: Detect Silent Data Corruption

This article explains the role of the btrfs scrub command in identifying and repairing silent data corruption on Ubuntu systems. It covers what silent data corruption is, how Btrfs uses checksum verification during a scrub to maintain storage health, how automatic repair operates under redundant configurations, and the specific commands needed to initiate and monitor scrubbing tasks.

Understanding Silent Data Corruption

Silent data corruption, often called "bit rot," occurs when data on a storage medium subtly degrades or changes due to hardware glitches, electromagnetic interference, firmware bugs, or aging drive platters and flash cells. Unlike catastrophic drive failures, silent corruption does not trigger typical operating system read or write errors. Traditional Linux filesystems like ext4 generally only compute checksums for filesystem metadata, leaving the actual file contents vulnerable to undetected decay until an application tries and fails to read the damaged file.

How btrfs scrub Works

The btrfs scrub command is an active integrity-checking mechanism designed specifically to address silent data corruption. Unlike standard read operations, which only verify data as applications access it, a scrub systematically reads every allocated data and metadata block across the entire filesystem or specified device.

Btrfs calculates checksums (such as CRC32c, xxHash, SHA256, or BLAKE2b) for both metadata and file data at the time of writing and stores these hashes in its metadata tree. When btrfs scrub runs:

  1. It reads all data and metadata blocks sequentially from the disk in the background.
  2. It recalculates the checksum for each block in real time.
  3. It compares the newly generated checksum against the stored checksum.
  4. If the checksums match, the data is verified as healthy. If they do not match, the block is flagged as corrupted.

Detection and Automatic Repair

Detection is only the first stage of the scrub process. What happens upon detecting corruption depends on the filesystem’s storage layout:

  • Redundant Profiles (RAID1, RAID1c3/c4, RAID10): If an integrity error is found on one mirror, Btrfs queries the alternate mirror containing the identical data. It verifies the healthy copy using its checksum, uses it to overwrite the damaged block on the corrupted drive, and repairs the data without administrative intervention or downtime.
  • Single Disk / Non-Redundant Profiles: If data is stored on a single drive without redundancy (profile single), Btrfs cannot repair corrupted user data. However, the scrub immediately detects the corruption, reports the exact extent of the damage, and logs an error to dmesg and the system journal. This prevents corrupted data from propagating undetected into system backups. Metadata, which typically defaults to the DUP (duplicate) profile on single-drive Btrfs setups, can still be repaired automatically because two copies exist on the drive.

Executing and Managing Scrub on Ubuntu

Ubuntu includes the core Btrfs tools through the btrfs-progs package. The scrub process runs entirely in the background at an idle I/O priority to avoid interrupting regular system performance.

Starting a Scrub

To initiate a scrub on a mounted Btrfs filesystem, provide the mount point:

sudo btrfs scrub start /

To run the scrub in the foreground and monitor its completion directly in the terminal, add the -B flag:

sudo btrfs scrub start -B /

Checking Scrub Status

If started in the background, you can inspect the progress, elapsed time, and error counters at any time:

sudo btrfs scrub status /

The output details the total bytes scrubbed, read errors, unverified errors, and how many errors were successfully corrected.

Canceling or Resuming

If heavy disk I/O requires the scrub to halt, use the cancel command:

sudo btrfs scrub cancel /

A paused or interrupted scrub can be resumed from the point it stopped:

sudo btrfs scrub resume /

Regularly scheduling btrfs scrub via systemd timers or cron jobs ensures that storage degradation on Ubuntu is identified early, giving administrators the opportunity to repair data or replace failing hardware before data loss becomes permanent.
