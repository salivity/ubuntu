Configure Ansible Pull on Boot for Ubuntu

Using ansible-pull on an Ubuntu laptop allows the machine to self-provision its software, dotfiles, and system settings at startup without requiring an external control node. This guide covers how to set up ansible-pull by pointing it to a Git repository, writing a baseline playbook, and creating a systemd service that triggers the configuration process automatically on boot once network connectivity is established.

Step 1: Install Ansible and Git

Install the necessary packages locally on your Ubuntu machine:

sudo apt update
sudo apt install -y ansible git

Step 2: Set Up the Git Playbook Repository

ansible-pull expects a Git repository containing an entry playbook, traditionally named local.yml.

Create a public or private repository (e.g., on GitHub or GitLab) and add a local.yml file. Here is a baseline example:

---
- hosts: localhost
  connection: local
  become: true
  tasks:
    - name: Ensure baseline utility packages are installed
      apt:
        name:
          - curl
          - htop
          - ufw
        state: present
        update_cache: yes

    - name: Ensure UFW is enabled and active
      ufw:
        state: enabled
        policy: deny
        direction: incoming

Step 3: Test Ansible Pull Manually

Before automating the process on boot, run ansible-pull manually to verify that it fetches the repository and applies the configuration without errors:

sudo ansible-pull -U https://github.com/your-username/your-ansible-repo.git local.yml

Note: If your repository is private, configure SSH keys for the root user located at /root/.ssh/id_rsa or use a personal access token in the HTTPS URL.

Step 4: Create a Systemd Service for Boot Execution

Create a systemd unit file to execute the ansible-pull command. The service must wait for a working network connection before attempting to fetch the repository.

Create /etc/systemd/system/ansible-pull.service:

sudo nano /etc/systemd/system/ansible-pull.service

Add the following configuration:

[Unit]
Description=Run Ansible Pull on Boot
After=network-online.target
Wants=network-online.target

[Service]
Type=oneshot
ExecStart=/usr/bin/ansible-pull -U https://github.com/your-username/your-ansible-repo.git local.yml
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target

Ensure systemd-networkd-wait-online or NetworkManager-wait-online is functioning so network-online.target blocks execution until the network is genuinely reachable.

Step 5: Enable and Test the Service

Reload the systemd daemon to recognize the new service, then enable it:

sudo systemctl daemon-reload
sudo systemctl enable ansible-pull.service

Test the execution immediately via systemd:

sudo systemctl start ansible-pull.service

Check the status and review the logs:

sudo systemctl status ansible-pull.service
sudo journalctl -u ansible-pull.service -e

Step 6: Handling Offline Boot Gracefully

If your laptop boots while offline, the service might fail. You can configure restart options or wrap the execution in a retry script. Modify the [Service] section if desired:

Restart=on-failure
RestartSec=30

With this configuration active, your Ubuntu laptop will automatically fetch the latest updates from your repository and align its state whenever it powers on.
