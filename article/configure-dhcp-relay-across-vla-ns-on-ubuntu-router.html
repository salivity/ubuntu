Configure DHCP Relay Across VLANs on Ubuntu Router

A DHCP relay agent allows devices residing on separated VLANs or subnets to obtain dynamic IP configurations from a centralized DHCP server. By default, DHCP broadcast requests cannot cross network boundaries created by VLANs. This guide explains how to install, configure, and verify the isc-dhcp-relay service (dhcrelay) on an Ubuntu router to forward DHCP broadcasts as unicast traffic to a central server across multiple network interfaces.

Prerequisites

  • An Ubuntu system configured as a router with at least two network or VLAN interfaces (e.g., vlan10, vlan20, or interface sub-interfaces like eth0.10).
  • A functioning DHCP server reachable by the Ubuntu router with defined address pools for each VLAN subnet.
  • Root or sudo privileges.

Step 1: Enable IPv4 Packet Forwarding

To ensure your Ubuntu machine can route traffic between subnets, enable kernel packet forwarding:

  1. Open /etc/sysctl.conf in a text editor: 
    sudo nano /etc/sysctl.conf
  2. Locate and uncomment or add the following line: 
    net.ipv4.ip_forward=1
  3. Apply the changes immediately: 
    sudo sysctl -p

Step 2: Install the DHCP Relay Package

Ubuntu provides the dhcrelay utility through the isc-dhcp-relay package. Install it via apt:

sudo apt update
sudo apt install isc-dhcp-relay -y

During installation, an interactive prompt will ask for DHCP server IP addresses and interfaces. You can leave these blank and configure them manually in the configuration file in the next step.

Step 3: Configure isc-dhcp-relay

Open the relay configuration file:

sudo nano /etc/default/isc-dhcp-relay

Set the appropriate values for your network topology:

  • SERVERS: The IP address of your central DHCP server.
  • INTERFACES: A space-separated list of interfaces on which dhcrelay should listen and forward traffic. This must include both the client-facing VLAN interfaces and the upstream interface connecting to the DHCP server.
  • OPTIONS: Any additional flags (can typically be left empty).

Example configuration:

# What servers should the DHCP relay forward requests to?
SERVERS="192.168.1.100"

# On what interfaces should the DHCP relay forward requests to?
INTERFACES="vlan10 vlan20 eth0"

# Additional options that are passed to the DHCP relay daemon?
OPTIONS=""

Save the file and exit the editor.

Step 4: Configure Firewall Rules

DHCP relies on UDP ports 67 (server/relay) and 68 (client). If you are running UFW or iptables, allow this traffic across your interfaces:

Using UFW:

sudo ufw allow 67/udp
sudo ufw allow 68/udp

Using iptables:

sudo iptables -A INPUT -p udp --dport 67:68 --sport 67:68 -j ACCEPT
sudo iptables -A FORWARD -p udp --dport 67:68 --sport 67:68 -j ACCEPT

Step 5: Start and Enable the Service

Restart the relay daemon to apply the configuration and enable it to start on boot:

sudo systemctl restart isc-dhcp-relay
sudo systemctl enable isc-dhcp-relay

Check the service status to verify that it is running without errors:

sudo systemctl status isc-dhcp-relay

Step 6: Verify Relay Operation

  1. Connect a client device to one of the configured VLANs and initiate a DHCP request.
  2. Monitor DHCP packets in real time on the Ubuntu router using tcpdump: 
    sudo tcpdump -i any -n port 67 or port 68
  3. You should observe:
    • A broadcast DHCP Discover arriving from the client on the VLAN interface.
    • A unicast packet forwarded by dhcrelay to the central DHCP server with the router's VLAN gateway IP in the giaddr (Gateway IP Address) field.
    • A unicast DHCP Offer returning from the server, which the relay forwards back to the client.
