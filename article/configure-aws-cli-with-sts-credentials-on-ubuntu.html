Configure AWS CLI with STS Credentials on Ubuntu

This article provides a direct guide on setting up the AWS Command Line Interface (CLI) on an Ubuntu workstation and configuring it with temporary AWS Security Token Service (STS) credentials. You will learn how to obtain temporary tokens, apply them using either the credentials configuration file or shell environment variables, and verify that your temporary session is active and authenticated.

1. Install AWS CLI on Ubuntu

If the AWS CLI is not already installed on your Ubuntu machine, install the AWS CLI v2 using the official package:

sudo apt update
sudo apt install curl unzip -y
curl "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o "awscliv2.zip"
unzip awscliv2.zip
sudo ./aws/install

Verify the installation:

aws --version

2. Obtain Temporary STS Credentials

Temporary credentials consist of an Access Key ID, a Secret Access Key, and a Session Token. You can generate these using an IAM user session or by assuming an IAM role.

To generate temporary credentials by assuming a role, run:

aws sts assume-role \
  --role-arn "arn:aws:iam::123456789012:role/YourRoleName" \
  --role-session-name "UbuntuSession"

To request session tokens directly for an IAM user (often with MFA):

aws sts get-session-token \
  --serial-number "arn:aws:iam::123456789012:mfa/YourUser" \
  --token-code 123456

The output returns JSON containing:

  • AccessKeyId
  • SecretAccessKey
  • SessionToken
  • Expiration

3. Apply STS Credentials to the Configuration File

You can store the temporary credentials in the standard AWS credentials file located at ~/.aws/credentials.

Open or create the file:

nano ~/.aws/credentials

Add a designated profile with the temporary keys and session token:

[temp-session]
aws_access_key_id = ASIAEXAMPLEKEYID
aws_secret_access_key = wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
aws_session_token = IQoJb3JpZ2luX2VjE...EXAMPLE_TOKEN_STRING...

Save and exit the file. Next, ensure the default region is set in ~/.aws/config:

[profile temp-session]
region = us-east-1
output = json

To use this profile with the CLI:

aws s3 ls --profile temp-session

4. Alternative: Export Credentials as Environment Variables

Alternatively, you can apply temporary credentials to your current Ubuntu terminal session using environment variables. These take precedence over profile files.

export AWS_ACCESS_KEY_ID="ASIAEXAMPLEKEYID"
export AWS_SECRET_ACCESS_KEY="wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY"
export AWS_SESSION_TOKEN="IQoJb3JpZ2luX2VjE...EXAMPLE_TOKEN_STRING..."
export AWS_DEFAULT_REGION="us-east-1"

These variables will remain active until you close your shell session or un-set them.

5. Verify the Temporary Credentials

Run the following command to verify that the AWS CLI is using the temporary credentials:

aws sts get-caller-identity

If using the profile method:

aws sts get-caller-identity --profile temp-session

The command output will display the assumed role ARN or session ARN, confirming that your Ubuntu workstation is operating under temporary STS authorization.
