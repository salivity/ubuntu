How to Configure VRF on Ubuntu with iproute2

Virtual Routing and Forwarding (VRF) allows a Linux host to handle multiple, isolated routing tables simultaneously on a single network stack. This guide provides a straightforward walkthrough for creating and managing VRF instances on Ubuntu using the standard iproute2 suite. You will learn how to create a VRF master device, bind physical or virtual interfaces to it, configure dedicated routing rules, and execute applications within an isolated routing domain.

1. Verify Kernel Support

Modern Ubuntu releases (18.04 LTS and newer) include kernel support for VRF by default. Ensure the vrf kernel module is loaded:

sudo modprobe vrf

2. Create the VRF Master Device

A VRF instance in Linux is represented as a virtual network interface associated with a dedicated routing table ID. Choose an arbitrary table ID (e.g., 100) and a name for the VRF (e.g., vrf-blue):

sudo ip link add dev vrf-blue type vrf table 100

Bring the VRF interface up:

sudo ip link set dev vrf-blue up

3. Enslave Network Interfaces to the VRF

Assign an existing interface (such as a physical interface, VLAN, or dummy device) to the newly created VRF.

Note: Assigning an interface to a VRF removes its current IP address configuration. Set the IP after binding the interface.

Bind the interface (eth1 in this example) to vrf-blue:

sudo ip link set dev eth1 master vrf-blue

Assign an IP address to the enclosed interface and bring it up:

sudo ip addr add 192.168.10.2/24 dev eth1
sudo ip link set dev eth1 up

4. Configure VRF Routes

Routes associated with the VRF must be added directly to the routing table mapped to that VRF (table 100):

sudo ip route add default via 192.168.10.1 dev eth1 table 100

To view the routing table for your VRF:

ip route show table 100

5. Verify and Test VRF Execution

Verify that the VRF interface and its slave devices are properly associated:

ip vrf show

To run commands or network tests within the context of the VRF, use ip vrf exec:

sudo ip vrf exec vrf-blue ping -c 4 192.168.10.1

You can also run service daemons or shells isolated inside the VRF:

sudo ip vrf exec vrf-blue bash

Any network traffic initiated within this shell will strictly adhere to the routes defined in table 100.

6. Make Configuration Persistent Across Reboots

Commands executed with ip are ephemeral and reset on reboot. On Ubuntu, persist this configuration using Netplan by modifying your YAML configuration file (typically in /etc/netplan/):

network:
  version: 2
  ethernets:
    eth1:
      dhcp4: false
  vrfs:
    vrf-blue:
      table: 100
      interfaces:
        - eth1
      routes:
        - to: default
          via: 192.168.10.1

Apply the Netplan configuration:

sudo netplan apply
