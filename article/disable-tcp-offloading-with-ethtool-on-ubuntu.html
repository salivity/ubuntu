Disable TCP Offloading with Ethtool on Ubuntu

TCP offloading delegates network packet processing tasks from the system CPU to the Network Interface Card (NIC) to improve throughput. While beneficial in high-traffic environments, it can cause packet capture distortion, checksum errors, latency jitter, and compatibility issues with specific virtualized environments or packet inspection tools. This guide explains how to inspect your current offload settings and use the ethtool utility to disable TCP offloading on an Ubuntu system, both temporarily and permanently.

Step 1: Install Ethtool

Most Ubuntu installations do not include ethtool by default. Install it using the apt package manager:

sudo apt update
sudo apt install ethtool -y

Step 2: Identify Your Network Interface

Find the logical name of the network interface you want to modify by listing all available interfaces:

ip link show

Note the interface name you need to configure (for example, eth0, enp3s0, or ens33).

Step 3: View Current TCP Offload Settings

Query the current offload parameters of the interface using the -k (or --show-features) flag:

ethtool -k eth0

Look for the following common TCP offloading features:

  • tcp-segmentation-offload (tso): Offloads TCP packet segmentation.
  • generic-segmentation-offload (gso): Offloads segmentation for protocols beyond standard TCP.
  • generic-receive-offload (gro): Reassembles incoming packets at the NIC layer.
  • large-receive-offload (lro): Aggregates incoming TCP segments into larger buffers.
  • rx-checksumming / tx-checksumming: Offloads packet checksum calculations.

Step 4: Disable TCP Offloading Temporarily

Use the -K (or --offload) flag to turn off specific offloading features. To disable the primary TCP offload mechanisms, run:

sudo ethtool -K eth0 tso off gso off gro off rx off tx off

Verify that the changes were applied:

ethtool -k eth0 | grep -E "segmentation|receive-offload|checksumming"

Note: Changes made directly via the ethtool command apply immediately but will revert after a system reboot or interface restart.

Step 5: Make the Changes Persistent

Ubuntu uses Netplan and systemd-networkd for network management. To ensure offload settings persist across reboots, use a systemd .link configuration.

  1. Determine the MAC address of your interface:
cat /sys/class/net/eth0/address
  1. Create a custom .link file in /etc/systemd/network/:
sudo nano /etc/systemd/network/10-disable-offload.link
  1. Add the following configuration, replacing eth0 and the MAC address with your device details:
[Match]
MACAddress=00:11:22:33:44:55
OriginalName=eth0

[Link]
ReceiveChecksumOffload=no
TransmitChecksumOffload=no
TCPSegmentationOffload=no
GenericSegmentationOffload=no
GenericReceiveOffload=no
LargeReceiveOffload=no
  1. Update your initramfs and apply the configuration:
sudo update-initramfs -u
sudo systemctl restart systemd-networkd

Alternatively, you can create a dedicated systemd one-shot service to run the ethtool command at boot if you prefer not to manage systemd.link files:

sudo nano /etc/systemd/system/disable-offload.service

Insert the following:

[Unit]
Description=Disable TCP Offloading via ethtool
After=network.target

[Service]
Type=oneshot
ExecStart=/sbin/ethtool -K eth0 tso off gso off gro off rx off tx off
RemainAfterExit=true

[Install]
WantedBy=multi-user.target

Enable the service to run on startup:

sudo systemctl daemon-reload
sudo systemctl enable disable-offload.service
