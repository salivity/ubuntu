Using xinput to Configure Touchpads on Ubuntu X11

The xinput utility is a specialized command-line tool in Ubuntu running the X Window System (X11) designed to query, test, and dynamically modify input devices such as touchpads, mice, and trackpoints. This article explains the primary role of xinput within X11, outlines how to identify pointing hardware and inspect driver properties, and details how to apply real-time configuration changes—such as adjusting sensitivity, enabling tap-to-click, and reversing scroll direction—without restarting the desktop environment.

The Purpose of xinput in X11

In an Ubuntu X11 session, the desktop relies on the X Input extension to process signals from pointing devices. While desktop environments like GNOME or XFCE provide graphical control panels for basic adjustments, these interfaces frequently hide advanced driver settings or fail to support non-standard hardware.

xinput acts as a direct bridge between the user and the X server. Its main purposes include:

  • Hardware Discovery: Detecting all connected master and slave input devices registered to the X server.
  • Property Inspection: Viewing available low-level parameters provided by input drivers such as libinput or synaptics.
  • Live Modification: Changing device parameters in real time without editing static configuration files or restarting the display manager.
  • Device Management: Enabling or disabling specific hardware components, such as deactivating a laptop touchpad while preserving an external mouse.

Identifying Devices

To configure a pointer or touchpad, you must first determine its device name or unique numeric identifier. Run the following command in the terminal:

xinput list

The output organizes devices into virtual core pointers and keyboards. Locate your target pointing device under Virtual core pointer. For example:

⎡ Virtual core pointer                    id=2    [master pointer (3)]
⎜   ↳ SynPS/2 Synaptics TouchPad          id=11   [slave  pointer (2)]
⎜   ↳ Logitech USB Optical Mouse          id=12   [slave  pointer (2)]

Devices can be targeted using either their full name in quotes (e.g., "SynPS/2 Synaptics TouchPad") or their assigned ID (e.g., 11). Using the name is generally preferred in scripts, as numeric IDs can change between reboots.

Viewing Configurable Properties

Drivers expose specific features as adjustable properties. To see every configurable option for a device, use the list-props command:

xinput list-props 11

The output displays property names, internal format types, and current values:

Device 'SynPS/2 Synaptics TouchPad':
    Device Enabled (153):   1
    libinput Tapping Enabled (310): 0
    libinput Natural Scrolling Enabled (288): 0
    libinput Accel Speed (296): 0.000000

Applying Runtime Configurations

You can modify settings immediately using the set-prop command. The basic syntax is:

xinput set-prop <device> <property-name> <value>

Common adjustments include:

  • Enable Tap-to-Click: Set the tapping property to 1 (enabled). 
    xinput set-prop "SynPS/2 Synaptics TouchPad" "libinput Tapping Enabled" 1
  • Enable Natural (Reverse) Scrolling: Set the natural scrolling property to 1. 
    xinput set-prop "SynPS/2 Synaptics TouchPad" "libinput Natural Scrolling Enabled" 1
  • Adjust Pointer Speed: Modify the acceleration speed using a floating-point value between -1.0 (slowest) and 1.0 (fastest), where 0.0 represents the default. 
    xinput set-prop "SynPS/2 Synaptics TouchPad" "libinput Accel Speed" 0.3

Enabling and Disabling Devices

xinput allows you to immediately toggle devices on or off without physically disconnecting them. This is useful for turning off a malfunctioning touchpad:

xinput disable "SynPS/2 Synaptics TouchPad"

To re-enable the device:

xinput enable "SynPS/2 Synaptics TouchPad"

Making Configurations Persistent

Changes applied via xinput set-prop remain active only for the duration of the current X11 session. When the computer reboots or the user logs out, the properties revert to system defaults.

To make settings permanent, you have two options:

  1. User Session Script: Add the desired xinput set-prop commands to your desktop environment’s "Startup Applications" or an initialization file such as ~/.xprofile.
  2. System-Wide Xorg Configuration: Create a custom .conf file inside /etc/X11/xorg.conf.d/ (such as 90-touchpad.conf) utilizing InputClass sections to set driver options globally on boot.
