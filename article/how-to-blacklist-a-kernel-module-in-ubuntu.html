How to Blacklist a Kernel Module in Ubuntu

Blacklisting a hardware driver or kernel module in Ubuntu prevents the operating system from loading problematic drivers that cause system instability, hardware conflicts, or boot loops. This guide walks you through identifying the faulty module, adding it to the modprobe blacklist configuration, updating your initial RAM filesystem (initramfs), and verifying that the module no longer loads at startup.

Step 1: Identify the Problematic Module

Before blacklisting a driver, you need its exact kernel module name. You can list all currently loaded modules using:

lsmod

To narrow down the list, pipe the output into grep:

lsmod | grep -i <keyword>

Alternatively, if you know the hardware device causing issues, run:

lspci -k

Locate the device in the output and note the name specified under Kernel modules: or Kernel driver in use:.

Step 2: Add the Module to the Blacklist File

Ubuntu manages kernel module loading through configuration files stored in /etc/modprobe.d/. It is best practice to create a dedicated configuration file for custom blacklists.

Open a terminal and create a new blacklist file using a text editor such as nano:

sudo nano /etc/modprobe.d/blacklist-custom.conf

Add the following line to the file, replacing module_name with the actual name of the driver:

blacklist module_name

If the module is automatically loaded as a dependency by another driver, simply blacklisting it may not prevent it from loading. To completely disable it, add this fallback line directly below the blacklist directive:

install module_name /bin/false

Save the file and exit the text editor (in Nano, press Ctrl + O, hit Enter, and then press Ctrl + X).

Step 3: Update the Initramfs

Ubuntu loads many critical drivers during the early boot process via the initramfs (initial RAM filesystem). To ensure your blacklisting rules apply before the root filesystem is even mounted, regenerate the initramfs image:

sudo update-initramfs -u

Wait for the process to complete successfully.

Step 4: Reboot and Verify

Restart your system to apply the changes:

sudo reboot

Once the system boots up, verify that the module is no longer active by running:

lsmod | grep module_name

If the command returns no output, the driver has been successfully blacklisted and will no longer load automatically.
