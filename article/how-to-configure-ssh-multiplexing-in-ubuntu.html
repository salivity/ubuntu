How to Configure SSH Multiplexing in Ubuntu

SSH multiplexing speeds up remote server connections in Ubuntu by reusing a single established TCP connection for multiple concurrent SSH sessions, eliminating the overhead of repeated authentication and key exchanges. This article outlines the step-by-step process of configuring SSH multiplexing on your Ubuntu system using the client-side ~/.ssh/config file, explaining key parameters like ControlMaster, ControlPath, and ControlPersist, and demonstrating how to manage active control sockets.

Step 1: Open the SSH Client Configuration File

SSH multiplexing is configured on the client machine. Open or create your user-level SSH configuration file using a text editor:

nano ~/.ssh/config

Ensure the file has the correct permissions if you are creating it for the first time:

chmod 600 ~/.ssh/config

Step 2: Add Multiplexing Configuration Directives

To enable multiplexing for all remote hosts (or specific ones), add the following directives to your ~/.ssh/config file:

Host *
    ControlMaster auto
    ControlPath ~/.ssh/control-%r@%h:%p
    ControlPersist 10m

Explanation of Settings:

  • Host *: Applies these settings to all remote servers. Replace * with a specific IP address or domain name if you only want it enabled for certain hosts.
  • ControlMaster auto: Tells SSH to automatically use a master connection if one exists, or create a new master connection if it does not.
  • ControlPath ~/.ssh/control-%r@%h:%p: Defines the path to the Unix control socket file used for sharing the connection.
    • %r = Remote username
    • %h = Remote host
    • %p = Remote port
  • ControlPersist 10m: Keeps the master connection alive in the background for 10 minutes after the initial terminal session is closed. Subsequent connections within this window will connect instantly. Set this to yes to keep it open indefinitely until manually stopped.

Save and close the file.

Step 3: Test the Configuration

  1. Establish your initial connection to the remote server:

    ssh user@remote_host

    This first connection will prompt for authentication (password or SSH key) and create the master control socket.

  2. Open a second terminal window on your local machine and connect to the same server:

    ssh user@remote_host

    This second session will connect instantly without prompting for passwords or re-authenticating.

Step 4: Managing Active Multiplexed Connections

You can check, stop, or manage existing control sockets directly using SSH command-line flags.

  • Check connection status:

    ssh -O check user@remote_host

  • Gracefully stop the master connection (prevents new sessions while letting active ones finish):

    ssh -O stop user@remote_host

  • Forcefully exit the master connection:

    ssh -O exit user@remote_host
