Restrict SSH User to Chroot Jail in Ubuntu

Restricting an SSH user to a chroot jail environment in Ubuntu enhances server security by isolating the user to a specific directory and preventing access to the rest of the filesystem. This guide covers the complete process of creating a restricted environment using OpenSSH, setting up the required strict directory permissions, and configuring sshd_config to lock a specific user into their designated directory.

Step 1: Create the Restricted User

Create a new user account that will be restricted to the chroot environment.

sudo adduser jailuser

Follow the prompts to set a secure password and complete the user creation process.

Step 2: Set Up the Chroot Directory

OpenSSH requires the target chroot directory and all parent directories in its path to be owned by root with permissions set to 755. The jailed user must not have write access to the main chroot folder.

  1. Create the base chroot directory:
sudo mkdir -p /var/chroot
  1. Set root as the owner and set the correct permissions:
sudo chown root:root /var/chroot
sudo chmod 755 /var/chroot
  1. Create a writable subdirectory inside the jail where the user can upload or manage files:
sudo mkdir -p /var/chroot/files
sudo chown jailuser:jailuser /var/chroot/files

Step 3: Configure OpenSSH Server

Edit the SSH daemon configuration file to apply the chroot restrictions to the target user.

  1. Open the configuration file in a text editor:
sudo nano /etc/ssh/sshd_config
  1. Scroll to the bottom of the file and add the following configuration block:
Match User jailuser
    ChrootDirectory /var/chroot
    ForceCommand internal-sftp
    AllowTcpForwarding no
    X11Forwarding no
  • Match User: Applies these rules only to jailuser.
  • ChrootDirectory: Specifies the directory to lock the user inside.
  • ForceCommand internal-sftp: Limits the user strictly to SFTP access (file transfer only), which avoids the complex requirement of copying essential system binaries and libraries into the chroot jail for shell access.
  • AllowTcpForwarding no / X11Forwarding no: Disables port and graphical forwarding for extra security.
  1. Save and close the file.

Step 4: Verify and Restart the SSH Service

Before restarting the SSH daemon, test the configuration syntax to prevent lockouts.

  1. Test the configuration syntax:
sudo sshd -t

If no errors are returned, the configuration is valid.

  1. Restart the SSH service:
sudo systemctl restart ssh

Step 5: Test the Chroot Jail Connection

  1. Attempt to connect using SFTP from a remote client:
sftp jailuser@server_ip
  1. Once logged in, print the working directory:
sftp> pwd
Remote working directory: /

The system will treat /var/chroot as the root (/) directory for jailuser. The user can read and write files inside /files, but cannot navigate outside the designated /var/chroot path.

  1. Test standard SSH shell access (this should be automatically rejected):
ssh jailuser@server_ip

The connection will close immediately with a message stating that the command was forced to SFTP mode, confirming the restriction is working as intended.
