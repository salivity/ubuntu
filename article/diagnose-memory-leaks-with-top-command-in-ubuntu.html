Diagnose Memory Leaks with Top Command in Ubuntu

Diagnosing memory leaks in Ubuntu using the top command involves monitoring system-level memory metrics and tracking process-specific resource consumption over time. A memory leak occurs when an application continuously allocates RAM without releasing it, causing available system memory to decrease steadily. By configuring top to sort processes by resident memory usage and tracking changes in memory metrics, system administrators can quickly identify problematic processes before they trigger Out-Of-Memory (OOM) errors.

Step 1: Launch and Sort top by Memory Usage

By default, the top command sorts active processes by CPU usage. To identify memory-heavy applications, you must sort the display by memory consumption.

  1. Open your terminal and run: 
    top
  2. Press Shift + M (or M depending on your version) to sort the process list by memory usage in descending order. The process using the highest percentage of RAM will appear at the top.

Step 2: Key Metrics for Detecting Memory Leaks

Focus on the following columns in the top output to evaluate process memory consumption:

  • VIRT (Virtual Memory): The total amount of virtual memory allocated by the process, including shared libraries, mapped files, and uncommitted memory. A high VIRT value is common and does not necessarily indicate a leak.
  • RES (Resident Set Size): The actual, non-swapped physical memory (RAM) consumed by the process. This is the primary metric for detecting memory leaks.
  • SHR (Shared Memory): The portion of memory shared with other processes.
  • %MEM: The percentage of available physical RAM occupied by the process's RES memory.

At the top of the interface, observe the summary rows:

  • MiB Mem: Shows total, free, used, and buffer/cache physical memory.
  • MiB Swap: Shows total, free, and used swap space.

Step 3: Identify the Memory Leak Pattern

A process operating normally will request memory, perform work, and release unused memory, causing its RES value to fluctuate and stabilize.

A process with a memory leak demonstrates the following patterns over time:

  1. Continuous RES Growth: The RES value steadily increases without ever decreasing or leveling off, even during idle periods.
  2. Depletion of System Free Memory: The global MiB Mem: free and buff/cache values continuously decline while used increases.
  3. Increasing Swap Usage: As physical RAM fills up, the system begins paging memory to swap, leading to an increase in MiB Swap: used and a degradation in overall system performance.

Step 4: Track Process Memory Over Time

To confirm a memory leak, monitor a suspected Process ID (PID) over a set period.

Interactive Tracking

Run top scoped directly to the suspect PID:

top -p <PID>

Observe whether the RES column increases consistently every few seconds.

Automated Logging

To collect long-term data, run top in batch mode using a shell script or cron job to output stats to a log file:

top -b -n 1 -p <PID> | grep <PID> >> memory_log.txt

Analyze memory_log.txt over several hours. If the RES column shows an uninterrupted upward trend, the process is leaking memory.
