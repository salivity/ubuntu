Run a Puppet Manifest Locally on Ubuntu

Running Puppet in a standalone or masterless setup allows you to apply configuration management rules directly on an Ubuntu machine without communicating with a centralized Puppet master. This article covers the specific command used to apply manifests locally, outlines how to run a test configuration, and details useful command-line options for debugging and dry-running changes.

The Command

To run a Puppet manifest locally without a master server on Ubuntu, use the puppet apply command:

sudo puppet apply /path/to/manifest.pp

You must run this command with administrative privileges (sudo) if your manifest manages system-level resources such as users, packages, or services.

Basic Usage Example

  1. Create a Manifest File
    Create a basic manifest named site.pp:

    nano site.pp

    Add a simple resource declaration, such as creating a text file:

    file { '/tmp/test_puppet.txt':
  ensure  => present,
  content => "Puppet ran locally on Ubuntu successfully.\n",
  mode    => '0644',
}

  2. Execute the Manifest
    Apply the manifest to the local machine:

    sudo puppet apply site.pp

    Puppet will compile the catalog locally, determine if changes are needed, and apply the configuration.

Essential Flags for puppet apply

  • Test without applying changes (--noop):
    Simulates a run to see what changes would occur without modifying the system.

    sudo puppet apply --noop site.pp

  • Detailed output (--verbose):
    Displays informational messages detailing the actions taken.

    sudo puppet apply --verbose site.pp

  • Debugging output (--debug):
    Provides comprehensive logs, useful for troubleshooting syntax errors, catalog compilation issues, or provider failures.

    sudo puppet apply --debug site.pp

  • Execute inline code (-e):
    Applies Puppet code directly from the command line without creating a file.

    sudo puppet apply -e "package { 'nginx': ensure => installed; }"
