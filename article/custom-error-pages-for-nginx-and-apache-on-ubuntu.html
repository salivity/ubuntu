Custom Error Pages for Nginx and Apache on Ubuntu

Configuring custom error pages (such as 404 Not Found or 500 Internal Server Error) improves user experience by providing a clean, branded response when server issues or missing pages occur. This guide provides step-by-step instructions for creating and setting up custom error pages on an Ubuntu server running either Nginx or Apache web servers.

Step 1: Create a Custom Error Page

Before updating web server configurations, create the HTML page that users will see when an error occurs.

  1. Create a new HTML file in your web root directory (commonly /var/www/html/):
sudo nano /var/www/html/custom_404.html
  1. Add your desired HTML content, such as:
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>Page Not Found</title>
    <style>
        body { font-family: Arial, sans-serif; text-align: center; padding: 50px; }
        h1 { font-size: 50px; color: #333; }
        p { font-size: 20px; color: #666; }
        a { color: #007bff; text-decoration: none; }
    </style>
</head>
<body>
    <h1>404</h1>
    <p>Oops! The page you are looking for does not exist.</p>
    <a href="/">Return to Home Page</a>
</body>
</html>
  1. Save and close the file.

Step 2: Configure Custom Error Pages in Nginx

  1. Open your Nginx site configuration file (e.g., the default file):
sudo nano /etc/nginx/sites-available/default
  1. Locate the server block and add the error_page directive along with a location block matching the error page filename:
server {
    listen 80;
    server_name example.com;
    root /var/www/html;

    # Point 404 errors to the custom page
    error_page 404 /custom_404.html;

    # Prevent direct access and define page root
    location = /custom_404.html {
        root /var/www/html;
        internal;
    }
}
  1. Test the Nginx configuration for syntax errors:
sudo nginx -t
  1. Reload Nginx to apply the changes:
sudo systemctl reload nginx

Step 3: Configure Custom Error Pages in Apache

  1. Open your Apache virtual host configuration file:
sudo nano /etc/apache2/sites-available/000-default.conf
  1. Add the ErrorDocument directive inside the <VirtualHost> block, specifying the HTTP status code and the URL path to the custom file:
<VirtualHost *:80>
    ServerName example.com
    DocumentRoot /var/www/html

    # Point 404 errors to the custom page
    ErrorDocument 404 /custom_404.html
</VirtualHost>

Alternatively, you can place the directive in an .htaccess file inside your web root directory if AllowOverride is enabled:

ErrorDocument 404 /custom_404.html
  1. Test the Apache configuration for syntax errors:
sudo apache2ctl configtest
  1. Reload Apache to apply the changes:
sudo systemctl reload apache2

Step 4: Verify the Setup

To verify that your custom error page is working correctly:

  1. Open a web browser.
  2. Visit a non-existent URL on your domain (e.g., http://your-server-ip/non-existent-page).
  3. Your newly configured custom 404 page should display instead of the default server error page.
