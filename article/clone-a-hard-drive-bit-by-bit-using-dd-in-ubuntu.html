Clone a Hard Drive Bit-by-Bit Using dd in Ubuntu

Cloning a hard drive bit-by-bit creates an exact, sector-level duplicate of the source disk, including its operating system, partitions, file systems, and boot records. In Ubuntu, this operation is performed using the low-level dd utility. The process involves identifying the source and target disk identifiers, unmounting active partitions, running the copy command with appropriate block-size and progress flags, and syncing disk caches to finalize the clone.

Step 1: Identify Source and Target Drives

Connect both the source drive and the target drive to your Ubuntu system. The target drive must have a capacity equal to or greater than the source drive.

Open a terminal and run the following command to list all connected block devices:

lsblk -d -o NAME,SIZE,MODEL,TRAN

Alternatively, use:

sudo fdisk -l

Locate the exact device paths (e.g., /dev/sda for the source and /dev/sdb for the target). Verify these carefully; targeting the wrong drive will permanently overwrite its data.

Step 2: Unmount Target and Source Partitions

Neither drive should have mounted partitions during a raw bit-by-bit clone to avoid file corruption or data inconsistency. Check for any mounted partitions and unmount them:

sudo umount /dev/sda*
sudo umount /dev/sdb*

(Replace /dev/sda* and /dev/sdb* with your actual device identifiers. If a partition is not mounted, the system will simply return an informative message.)

Step 3: Execute the dd Command

Execute the bit-by-bit clone with root privileges using sudo.

sudo dd if=/dev/sda of=/dev/sdb bs=64K status=progress conv=noerror,sync

Breakdown of the parameters used:

  • if=/dev/sda: Input File (the source drive to copy from).
  • of=/dev/sdb: Output File (the target drive to copy to).
  • bs=64K: Block Size. Setting this to 64K or 4M significantly increases transfer speed compared to the default 512 bytes.
  • status=progress: Displays transfer speed, data copied, and elapsed time in real time.
  • conv=noerror,sync: Instructs dd to continue operation if it encounters read errors (noerror) and pad missing data blocks with null bytes (sync) to maintain partition alignment.

Step 4: Flush Disk Buffers and Verify

Once the transfer reaches 100% and returns to the command prompt, flush the write buffers to ensure all cached data is written to the physical storage:

sync

To verify that the partition scheme and tables were copied identically, inspect the newly cloned drive:

sudo fdisk -l /dev/sdb

The output should reflect the exact layout of the source disk. The cloned drive is now ready for use.
