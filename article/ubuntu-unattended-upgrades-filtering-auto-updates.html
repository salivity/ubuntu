Ubuntu Unattended Upgrades: Filtering Auto-Updates

The unattended-upgrades configuration file in Ubuntu serves as the central control mechanism for determining precisely which software packages are allowed to update automatically and which are restricted. Located at /etc/apt/apt.conf.d/50unattended-upgrades, this configuration file enables system administrators to strike a balance between maintaining critical security patches and preventing unexpected system instability caused by automated software changes.

The Role of /etc/apt/apt.conf.d/50unattended-upgrades

By default, Ubuntu's unattended-upgrades utility is designed to download and install security updates without user intervention. However, applying updates blindly across an entire system can introduce breaking changes to databases, web servers, or custom application stacks. The configuration file provides granular filtering rules using two primary mechanisms: repository-level filtering and package-level filtering.

Repository Filtering: Allowed Origins

The configuration file defines the origins from which updates may be pulled using the Allowed-Origins (or Origins-Pattern) directive.

This setting allows you to specify whether the system should apply:

  • Security updates only: By default, patterns like "${distro_id}:${distro_codename}-security"; are enabled. This ensures that only packages released specifically to patch vulnerabilities are installed automatically.
  • Standard updates: Administrators can explicitly uncomment or add patterns for standard updates (${distro_codename}-updates) or proposed updates (${distro_codename}-proposed), though this increases the risk of functional changes.

By filtering by origin, the configuration prevents major software version bumps while still addressing Common Vulnerabilities and Exposures (CVEs).

Package-Level Blocklisting

The Package-Blacklist directive provides explicit, package-specific exclusion rules. Any package listed in this section will never be automatically upgraded, even if an update is available from an allowed security repository.

This is commonly used to freeze:

  • Core database engines (e.g., mysql-server, postgresql) to avoid unexpected schema changes or service restarts.
  • Web servers and proxies (e.g., nginx, apache2) to prevent downtime during peak production hours.
  • Kernel updates, avoiding sudden changes to hardware drivers or reboot requirements.

The blacklist supports regular expressions, allowing administrators to block entire families of packages using patterns like "^linux-.*";.

Package-Level Allowlisting

Conversely, the Package-Whitelist directive allows for an opt-in approach. When populated, the unattended-upgrades service restricts automated installations exclusively to the packages defined in this list, ignoring all other available updates. This provides the highest level of isolation for mission-critical servers where only a minimal set of non-disruptive packages should ever update automatically.

Summary

The unattended-upgrades configuration file exists to give administrators deterministic control over automated maintenance. By leveraging repository origins alongside explicit package blacklists and whitelists, the file ensures security patches are applied reliably without risking unintended service disruption.
