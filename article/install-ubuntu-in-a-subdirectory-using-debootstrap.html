Install Ubuntu in a Subdirectory Using Debootstrap

The tool debootstrap allows system administrators to install a minimal Debian or Ubuntu base system directly into a specified directory on an existing Linux installation without requiring installation media. This article provides a step-by-step technical guide on setting up debootstrap, executing the installation process to create an Ubuntu base system within a target subdirectory, mounting the necessary kernel filesystems, chrooting into the environment, and finalizing essential post-installation configurations.

Prerequisites

Before starting, ensure you have root or sudo privileges on the host Linux machine and sufficient disk space available for the target directory.

Step 1: Install Debootstrap

Install debootstrap and the Ubuntu keyring package on your host system using your system’s package manager.

sudo apt update
sudo apt install debootstrap ubuntu-keyring

Step 2: Create the Target Subdirectory

Create the directory where the new Ubuntu base system will reside.

sudo mkdir -p /mnt/ubuntu-target

Step 3: Run Debootstrap to Install the Base System

Execute debootstrap by specifying the target Ubuntu release suite (e.g., jammy for 22.04 LTS or noble for 24.04 LTS), the destination directory, and an official mirror URL.

sudo debootstrap --arch=amd64 noble /mnt/ubuntu-target http://archive.ubuntu.com/ubuntu/

Key arguments used: * --arch=amd64: Specifies the architecture (e.g., amd64, arm64). * noble: Specifies the Ubuntu release name. * /mnt/ubuntu-target: The destination subdirectory. * http://archive.ubuntu.com/ubuntu/: The package repository URL.

debootstrap will download the necessary .deb packages, extract them into the target directory, and perform the initial base setup.

Step 4: Mount Host Pseudo-Filesystems

For the isolated environment to function correctly when accessed, you must mount pseudo-filesystems (/proc, /sys, /dev, /dev/pts) from the host system into the target directory.

sudo mount -t proc /proc /mnt/ubuntu-target/proc
sudo mount -t sysfs /sys /mnt/ubuntu-target/sys
sudo mount --bind /dev /mnt/ubuntu-target/dev
sudo mount --bind /dev/pts /mnt/ubuntu-target/dev/pts

Step 5: Enter the Chroot Environment

Chroot into the freshly populated subdirectory to interact directly with the new base installation.

sudo chroot /mnt/ubuntu-target /bin/bash

Step 6: Perform Base System Configuration

Once inside the chroot environment, complete the essential post-installation configuration steps.

1. Set the Hostname

Define a hostname for the guest environment:

echo "ubuntu-chroot" > /etc/hostname

2. Configure Package Repositories

Create a functional /etc/apt/sources.list file to allow software management via apt.

cat <<EOF > /etc/apt/sources.list
deb http://archive.ubuntu.com/ubuntu noble main restricted universe multiverse
deb http://archive.ubuntu.com/ubuntu noble-updates main restricted universe multiverse
deb http://archive.ubuntu.com/ubuntu noble-security main restricted universe multiverse
EOF

Update the package lists:

apt update

3. Configure Locales and Timezone

Set up local environment parameters:

apt install -y locales tzdata
locale-gen en_US.UTF-8
dpkg-reconfigure tzdata

4. Create User Accounts and Set Passwords

Set the password for the root user:

passwd

Create a standard user account with sudo privileges if required:

apt install -y sudo
adduser myuser
usermod -aG sudo myuser

Step 7: Clean Up and Exit

After completing the setup, exit the chroot shell and unmount the virtual filesystems.

Inside the chroot environment:

exit

On the host machine, unmount the directories in reverse order:

sudo umount /mnt/ubuntu-target/dev/pts
sudo umount /mnt/ubuntu-target/dev
sudo umount /mnt/ubuntu-target/sys
sudo umount /mnt/ubuntu-target/proc

The subdirectory /mnt/ubuntu-target now contains a self-contained, fully configured base Ubuntu system suitable for containerization, testing, chroot operations, or custom image building.
