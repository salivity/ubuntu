Purpose of /etc/modules in Ubuntu Startup

The /etc/modules file in Ubuntu is a system configuration file used to specify kernel modules that must be loaded automatically during the boot process. Kernel modules are device drivers or system components that extend the functionality of the core Linux kernel. By listing module names inside this file, administrators ensure that critical drivers, software-defined hardware interfaces, or specialized system features are available immediately upon system startup without requiring manual loading.

How Kernel Modules Work in Ubuntu

The Linux kernel uses a modular design, meaning not all code is loaded into memory at once. Instead, the kernel loads smaller pieces of code—known as kernel modules (.ko files)—on demand. While many hardware drivers are loaded dynamically when devices are detected by udev, some modules need to be loaded explicitly because they do not correspond to physically pluggable hardware.

The Role of /etc/modules During Boot

During the Ubuntu startup process, the init system (Systemd) initializes core services. As part of this sequence, Systemd executes the systemd-modules-load.service. This service reads /etc/modules along with configuration files located in /etc/modules-load.d/.

When systemd-modules-load.service runs, it calls the modprobe utility for each non-commented line in /etc/modules. The modprobe tool then locates the module, resolves any dependencies it requires, and inserts it into the running Linux kernel.

File Format and Usage

The format of /etc/modules is straightforward:

  • Each line contains the exact name of a single kernel module.
  • Empty lines are ignored.
  • Lines starting with a hash symbol (#) are treated as comments.

For example, if a system requires a loop device module, a network bonding driver, and hardware monitoring sensors, the /etc/modules file might look like this:

# Kernel modules to load at boot time
loop
bonding
coretemp

When to Use /etc/modules

While standard hardware drivers (like graphics drivers or USB controller drivers) are automatically detected and loaded by udev, /etc/modules is specifically used for:

  • Software Drivers: Modules that do not rely on hardware detection, such as network bonding (bonding), TUN/TAP virtual network adapters, or crypto modules.
  • Legacy or Custom Hardware: Older hardware or custom sensors that udev fails to auto-detect.
  • Forced Preloading: Ensuring a driver is loaded before specific services or applications attempt to run during the boot sequence.
