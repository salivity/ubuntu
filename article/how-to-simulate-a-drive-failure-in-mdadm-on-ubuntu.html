How to Simulate a Drive Failure in mdadm on Ubuntu

Testing redundancy notifications is a critical step in verifying that your Ubuntu server will properly alert you when a storage drive degrades. This article explains how to safely simulate a disk failure in an active mdadm software RAID array, observe the system's automated alerting mechanism, and subsequently restore the drive to rebuild the array back to a healthy state.

1. Identify the Array and Member Disks

Before modifying your RAID configuration, verify the name of your array and its constituent partitions. Run the following command:

cat /proc/mdstat

Alternatively, query the array details:

sudo mdadm --detail /dev/md0

Locate your target array (typically /dev/md0 or /dev/md127) and note the component devices (such as /dev/sda1 or /dev/sdb1). Ensure that the array is currently healthy and not in the middle of a rebuild before proceeding.

2. Mark a Drive as Failed

To simulate a disk fault without physically disconnecting hardware, use the --fail (or -f) flag with mdadm. Replace /dev/md0 with your array device and /dev/sdb1 with the partition you want to simulate failing:

sudo mdadm --fail /dev/md0 /dev/sdb1

The kernel will immediately mark the drive as faulty and drop it from the active set of working drives.

3. Verify the Degraded State and Alerts

Confirm the array's degraded status:

cat /proc/mdstat

The output should show the disk marked with (F) and the array status updated (e.g., [U_] instead of [UU]).

At this stage, your alert system should trigger:

  • Check your system mail or root inbox if configured via the MAILADDR directive in /etc/mdadm/mdadm.conf: 
    sudo mail
  • Review the kernel log buffer to verify the failure event was logged: 
    dmesg | grep -i md
  • Verify third-party monitoring services (such as Prometheus node_exporter, Zabbix, or Datadog) to ensure they register the degraded array state.

4. Remove the Faulty Drive

Before a failed drive can be re-added or replaced, it must be logically removed from the array configuration:

sudo mdadm --remove /dev/md0 /dev/sdb1

5. Re-add the Drive and Rebuild the Array

Once you have verified that your notification pipeline operates as expected, return the disk to the array to trigger the synchronization process:

sudo mdadm --add /dev/md0 /dev/sdb1

6. Monitor the Rebuild Process

Track the rebuild progress until the array returns to a fully redundant, clean state:

watch -n 1 cat /proc/mdstat

Once the synchronization reaches 100%, the array will display [UU] (or equivalent fully active status), indicating that normal operations and redundancy have been completely restored.
