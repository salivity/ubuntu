Configure Multipathd for Redundant Storage in Ubuntu

This guide provides a practical, step-by-step walkthrough for configuring multipathd (Device Mapper Multipathing) on Ubuntu to manage redundant storage fabric paths, such as Fibre Channel or iSCSI SAN connections. You will learn how to install the required multipath utilities, generate and customize the configuration file, map logical devices using World Wide Identifiers (WWIDs), and verify path aggregation and automatic failover.

1. Install Multipath Tools

Update your package index and install the multipath-tools package:

sudo apt update
sudo apt install multipath-tools

2. Identify Device WWIDs

Device Mapper Multipathing relies on the unique World Wide Identifier (WWID) of a SCSI device to group multiple paths leading to the same logical unit (LUN).

To list connected block devices and identify the paths to your SAN LUNs:

lsblk

To determine the WWID of an individual block device (for example, /dev/sdb):

sudo /lib/udev/scsi_id -g -u -d /dev/sdb

Record this WWID string; you will use it to assign friendly aliases and path-specific policies.

3. Create the Multipath Configuration File

If /etc/multipath.conf does not exist, create a clean configuration file.

sudo touch /etc/multipath.conf

Add the following base configuration:

defaults {
    user_friendly_names yes
    find_multipaths     yes
    path_grouping_policy multibus
    path_checker        tur
    failback            immediate
    no_path_retry       queue
}

blacklist {
    # Exclude internal/boot drives by device node regex
    devnode "^(ram|raw|loop|fd|md|dm-|sr|scd|st)[0-9]*"
    devnode "^sda[0-9]*"
}

multipaths {
    multipath {
        wwid    36001405a1b2c3d4e5f60000000000000
        alias   san_data_vol1
    }
}

Key Directives Explained:

  • find_multipaths yes: Automatically configures multipathing on devices that appear on more than one path, reducing the need to manually whitelist every drive.
  • path_grouping_policy multibus: Groups all valid paths into a single path group, allowing load balancing across all operational fabric links. Alternatively, use failover or group_by_prio.
  • path_checker tur: Uses the "Test Unit Ready" SCSI command to periodically check if a path is online.
  • no_path_retry queue: Queues I/O requests if all paths fail, preventing immediate data-corruption errors while fabric links recover.
  • blacklist: Prevents local operating system drives (like /dev/sda) from being placed into multipath maps.

4. Enable and Start the Multipath Service

Reload the system systemd configuration and start the multipathd daemon:

sudo systemctl restart multipathd
sudo systemctl enable multipathd

Update your initial RAM filesystem (initramfs) so that multipath configurations are applied during the early boot phase:

sudo update-initramfs -u -k all

5. Verify the Multipath Topology

To confirm that multipathd has bound the redundant links to a single device mapper target, run:

sudo multipath -ll

A healthy output displays the alias, WWID, sysfs status, and grouped paths:

san_data_vol1 (36001405a1b2c3d4e5f60000000000000) dm-1 NETAPP,LUN C-Mode
size=500G features='1 queue_if_no_path' hwhandler='1 alua' wp=rw
`-+- policy='round-robin 0' prio=50 status=active
  |- 1:0:0:1 sdb 8:16 active ready running
  `- 2:0:0:1 sdc 8:32 active ready running

In this output, /dev/sdb and /dev/sdc are two physical connections to the same LUN, unified under /dev/mapper/san_data_vol1.

6. Format and Mount the Multipath Device

Never partition, format, or mount the individual underlying SCSI paths directly (such as /dev/sdb). Instead, only perform filesystem operations on the unified Device Mapper device:

# Format the multipath target
sudo mkfs.ext4 /dev/mapper/san_data_vol1

# Create a mount point and mount the device
sudo mkdir -p /mnt/san_storage
sudo mount /dev/mapper/san_data_vol1 /mnt/san_storage

For persistent mounting across reboots, obtain the filesystem UUID with sudo blkid /dev/mapper/san_data_vol1 and add it to /etc/fstab using the _netdev mount option to ensure the network or fabric layer initializes before the volume mounts.
