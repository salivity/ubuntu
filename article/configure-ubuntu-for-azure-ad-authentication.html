Configure Ubuntu for Azure AD Authentication

This article provides a step-by-step guide to configuring an Ubuntu machine to authenticate users against an Azure Active Directory Domain Services (Azure AD DS) domain. You will learn how to configure DNS resolution, install the required authentication packages, join the machine to your managed domain using SSSD and realmd, and enable automatic home directory creation for domain users.

Prerequisites

  • An Ubuntu server or desktop (20.04 LTS or 22.04 LTS recommended).
  • An active Azure Active Directory Domain Services (AAD DS) managed domain.
  • Virtual network peering configured between your Ubuntu machine and the Azure AD DS virtual network, if running across different networks.
  • An Azure AD user account with administrative privileges belonging to the AAD DC Administrators group.

Step 1: Configure DNS Settings

The Ubuntu machine must use your Azure AD DS domain controllers as its DNS servers to resolve the domain.

  1. Open your Netplan configuration file (usually located in /etc/netplan/):

    sudo nano /etc/netplan/01-netcfg.yaml

  2. Under your primary network interface, update the nameservers section with the IP addresses of your Azure AD DS instances:

    network:
  version: 2
  ethernets:
    eth0:
      dhcp4: true
      nameservers:
        addresses: [10.0.0.4, 10.0.0.5]
        search: [yourdomain.onmicrosoft.com]

  3. Apply the network configuration:

    sudo netplan apply

  4. Verify that the domain resolves correctly:

    ping yourdomain.onmicrosoft.com

Step 2: Install Required Packages

Update the package index and install the required packages for Active Directory integration, Kerberos authentication, and SSSD:

sudo apt update
sudo apt install -y realmd sssd sssd-tools adcli samba-common-bin packagekit krb5-user

During the installation of krb5-user, you may be prompted to enter the default Kerberos realm. Enter your domain name in all uppercase letters (e.g., YOURDOMAIN.ONMICROSOFT.COM).

Step 3: Discover the Domain

Verify that realmd can detect the Azure AD DS domain:

sudo realm discover yourdomain.onmicrosoft.com

The output will display domain details such as the realm name, configured software (sssd), and required packages.

Step 4: Join Ubuntu to the Domain

Join the machine to the domain using an account that is a member of the AAD DC Administrators group:

sudo realm join -U adminuser@yourdomain.onmicrosoft.com yourdomain.onmicrosoft.com

Enter the password when prompted. If the command completes without errors, the machine has successfully joined the domain.

Step 5: Configure Automatic Home Directory Creation

By default, Linux does not create home directories for new domain users upon their first login. Configure PAM to create them automatically:

  1. Enable the mkhomedir module:

    sudo pam-auth-update --enable mkhomedir

  2. Alternatively, ensure the following line exists in /etc/pam.d/common-session:

    session required pam_mkhomedir.so skel=/etc/skel/ umask=0077

Step 6: Configure SSSD Defaults (Optional)

To allow domain users to log in without typing the full domain suffix, edit the SSSD configuration:

  1. Open /etc/sssd/sssd.conf:

    sudo nano /etc/sssd/sssd.conf

  2. Change use_fully_qualified_names from True to False:

    use_fully_qualified_names = False
fallback_homedir = /home/%u

  3. Restart the SSSD service to apply changes:

    sudo systemctl restart sssd

Step 7: Verify Domain Authentication

  1. Verify that user information can be retrieved from Azure AD DS:

    id user@yourdomain.onmicrosoft.com

  2. Switch to a domain user account to test local login:

    su - user@yourdomain.onmicrosoft.com

  3. If SSSD was configured with use_fully_qualified_names = False, test using the short username:

    su - user

Authentication is now fully configured, allowing Azure AD domain users to access the Ubuntu system via SSH and local console.
