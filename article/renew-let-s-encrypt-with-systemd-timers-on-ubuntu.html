Renew Let's Encrypt with Systemd Timers on Ubuntu

This guide demonstrates how to automate the renewal of Let's Encrypt SSL/TLS certificates using systemd timers on Ubuntu. Systemd timers provide a modern, robust alternative to standard cron jobs, offering better logging via journalctl, flexible execution controls, and randomized delays to prevent server congestion. Follow the steps below to configure a dedicated service unit and timer to keep your certificates continuously valid.

Step 1: Create the Systemd Service Unit

A systemd service defines the command that performs the certificate renewal.

Create a new service file using a text editor:

sudo nano /etc/systemd/system/certbot-renewal.service

Add the following configuration:

[Unit]
Description=Renew Let's Encrypt Certificates
After=network-online.target
Wants=network-online.target

[Service]
Type=oneshot
ExecStart=/usr/bin/certbot renew --quiet --agree-tos
ExecStartPost=/bin/systemctl reload nginx

Note: Replace nginx with apache2 or your specific web server service name if necessary. If you do not need to reload a web service, remove the ExecStartPost line.

Save and close the file.

Step 2: Create the Systemd Timer Unit

The timer defines when and how frequently the renewal service executes. Let's Encrypt recommends checking renewal status twice a day.

Create the timer configuration file:

sudo nano /etc/systemd/system/certbot-renewal.timer

Add the following configuration:

[Unit]
Description=Run Certbot Renewal Twice Daily

[Timer]
OnCalendar=*-*-* 00,12:00:00
RandomizedDelaySec=43200
Persistent=true

[Install]
WantedBy=timers.target
  • OnCalendar=*-*-* 00,12:00:00: Schedules execution at midnight and noon daily.
  • RandomizedDelaySec=43200: Adds a random delay up to 12 hours to distribute server load across Let's Encrypt infrastructure.
  • Persistent=true: Ensures the job runs immediately if the server was powered off during a scheduled run.

Save and close the file.

Step 3: Enable and Start the Timer

Reload the systemd manager configuration to recognize the new files:

sudo systemctl daemon-reload

Enable the timer so it starts automatically at boot, and start it immediately:

sudo systemctl enable --now certbot-renewal.timer

Step 4: Verify the Configuration

Verify that the timer is active and view its next scheduled execution time:

systemctl list-timers certbot-renewal.timer

To test the renewal command without waiting for the timer, manually invoke the service:

sudo systemctl start certbot-renewal.service

Check the output and execution logs to confirm success:

sudo journalctl -u certbot-renewal.service
