How to Setup Corosync and Pacemaker on Ubuntu

High availability clusters prevent downtime by automatically migrating services to a standby node if the active node fails. This guide provides a step-by-step walkthrough for configuring a two-node Corosync and Pacemaker cluster on Ubuntu to achieve automatic service failover. You will learn how to configure network communication, initialize cluster membership using Corosync, manage resources with Pacemaker via the pcs utility, and set up a virtual IP with a sample web service.

Prerequisites

Ensure you have two Ubuntu servers (referred to as node1 and node2) on the same local network with static IP addresses.

Edit /etc/hosts on both nodes to map hostnames to IP addresses:

sudo nano /etc/hosts

Add entries matching your environment:

192.168.1.10 node1
192.168.1.11 node2

Step 1: Install Pacemaker, Corosync, and PCS

Run the following command on both nodes to install the necessary clustering packages:

sudo apt update
sudo apt install -y pacemaker corosync pcs

Ensure the cluster configuration daemon is enabled and running on both nodes:

sudo systemctl enable pcsd
sudo systemctl start pcsd

Step 2: Authenticate Cluster Nodes

The package installation creates a system user named hacluster. Set the same password for this user on both nodes:

sudo passwd hacluster

Authenticate the nodes from node1 using the pcs tool:

sudo pcs host auth node1 node2 -u hacluster

Enter the hacluster password when prompted.

Step 3: Create and Start the Cluster

From node1, create and name the cluster:

sudo pcs cluster setup my_cluster node1 node2

Start the cluster services and enable them to run at boot on all nodes:

sudo pcs cluster start --all
sudo pcs cluster enable --all

Verify that both nodes are online:

sudo pcs status

Step 4: Configure Cluster Properties

For a two-node cluster, you must adjust specific quorum and fencing settings to ensure proper operation:

  1. Disable STONITH (Fencing): Fencing ensures nodes with split-brain issues are powered off. If hardware fencing devices are not present, disable it temporarily: 
    sudo pcs property set stonith-enabled=false
  2. Ignore Quorum Policy: Since standard quorum requires more than half of the nodes, disable it for a two-node setup: 
    sudo pcs property set no-quorum-policy=ignore

Step 5: Configure Resources for Failover

Clusters typically control a Floating Virtual IP (VIP) and an active service (such as NGINX or Apache).

  1. Install the service on both nodes:

    sudo apt install -y nginx
sudo systemctl stop nginx
sudo systemctl disable nginx

    Note: Pacemaker must manage the service lifecycle, so disable native systemd startup.

  2. Create the Floating IP Resource on node1:

    sudo pcs resource create VirtualIP ocf:heartbeat:IPaddr2 ip=192.168.1.100 cidr_netmask=24 op monitor interval=10s

  3. Create the Service Resource on node1:

    sudo pcs resource create WebServer systemd:nginx op monitor interval=10s

  4. Group the Resources: Ensure the IP address and the service run on the same node and start in order:

    sudo pcs resource group add WebGroup VirtualIP WebServer

Step 6: Test Failover

Check where the resources are currently running:

sudo pcs status resources

To test failover, place the active node into standby mode:

sudo pcs node standby node1

Run sudo pcs status to confirm that the WebGroup resources (VirtualIP and WebServer) have automatically migrated to node2.

To return the node to the active cluster pool, run:

sudo pcs node unstandby node1
