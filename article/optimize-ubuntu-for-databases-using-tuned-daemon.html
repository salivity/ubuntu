Optimize Ubuntu for Databases Using Tuned Daemon

Optimizing an Ubuntu server for database workloads requires fine-tuning kernel parameters, memory management, disk I/O, and CPU governance. This guide provides a straightforward walkthrough on installing the Tuned dynamic adaptive system tuning daemon on Ubuntu, understanding performance baselines, and configuring built-in or custom profiles specifically tailored to maximize throughput and minimize latency for database engines like PostgreSQL, MySQL, and MongoDB.

Step 1: Install and Enable Tuned

Tuned is available in standard Ubuntu repositories. Install the package and start the systemd service:

sudo apt update
sudo apt install tuned -y
sudo systemctl enable --now tuned

Verify that the daemon is running properly:

systemctl status tuned

Step 2: Review Available Profiles

Tuned includes preconfigured profiles for various workloads. Run the following command to see all installed profiles:

tuned-adm list

Identify the currently active profile:

tuned-adm active

For general high-throughput database workloads, the built-in throughput-performance profile serves as a standard starting point. However, databases require specific memory and I/O tuning that standard profiles do not fully address.

Step 3: Create a Custom Database Profile

Creating a custom profile derived from an existing profile allows you to retain baseline optimizations while applying database-specific adjustments, such as disabling Transparent Huge Pages (THP) and controlling virtual memory flushing.

  1. Create a directory for your custom profile:
sudo mkdir /etc/tuned/database-server
  1. Create and open the tuned.conf configuration file:
sudo nano /etc/tuned/database-server/tuned.conf
  1. Paste the following configuration, tailored for relational and NoSQL databases:
[main]
summary=Optimized profile for database workloads on Ubuntu
include=throughput-performance

[cpu]
governor=performance
energy_perf_bias=performance
min_perf_pct=100

[vm]
# Minimize aggressive swapping while retaining a safety buffer
transparent_hugepages=never

[sysctl]
# Reduce swappiness to keep database working sets in RAM
vm.swappiness=10

# Optimize dirty page writeback to avoid I/O bottlenecks during heavy writes
vm.dirty_background_ratio=3
vm.dirty_ratio=10

# Increase maximum open files and connection tracking limits
fs.file-max=2097152
net.core.somaxconn=4096

# Increase network socket memory buffer sizes
net.ipv4.tcp_rmem=4096 87380 16777216
net.ipv4.tcp_wmem=4096 65536 16777216

[disk]
# Set read-ahead values appropriately (adjust sda/nvme0n1 to match your data drive)
# devices=sda,sdb,nvme0n1
readahead=4096

Save and exit the file.

Step 4: Apply the Custom Profile

Apply your newly created database-server profile using tuned-adm:

sudo tuned-adm profile database-server

Confirm that the profile is active:

tuned-adm active

The output should confirm:

Current active profile: database-server

Step 5: Verify Applied Optimizations

Verify that the profile has successfully updated your kernel parameters and hardware settings without conflicts:

tuned-adm verify

If everything matches the configuration, the command returns Verification succeeded in all specified profiles.

You can also manually check specific critical database settings:

  • Transparent Huge Pages:

    cat /sys/kernel/mm/transparent_hugepage/enabled

    (Output should show [never])

  • Swappiness:

    sysctl vm.swappiness

    (Output should show vm.swappiness = 10)

  • CPU Governor:

    cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor

    (Output should show performance)

Any subsequent changes made to /etc/tuned/database-server/tuned.conf can be reapplied instantly by running sudo tuned-adm profile database-server.
