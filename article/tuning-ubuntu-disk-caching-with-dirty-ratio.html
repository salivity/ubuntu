Tuning Ubuntu Disk Caching with dirty_ratio

The /proc/sys/vm/dirty_ratio file is a critical Linux kernel parameter used to manage memory and disk I/O performance in Ubuntu. This article explains the purpose of dirty_ratio, how it controls the caching of unwritten data in RAM, its impact on system responsiveness, and how to safely adjust its value to optimize disk caching for your workload.

When applications perform write operations on Ubuntu, the operating system does not immediately write the changes to physical storage. Instead, it writes the data to system RAM as "dirty pages" (modified data not yet committed to disk) to provide fast write speeds. The /proc/sys/vm/dirty_ratio parameter defines the absolute maximum percentage of total system memory that can be occupied by these dirty pages.

Once the volume of dirty memory hits the threshold defined in dirty_ratio, the kernel forces any application generating new write requests to pause and write its data directly to disk. This is known as synchronous writeback. Unlike dirty_background_ratio—which wakes background kernel threads to flush data silently while applications continue running—exceeding dirty_ratio directly blocks active processes until memory usage drops below the limit.

Setting an appropriate value involves balancing write throughput against system latency:

  • High values (e.g., 20–30%): Allow larger bursts of writes to be absorbed quickly in RAM, boosting throughput for write-heavy batch operations. However, this creates a risk of massive I/O bottlenecks and temporary system freezes when the kernel finally flushes gigabytes of data to slower storage devices. It also increases the window for potential data loss during sudden power outages or crashes.
  • Low values (e.g., 5–10%): Prevent large build-ups of unwritten data, ensuring smoother performance, lower disk latency, and reduced stalls on desktop systems or servers with fast, continuous writes. The tradeoff is lower burst-write speeds, as storage writes happen more frequently.

To view the current dirty_ratio on an Ubuntu system, run:

cat /proc/sys/vm/dirty_ratio

Alternatively:

sysctl vm.dirty_ratio

To test a new value temporarily, write directly to the interface:

sudo sysctl -w vm.dirty_ratio=10

To make the setting permanent across reboots, add or modify the following line in /etc/sysctl.conf or a dedicated file inside /etc/sysctl.d/:

vm.dirty_ratio = 10

Apply the permanent changes immediately by running sudo sysctl -p. Proper configuration of dirty_ratio prevents I/O starvation and ensures that write-heavy processes do not degrade overall system responsiveness.
