How to Prune Docker Images, Containers, and Volumes

Over time, Docker can consume significant disk space on an Ubuntu system by accumulating stopped containers, dangling images, unused networks, and orphaned volumes. This guide explains the exact Docker CLI commands required to safely reclaim storage by removing these unused components without affecting running services.

The All-in-One Prune Command

To safely remove all stopped containers, unused networks, unreferenced images, and unused data volumes in a single operation, run:

docker system prune -a --volumes

If your user is not part of the docker group on Ubuntu, prepend sudo:

sudo docker system prune -a --volumes

How the Command Works Safely

By default, Docker prevents data loss by only targeting resources that are not currently associated with a running container. Here is what each flag does:

  • docker system prune: Removes all stopped containers, unused networks, dangling images (images without a tag), and the build cache.
  • -a (or --all): Extends the cleanup to remove all unused images, not just dangling ones. Any image not actively used by an existing container will be deleted.
  • --volumes: Instructs Docker to also remove unused volumes. By default, docker system prune leaves volumes untouched to prevent accidental loss of persistent data.

Verification and Safety Steps

Before running the destructive prune command, inspect how much space Docker is currently using by running:

docker system df

When you execute docker system prune -a --volumes, Docker displays a warning prompt asking for confirmation:

WARNING! This will remove:
  - all stopped containers
  - all networks not used by at least one container
  - all volumes not used by at least one container
  - all images without at least one container associated to them
  - all build cache

Are you sure you want to continue? [y/N]

Type y and press Enter to proceed. Docker will delete the unreferenced assets and output the total amount of reclaimed disk space.
