Verify Package Integrity Using debsums in Ubuntu

This guide explains how to install and utilize the debsums utility in Ubuntu to verify the integrity of your installed packages. By comparing the current MD5 checksums of system files against the original checksums recorded at installation, debsums allows system administrators to quickly identify modified, corrupted, or potentially compromised binaries and configuration files across the operating system.

Installing debsums

The debsums tool is not installed by default on Ubuntu systems. You can install it using the default package manager:

sudo apt update
sudo apt install debsums

During installation, you may be prompted to automatically run debsums weekly or generate checksums for packages that lack them. Choose the options that best match your administrative preferences.

Checking All Installed Packages

To scan every installed package and output the status of each file:

sudo debsums

Because this command prints an entry for every verified file, the output can be overwhelming. To display only files that have been modified or failed verification, use the -c (changed) flag:

sudo debsums -c

To suppress normal output and only display actual errors (such as missing files or failed checksums):

sudo debsums -s

Checking Configuration Files

By default, debsums ignores configuration files located in /etc because they are expected to change during standard system administration. If you want to include configuration files in your integrity check, add the -a (all) flag:

sudo debsums -a -c

This command will report any file—including configuration files—that differs from its default post-installation state.

Verifying a Specific Package

If you suspect an issue with a single service or tool, you can limit the verification process to that specific package by passing its name:

sudo debsums apache2

To check only for modified files within that specific package:

sudo debsums -c apache2

Restoring Modified or Corrupted Files

If debsums flags critical system binaries that should not have been altered, you can restore them to their official state by reinstalling the affected package with apt:

sudo apt install --reinstall <package-name>

Replace <package-name> with the name of the package containing the modified files. After reinstallation, run debsums again on that package to confirm all files match their official checksums.
