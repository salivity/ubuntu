Using kpartx to Mount Disk Image Partitions in Ubuntu

This article explores how the kpartx utility facilitates accessing individual partitions contained within raw disk images on Ubuntu. When working with full-disk images—such as virtual machine drives, forensic acquisitions, or Raspberry Pi operating system images—a single file often contains an entire partition table. kpartx bridges the gap between disk image files and the Linux kernel by reading partition tables and creating dedicated device maps for each partition, allowing administrators to mount and modify nested filesystems without booting a virtual machine.

The Challenge of Multi-Partition Disk Images

Standard mounting in Linux typically works with single-filesystem images via the basic loopback driver. However, when an image represents a full physical disk containing an MBR or GPT partition table, attempting to mount the file directly with mount -o loop image.img /mnt fails because the operating system encounters the partition table header rather than a recognized filesystem.

While manual workarounds exist—such as using fdisk to inspect sector sizes, calculating byte offsets, and running losetup with the -o parameter—this manual process is error-prone, cumbersome, and inefficient.

The Role and Function of kpartx

kpartx is part of the multipath-tools package in Ubuntu. Its primary role is to interpret partition tables on specified devices or files and create device-mapper entries using the Linux kernel's device-mapper framework.

When invoked on a disk image, kpartx performs several key actions:

  1. It attaches the raw image file to an available loop device (e.g., /dev/loop0).
  2. It reads and parses the image's partition table (supporting MBR, GPT, BSD, and others).
  3. It exposes each detected slice as an independent device-mapper node in the /dev/mapper/ directory, following the naming convention /dev/mapper/loopXpY (where X is the loop device number and Y is the partition number).

Standard Usage and Workflow on Ubuntu

Working with kpartx on Ubuntu requires installation via apt and a standard operational sequence:

1. Installation

sudo apt update
sudo apt install kpartx

2. Exposing the Partitions To scan the disk image and create device mappings, use the -a (add) and -v (verbose) flags:

sudo kpartx -av disk_image.img

The verbose output confirms the creation of mapping nodes, such as add map loop0p1 ... and add map loop0p2 ....

3. Mounting and Modifying the Filesystem Once mapped, individual partitions behave like native block devices. You can inspect, mount, or repair them directly:

sudo mount /dev/mapper/loop0p1 /mnt

At this point, system files inside the image are accessible for backups, offline configuration changes, or log analysis.

4. Dismounting and Cleanup Proper cleanup prevents orphaned loop devices and locked files. First, unmount the filesystem, then instruct kpartx to remove the device mappings using the -d (delete) flag:

sudo umount /mnt
sudo kpartx -dv disk_image.img

Key Use Cases

kpartx serves an essential role across several system administration disciplines:

  • Virtualization Management: Modifying configuration files or resetting user passwords within KVM/QEMU, Xen, or Proxmox raw disk images without starting the guest instance.
  • Embedded Development: Customizing operating system images for Single Board Computers (like the Raspberry Pi) by pre-configuring network settings in the /boot or /root partitions before writing the image to an SD card.
  • Disaster Recovery and Forensics: Safely inspecting non-bootable storage archives or forensic disk dumps in read-only mode to extract vital operational data.
