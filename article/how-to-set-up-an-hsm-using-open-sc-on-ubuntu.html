How to Set Up an HSM Using OpenSC on Ubuntu

Setting up a Hardware Security Module (HSM) or smart card token on Ubuntu using OpenSC enables secure cryptographic key generation, storage, and authentication. This guide provides a straightforward process for preparing an Ubuntu system, installing the necessary drivers and OpenSC utilities, detecting your hardware token, and verifying cryptographic functionality via PKCS#11 tools.

Step 1: Install OpenSC and PC/SC Middleware

Ubuntu requires the PC/SC (Personal Computer/Smart Card) daemon and the OpenSC suite to interface with cryptographic hardware. Open a terminal and update your package lists, then install the required packages:

sudo apt update
sudo apt install opensc pcscd pcsc-tools libccid
  • pcscd: The background daemon that handles communication with smart cards and USB HSMs.
  • libccid: The generic USB Chip/Smart Card Interface Devices driver.
  • opensc: The core library and utilities implementing PKCS#11 and PKCS#15 standards.
  • pcsc-tools: Helpful diagnostic utilities, including pcsc_scan.

Step 2: Enable and Start the PC/SC Daemon

Ensure the pcscd service is running and configured to launch automatically on boot:

sudo systemctl enable pcscd
sudo systemctl start pcscd

Verify that the service is active:

sudo systemctl status pcscd

Step 3: Connect and Detect the HSM

Connect your USB HSM or smart card reader to the Ubuntu machine. Verify that the operating system recognizes the hardware using pcsc_scan:

pcsc_scan

The output should display your card reader and card status, showing an ATR (Answer to Reset) string. Press Ctrl+C to exit the scan.

Next, confirm that OpenSC can interact with the device:

opensc-tool -l

To view the card's profile and ATR details directly through OpenSC, run:

opensc-tool -a

Step 4: Inspect Token Structure

To check whether the token is already initialized and formatted with a PKCS#15 structure, run:

pkcs15-tool --dump

If the device is initialized, this command outputs details about the cardholder, PINs, public keys, and certificates present on the device.

Step 5: Generate Keys and Perform Cryptographic Operations

You can manage the HSM using pkcs11-tool, which communicates with the HSM via the OpenSC PKCS#11 module located at /usr/lib/x86_64-linux-gnu/opensc-pkcs11.so.

To view available slots and token labels:

pkcs11-tool --module /usr/lib/x86_64-linux-gnu/opensc-pkcs11.so --list-slots

To generate a 2048-bit RSA key pair on the HSM (replace 123456 with your user PIN):

pkcs11-tool --module /usr/lib/x86_64-linux-gnu/opensc-pkcs11.so \
  --login --pin 123456 \
  --keypairgen --key-type rsa:2048 \
  --label "hsm-demo-key" --id 01

List all cryptographic objects stored on the device to confirm the key creation:

pkcs11-tool --module /usr/lib/x86_64-linux-gnu/opensc-pkcs11.so --list-objects

Step 6: Test Device Performance and Cryptography

Validate that the token operates properly under cryptographic load using the built-in PKCS#11 test suite:

pkcs11-tool --module /usr/lib/x86_64-linux-gnu/opensc-pkcs11.so \
  --login --pin 123456 --test

This command runs automated signature, decryption, and hash verification tests directly on the hardware module, confirming that your HSM is fully operational and ready for integration with applications such as OpenSSL, OpenVPN, or Apache.
