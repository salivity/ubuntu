Configure LXD Macvlan for Physical IPs on Ubuntu

This guide explains how to configure LXD with a Macvlan network profile on an Ubuntu host. By default, LXD provisions containers behind an internal NAT bridge (lxdbr0). Using Macvlan allows containers to attach directly to your local physical network adapter, enabling them to obtain IP addresses directly from your local router or DHCP server as if they were standalone physical machines.

Step 1: Identify Your Host Network Interface

Before creating the LXD profile, determine the name of the physical network interface on your Ubuntu host connected to your local network.

Run the following command:

ip route show default

Look for the interface name after dev (common examples include eth0, enp3s0, or ens18). Note this interface name for the next steps.

Step 2: Create a New LXD Profile

Instead of modifying the default LXD profile, create a dedicated profile for Macvlan:

lxc profile create macvlan

Step 3: Configure the Macvlan Profile

Add a network interface (eth0 inside the container) to the newly created profile, setting its type to macvlan and pointing it to your host's physical network adapter. Replace enp3s0 with your actual host interface identified in Step 1:

lxc profile device add macvlan eth0 nic nictype=macvlan parent=enp3s0

Step 4: Launch a Container Using the Profile

When launching a container, attach both the default profile (which provides storage and the root disk device) and the macvlan profile.

Launch a container named test-container:

lxc launch ubuntu:24.04 test-container -p default -p macvlan

Step 5: Verify the Physical IP Assignment

Wait a few seconds for the container to query the local DHCP server, then check its IP address:

lxc list

The container's eth0 will display an IP address belonging to your local physical network subnet rather than the default LXD bridge subnet. You can verify network connectivity directly from another device on the physical network:

ping <CONTAINER_IP>

Important Macvlan Limitation

By design, Linux kernel Macvlan interfaces isolate the host operating system from the guest containers. While other physical devices and external networks can communicate with the container, the Ubuntu host itself cannot directly ping or establish network connections to the container's Macvlan IP without setting up an additional Macvlan sub-interface on the host.
