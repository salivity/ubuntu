Role of Rsyslog in Older Ubuntu Log Management

In older Ubuntu versions, the rsyslog daemon serves as the primary system logging utility responsible for collecting, processing, filtering, and routing system and application logs. Acting as an enhanced successor to the traditional syslog daemon, rsyslog captures log messages generated by the Linux kernel, system services, and local applications. It organizes these messages according to pre-defined rules, writing them to specific text files within the /var/log directory or forwarding them to remote log management servers for centralized analysis.

Core Functions of Rsyslog in Older Ubuntu Systems

1. Log Collection and Socket Listening

rsyslog continuously listens for incoming log messages from various system sources. It collects kernel messages via /proc/kmsg and application or service logs through the local UNIX domain socket /dev/log. This ensures that all events—ranging from system boot notifications to application errors—are captured in real time.

2. Rule-Based Filtering and Routing

Log classification in rsyslog relies on two main criteria: Facility (the source of the message, such as auth, kernel, cron, or daemon) and Severity/Priority (the importance of the message, such as info, warning, error, or emerg).

Using the configuration files located at /etc/rsyslog.conf and within the /etc/rsyslog.d/ directory, rsyslog routes incoming data based on these criteria:

  • auth.log: Captures authentication attempts and authorization logs.
  • syslog: Stores general system messages that do not belong to specific sub-categories.
  • kern.log: Holds kernel-level events and hardware alerts.
  • dpkg.log: Records package installation and update activities.

3. Remote Logging and Centralization

A key feature of rsyslog on older enterprise systems is network logging. It can act as both a client and a server using UDP, TCP, or the RELP (Reliable Event Logging Protocol) protocol.

  • As a Client: It forwards local log messages to a central server, ensuring logs are preserved even if the local machine experiences hardware failure or security breaches.
  • As a Server: It accepts network log streams from other host machines and stores them in structured directories.

4. High Performance and Reliability

Unlike older syslog daemons, rsyslog supports multi-threading and asynchronous message processing. It includes disk-assisted memory queues, which buffer log entries during network outages or heavy system loads to prevent data loss.

5. Coexistence with Log Maintenance Tools

rsyslog handles the real-time writing of logs, while relying on utilities like logrotate to prevent log files from consuming all available disk space. logrotate periodically compresses, archives, and truncates the active log files created by rsyslog, issuing a command to signal rsyslog to reopen its file handles cleanly once rotation completes.
