How Keepalived Provides High Availability on Ubuntu

The keepalived service plays a critical role in establishing high availability (HA) for Ubuntu systems by managing Virtual IP (VIP) addresses and performing continuous health checks across server nodes. By utilizing the Virtual Router Redundancy Protocol (VRRP), keepalived ensures that if a primary server fails, a backup server seamlessly takes over incoming traffic without service disruption. This article explains the underlying mechanisms of keepalived, its health monitoring capabilities, and how it secures continuous uptime for core infrastructure on Ubuntu.

Virtual IP Management via VRRP

At the heart of keepalived is the Virtual Router Redundancy Protocol (VRRP). In an Ubuntu high-availability cluster, two or more servers share a single Virtual IP address (VIP). Clients direct their traffic to this VIP rather than to the individual static IP addresses of the underlying physical or virtual machines.

keepalived assigns the VIP to a designated primary node (the MASTER). The MASTER node periodically broadcasts advertisement packets across the local network to secondary nodes (the BACKUPs) to confirm that it is operational and healthy.

Automatic Failover and Recovery

If the MASTER node stops sending VRRP heartbeats due to a hardware failure, kernel crash, or network outage, the BACKUP nodes notice the missing signals.

Through an automated election process based on pre-assigned priority values:

  1. The BACKUP node with the highest priority takes ownership of the Virtual IP.
  2. The new MASTER sends Gratuitous ARP (GARP) messages to update the MAC address tables of adjacent network switches.
  3. Incoming network traffic immediately routes to the replacement node without manual intervention.

Once the original MASTER recovers, keepalived can automatically fail back to the primary server or leave traffic on the active backup server, depending on the failover policy defined in the configuration.

Active Service Health Checking

keepalived goes beyond monitoring whether a server host is online. It actively tracks the health of specific applications running on the Ubuntu OS, such as web servers, load balancers, or database services.

It performs health checks using two main methods:

  • Native Checkers: Built-in mechanisms to verify TCP ports, HTTP responses, or SSL certificates.
  • Custom Tracking Scripts: User-defined shell scripts execute at set intervals. If a script returns a failure status (e.g., HAProxy is not responding), keepalived lowers the node's priority or stops the VRRP instance.

This capability ensures that if a critical service crashes—even if the underlying Ubuntu operating system remains responsive—keepalived shifts the VIP to a node with a working service stack.

Load Balancer Redundancy

On Ubuntu, keepalived is commonly paired with software load balancers like HAProxy or Nginx. While the load balancer handles traffic distribution across backend application servers, keepalived provides redundancy for the load balancers themselves. This architecture eliminates single points of failure at the entry layer of the infrastructure.

Key Operational Advantages

  • Low Overhead: Written in C, keepalived consumes negligible CPU and RAM, making it suitable for both lightweight virtual machines and heavy bare-metal instances.
  • Simple Management: Configuration is consolidated into a single file (/etc/keepalived/keepalived.conf).
  • Systemd Integration: Native integration with Ubuntu's service manager allows standard management via systemctl enable keepalived and systemctl start keepalived.
