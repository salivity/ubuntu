How to Create a Custom AppArmor Profile in Ubuntu

AppArmor protects Linux systems by restricting applications to a minimal set of necessary resources through Mandatory Access Control (MAC) profiles. Creating a custom AppArmor profile for an application involves generating a profile template, running the program in learning mode to record system calls, approving access rules via audit logs, and switching the profile into enforcement mode. This guide details the step-by-step workflow required to build, test, and activate a tailored AppArmor profile on Ubuntu.

Step 1: Install AppArmor Utilities

Ubuntu includes AppArmor by default, but the interactive profile generation tools are packaged separately. Install the apparmor-utils package:

sudo apt update
sudo apt install apparmor-utils

This package provides commands like aa-genprof, aa-logprof, aa-complain, and aa-enforce.

Step 2: Initialize the Profile with aa-genprof

The fastest way to profile an application is using aa-genprof, which sets up a profile in "complain" mode and monitors its activity.

Run the tool followed by the absolute path to your target executable:

sudo aa-genprof /usr/local/bin/myapp

When launched, aa-genprof performs three actions:

  1. Creates a baseline profile file in /etc/apparmor.d/ named after the binary path (e.g., etc.apparmor.d/usr.local.bin.myapp).
  2. Sets the profile to complain mode (violations are logged instead of blocked).
  3. Pauses execution and prompts you to test the application in another terminal window.

Step 3: Exercise the Application

Keep the aa-genprof terminal open. Open a separate terminal window and run your application through all standard usage paths to trigger all required file, network, and execution permissions.

/usr/local/bin/myapp

Perform typical actions such as loading configuration files, saving output, binding network ports, and executing helper binaries. Missing any action during this phase may lead to blocked functionality once the profile is enforced.

Step 4: Review and Generate Rules

Return to the terminal running aa-genprof and press S (Scan).

The tool reads the kernel audit logs (located in /var/log/syslog or /var/log/audit/audit.log) and prompts you to allow or deny each detected action:

  • Allow (A): Grants the requested permission.
  • Deny (D): Explicitly blocks the requested action.
  • Glob (G): Broadens a specific file path to a wildcard pattern.
  • Inherit (I) / Profile (P): Specifies execution modes if the application runs child processes.

After reviewing all prompts, press F (Finish) to save the generated profile and automatically enable enforcement mode.

Step 5: Manually Inspect the Profile

Custom profiles are stored in /etc/apparmor.d/. Inspect the generated file to ensure rules are accurate and follow least-privilege principles:

sudo nano /etc/apparmor.d/usr.local.bin.myapp

Common AppArmor access flags include:

  • r: Read
  • w: Write
  • a: Append
  • k: File locking
  • m: Memory map executable
  • px: Execute under a specific profile
  • ix: Inherit execution environment

Save and reload the profile if you make manual edits:

sudo apparmor_parser -r /etc/apparmor.d/usr.local.bin.myapp

Step 6: Verify and Enforce

Verify that the profile is active and in enforce mode using aa-status:

sudo aa-status

Look for your application binary under the profiles are in enforce mode section.

If the profile is in complain mode and you want to enforce it manually, run:

sudo aa-enforce /etc/apparmor.d/usr.local.bin.myapp

To update the profile in the future after application upgrades or feature additions, run sudo aa-logprof to scan for newly denied events and append missing rules.
