How to Set Up a Chroot Jail in Ubuntu

Setting up a chroot environment in Ubuntu isolates a process and its dependencies from the main operating system, creating a restricted directory tree to safely host vulnerable or untrusted applications. This article provides a straightforward, step-by-step guide to building a minimal chroot jail, mounting necessary system resources, copying essential dependencies, and executing your application with restricted permissions.

1. Create the Chroot Directory

First, create the root directory for your jail along with the essential system subdirectories required by most Linux applications.

sudo mkdir -p /var/chroot/jail
sudo mkdir -p /var/chroot/jail/{bin,lib,lib64,dev,proc,sys,etc}

2. Mount Necessary Virtual Filesystems

Many applications require access to pseudo-filesystems like /proc and /dev to function properly.

sudo mount -t proc proc /var/chroot/jail/proc
sudo mount -t sysfs sys /var/chroot/jail/sys
sudo mount --bind /dev /var/chroot/jail/dev

Note: To make these mounts persistent across reboots, add corresponding entries to your /etc/fstab file.

3. Copy Required Binaries and Libraries

A chrooted process cannot access files outside its designated directory. You must copy the application binary and all its shared library dependencies into the jail.

Find Library Dependencies

Use the ldd command to identify the libraries required by your application (for example, /bin/bash or your target application):

ldd /bin/bash

Copy Binaries and Libraries

Copy the executable and each listed library file into the corresponding /bin, /lib, or /lib64 directories inside /var/chroot/jail/.

For example:

sudo cp /bin/bash /var/chroot/jail/bin/
sudo cp /lib/x86_64-linux-gnu/libc.so.6 /var/chroot/jail/lib/
sudo cp /lib64/ld-linux-x86-64.so.2 /var/chroot/jail/lib64/

(Repeat this process for all shared libraries returned by ldd for your specific vulnerable application).

4. Set Directory Permissions

To prevent an attacker from escaping the chroot environment or modifying binary files, ensure the jail root is owned by root and not writable by non-root users.

sudo chown -R root:root /var/chroot/jail
sudo chmod 755 /var/chroot/jail

Create a dedicated directory inside the jail if the application needs write access to write logs or temp files:

sudo mkdir -p /var/chroot/jail/tmp
sudo chmod 1777 /var/chroot/jail/tmp

5. Execute the Application Securely

Never run a vulnerable application as the root user inside a chroot environment, as root users can often break out of chroot jails. Drop privileges to an unprivileged user (such as nobody) when launching the environment.

To test the environment using bash:

sudo chroot --userspec=nobody:nogroup /var/chroot/jail /bin/bash

To run your application directly:

sudo chroot --userspec=nobody:nogroup /var/chroot/jail /bin/your_application

6. Unmounting the Environment

When you are done testing or need to dismantle the jail, unmount the pseudo-filesystems before deleting any directories:

sudo umount /var/chroot/jail/proc
sudo umount /var/chroot/jail/sys
sudo umount /var/chroot/jail/dev
