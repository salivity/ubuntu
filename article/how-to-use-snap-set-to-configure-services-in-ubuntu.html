How to Use Snap Set to Configure Services in Ubuntu

The snap set command in Ubuntu serves as the standard interface for dynamically configuring runtime options, environment variables, and operational parameters for installed snaps and their background services. Because snaps are mounted as read-only SquashFS filesystems, traditional configuration workflows involving manual file edits in /etc do not apply. This article explains how snap set interacts with background daemons, how it triggers system-level updates through internal hooks, and how administrators can use it to modify service behavior on a running system.

The Role of snap set in Snap Architecture

Snap packages operate in confined, read-only environments. To allow customization while maintaining package integrity, snapd (the snap management daemon) provides an internal key-value configuration store.

The snap set command allows system administrators to write configuration keys directly to this internal store. Its primary role is to expose customizable daemon settings—such as listening ports, memory limits, logging levels, or worker processes—without requiring root access to modify the application's underlying code or package files.

How snap set Modifies Background Services

When you execute snap set, the change does not merely update a database; it actively engages the snap's lifecycle via the configure hook.

The process unfolds in the following sequence:

  1. Input Submission: An administrator runs sudo snap set <snap-name> <key>=<value>.
  2. Hook Execution: snapd executes the snap's internal configure hook script located within the package metadata.
  3. Application of Settings: The configure hook reads the submitted key-value pairs, writes them to writable directories (such as $SNAP_DATA or $SNAP_COMMON), and validates the parameters.
  4. Service Reload or Restart: If the modified option impacts a running background service, the hook instructs systemd to restart or reload the specific snap daemon so the changes take effect immediately.

Practical Usage and Examples

The syntax for modifying service configurations requires root privileges and pairs a key with its target value.

To change the operational port of a background service (such as Nextcloud):

sudo snap set nextcloud ports.http=8080

To configure multiple parameters simultaneously:

sudo snap set <snap-name> mode=production workers=4 log.level=debug

To reset an option to its default state, the exclamation mark (!) syntax is used:

sudo snap set <snap-name> workers!

Inspecting Configured Options

To verify that changes have been applied to the background service, the complementary snap get command retrieves current configurations:

  • View all configured settings for a snap: 
    sudo snap get <snap-name>
  • View a specific configuration key: 
    sudo snap get <snap-name> ports.http

By relying on snap set, Ubuntu ensures that background daemon configurations remain isolated, reproducible, and persistent across automatic snap package updates.
