Understanding the miimon Parameter in Ubuntu Bonding

In an Ubuntu network bond configuration, the miimon parameter serves as the heartbeat monitor for physical interfaces participating in a bonded link. This article explains what miimon is, how it operates to detect link failures, the standard values used for configuration, and how it is implemented within Ubuntu using Netplan to guarantee reliable network redundancy and failover.

What is the miimon Parameter?

The term miimon stands for Media Independent Interface Monitor. In Linux and Ubuntu bonding drivers, it specifies the frequency, measured in milliseconds, at which the bonding driver inspects the carrier state of each physical slave interface to determine whether the link is up or down.

When configuring network interface bonding—whether for redundancy (like active-backup) or increased bandwidth (like LACP/802.3ad)—the operating system must know immediately if a physical cable is unplugged, a network card fails, or a connected switch port goes offline. The miimon parameter provides this failure detection mechanism.

How miimon Works

  1. State Inspection: At regular intervals determined by the assigned numerical value, the kernel driver queries the network interface's MII registers or carrier state.
  2. Failure Detection: If the interface reports a loss of carrier signal, the bonding driver flags that specific slave interface as inactive.
  3. Failover Execution: The bonding module redirects outgoing and incoming traffic to the remaining healthy slave interfaces according to the bonding mode in use.
  4. Link Recovery: Once the link state returns to active, the driver recognizes the restored interface and can reintegrate it into the active pool.

If miimon is set to 0, MII link monitoring is completely disabled. Disabling miimon means the bond will not automatically detect physical link losses via carrier checks, which can lead to silent network failure where traffic is directed to a dead interface.

Recommended Values and Complementary Timers

The most commonly recommended value for miimon is 100 (representing 100 milliseconds, or 10 checks per second). This value provides an optimal balance between fast link-state failure detection and minimal CPU overhead.

To prevent erratic behavior caused by a flapping link (a port rapidly switching between up and down states), miimon is typically paired with two companion parameters:

  • updelay: The time in milliseconds to wait before declaring an interface fully restored after a link-up event is detected. This must be a multiple of the miimon value.
  • downdelay: The time in milliseconds to wait before disabling an interface after a link-down event is detected. This also must be a multiple of the miimon value.

Ubuntu Netplan Configuration Example

Ubuntu utilizes Netplan for network management. The miimon parameter is defined under the bond parameters in the Netplan YAML configuration (typically located in /etc/netplan/):

network:
  version: 2
  renderer: networkd
  ethernets:
    enp3s0: {}
    enp4s0: {}
  bonds:
    bond0:
      interfaces:
        - enp3s0
        - enp4s0
      addresses:
        - 192.168.1.50/24
      parameters:
        mode: active-backup
        mii-monitor-interval: 100
        up-delay: 200
        down-delay: 200

Note: In Netplan syntax, the miimon parameter is explicitly mapped using the mii-monitor-interval key.

Summary

The miimon parameter is an essential setting in Ubuntu network bonding that ensures network resilience. By routinely checking the physical state of every bonded interface at a millisecond-level interval, it enables the Linux kernel to react swiftly to hardware and link disruptions, redirecting packets before application-level connections time out.
