Ansible ansible_distribution Fact for Ubuntu Playbooks

The ansible_distribution fact is a core variable gathered by Ansible during the setup phase that specifically identifies the operating system name running on a target host. When writing playbooks tailored for Ubuntu, this fact allows administrators to implement precise conditional logic, include distribution-specific variables, and execute tasks uniquely intended for Ubuntu without impacting other systems. This article details the purpose of ansible_distribution, why it is essential for Ubuntu environments, and how to effectively implement it in automation workflows.

Identifying the Operating System Accurately

When Ansible connects to a managed node, its setup module automatically gathers system properties known as facts. For an Ubuntu system, the ansible_distribution variable returns the string "Ubuntu".

While Ansible also collects ansible_os_family, that fact returns "Debian" for Ubuntu machines. Relying solely on ansible_os_family makes it impossible to differentiate between a native Debian server and an Ubuntu system. The ansible_distribution fact provides the exact granularity needed to confirm that the host is indeed running Ubuntu.

Managing Ubuntu-Specific Features and Repositories

Ubuntu introduces several tools, utilities, and repository structures that are not present or functional on other distributions, even those within the Debian family:

  • Personal Package Archives (PPAs): Ubuntu relies heavily on PPAs via the add-apt-repository tool. Attempting to add a PPA on a pure Debian host or non-Debian distribution using the ansible.builtin.apt_repository module can cause failures.
  • Canonical-Specific Packages: Ubuntu often names packages differently or uses Canonical-specific packages such as ubuntu-advantage-tools, landscape-client, or Snap packages (snapd), which may not be present or desired on generic Debian installations.
  • Hardware and Kernel Enablement: Hardware Enablement (HWE) kernels and specific proprietary driver managers are unique to Ubuntu environments.

Applying Conditional Logic with when Statements

The primary technical purpose of ansible_distribution is to serve as a guardrail in conditional statements. It ensures that tasks targeted specifically at Ubuntu are skipped automatically on any other host in the inventory.

- name: Add an Ubuntu PPA repository
  ansible.builtin.apt_repository:
    repo: ppa:git-core/ppa
    state: present
  when: ansible_distribution == "Ubuntu"

In heterogeneous environments containing multiple Linux distributions, this pattern guarantees that non-Ubuntu servers do not fail when processing the play.

Loading Distribution-Specific Variables

The ansible_distribution fact is frequently used to dynamically load configuration variables suited specifically to Ubuntu. By structuring variable files around distribution names, a single playbook can configure multiple platforms cleanly:

- name: Load distribution-specific variables
  ansible.builtin.include_vars: "{{ ansible_distribution }}.yml"

In this setup, an Ubuntu.yml file can contain package lists, configuration file paths, and service names designated specifically for Ubuntu, keeping the core playbook clean and maintainable.

Combining with Version Facts for Finer Control

Ubuntu releases differ significantly between versions (such as LTS releases 20.04, 22.04, and 24.04). The ansible_distribution fact is commonly combined with ansible_distribution_version or ansible_distribution_major_version to target specific Ubuntu releases:

- name: Apply configuration for Ubuntu 22.04 and newer
  ansible.builtin.template:
    src: netplan_config.j2
    dest: /etc/netplan/01-netcfg.yaml
  when: 
    - ansible_distribution == "Ubuntu"
    - ansible_distribution_version is version('22.04', '>=')

This multi-level approach allows automation engineers to isolate Ubuntu from other distributions while also accounting for architectural and configuration changes across Ubuntu lifecycle releases.
