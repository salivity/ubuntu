Create Systemd Timer to Replace Cron in Ubuntu

Systemd timers offer a modern, reliable alternative to traditional cron jobs in Ubuntu, featuring native logging via journalctl, precise scheduling, and dependency management. Unlike cron, which handles execution within a single configuration file, a systemd timer setup requires two distinct components: a service unit that defines the task to execute and a timer unit that defines when to execute it. This guide explains how to build, enable, and monitor both units to automate scheduled tasks seamlessly.

Step 1: Create the Service Unit

The service unit defines the command or script you want to run. Create a new service file in /etc/systemd/system/ using your preferred text editor.

sudo nano /etc/systemd/system/mytask.service

Add the following configuration:

[Unit]
Description=Run custom maintenance script

[Service]
Type=oneshot
ExecStart=/usr/local/bin/myscript.sh
  • Type=oneshot: Ideal for scripts that run and exit immediately.
  • ExecStart: Specifies the absolute path to the executable or script.

Ensure that the target script exists and has executable permissions (chmod +x /usr/local/bin/myscript.sh).

Step 2: Create the Timer Unit

The timer unit must have the exact same base name as the service file, ending with .timer. Create the timer file in the same directory:

sudo nano /etc/systemd/system/mytask.timer

Add the following configuration:

[Unit]
Description=Schedule for custom maintenance script

[Timer]
OnCalendar=*-*-* 02:00:00
Persistent=true

[Install]
WantedBy=timers.target
  • OnCalendar: Defines the schedule using systemd calendar format (e.g., *-*-* 02:00:00 runs daily at 2:00 AM).
  • Persistent=true: Ensures that if the system was powered off when the task was scheduled, it runs immediately after the next boot (similar to anacron).
  • WantedBy=timers.target: Ensures the timer activates automatically on boot.

Step 3: Reload and Enable the Timer

After creating both files, reload the systemd manager configuration to recognize the new units:

sudo systemctl daemon-reload

Enable and start the timer (do not enable the service directly, as the timer will trigger it):

sudo systemctl enable --now mytask.timer

Step 4: Verify and Manage the Timer

Check the status of your newly created timer:

systemctl status mytask.timer

List all active timers on the system to verify the next execution time:

systemctl list-timers

To view the output and logs generated by the script, use journalctl:

sudo journalctl -u mytask.service
