Rate Limit SSH with UFW on Ubuntu

Securing an Ubuntu server against brute-force attacks is essential, and configuring the Uncomplicated Firewall (UFW) to rate-limit SSH connections provides an immediate layer of defense. This guide explains how to replace standard SSH allow rules with UFW's built-in rate-limiting feature, which automatically blocks IP addresses that attempt six or more connections within a 30-second window.

Step 1: Check Current UFW Status

Before making changes, verify whether UFW is currently active and review the existing rules by opening your terminal and running:

sudo ufw status numbered

If you already have a rule allowing standard SSH access (such as 22/tcp ALLOW IN), take note of its rule number so it can be updated or replaced.

Step 2: Remove Existing SSH Allow Rules

If you have an unrestricted allow rule for SSH, delete it to ensure the rate limit rule takes precedence. If rule 1 is your existing SSH rule, run:

sudo ufw delete 1

Alternatively, you can delete it by name:

sudo ufw delete allow ssh

(If your SSH service runs on standard port 22 and was added as a port rule, use sudo ufw delete allow 22/tcp instead.)

Step 3: Apply the Rate Limit Rule

Apply the built-in rate-limiting directive using the service name:

sudo ufw limit ssh

If your SSH daemon is configured to use a custom port (for example, port 2222), specify the port number and protocol:

sudo ufw limit 2222/tcp

Step 4: Enable and Reload UFW

If UFW is not already enabled on your system, enable it now:

sudo ufw enable

If it was already running, reload the configuration to apply the new rule:

sudo ufw reload

Step 5: Verify the Configuration

Confirm that the limit rule is active by checking the firewall status:

sudo ufw status verbose

The output should show:

To                         Action      From
--                         ------      ----
22/tcp (ssh)               LIMIT IN    Anywhere
22/tcp (ssh (v6))          LIMIT IN    Anywhere (v6)

How the Rate Limit Works

UFW's limit rule uses the iptables recent module. It denies new connections from an IP address if that address has initiated 6 or more connections within the last 30 seconds. Legitimate users who authenticate successfully on the first or second attempt will not be impacted, while automated scripts attempting rapid credential guessing will be temporarily blocked.
