Purpose of /sys Filesystem in Ubuntu Hardware Diagnosis

The /sys filesystem (sysfs) in Ubuntu is a virtual filesystem created by the Linux kernel that exports information about system devices, drivers, and kernel subsystems in a structured, user-readable format. Serving as an interactive window into the kernel's device model, it enables system administrators and developers to inspect hardware states, analyze device configurations, and diagnose underlying hardware issues in real time without requiring specialized diagnostic utilities.

Understanding the Structure of /sys

Unlike traditional filesystems stored on a hard drive, /sys exists entirely in memory. The kernel generates its contents dynamically as hardware is detected and drivers are loaded. Every directory and file within /sys represents a specific kernel object, attribute, or relationship.

The directory layout categorizes hardware into distinct logical views:

  • /sys/class/: Groups devices by their functional class (e.g., net, power_supply, thermal, block, sound). This is usually the most convenient location for diagnostic tasks.
  • /sys/bus/: Groups devices according to the physical or virtual bus they connect to (e.g., pci, usb, i2c, scsi).
  • /sys/devices/: Contains the global device hierarchy, representing the actual physical layout of hardware as attached to the system.
  • /sys/block/: Contains entries for each block device (disks, partitions) present on the system.

Key Hardware Diagnostic Capabilities

Using standard command-line tools like cat, grep, or ls, users can read files in /sys to retrieve instant hardware diagnostics.

1. Network Diagnostics

Network device health and operational status can be checked directly under /sys/class/net/.

  • Check physical link state: cat /sys/class/net/eth0/operstate
  • View link speed: cat /sys/class/net/eth0/speed
  • Inspect error counters: cat /sys/class/net/eth0/statistics/rx_errors

2. Power and Battery Health

Laptops and UPS units report power metrics under /sys/class/power_supply/.

  • Check battery charge status: cat /sys/class/power_supply/BAT0/status
  • Determine remaining energy vs. design capacity: Read energy_now and energy_full_design to assess battery degradation.

3. Thermal and CPU Monitoring

Thermal sensors expose temperature readings and cooling device states via /sys/class/thermal/.

  • Read CPU thermal zone temperatures: cat /sys/class/thermal/thermal_zone0/temp (value is in millidegrees Celsius).
  • Check current CPU frequency scaling and policies under /sys/devices/system/cpu/.

4. USB and PCI Device Identification

When a device fails to function, /sys/bus/pci/ and /sys/bus/usb/ provide raw vendor IDs, product IDs, and driver binding status.

  • Verify if a driver bound to a PCI device: ls -l /sys/bus/pci/devices/0000:01:00.0/driver
  • Check power management and runtime suspend states for connected devices.

Modifying Hardware Attributes at Runtime

In addition to read-only diagnostics, many files in /sys accept write operations to modify device behavior dynamically for testing purposes. For example, writing values to a device's power/control file allows enabling or disabling runtime power management to troubleshoot device stability issues.

Advantages of Using /sys for Troubleshooting

  • No Dependency on External Tools: Diagnostics can be performed on minimal or recovery installations of Ubuntu where utilities like lshw, inxi, or hardinfo are unavailable.
  • Scriptability: Because attributes are presented as standard text files, shell scripts can easily monitor hardware health, log statistics, or generate alerts.
  • Kernel-Level Accuracy: Information reflects the exact state maintained by the Linux kernel drivers rather than user-space approximations.
