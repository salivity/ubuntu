Restrict Cron Access Using cron.allow in Ubuntu

Restricting access to the cron daemon in Ubuntu ensures that only authorized system users can schedule automated background tasks. By default, all standard users are permitted to create cron jobs unless explicitly blocked. This guide explains how to use the /etc/cron.allow file to implement an allowlist policy, granting cron access exclusively to specified users while automatically denying access to everyone else.

How cron.allow and cron.deny Work

Ubuntu's cron daemon checks two primary files located in the /etc directory to determine user permissions:

  • /etc/cron.allow: If this file exists, only the users listed inside it can use the crontab command. Any user not listed is automatically blocked, and the system ignores /etc/cron.deny.
  • /etc/cron.deny: If /etc/cron.allow does not exist, all users can schedule jobs except those listed in this file.
  • Root user: The root user retains access to cron regardless of these configurations.

To enforce strict security, creating /etc/cron.allow is the recommended approach because it defaults to denying everyone except explicitly named accounts.

Step 1: Create or Edit /etc/cron.allow

By default, /etc/cron.allow usually does not exist on a fresh Ubuntu installation. You must create it with administrative privileges.

Open or create the file using a text editor such as nano:

sudo nano /etc/cron.allow

Step 2: Add Authorized Users

Add each username that should have permission to create and manage cron jobs. List each user on a separate line.

Example:

root
ubuntu
deploy

Ensure there are no leading or trailing spaces, empty lines, or special characters. Once finished, save the file (in nano, press Ctrl+O, Enter, then Ctrl+X).

Step 3: Secure File Permissions

Set the appropriate ownership and permissions on the /etc/cron.allow file to prevent unauthorized users from modifying it:

sudo chown root:root /etc/cron.allow
sudo chmod 644 /etc/cron.allow

This configuration ensures only root can modify the file, while the cron service can read it.

Step 4: Handle /etc/cron.deny (Optional)

Because /etc/cron.allow takes precedence over /etc/cron.deny, the system automatically ignores /etc/cron.deny once /etc/cron.allow is present. However, to prevent confusion during administrative audits, you can remove the deny file:

sudo rm -f /etc/cron.deny

Step 5: Verify the Configuration

You do not need to restart the cron daemon; the changes apply immediately.

To test the restriction:

  1. Switch to an unauthorized user account: 
    su - testuser
  2. Attempt to open or list the crontab: 
    crontab -e

If the restrictions are active, the system will output the following message:

You (testuser) are not allowed to use this program (crontab)
See crontab(1) for more information

Next, switch to an authorized user listed in /etc/cron.allow and run the same command to verify that crontab opens without error.
