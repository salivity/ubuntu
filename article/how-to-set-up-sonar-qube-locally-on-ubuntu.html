How to Set Up SonarQube Locally on Ubuntu

Setting up a local SonarQube instance on Ubuntu enables developers to automatically inspect code quality, detect security vulnerabilities, and track technical debt directly within their development environment. This guide covers the end-to-end installation process, including system prerequisite configuration, Java OpenJDK installation, PostgreSQL database setup, SonarQube service deployment, and initial access to the SonarQube web dashboard.

1. System Requirements and Kernel Tuning

SonarQube relies on an embedded Elasticsearch instance, which requires specific Linux kernel parameters to function properly.

Update the system package repository:

sudo apt update && sudo apt upgrade -y

Increase system file limits and memory map limits by editing /etc/sysctl.conf:

sudo nano /etc/sysctl.conf

Append the following lines to the bottom of the file:

vm.max_map_count=524288
fs.file-max=131072
fs.suid_dumpable=0

Apply the changes immediately:

sudo sysctl --system

Next, configure file limits for the user running SonarQube by editing /etc/security/limits.conf:

sudo nano /etc/security/limits.conf

Add these lines before # End of file:

sonarqube   nofile   131072
sonarqube   nproc    8192

2. Install OpenJDK 17

Recent versions of SonarQube require Java 17. Install OpenJDK 17 along with required decompression utilities:

sudo apt install -y openjdk-17-jdk unzip wget

Verify the Java installation:

java -version

3. Install and Configure PostgreSQL

SonarQube uses a relational database to store configuration data and analysis metrics.

Install PostgreSQL and start the service:

sudo apt install -y postgresql postgresql-contrib
sudo systemctl enable postgresql
sudo systemctl start postgresql

Switch to the PostgreSQL user and open the PostgreSQL prompt:

sudo -u postgres psql

Execute the following commands to create a user and database dedicated to SonarQube:

CREATE USER sonar WITH ENCRYPTED PASSWORD 'StrongPassword123';
CREATE DATABASE sonarqube OWNER sonar;
GRANT ALL PRIVILEGES ON DATABASE sonarqube TO sonar;
\q

4. Download and Install SonarQube

Create a dedicated system user to execute SonarQube without root privileges:

sudo useradd -b /opt/sonarqube -d /opt/sonarqube -m -s /bin/bash sonarqube

Download the latest LTS version of SonarQube Community Edition:

cd /tmp
wget https://binaries.sonarsource.com/Distribution/sonarqube/sonarqube-10.4.1.88267.zip
sudo unzip sonarqube-10.4.1.88267.zip -d /opt/
sudo mv /opt/sonarqube-10.4.1.88267/* /opt/sonarqube/
sudo rm -rf /opt/sonarqube-10.4.1.88267

Assign file permissions to the sonarqube user:

sudo chown -R sonarqube:sonarqube /opt/sonarqube

5. Configure SonarQube Properties

Edit the configuration file to link SonarQube with your PostgreSQL database:

sudo nano /opt/sonarqube/conf/sonar.properties

Locate and modify the following configuration keys (remove # if commented):

sonar.jdbc.username=sonar
sonar.jdbc.password=StrongPassword123
sonar.jdbc.url=jdbc:postgresql://localhost/sonarqube
sonar.web.host=127.0.0.1
sonar.web.port=9000

6. Configure Systemd Service

Create a systemd unit file to manage the SonarQube service:

sudo nano /etc/systemd/system/sonarqube.service

Paste the following service definition:

[Unit]
Description=SonarQube service
After=syslog.target network.target

[Service]
Type=forking
ExecStart=/opt/sonarqube/bin/linux-x86-64/sonar.sh start
ExecStop=/opt/sonarqube/bin/linux-x86-64/sonar.sh stop
User=sonarqube
Group=sonarqube
Restart=always
LimitNOFILE=131072
LimitNPROC=8192

[Install]
WantedBy=multi-user.target

Reload the systemd daemon, enable, and start SonarQube:

sudo systemctl daemon-reload
sudo systemctl enable sonarqube
sudo systemctl start sonarqube

Check the status of the service:

sudo systemctl status sonarqube

7. Access SonarQube Interface

  1. Open a web browser and navigate to http://localhost:9000 (or http://<your-server-ip>:9000).
  2. Log in using the default administrative credentials:
    • Username: admin
    • Password: admin
  3. Upon first login, update the default password to secure the instance.

Once logged in, the local SonarQube server is ready to integrate with local projects or build pipelines using the SonarScanner CLI, Maven, Gradle, or other supported build tools.
