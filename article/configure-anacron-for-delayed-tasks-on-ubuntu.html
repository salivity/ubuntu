Configure Anacron for Delayed Tasks on Ubuntu

This article explains how to set up and configure Anacron on an Ubuntu laptop to ensure scheduled tasks execute reliably, even when the machine is shut down or suspended during regular runtimes. Unlike standard cron, which assumes continuous uptime and skips jobs when a computer is off, Anacron tracks intervals and executes pending tasks shortly after the system boots. Below, you will find instructions for verifying your installation, editing the configuration file, scheduling custom jobs, and testing your setup.

Why Use Anacron on a Laptop?

The standard cron daemon relies on continuous execution: if a task is scheduled for 03:00 AM and your laptop is closed, the task is skipped entirely until the next scheduled window. Anacron solves this by recording timestamps for completed jobs in /var/spool/anacron. When your laptop boots, Anacron checks these timestamps. If the defined period has elapsed, it waits for a designated delay time and then runs the command.

Step 1: Verify Anacron Installation

Anacron is installed by default on standard Ubuntu Desktop installations. To verify it is installed and active, run:

sudo apt update
sudo apt install anacron

Check the status of the Anacron systemd service:

systemctl status anacron.service

Step 2: Understand the Anacrontab Syntax

Anacron is controlled by the configuration file /etc/anacrontab. Open it using a text editor with administrative privileges:

sudo nano /etc/anacrontab

Entries in this file follow a specific four-field format:

period_in_days   delay_in_minutes   job_identifier   command
  • period_in_days: How often the job runs (e.g., 1 for daily, 7 for weekly, 30 for monthly). You can also use named macros like @daily or @monthly.
  • delay_in_minutes: The number of minutes Anacron waits after system boot before starting the command. This prevents disk I/O bottlenecks when the OS is starting.
  • job_identifier: A unique name for the task used to create a timestamp file in /var/spool/anacron/.
  • command: The terminal command, script, or binary to execute.

Step 3: Add a Custom Job

You can configure tasks directly in /etc/anacrontab or leverage Ubuntu's predefined directories.

Method A: Adding Direct Entries to /etc/anacrontab

To execute a custom backup script every three days, with a 15-minute delay after system boot, append the following line to /etc/anacrontab:

3   15   user_laptop_backup   /usr/local/bin/backup_script.sh

Ensure your script is executable:

sudo chmod +x /usr/local/bin/backup_script.sh

Method B: Using Standard Cron Directories

By default, Ubuntu's /etc/anacrontab already delegates execution to standard cron directories:

1   5    cron.daily     run-parts --report /etc/cron.daily
7   10   cron.weekly    run-parts --report /etc/cron.weekly
@monthly 15 cron.monthly run-parts --report /etc/cron.monthly

You can simply place executable scripts inside /etc/cron.daily/, /etc/cron.weekly/, or /etc/cron.monthly/. Anacron will automatically pick them up and run them sequentially.

Step 4: Configure Power and Battery Settings

By default, Ubuntu prevents Anacron from running when the laptop is disconnected from AC power to preserve battery life.

If your laptop spends significant time running on battery and you want Anacron to execute regardless of power state, you can adjust this behavior by overriding the systemd condition:

  1. Edit the systemd service override: 
    sudo systemctl edit anacron.service
  2. Add the following lines to bypass the AC power check: 
    [Unit]
ConditionACPower=
  3. Save and close the file. Reload systemd: 
    sudo systemctl daemon-reload

Step 5: Test and Validate the Configuration

To check /etc/anacrontab for syntax errors without running any commands:

sudo anacron -T

If no errors are returned, the syntax is valid.

To force immediate execution of all tasks—ignoring delays and timestamp records—run:

sudo anacron -f -n
  • -f forces the execution of all jobs regardless of whether their run period has expired.
  • -n runs the jobs immediately without waiting for the configured delay period.

To inspect the last time specific jobs were executed, view the timestamp files:

ls -l /var/spool/anacron/
cat /var/spool/anacron/user_laptop_backup
