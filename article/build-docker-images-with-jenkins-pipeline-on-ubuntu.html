Build Docker Images with Jenkins Pipeline on Ubuntu

This guide provides a straightforward walkthrough for configuring a Jenkins declarative pipeline to build Docker images on an Ubuntu agent. It covers essential node-level prerequisites, user permissions, and the declarative Jenkinsfile syntax required to execute Docker build commands smoothly within your CI/CD workflow.

1. Prepare the Ubuntu Agent

Before running Docker commands inside a Jenkins pipeline, your Ubuntu node must have Docker installed and the jenkins user must have permissions to communicate with the Docker daemon.

Run the following commands on your Ubuntu node:

# Update and install Docker
sudo apt-get update
sudo apt-get install -y docker.io

# Add the jenkins user to the docker group
sudo usermod -aG docker jenkins

# Apply group changes immediately (or restart the Jenkins agent service)
sudo systemctl restart docker
sudo systemctl restart jenkins

Note: If your Ubuntu system acts as an SSH or inbound agent, disconnect and reconnect the agent from the Jenkins controller so the group permissions take effect.

2. Configure the Declarative Pipeline

In Jenkins, create a new Pipeline job or reference a Jenkinsfile in your source code repository. Ensure your Ubuntu agent has a label (for example, ubuntu-node) assigned in Manage Jenkins > Nodes.

Here is a complete declarative pipeline configuration:

pipeline {
    agent {
        node {
            label 'ubuntu-node'
        }
    }

    environment {
        IMAGE_NAME = 'my-app'
        IMAGE_TAG  = "${BUILD_NUMBER}"
    }

    stages {
        stage('Checkout') {
            steps {
                checkout scm
            }
        }

        stage('Build Docker Image') {
            steps {
                script {
                    sh "docker build -t ${IMAGE_NAME}:${IMAGE_TAG} ."
                    sh "docker tag ${IMAGE_NAME}:${IMAGE_TAG} ${IMAGE_NAME}:latest"
                }
            }
        }

        stage('Verify Image') {
            steps {
                sh "docker images | grep ${IMAGE_NAME}"
            }
        }
    }

    post {
        always {
            // Optional: clean up dangling images to save disk space
            sh 'docker image prune -f'
        }
        success {
            echo "Docker image ${IMAGE_NAME}:${IMAGE_TAG} built successfully."
        }
        failure {
            echo "Docker build failed."
        }
    }
}

3. Pipeline Breakdown

  • agent { node { label 'ubuntu-node' } }: Directs Jenkins to run the pipeline exclusively on the Ubuntu node configured with Docker.
  • environment: Defines global variables, such as image name and dynamic build tags, keeping commands clean and reusable.
  • sh "docker build ...": Executes the standard Docker CLI build command using the Dockerfile present in the root of the workspace.
  • post block: Handles post-build cleanup routines, such as removing dangling layers to prevent the agent's disk from filling up over time.
