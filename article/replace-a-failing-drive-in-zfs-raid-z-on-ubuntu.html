Replace a Failing Drive in ZFS RAID-Z on Ubuntu

Replacing a failing disk in an active ZFS RAID-Z pool on Ubuntu can be accomplished without taking your storage offline. This guide covers how to identify the degraded drive, locate its physical counterpart, introduce the replacement disk, and initiate the ZFS resilvering process to restore pool redundancy safely.

1. Identify the Failing Disk

Check the status of your ZFS pools to determine which drive is generating read, write, or checksum errors:

sudo zpool status

In the output, note the pool name and the identifier of the failing device (ideally a persistent identifier such as /dev/disk/by-id/... or a numerical GUID if the drive has dropped offline entirely).

To match the logical drive to its physical serial number, query it using udevadm or smartctl:

sudo smartctl -i /dev/sdX

(Replace /dev/sdX with your drive's kernel name if accessible)

Record the serial number so you do not accidentally pull the wrong drive.

2. Physically Swap the Drive

If your system supports hot-swapping, remove the failing drive using the serial number verified in the previous step and insert the new drive.

If your motherboard does not support hot-swapping and you cannot attach the new drive simultaneously:

  1. Export the pool or shut down the machine cleanly.
  2. Swap the physical hardware.
  3. Power on the system.

If you have an available drive bay, you can attach the replacement drive while keeping the failing drive connected, allowing ZFS to read good data directly from the failing drive during the rebuild.

3. Identify the Replacement Disk Identifier

ZFS works best with stable identifiers located in /dev/disk/by-id/ rather than transient names like /dev/sdb. Find the ID of your newly connected drive:

ls -l /dev/disk/by-id/

Locate the entry that corresponds to the serial number printed on your new drive, avoiding partition paths (e.g., -part1) and selecting the whole-disk identifier (e.g., ata-WDC_WD40EFRX-68N32N0_WD-WCC7K1XXXXXX).

4. Initiate the ZFS Replacement

Run the zpool replace command to assign the new disk to the pool and start the rebuild:

sudo zpool replace <pool-name> <old-device-or-guid> /dev/disk/by-id/<new-device-id>
  • If the old drive is completely missing, supply the numerical GUID shown in zpool status in place of <old-device-or-guid>.
  • If you swapped the drive into the exact same port and the old drive is gone, simply running sudo zpool replace <pool-name> /dev/disk/by-id/<new-device-id> often suffices.

5. Monitor the Resilvering Process

ZFS will immediately begin resilvering (reconstructing data onto the new drive). Monitor progress by running:

sudo zpool status

The output will display the percentage completed, current scan speed, and estimated time to completion. Once the resilver finishes, the old drive will automatically detach from the pool configuration, and the pool state will return to ONLINE.
