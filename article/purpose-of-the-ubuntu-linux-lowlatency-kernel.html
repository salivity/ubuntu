Purpose of the Ubuntu linux-lowlatency Kernel

The linux-lowlatency kernel in the Ubuntu repositories is a pre-compiled, alternative Linux kernel tailored for time-critical tasks that require predictable, minimal response times. While the standard Ubuntu generic kernel prioritizes maximum throughput and energy efficiency, the lowlatency kernel is configured to reduce audio and input lag, eliminate system micro-stutters, and prevent buffer under-runs. This makes it an essential tool for digital audio workstations (DAWs), live multimedia streaming, and interactive data acquisition where execution timing must be deterministic.

Core Differences from the Generic Kernel

The primary difference between Ubuntu’s default linux-generic kernel and the linux-lowlatency package lies in its compile-time configuration parameters:

  • Kernel Preemption (CONFIG_PREEMPT): The generic kernel uses voluntary preemption (CONFIG_PREEMPT_VOLUNTARY), which allows the kernel to finish certain tasks before yielding CPU time to higher-priority processes. The lowlatency kernel enables full preemption, allowing high-priority threads (such as real-time audio threads) to interrupt kernel code almost immediately, drastically reducing task-scheduling latency.
  • Timer Frequency (CONFIG_HZ): The generic kernel typically runs at a timer frequency of 250Hz (ticking every 4 milliseconds). The lowlatency kernel raises this to 1000Hz (ticking every 1 millisecond). This fourfold increase ensures that the system checks for pending tasks much more frequently, providing finer granularity for scheduling.

Primary Use Cases

The linux-lowlatency package is specifically targeted toward workloads where delayed execution causes perceptible errors or failure:

  • Professional Audio Production: In music production setups using JACK or PipeWire, audio buffers must be emptied and filled within a few milliseconds. If the CPU fails to process an audio block in time, an "xrun" (buffer underrun/overrun) occurs, resulting in audible clicks, pops, or dropouts. The lowlatency kernel prevents these interrupts.
  • Live Video Capture and Broadcasting: Live streaming and software-defined video switching benefit from deterministic frame capture and processing without dropped frames.
  • Real-Time Input and MIDI Control: Live performance setups require minimal delay between pressing a MIDI controller key and hearing the synthesized output. The lowlatency kernel reduces this round-trip time below the human perception threshold (under 5–10 milliseconds).

Lowlatency vs. Hard Real-Time (PREEMPT_RT)

It is important to distinguish the linux-lowlatency kernel from a true real-time kernel (PREEMPT_RT):

  • linux-lowlatency provides "soft" real-time performance. It minimizes latency using standard mainline kernel mechanisms without breaking compatibility with proprietary drivers (like NVIDIA).
  • linux-realtime (PREEMPT_RT) provides "hard" real-time guarantees, ensuring tasks execute strictly within a deterministic window. It is generally reserved for industrial automation, robotics, and medical devices.

System Trade-Offs

Choosing the lowlatency kernel involves a few specific compromises:

  • Throughput Loss: Because the CPU switches tasks and checks timers more frequently, more processing power is spent on context switching rather than raw computation. Heavy background tasks like 3D rendering or file compression may take slightly longer.
  • Power Consumption: The higher 1000Hz tick rate prevents the CPU from remaining in deep sleep (C-states) for extended periods, resulting in higher power draw and reduced battery life on laptops.

Installation

For users who require these optimizations, the kernel can be installed directly from the standard repositories without needing third-party repositories:

sudo apt update
sudo apt install linux-lowlatency

Once installed, rebooting the system allows the GRUB bootloader to initialize the new kernel, which will then handle all ongoing time-sensitive computing tasks.
