Serve Static Files from Redis with Nginx on Ubuntu

This guide explains how to configure Nginx to serve static files directly from an in-memory Redis cache on Ubuntu. By routing requests directly to Redis and falling back to the local filesystem only when a cache miss occurs, you eliminate disk I/O bottlenecks and drastically reduce response times for static web assets.

Step 1: Install Nginx and Redis

Update your package index and install Redis and Nginx. Ubuntu provides the standard nginx package which includes the ngx_http_redis module by default.

sudo apt update
sudo apt install nginx redis-server -y

Ensure both services are enabled and running:

sudo systemctl enable --now redis-server
sudo systemctl enable --now nginx

Step 2: Configure Redis

By default, Redis binds to localhost (127.0.0.1:6379), which is suitable for Nginx running on the same server. Verify Redis is active:

redis-cli ping

It should respond with PONG.

Step 3: Populate Redis with Static Content

The ngx_http_redis module retrieves raw strings from Redis based on a key (typically the request URI). You can test caching an asset by storing a sample HTML or CSS snippet using redis-cli:

redis-cli SET /sample.html "<html><body><h1>Served directly from Redis!</h1></body></html>"

Step 4: Configure Nginx to Query Redis

Open or create an Nginx server block configuration file:

sudo nano /etc/nginx/sites-available/default

Modify the configuration to look up incoming URIs in Redis before falling back to local files:

server {
    listen 80;
    server_name _;

    root /var/www/html;
    index index.html index.htm;

    location / {
        # Define the Redis key using the normalized request URI
        set $redis_key $uri;

        # Forward the lookup to the Redis server
        redis_pass 127.0.0.1:6379;

        # Fallback to local disk if key is missing (404) or Redis is down (502)
        error_page 404 502 = @fallback;

        # Default MIME type if not determined
        default_type text/html;
    }

    # Fallback location block for disk retrieval
    location @fallback {
        try_files $uri $uri/ =404;
    }
}

Step 5: Test and Reload Nginx

Verify that the Nginx configuration syntax is correct:

sudo nginx -t

If the test is successful, reload Nginx to apply the changes:

sudo systemctl reload nginx

Step 6: Verify the Setup

  1. Request the cached key:

    curl -i http://localhost/sample.html

    You will receive the content stored in Redis.

  2. Request an uncached file:

    echo "Served from disk" | sudo tee /var/www/html/disk.html
curl -i http://localhost/disk.html

    Nginx fails to find the key in Redis, triggers the @fallback block, and serves the file directly from /var/www/html/.
