Ubuntu Account Lockout: pam_faillock and pam_tally2

This article explains the purpose and functionality of the pam_faillock and pam_tally2 modules within Ubuntu's Pluggable Authentication Module (PAM) architecture. You will learn how these modules defend systems against brute-force attacks by enforcing account lockout policies, how they differ, and why pam_faillock has replaced pam_tally2 in modern Linux releases.

The Primary Purpose of Account Lockout Modules

The primary purpose of both pam_tally2 and pam_faillock is to prevent unauthorized access through automated password-guessing or brute-force attacks. When exposed services like SSH or local login prompts are targeted, attackers repeatedly guess passwords until they succeed.

These PAM modules track consecutive failed authentication attempts against system accounts. When failures exceed a defined threshold within a specific timeframe, the module temporarily or permanently disables the account, stopping automated attacks in their tracks.

The Transition from pam_tally2 to pam_faillock

Historically, pam_tally2 was the standard module for tracking failed logins on Debian and Ubuntu systems. However, upstream Linux-PAM deprecated and eventually removed pam_tally2 in version 1.4.0 due to architectural limitations, including issues with thread safety and data corruption in high-concurrency environments.

Ubuntu systems now rely on pam_faillock as the modern, robust replacement:

  • Ubuntu 18.04 LTS and earlier: Relied primarily on pam_tally2.
  • Ubuntu 20.04 LTS: Supported both modules as an interim transition.
  • Ubuntu 22.04 LTS and newer: Uses pam_faillock exclusively; pam_tally2 is no longer available.

How pam_faillock Operates

The pam_faillock module functions by logging failed attempts in a temporary directory (typically /run/faillock/) on a per-user basis. During authentication, PAM evaluates whether the user has exceeded the allowed failure count before prompting for or verifying credentials.

Key configurable parameters include:

  • deny = N: Specifies the maximum number of failed attempts allowed before the account is locked.
  • unlock_time = N: Defines the duration, in seconds, an account remains locked after reaching the threshold. If set to 0, manual intervention by an administrator is required.
  • fail_interval = N: Sets the observation window in seconds. If the consecutive failures occur outside this interval, the failure counter resets.
  • even_deny_root: Extends the lockout policy to the root account to prevent targeted attacks against system administration privileges.

Managing and Unlocking Accounts

System administrators can inspect failure tallies and unlock accounts using dedicated command-line utilities.

For modern systems using pam_faillock:

  • View failed attempts for a user: 
    faillock --user <username>
  • Reset the failure counter and unlock the account: 
    faillock --user <username> --reset

For legacy systems using pam_tally2:

  • View failed attempts for a user: 
    pam_tally2 --user <username>
  • Reset the failure counter and unlock the account: 
    pam_tally2 --user <username> --reset

Configuring these modules in /etc/pam.d/common-auth and /etc/pam.d/common-account provides an essential baseline security control, ensuring Ubuntu environments remain compliant with major security standards such as CIS Benchmarks, NIST, and PCI-DSS.
