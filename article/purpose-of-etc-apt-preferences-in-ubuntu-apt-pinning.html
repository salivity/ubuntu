Purpose of /etc/apt/preferences in Ubuntu APT Pinning

The /etc/apt/preferences file in Ubuntu controls package version selection through a process known as APT pinning. By modifying this configuration file, system administrators can override the default Advanced Package Tool (APT) behavior to lock packages to specific versions, prevent unwanted upgrades, prioritize specific repositories, or downgrade packages safely.

Core Functions of /etc/apt/preferences

APT automatically selects and installs the highest available version of a package from enabled repositories. The /etc/apt/preferences file changes this behavior by assigning a numeric weight, known as a Pin-Priority, to specific packages or repositories.

The primary use cases include:

  • Preventing Package Upgrades: Pinning a package to its currently installed version prevents system updates from overriding critical custom modifications or breaking application compatibility.
  • Repository Prioritization: Assigning higher priorities to preferred repositories (such as official backports or specific PPAs) ensures APT pulls packages from those sources instead of standard repositories.
  • Allowing Safe Downgrades: Giving a specific version a priority higher than 1000 forces APT to downgrade an installed package to that version.
  • Blocking Packages: Setting a priority below 0 prevents specified packages from ever being installed automatically or manually.

Syntax and Configuration Structure

Entries in the /etc/apt/preferences file (or individual .pref files inside the /etc/apt/preferences.d/ directory) follow a standardized three-line block format:

Package: package_name
Pin: release_or_version_specifier
Pin-Priority: number
  • Package: Specifies the target package name. Using an asterisk (*) applies the rule to all packages.
  • Pin: Defines the match criteria, such as an exact version (version 2.4.1), a release name (release a=jammy), or an origin (origin ppa.launchpad.net).
  • Pin-Priority: A positive or negative integer defining the weight of the rule.

How Pin-Priority Values Work

APT interprets the numeric values assigned to Pin-Priority as follows:

  • P > 1000: The package version is installed even if it requires a downgrade of the currently installed package.
  • 990 <= P < 1000: The target version is installed even if it does not come from the default target release, provided it is newer than the installed version.
  • 500 <= P < 990: The default behavior for standard repositories. Versions are installed unless an installed version is newer.
  • 100 <= P < 500: The version is installed only if no other version is available from another repository or if no version is currently installed.
  • 0 < P < 100: The version is installed only if no installed version exists and no other repository offers it.
  • P < 0: Prevents the target package version from being installed under any circumstance.

Practical Example: Pinning a Package Version

To prevent the nginx package from upgrading past version 1.18.0, add the following entry to /etc/apt/preferences:

Package: nginx
Pin: version 1.18.0*
Pin-Priority: 1001

Because the priority is set above 1000, APT will maintain version 1.18.0 even when newer versions exist in the Ubuntu repositories during an apt upgrade.
