How to Limit LXD Container Disk I/O with Profiles

This guide explains how to restrict disk input/output (I/O) performance for Ubuntu containers using LXD profiles. By defining read and write limits for throughput (bytes per second) or IOPS (input/output operations per second), you can prevent high-load containers from saturating host storage and ensure balanced performance across all instances.

Prerequisites

LXD enforces disk I/O limits using Linux Control Groups (cgroups). To apply these limits, ensure the following:

  • The host runs a Linux kernel that supports the blkio (cgroups v1) or io (cgroups v2) controller.
  • The container uses a storage pool backed by standard block devices (such as ZFS, Btrfs, or LVM). Note that directory-based storage (dir) does not support cgroup-based block I/O throttling.

Step 1: Create a Dedicated LXD Profile

While you can edit the default profile directly, creating a specialized profile keeps your configuration modular.

Create a new profile named io-limited:

lxc profile create io-limited

Step 2: Configure the Root Disk Device Limits

Disk limits are defined on the container's root disk device. If your container inherits its root disk from the default profile, you must specify the root disk device in your new profile to override its limits.

Add the root disk device to the profile, linking it to your storage pool (replace default with your pool's name if different):

lxc profile device add io-limited root disk path=/ pool=default

Limiting Throughput (Bps)

You can limit sequential throughput by specifying values in bytes per second (e.g., KB, MB, GB).

To set a combined ceiling for both reading and writing:

lxc profile device set io-limited root limits.max 20MB

To configure separate limits for read and write operations:

lxc profile device set io-limited root limits.read 30MB
lxc profile device set io-limited root limits.write 10MB

Limiting Operations (IOPS)

If your workload involves random reads and writes, limiting IOPS is often more effective than limiting throughput. Specify values using the iops suffix:

lxc profile device set io-limited root limits.read 500iops
lxc profile device set io-limited root limits.write 250iops

Step 3: Apply the Profile to an Ubuntu Container

You can assign the profile to an existing container or attach it during container creation.

For an Existing Container

Attach the profile to your running or stopped container:

lxc profile add <container_name> io-limited

If you prefer to assign a specific list of profiles directly:

lxc profile assign <container_name> default,io-limited

For a New Container

Launch an Ubuntu container with the profile attached:

lxc launch ubuntu:22.04 <container_name> --profile default --profile io-limited

Step 4: Verify the Configuration

To confirm that the limits are actively inherited by the container, inspect its expanded configuration:

lxc config show <container_name> --expanded

Look for the devices section in the output to ensure the limits are listed under the root device:

devices:
  root:
    limits.read: 30MB
    limits.write: 10MB
    path: /
    pool: default
    type: disk

You can test the limit inside the container by running a basic write test using dd:

lxc exec <container_name> -- dd if=/dev/zero of=/tmp/testfile bs=1M count=100 oflag=direct

The output transfer speed should match the threshold set in the LXD profile.
