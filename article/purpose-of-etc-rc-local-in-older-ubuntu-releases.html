Purpose of /etc/rc.local in Older Ubuntu Releases

The /etc/rc.local file in older Ubuntu releases served as a dedicated shell script executed at the very end of the system boot sequence, allowing administrators to easily run custom commands or scripts automatically upon startup. Prior to Ubuntu's transition to Systemd as its default init system, this file provided a simple, centralized mechanism to execute startup tasks with root privileges without needing to write complex init scripts.

Primary Functions of /etc/rc.local

  • Executing Custom Commands: System administrators used this file to launch background processes, mount network drives, set custom networking parameters, or start application servers that lacked native service scripts.
  • Boot Sequence Order: The script was executed after all standard System V init runlevel services (or Upstart tasks) had completed, ensuring all network interfaces, filesystems, and core system utilities were fully initialized and available.
  • Root Execution Context: Commands placed inside /etc/rc.local inherited system root privileges automatically, bypassing the need for explicit sudo execution.

Structure and Usage

By default, /etc/rc.local contained a template header and ended with the line exit 0. Any custom commands had to be placed above this final line:

#!/bin/sh -e
#
# rc.local
#

# Custom startup commands go here
/usr/local/bin/myscript.sh

exit 0

Because the script executed using the -e flag (#!/bin/sh -e), any single command that returned a non-zero exit status would cause the script to abort immediately. For this reason, commands designed to run indefinitely or in the background had to be appended with an ampersand (&) to detach them from the main boot process.

Shift in Modern Ubuntu Distributions

Starting with Ubuntu 15.04, canonical releases adopted Systemd as the default init system, superseding the legacy init systems. Consequently, /etc/rc.local was deprecated and is no longer included or enabled by default in modern Ubuntu releases. While Systemd maintains backward compatibility through a built-in rc-local.service, modern best practices encourage creating dedicated Systemd service unit files (/etc/systemd/system/) for managing startup tasks and background services.
