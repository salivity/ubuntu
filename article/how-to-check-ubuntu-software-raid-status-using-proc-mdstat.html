How to Check Ubuntu Software RAID Status Using /proc/mdstat

The /proc/mdstat file is a specialized virtual interface provided by the Linux kernel that delivers immediate, real-time diagnostic information about the status and health of software RAID arrays managed by the Multiple Device (MD) driver and mdadm. This article explains the primary purpose of /proc/mdstat, the critical operational metrics it exposes, and how administrators use it to detect degraded arrays and monitor rebuild processes on Ubuntu systems.

Real-Time Health and State Monitoring

The core purpose of /proc/mdstat is to act as an instantaneous reporting snapshot of all active software RAID configurations. Because it exists in the /proc virtual filesystem, reading this file reads directly from kernel memory with negligible performance overhead.

Running cat /proc/mdstat displays:

  • Active Arrays: Lists each defined array identifier (e.g., md0, md127) and whether it is currently active or inactive.
  • RAID Levels: Identifies the configured topology (such as raid1, raid5, or raid10).
  • Underlying Member Devices: Details the physical drive partitions assigned to each array (such as sda1[0], sdb1[1]).

Detection of Degraded Arrays and Failed Drives

A critical use case for /proc/mdstat is rapid fault detection. The kernel uses drive status brackets to denote the operational state of disks within an array. For example:

  • [UU] indicates a two-drive RAID 1 array where both drives are healthy and operational ("Up").
  • [U_] or [_U] denotes a degraded array where one physical drive has failed, disconnected, or been removed.

This concise visual notation allows system administrators and automated monitoring scripts to quickly confirm whether an array has lost redundancy.

Tracking Resynchronization and Recovery

When a replacement disk is added to a degraded array, or during an initial array build or parity check, /proc/mdstat provides dynamic progress metrics. During these operations, the file updates in real time to show:

  • The current operation type (recovery, resync, or check).
  • Percentage of completion and a progress bar.
  • Current data throughput speed (e.g., 52340K/sec).
  • Estimated time to completion (ETA).

Continuous Monitoring

To monitor an ongoing array rebuild or check operation continuously on Ubuntu, administrators typically pair the file with the watch utility:

watch -n 2 cat /proc/mdstat

This command updates the terminal every two seconds, providing a live dashboard of recovery progress without needing to manually query mdadm directly.
