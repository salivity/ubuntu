Mount Windows SMB Share with Kerberos on Ubuntu

Mounting a remote Windows SMB share using Kerberos authentication allows Ubuntu users to access network shares securely using single sign-on (SSO) credentials without passing plain-text passwords over the network. This guide covers the required mount command syntax, prerequisites, and essential mount options needed to establish a Kerberos-authenticated CIFS connection on Ubuntu.

Prerequisites

Before mounting, ensure the system has the required utilities installed and an active Kerberos ticket:

  1. Install CIFS and Kerberos packages:

    sudo apt update
sudo apt install cifs-utils krb5-user

  2. Request a Kerberos ticket for your domain user:

    kinit username@DOMAIN.COM

The Mount Command

To mount the share using the acquired Kerberos ticket, use the mount command with the -t cifs filesystem type and specify sec=krb5 alongside the credential owner's user ID (cruid):

sudo mount -t cifs //server.domain.com/share /mnt/point -o sec=krb5,cruid=$UID

Command Breakdown and Options

  • //server.domain.com/share: The remote network path. Kerberos requires using the Fully Qualified Domain Name (FQDN) rather than an IP address so the system can locate the correct Service Principal Name (SPN).
  • /mnt/point: The local directory where the share will be mounted.
  • sec=krb5: Enforces Kerberos v5 authentication. Alternative security variations include:
    • sec=krb5i: Kerberos authentication with packet integrity (signing).
    • sec=krb5p: Kerberos authentication with packet privacy (full encryption).
  • cruid=$UID: Identifies which local user's Kerberos credentials cache to read. Without this option, the kernel looks for a ticket belonging to root, causing the authentication to fail if kinit was run by a regular user.
