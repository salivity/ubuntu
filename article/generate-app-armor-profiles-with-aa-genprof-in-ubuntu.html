Generate AppArmor Profiles with aa-genprof in Ubuntu

This guide explains how to use the aa-genprof profiling utility to automatically generate AppArmor security profiles for applications on Ubuntu. By monitoring an application while it runs, aa-genprof captures its file access, networking, and permission requirements, allowing you to build tailored profiles quickly without writing complex rule sets manually. You will learn how to install the required tools, launch the profiler, interactively review logged security events, and enforce the resulting profile.

Step 1: Install AppArmor Utilities

The aa-genprof tool is part of the apparmor-utils package. Ensure it is installed on your Ubuntu system by running:

sudo apt update
sudo apt install apparmor-utils

Step 2: Start aa-genprof

To begin profiling, execute aa-genprof followed by the full binary path or the command name of the application you want to restrict:

sudo aa-genprof /path/to/application

For example, to profile the nginx web server:

sudo aa-genprof nginx

Once executed, aa-genprof places the target binary into AppArmor's "complain mode" (where actions are logged rather than blocked) and waits for you to run the application.

Step 3: Exercise the Target Application

Leave the terminal running aa-genprof open. Open a separate terminal or use your graphical interface to execute and thoroughly test the application.

Ensure you exercise all typical functions of the program, such as:

  • Starting, stopping, and restarting the service.
  • Accessing relevant files, directories, and configuration paths.
  • Generating network traffic or opening listening ports.

The more comprehensive your testing is, the more accurate the resulting profile will be.

Step 4: Scan the Logs and Define Rules

Return to the terminal running aa-genprof and press S to scan the system audit logs for events generated by the application.

The utility will present prompts for each detected action (such as reading a file, executing a sub-process, or binding to a network port) and offer options:

  • (A)llow: Grants the application permission to perform the action.
  • (D)eny: Explicitly blocks the action.
  • (G)lob: Broadens file paths with wildcards (e.g., matching /var/log/* instead of a single specific log file).
  • (I)nherit / (C)hild / (P)x: Defines execution permissions if the application spawns other programs.

Work through the interactive prompts to approve or restrict the detected actions.

Step 5: Save and Finish

After reviewing all recorded events:

  1. Press S again if you performed additional testing, or proceed to save.
  2. Press F to finish the profiling process.

aa-genprof will write the newly generated profile to the /etc/apparmor.d/ directory (named after the binary's path, replacing slashes with dots) and automatically transition the application from complain mode to enforce mode.

Step 6: Verify Profile Enforcement

To confirm that the new AppArmor profile is active and enforcing security rules, check the status:

sudo aa-status

Look for your application's binary listed under the profiles are in enforce mode section to ensure it is properly confined.
