Configure Remote Syslog Server for Ubuntu Logs

Aggregating system logs from multiple Ubuntu machines into a single central remote server simplifies monitoring, enhances security auditing, and speeds up troubleshooting across your network. This guide details the complete process for setting up centralized log management on Ubuntu using the default rsyslog service. You will learn how to configure a central log server to receive incoming messages, set up client nodes to forward their local logs, secure firewall rules, and verify log delivery.

Step 1: Configure the Central Remote Syslog Server

By default, Ubuntu includes rsyslog, but it only listens for local messages. You must enable network reception on the designated central server.

  1. Open the primary rsyslog configuration file in a text editor:

    sudo nano /etc/rsyslog.conf

  2. Locate the MODULES section and enable either UDP, TCP, or both protocols by uncommenting the corresponding lines:

    For UDP reception (faster, lower overhead):

    module(load="imudp")
input(type="imudp" port="514")

    For TCP reception (reliable, guaranteed delivery):

    module(load="imtcp")
input(type="imtcp" port="514")

  3. (Optional) Define a template to organize incoming logs into specific directories based on the client hostname. Add the following block to the bottom of /etc/rsyslog.conf:

    $template RemoteLogs,"/var/log/remote/%HOSTNAME%/%PROGRAMNAME%.log"
*.* ?RemoteLogs
& stop

  4. Save the file and exit the editor.

  5. Restart the rsyslog service to apply the configuration changes:

    sudo systemctl restart rsyslog

  6. Verify that rsyslog is listening on port 514:

    sudo ss -tuln | grep 514

Step 2: Configure Server Firewall

If the server uses Uncomplicated Firewall (UFW), allow incoming traffic on port 514.

  • For UDP:

    sudo ufw allow 514/udp

  • For TCP:

    sudo ufw allow 514/tcp

Reload UFW to ensure the rules take effect:

sudo ufw reload

Step 3: Configure Ubuntu Client Nodes to Forward Logs

Each Ubuntu client machine must be configured to direct its logs to the IP address of the central syslog server.

  1. Create a dedicated configuration file on the client machine:

    sudo nano /etc/rsyslog.d/60-remote-target.conf

  2. Add the log forwarding directive pointing to your central server’s IP address:

    To forward all logs via UDP (use a single @):

    *.* @<SERVER_IP_ADDRESS>:514

    To forward all logs via TCP (use double @@):

    *.* @@<SERVER_IP_ADDRESS>:514

    Replace <SERVER_IP_ADDRESS> with the actual IP address of your central log server.

  3. Save and close the file.

  4. Restart rsyslog on the client:

    sudo systemctl restart rsyslog

Step 4: Verify Remote Logging Connection

  1. Send a manual test log message from the client system using the logger utility:

    logger "Test message: Centralized logging setup successful."

  2. Log into the central syslog server and check for the incoming message:

    • If you configured custom templates, check /var/log/remote/<CLIENT_HOSTNAME>/:

      cat /var/log/remote/*/*.log | grep "Test message"

    • If you did not use a template, inspect the default system log:

      tail -f /var/log/syslog | grep "Test message"
