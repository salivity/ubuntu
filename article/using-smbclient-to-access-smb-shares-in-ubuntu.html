Using smbclient to Access SMB Shares in Ubuntu

This article explores the role of the smbclient command-line utility in Ubuntu, detailing how it facilitates direct communication with Server Message Block (SMB) and Common Internet File System (CIFS) shares. Readers will learn the core purpose of smbclient, its advantages over full filesystem mounting, how to install and execute common commands, and how to use it for troubleshooting and routine file transfers.

What is smbclient?

The smbclient tool is part of the Samba suite. It acts as an FTP-like command-line client that allows an Ubuntu system to communicate directly with SMB/CIFS file shares hosted on Windows servers, NAS devices, or other Linux machines running Samba.

Instead of attaching a remote share permanently to the Ubuntu filesystem tree, smbclient establishes a direct, interactive session. This makes it an essential tool for rapid file transfers, automated scripts, and network diagnostics.

Installing smbclient on Ubuntu

While Ubuntu includes many network protocols out of the box, smbclient is typically installed via the terminal using the standard samba-client package:

sudo apt update
sudo apt install smbclient

Core Roles and Use Cases

1. Listing Available Shares

One of the primary diagnostic functions of smbclient is discovering which shares are published by a host. By using the -L (list) flag, users can query a remote server for public or user-restricted shares:

smbclient -L //192.168.1.50 -U username

This returns an inventory of share names, share types, and server comments, allowing administrators to verify network visibility and permissions before attempting to configure persistent mounts.

2. Interactive File Access Without Mounting

Mounting a network drive via mount.cifs requires root privileges, /etc/fstab configuration, or auxiliary tools like gvfs. In contrast, smbclient operates entirely in user space.

To start an interactive session with a remote share:

smbclient //192.168.1.50/documents -U username

Once authenticated, users enter an interactive prompt (smb: \>) supporting commands similar to traditional FTP clients:

  • ls or dir: Lists files and directories in the current remote path.
  • cd: Changes the remote working directory.
  • get <filename>: Downloads a file from the SMB share to the local current directory.
  • put <filename>: Uploads a local file to the remote SMB share.
  • del: Deletes a file on the remote share.
  • exit or quit: Terminates the session.

3. Non-Interactive Scripting and Automation

The smbclient utility can execute operations directly from the shell without prompting for input, which is ideal for backup routines and automation scripts. The -c flag allows you to pass a specific command string:

smbclient //192.168.1.50/backups -U username%password -c "put database.tar.gz; exit"

This command connects, authenticates using inline credentials, uploads database.tar.gz, and immediately closes the connection.

Advantages in an Ubuntu Environment

  • Zero Root Dependency: Users do not need sudo privileges to download or upload files from an SMB resource.
  • Network Troubleshooting: Quickly isolates whether an SMB issue is caused by permission problems, network configuration, or the local kernel-level mount process.
  • Low Overhead: Does not consume system resources to maintain a constant filesystem link when intermittent access is all that is required.
