How to Install and Configure Kubernetes on Ubuntu

This guide provides a step-by-step walkthrough for installing and configuring a production-ready Kubernetes cluster on Ubuntu. You will learn how to prepare your nodes, install the containerd runtime, set up the official Kubernetes repository, install essential components (kubeadm, kubelet, and kubectl), initialize the control plane, install a CNI network plugin, and join worker nodes to the cluster.

Prerequisites

  • At least two Ubuntu servers (22.04 LTS or newer recommended):
    • 1 Control Plane Node (minimum 2 CPUs, 2 GB RAM)
    • 1 or more Worker Nodes (minimum 1 CPU, 2 GB RAM)
  • Unique hostname, MAC address, and static IP address for each node.
  • sudo or root access on all machines.

Step 1: Prepare All Nodes

Perform these steps on all nodes (control plane and workers).

1. Disable Swap

Kubernetes requires swap memory to be disabled to ensure proper resource scheduling.

sudo swapoff -a
sudo sed -i '/ swap / s/^\(.*\)$/#\1/g' /etc/fstab

2. Load Required Kernel Modules

Enable the necessary kernel modules for container runtime and network bridging.

cat <<EOF | sudo tee /etc/modules-load.d/k8s.conf
overlay
br_netfilter
EOF

sudo modprobe overlay
sudo modprobe br_netfilter

3. Configure Sysctl Settings

Set network parameters to allow iptables to inspect bridged traffic and enable IP forwarding.

cat <<EOF | sudo tee /etc/sysctl.d/k8s.conf
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF

sudo sysctl --system

Step 2: Install Containerd Runtime

Kubernetes requires a container runtime interface (CRI). containerd is the standard choice.

1. Install Containerd

sudo apt update
sudo apt install -y containerd

2. Configure Systemd Cgroup Driver

Generate the default configuration and enable SystemdCgroup so containerd matches Kubernetes’ cgroup management.

sudo mkdir -p /etc/containerd
containerd config default | sudo tee /etc/containerd/config.toml >/dev/null
sudo sed -i 's/SystemdCgroup = false/SystemdCgroup = true/g' /etc/containerd/config.toml

3. Restart and Enable Containerd

sudo systemctl restart containerd
sudo systemctl enable containerd

Step 3: Install Kubernetes Package Tooling

Install kubeadm (cluster bootstrap), kubelet (node agent), and kubectl (command-line tool) on all nodes.

1. Install Dependency Packages

sudo apt update
sudo apt install -y apt-transport-https ca-certificates curl gnupg

2. Add Kubernetes Package Repository

Download the official Kubernetes GPG key and add the repository (adjust version v1.30 if a newer version is desired).

sudo mkdir -p -m 755 /etc/apt/keyrings
curl -fsSL https://pkgs.k8s.io/core:/stable:/v1.30/deb/Release.key | sudo gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg

echo 'deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.30/deb/ /' | sudo tee /etc/apt/sources.list.d/kubernetes.list

3. Install Kubelet, Kubeadm, and Kubectl

sudo apt update
sudo apt install -y kubelet kubeadm kubectl
sudo apt-mark hold kubelet kubeadm kubectl

Step 4: Initialize the Control Plane Node

Execute these commands only on the Control Plane node.

1. Initialize Kubeadm

Run kubeadm init specifying the pod network CIDR block required by your intended network plugin (e.g., 10.244.0.0/16 for Flannel).

sudo kubeadm init --pod-network-cidr=10.244.0.0/16

2. Configure Kubectl for Non-Root User

Copy the administrative kubeconfig file to your regular user account to enable kubectl commands.

mkdir -p $HOME/.kube
sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config

Note: Save the kubeadm join command printed at the end of the initialization output. You will need it to attach worker nodes.

Step 5: Install a Container Network Interface (CNI)

A CNI plugin is required for pod-to-pod communication across nodes. Apply the Flannel overlay network manifest on the Control Plane node.

kubectl apply -f https://github.com/flannel-io/flannel/releases/latest/download/kube-flannel.yml

Step 6: Join Worker Nodes to the Cluster

Run the kubeadm join command saved from Step 4 on each Worker node using sudo.

Example:

sudo kubeadm join <CONTROL_PLANE_IP>:6443 --token <TOKEN> --discovery-token-ca-cert-hash sha256:<HASH>

(If you lose the join command, generate a new token on the control plane node with kubeadm token create --print-join-command)

Step 7: Verify Cluster Status

Run the following command on the Control Plane node to verify that all nodes are connected and operating correctly:

kubectl get nodes

When all nodes show a status of Ready, your Kubernetes cluster installation and configuration is complete.
