Map Network Drives on Login Using pam_mount in Ubuntu

This guide explains how to automatically mount network shares—such as SMB/CIFS or NFS—upon user login in Ubuntu using the pam_mount module. By integrating with the Pluggable Authentication Module (PAM) architecture, pam_mount dynamically mounts assigned remote directories using the user's active session credentials and unmounts them upon logout, eliminating the need to store plaintext passwords in configuration files.

Step 1: Install Required Packages

First, update your package lists and install libpam-mount. If you plan to mount Windows or Samba shares (SMB/CIFS), you will also need the cifs-utils package:

sudo apt update
sudo apt install libpam-mount cifs-utils

For NFS shares, ensure nfs-common is installed instead:

sudo apt install nfs-common

Step 2: Configure PAM Integration

During installation, Ubuntu typically updates PAM configurations automatically. You can verify that the pam_mount module is enabled by running:

sudo pam-auth-update

Ensure that the option for PAM mount is selected with an asterisk [*], then select OK to save and exit.

Step 3: Configure pam_mount.conf.xml

All volume definitions are managed in /etc/security/pam_mount.conf.xml. Open this file in a text editor with administrative privileges:

sudo nano /etc/security/pam_mount.conf.xml

Locate the <!-- Volume definitions --> section and add your mount definition inside the <pam_mount> block.

Example: Mounting an SMB/CIFS Share

To mount an SMB share matching the user's system username to a local folder named NetworkShare in their home directory, insert:

<volume 
    user="*" 
    fstype="cifs" 
    server="nas.local" 
    path="shares/%(USER)" 
    mountpoint="~/NetworkShare" 
    options="vers=3.0,uid=%(USERUID),gid=%(USERGID)" />

Key attributes include:

  • user: Defines which local users this rule applies to. Using * applies it to all users, or you can specify a single username.
  • fstype: The filesystem type (typically cifs for Samba or nfs for NFS).
  • server: The hostname or IP address of the file server.
  • path: The path to the shared folder on the remote server. Variable %(USER) expands to the logged-in username.
  • mountpoint: The local target path where the share will appear.
  • options: Mount parameters. uid=%(USERUID),gid=%(USERGID) ensures the user retains ownership and write permissions over the mounted directory.

Save the file and exit the editor.

Step 4: Create the Local Mount Point

The local mount directory must exist for the process to succeed. For a single user, create the directory inside their home folder:

mkdir -p ~/NetworkShare

If configuring for multiple users, you can ensure each user gets this directory created automatically by adding it to /etc/skel/:

sudo mkdir -p /etc/skel/NetworkShare

Step 5: Test the Configuration

Log out of your current Ubuntu session and log back in using your credentials. Open a terminal and check if the share is active:

df -h

If the share mounted properly, you will see your network location mapped to ~/NetworkShare. If the share does not appear, inspect the system authentication logs to debug potential connectivity or permission errors:

sudo journalctl -u systemd-logind -b
