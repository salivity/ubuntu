Configure Elasticsearch Heap Size on Ubuntu

Configuring the Java Virtual Machine (JVM) heap size is a critical step for optimizing Elasticsearch performance and stability on an Ubuntu system. This guide explains how to properly size your heap, where to locate the configuration files on Ubuntu, and how to apply and verify the new memory settings using standard system administration tools.

Heap Size Rules of Thumb

Before altering any configuration files, determine the appropriate heap size based on two core principles:

  1. Set the minimum and maximum heap sizes to be identical: Setting -Xms (minimum heap) and -Xmx (maximum heap) to the same value prevents the JVM from resizing the heap during runtime, which can cause latency spikes.
  2. Do not exceed 50% of physical RAM: Elasticsearch uses heap memory for internal operations, but the underlying Lucene engine relies heavily on the operating system’s filesystem cache. Leaving at least 50% of system memory free ensures efficient data retrieval.
  3. Stay below the 32 GB threshold: Never allocate more than 31 GB (typically recommended under 30 GB or 31 GB depending on the system) to maintain Compressed Ordinary Object Pointers (Compressed OOPs). Exceeding this limit drops pointer compression and wastes memory.

Step 1: Create a Custom JVM Options File

In modern versions of Elasticsearch (7.x and 8.x) installed via the .deb package on Ubuntu, custom settings should be placed in the /etc/elasticsearch/jvm.options.d/ directory rather than modifying the default /etc/elasticsearch/jvm.options file directly.

Create a new file called heap.options:

sudo nano /etc/elasticsearch/jvm.options.d/heap.options

Step 2: Define Heap Allocation

Add your desired heap size values to this file. For example, to allocate 4 GB of RAM to an Elasticsearch node on an 8 GB Ubuntu server, enter:

-Xms4g
-Xmx4g

If specifying values in megabytes, use the m suffix instead (e.g., -Xms2048m). Save and close the file.

Step 3: Ensure Correct Permissions

Ensure that the newly created file has the proper ownership so the Elasticsearch process can read it:

sudo chown root:elasticsearch /etc/elasticsearch/jvm.options.d/heap.options
sudo chmod 660 /etc/elasticsearch/jvm.options.d/heap.options

Step 4: Restart the Elasticsearch Service

Apply the new memory configuration by restarting the Elasticsearch service via systemctl:

sudo systemctl restart elasticsearch

Verify that the service is running without errors:

sudo systemctl status elasticsearch

Step 5: Verify the New Heap Size

Confirm that Elasticsearch is actively running with the updated JVM parameters using the nodes API:

curl -s -X GET "localhost:9200/_nodes/jvm?pretty" | grep heap_max_in_bytes

Alternatively, inspect the running process directly from the command line:

ps aux | grep elasticsearch | grep -E '\-Xm[sx]'

The output will display the active -Xms and -Xmx values confirming the new configuration is operational.
