Setup HA NFS with DRBD and Pacemaker on Ubuntu

High Availability (HA) NFS eliminates single points of failure in shared storage environments by combining continuous data replication with automated cluster failover. This guide details the process of building an active/passive HA NFS cluster on Ubuntu using Distributed Replicated Block Device (DRBD) for block-level replication, Corosync for cluster membership, and Pacemaker to manage cluster resources, including the virtual IP and file-locking daemons.

1. Prerequisites and Network Preparation

Deploy two identical Ubuntu servers (e.g., node1 with IP 192.168.1.11 and node2 with IP 192.168.1.12). Ensure each node has a secondary, unformatted disk or partition (e.g., /dev/sdb) dedicated to DRBD.

Configure /etc/hosts identically on both nodes:

192.168.1.11 node1
192.168.1.12 node2
192.168.1.100 nfs-vip

2. Install and Configure DRBD

Install the DRBD utilities on both nodes:

sudo apt update
sudo apt install -y drbd-utils

Create the resource configuration file /etc/drbd.d/r0.res on both nodes:

resource r0 {
    protocol C;
    startup {
        wfc-timeout 15;
        degr-wfc-timeout 60;
    }
    net {
        cram-hmac-alg sha1;
        shared-secret "ClusterSecretPass";
    }
    on node1 {
        device /dev/drbd0;
        disk /dev/sdb;
        address 192.168.1.11:7788;
        meta-disk internal;
    }
    on node2 {
        device /dev/drbd0;
        disk /dev/sdb;
        address 192.168.1.12:7788;
        meta-disk internal;
    }
}

Initialize the metadata and bring up the device on both nodes:

sudo drbdadm create-md r0
sudo drbdadm up r0

On node1 only, force the node to be primary and format the device:

sudo drbdadm primary --force r0
sudo mkfs.ext4 /dev/drbd0

Create a mount point on both nodes:

sudo mkdir -p /srv/nfs_share

3. Install NFS Utilities

Install the NFS server packages on both nodes. Once installed, disable systemd from managing the service at boot, as Pacemaker must handle start/stop routines:

sudo apt install -y nfs-kernel-server
sudo systemctl stop nfs-server
sudo systemctl disable nfs-server

Create the export directory configuration in /etc/exports identically on both nodes:

/srv/nfs_share 192.168.1.0/24(rw,sync,no_subtree_check,no_root_squash)

4. Install and Initialize Pacemaker and Corosync

Install Pacemaker, Corosync, and PCS on both nodes:

sudo apt install -y pacemaker corosync pcs

Set a password for the cluster system account (hacluster) on both nodes:

echo "hacluster:StrongClusterPassword" | sudo chpasswd
sudo systemctl enable --now pcsd

Authenticate the cluster from node1:

sudo pcs host auth node1 node2 -u hacluster -p StrongClusterPassword

Create and start the cluster on node1:

sudo pcs cluster setup ha_cluster node1 node2
sudo pcs cluster start --all
sudo pcs cluster enable --all

Disable STONITH (for testing environments without fencing hardware) and adjust quorum handling for a two-node architecture:

sudo pcs property set stonith-enabled=false
sudo pcs property set no-quorum-policy=ignore

5. Configure Pacemaker Cluster Resources

All cluster resources are managed via PCS on node1.

A. DRBD Resource

Configure DRBD as a promotable resource:

sudo pcs resource create drbd_data ocf:linbit:drbd drbd_resource=r0 op monitor interval=15s
sudo pcs resource promotable drbd_data promoted-max=1 promoted-node-max=1 clone-max=2 clone-node-max=1 notify=true

B. Filesystem Resource

Define the filesystem mount for /dev/drbd0:

sudo pcs resource create nfs_fs ocf:heartbeat:Filesystem \
    device="/dev/drbd0" directory="/srv/nfs_share" fstype="ext4" \
    op monitor interval=20s

C. Virtual IP and NFS Daemons

Create the Virtual IP, NFS daemon, and NFS export resources:

sudo pcs resource create virtual_ip ocf:heartbeat:IPaddr2 \
    ip=192.168.1.100 cidr_netmask=24 op monitor interval=10s

sudo pcs resource create nfs_daemon ocf:heartbeat:nfsserver \
    nfs_shared_infodir="/srv/nfs_share/nfsinfo" op monitor interval=30s

sudo pcs resource create nfs_export ocf:heartbeat:exportfs \
    clientspec="192.168.1.0/24" options="rw,sync,no_root_squash" \
    directory="/srv/nfs_share" fsid=1 op monitor interval=10s

D. Resource Grouping and Ordering

Group the dependent services to ensure they migrate together:

sudo pcs resource group add nfs_group virtual_ip nfs_fs nfs_daemon nfs_export

Enforce colocation and start ordering relative to the DRBD master role:

sudo pcs constraint colocation add nfs_group with master drbd_data-clone
sudo pcs constraint order promote drbd_data-clone then start nfs_group

6. Verify and Test Failover

Check the cluster health:

sudo pcs status

Verify that drbd_data-clone is Master on one node, and that virtual_ip, nfs_fs, nfs_daemon, and nfs_export are running on the same node.

To test automatic failover, simulate a node failure by placing the active node into standby:

sudo pcs node standby node1

Run pcs status to verify that node2 assumes the master role and starts all NFS resources. Once verified, return the node to the cluster:

sudo pcs node unstandby node1

Clients can now mount the exported share redundantly using the Virtual IP:

sudo mount -t nfs 192.168.1.100:/srv/nfs_share /mnt
