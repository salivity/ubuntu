Test UDP Packet Loss and Jitter with iPerf3 on Ubuntu

This guide demonstrates how to measure network performance metrics, specifically UDP packet loss and jitter, between two Ubuntu servers using the iperf3 utility. By default, iperf3 measures TCP throughput, but with specific flags, it can generate UDP traffic to evaluate real-time transport reliability. You will learn how to install iperf3, configure one server as a listener, execute the client-side UDP test, and accurately read the resulting jitter and loss statistics.

Step 1: Install iperf3 on Both Servers

Update the package lists and install iperf3 on both your target servers (Server A and Server B) by running:

sudo apt update
sudo apt install iperf3 -y

Step 2: Open the Required Ports

iperf3 uses port 5201 by default. Because UDP tests still require a TCP control connection to exchange test setup parameters, you must allow both TCP and UDP traffic on port 5201 on the receiving server (Server A).

If you are using UFW (Uncomplicated Firewall), run the following on Server A:

sudo ufw allow 5201/tcp
sudo ufw allow 5201/udp

Step 3: Start the iperf3 Server

Designate one server (Server A) as the receiver. Start iperf3 in server mode:

iperf3 -s

The terminal will display:

-----------------------------------------------------------
Server listening on 5201 (test #1)
-----------------------------------------------------------

Step 4: Run the UDP Test from the Client

Log in to the second server (Server B) to initiate the test. To measure UDP metrics, you must specify the target bandwidth; otherwise, iperf3 defaults to a restrictive 1 Mbit/sec limit for UDP.

Run the test using this command (replace SERVER_A_IP with the actual IP address of Server A):

iperf3 -c SERVER_A_IP -u -b 100M -t 30

Key flags explained:

  • -c SERVER_A_IP: Specifies client mode and connects to the target IP.
  • -u: Switches the test protocol to UDP instead of TCP.
  • -b 100M: Sets the target bandwidth (e.g., 100 Mbits/sec). Adjust this to match your testing capacity (e.g., 50M, 1G).
  • -t 30: Sets the duration of the test to 30 seconds.

Step 5: Read Packet Loss and Jitter Results

Once the test completes, iperf3 prints a summary report on both the client and server. Focus on the final lines of the output under the receiver summary on Server B:

[ ID] Interval           Transfer     Bitrate         Jitter    Lost/Total Datagrams
[  5]   0.00-30.00  sec   357 MBytes  99.9 Mbits/sec  0.035 ms  0/45696 (0%)  receiver
  • Jitter: The variation in packet arrival time, displayed in milliseconds (ms). Lower values indicate a more stable connection, which is critical for real-time applications like VoIP and video streaming.
  • Lost/Total Datagrams: Shows the total number of dropped UDP packets alongside the total packets sent, followed by the percentage of packet loss. A non-zero percentage indicates network congestion, hardware buffer overruns, or intermediate link degradation.

Optional: Test the Reverse Direction

To test packet loss and jitter from Server A to Server B without restarting the server daemon, append the -R flag to the client command to run the test in reverse mode:

iperf3 -c SERVER_A_IP -u -b 100M -t 30 -R
