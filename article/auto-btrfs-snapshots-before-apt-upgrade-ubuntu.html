Auto Btrfs Snapshots Before Apt Upgrade Ubuntu

This guide explains how to configure an Ubuntu system with a Btrfs root filesystem to automatically create snapshots before executing package updates or installations via apt. Using Snapper and its integrated APT plugin, you can maintain automatic "pre" and "post" snapshots for every software modification, creating a reliable safety net that allows you to easily restore a working system state if an update introduces breaking changes.

Prerequisites

Ensure your root partition (/) is formatted with Btrfs. You can verify this by running:

df -T /

The output should show btrfs under the Type column.

Step 1: Install Snapper and the APT Integration Plugin

Snapper is a robust Btrfs management utility originally developed by openSUSE, and Ubuntu includes packages for Snapper along with a hook for APT:

sudo apt update
sudo apt install snapper snapper-apt

The snapper-apt package installs an APT configuration hook located at /etc/apt/apt.conf.d/80snapper that triggers snapshot creation automatically during apt operations.

Step 2: Configure Snapper for the Root Subvolume

Create a new configuration profile named root targeting the root mount point:

sudo snapper -c root create-config /

This command generates a configuration file at /etc/snapper/configs/root and creates a subvolume at /.snapshots where metadata and snapshots are tracked.

If your installation already contains a /.snapshots directory as a regular folder, the command may fail. To resolve this, remove the existing directory and re-run the configuration:

sudo rm -rf /.snapshots
sudo snapper -c root create-config /

Step 3: Adjust Permissions and Retention Policies

By default, only the root user can view snapshots. To allow your user account to run Snapper commands without sudo, edit the configuration file:

sudo nano /etc/snapper/configs/root

Modify the following lines to grant permissions and adjust retention:

  1. Allow non-root access:

    ALLOW_USERS="your_username"
SYNC_ACL="yes"

  2. Adjust cleanup limits: To prevent snapshots from consuming all available disk space, configure how many snapshots to keep. Modify the number cleanup limits as needed:

    NUMBER_MIN_AGE="1800"
NUMBER_LIMIT="10"
NUMBER_LIMIT_IMPORTANT="5"

Save and exit the file. Apply the new permissions to the snapshot directory:

sudo chmod 750 /.snapshots

Step 4: Enable Automatic Cleanup Timers

Snapper uses systemd timers to periodically remove old snapshots based on the limits defined in your configuration:

sudo systemctl enable --now snapper-cleanup.timer

Step 5: Test the APT Snapshot Automation

Run a simulated package installation or update to trigger the hook:

sudo apt install --reinstall bzip2

Once the process finishes, list the snapshots to confirm that both a "pre" snapshot (captured before the package was altered) and a "post" snapshot (captured after completion) were taken:

snapper -c root list

The output will display snapshot IDs, types (pre, post, or single), and a description showing the exact apt command executed.
