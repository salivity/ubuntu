Deploying a HashiCorp Nomad Cluster on Ubuntu

This guide provides a step-by-step walkthrough for deploying a HashiCorp Nomad cluster on Ubuntu to schedule and manage containerized and non-containerized applications. You will learn how to install Nomad, configure dedicated server and client nodes, establish cluster communication, verify node health, and submit a basic application job specification to confirm operational readiness.

Prerequisites

  • At least two Ubuntu instances (one designated as a Nomad server, one designated as a Nomad client).
  • Root or sudo access on all instances.
  • Network connectivity between instances with ports 4646 (HTTP API/UI), 4647 (RPC), and 4648 (Serf gossip) open.

Step 1: Install Nomad on All Nodes

Run the following commands on every Ubuntu node (both servers and clients) to add the official HashiCorp package repository and install Nomad.

# Update package lists and install prerequisite utilities
sudo apt-get update && sudo apt-get install -y wget gpg coreutils

# Add the HashiCorp GPG key
wget -O- https://apt.releases.hashicorp.com/gpg | sudo gpg --dearmor -o /usr/share/keyrings/hashicorp-archive-keyring.gpg

# Add the official HashiCorp Linux repository
echo "deb [signed-by=/usr/share/keyrings/hashicorp-archive-keyring.gpg] https://apt.releases.hashicorp.com $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/hashicorp.list

# Update package lists and install Nomad
sudo apt-get update && sudo apt-get install -y nomad

Step 2: Configure the Server Node

The server node handles scheduling, evaluates job specifications, and manages cluster state.

  1. Open /etc/nomad.d/nomad.hcl on your server instance:
sudo nano /etc/nomad.d/nomad.hcl
  1. Replace the contents with the following configuration (replace <SERVER_IP> with the private IP address of the server node):
datacenter = "dc1"
data_dir   = "/opt/nomad/data"
bind_addr  = "0.0.0.0"

server {
  enabled          = true
  bootstrap_expect = 1
}

advertise {
  http = "<SERVER_IP>:4646"
  rpc  = "<SERVER_IP>:4647"
  serf = "<SERVER_IP>:4648"
}

Note: For production environments, configure bootstrap_expect = 3 or 5 across multiple server nodes for high availability.

  1. Start and enable the Nomad service:
sudo systemctl enable --now nomad

Step 3: Configure the Client Node

Client nodes register with servers and execute assigned task groups. If you plan to run containerized workloads, install Docker on the client node first:

sudo apt-get install -y docker.io
sudo systemctl enable --now docker
  1. Open /etc/nomad.d/nomad.hcl on your client instance:
sudo nano /etc/nomad.d/nomad.hcl
  1. Replace the contents with the following configuration (replace <SERVER_IP> with the server node's IP address and <CLIENT_IP> with the client node's IP):
datacenter = "dc1"
data_dir   = "/opt/nomad/data"
bind_addr  = "0.0.0.0"

client {
  enabled = true
  servers = ["<SERVER_IP>:4647"]
}

advertise {
  http = "<CLIENT_IP>:4646"
  rpc  = "<CLIENT_IP>:4647"
  serf = "<CLIENT_IP>:4648"
}
  1. Start and enable the Nomad service on the client:
sudo systemctl enable --now nomad

Step 4: Verify Cluster Status

Run verification commands from the server node to ensure the nodes have joined and are communicating properly.

Check the server members:

nomad server members

Check the registered client nodes:

nomad node status

Both commands should return the nodes with a ready or alive state. You can also access the Nomad Web UI by navigating to http://<SERVER_IP>:4646 in your web browser.

Step 5: Deploy a Test Application

To verify that the orchestrator is functioning correctly, deploy a simple HTTP application using Docker.

  1. Generate an example job file:
nomad job init-example http-echo.nomad
  1. Alternatively, create a file named http-echo.nomad:
job "http-echo" {
  datacenters = ["dc1"]
  type        = "service"

  group "web" {
    count = 1

    network {
      port "http" {
        to = 5678
      }
    }

    task "server" {
      driver = "docker"

      config {
        image = "hashicorp/http-echo:latest"
        args  = ["-text", "Nomad cluster deployed successfully!", "-listen", ":5678"]
        ports = ["http"]
      }

      resources {
        cpu    = 100
        memory = 64
      }
    }
  }
}
  1. Run the job:
nomad job run http-echo.nomad
  1. Check the deployment status:
nomad job status http-echo

Once the allocation status shows running, the Nomad cluster is fully operational and capable of scheduling container workloads across your Ubuntu nodes.
