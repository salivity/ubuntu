How to Publish an LXD Container as an Image

Publishing a modified LXD container as a reusable image template allows you to capture configurations, installed packages, and custom files to quickly deploy identical container instances. This article covers the exact command required to export an existing container into the local LXD image store, the recommended preparation steps, and how to verify and deploy new instances using your newly generated template in Ubuntu.

The Command: lxc publish

The primary command used to convert a modified LXD container into a reusable image is lxc publish.

The standard syntax is:

lxc publish <container_name> --alias <new_image_name>

When executed, LXD creates a compressed image tarball from the specified container or snapshot and registers it directly into your local image repository.

Step-by-Step Guide

1. Prepare and Stop the Container

While you can publish a running container or a snapshot, stopping the container ensures all processes are halted, preventing filesystem inconsistencies.

lxc stop my-container

(Optional) If you must keep the container running during this process, take a snapshot and publish the snapshot instead:

lxc snapshot my-container snapshot-name
lxc publish my-container/snapshot-name --alias my-custom-image

2. Publish the Container as an Image

Run the publish command with an alias to easily identify your image template:

lxc publish my-container --alias my-custom-image

You can also attach useful metadata such as a description or versioning:

lxc publish my-container --alias my-custom-image description="Base Ubuntu with NGINX pre-configured"

3. Verify the Created Image

Check your local image store to confirm the template is available:

lxc image list

Your new image will appear in the output with its assigned alias, fingerprint, architecture, and size.

4. Launch a New Container from the Template

Once published, you can instantiate any number of new containers from this template:

lxc launch my-custom-image new-instance-01

The new instance will immediately boot with all the packages, configurations, and modifications present in the original template container.
