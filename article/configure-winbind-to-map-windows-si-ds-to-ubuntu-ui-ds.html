Configure Winbind to Map Windows SIDs to Ubuntu UIDs

This guide outlines how to configure the Winbind service on Ubuntu to translate Active Directory Security Identifiers (SIDs) into local Linux User Identifiers (UIDs) and Group Identifiers (GIDs). By leveraging Samba's idmap_rid or idmap_autorid backends, Ubuntu can deterministically map Windows SIDs to unique, consistent POSIX IDs without requiring custom schema modifications inside Active Directory.

1. Install Required Packages

Update your local package index and install Samba, Winbind, and the associated Name Service Switch (NSS) and PAM libraries:

sudo apt update
sudo apt install samba winbind libnss-winbind libpam-winbind krb5-user

During installation, the Kerberos prompt will ask for your default realm. Enter your fully qualified Active Directory realm name in uppercase (e.g., EXAMPLE.COM).

2. Configure Samba and Winbind ID Mapping

Edit the primary Samba configuration file located at /etc/samba/smb.conf.

Open the file:

sudo nano /etc/samba/smb.conf

Under the [global] section, configure the domain settings and ID mapping backend. The rid backend is recommended because it maps SIDs directly to mathematical UIDs based on the user's relative identifier (RID), ensuring identical UIDs across all Linux clients joined to the domain.

Add or update the following configuration:

[global]
   workgroup = EXAMPLE
   security = ADS
   realm = EXAMPLE.COM

   # Winbind settings
   winbind use default domain = true
   winbind refresh tickets = true
   winbind offline logon = false
   winbind enum users = yes
   winbind enum groups = yes

   # Default allocation for local/built-in IDs
   idmap config * : backend = tdb
   idmap config * : range = 3000-7999

   # SID to UID mapping for the domain using the RID backend
   idmap config EXAMPLE : backend = rid
   idmap config EXAMPLE : range = 10000-999999

Note: Ensure the range 10000-999999 does not overlap with local Linux system accounts or the fallback range 3000-7999.

3. Update the Name Service Switch Configuration

To allow the operating system to query Winbind for user and group resolution, update /etc/nsswitch.conf.

Open the file:

sudo nano /etc/nsswitch.conf

Modify the passwd and group lines to include winbind:

passwd:         files systemd winbind
group:          files [SUCCESS=merge] systemd winbind
shadow:         files
gshadow:        files

4. Join the Ubuntu Host to the Active Directory Domain

Verify that your system can resolve the domain controller, obtain a Kerberos ticket, and join the domain using domain administrative credentials:

sudo net ads join -U Administrator

Upon success, you will see a message confirming the host has joined the realm.

5. Restart Services

Restart the Samba and Winbind daemons to apply the configuration:

sudo systemctl restart smbd nmbd winbind
sudo systemctl enable winbind

6. Verify SID to UID Resolution

Test Winbind's ability to communicate with Active Directory and resolve identities.

Check that Winbind lists domain users:

wbinfo -u

Convert a known Windows domain username to a SID:

wbinfo -n "username"

Resolve the generated SID directly into a Linux UID:

wbinfo -s <SID>
wbinfo -S <SID>

Verify that the Ubuntu system natively recognizes the user and assigns the mapped UID:

id username

If configured properly, the id command will output the UID, primary GID, and associated group memberships directly derived from the Windows SID using your specified ID map range.
