Limit SSH Access to a Specific Subnet in Ubuntu

Restricting SSH access to a specific subnet enhances server security by blocking connection attempts from unauthorized IP addresses across the internet. This guide explains how to configure the OpenSSH daemon directly on Ubuntu to allow access exclusively from a designated network range using built-in configuration directives.

Step 1: Open the SSH Daemon Configuration

Connect to your Ubuntu server and open the primary SSH daemon configuration file in a text editor with administrative privileges:

sudo nano /etc/ssh/sshd_config

Alternatively, on modern Ubuntu installations, you can create a dedicated configuration snippet in the /etc/ssh/sshd_config.d/ directory:

sudo nano /etc/ssh/sshd_config.d/subnet-restriction.conf

Step 2: Define Subnet Access Rules

You can restrict access to a subnet using either the AllowUsers directive or a Match Address block. Replace 192.168.1.0/24 with your target subnet in CIDR notation.

Method A: Using AllowUsers (Recommended for simplicity)

To permit all valid system users from a specific subnet, add:

AllowUsers *@192.168.1.0/24

To restrict access so that only a specific username (such as ubuntu) can connect from that subnet:

AllowUsers ubuntu@192.168.1.0/24

Method B: Using a Match Address Block

If you want to deny authentication methods to any connection not originating from your designated subnet, append this block to the bottom of the file:

Match Address *,!192.168.1.0/24
    AuthenticationMethods none

This directive checks incoming connections and disables all authentication methods for any IP address outside the 192.168.1.0/24 range.

Step 3: Test the Configuration

Before applying changes, validate the configuration file for syntax errors to avoid locking yourself out of the server:

sudo sshd -t

If the command returns no output, the syntax is valid. If errors appear, reopen the file and correct them.

Step 4: Restart the SSH Service

Apply the new restrictions by restarting the SSH daemon:

sudo systemctl restart ssh

Keep your current terminal session open and test the connection from a new terminal window to confirm that access is permitted from within the subnet and rejected from outside it.
