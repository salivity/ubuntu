Deploy High Availability PostgreSQL with Patroni on Ubuntu

This guide provides a direct, step-by-step walkthrough for deploying a production-ready, highly available PostgreSQL cluster on Ubuntu using Patroni and etcd. By implementing Patroni as an orchestration template and etcd as the Distributed Configuration Store (DCS), your database infrastructure achieves automatic failover, consensus-driven leader election, and resilient state synchronization across multiple nodes.

Prerequisites

To build a fault-tolerant cluster, provision three Ubuntu 22.04 or 24.04 LTS servers to prevent split-brain scenarios:

  • Node 1: 192.168.1.11
  • Node 2: 192.168.1.12
  • Node 3: 192.168.1.13

Each node requires root or sudo privileges. Ensure firewalls allow communication across ports 2379/2380 (etcd), 5432 (PostgreSQL), and 8008 (Patroni REST API).

Step 1: Install and Configure etcd

etcd manages the cluster state and ensures consensus during leader election. Run the following on all three nodes to install etcd:

sudo apt update
sudo apt install -y etcd

Edit /etc/default/etcd on each node to define the cluster endpoints. Replace the node-specific IP addresses accordingly:

ETCD_NAME="node1"
ETCD_DATA_DIR="/var/lib/etcd/default.etcd"
ETCD_LISTEN_QUOTES_URLS="http://0.0.0.0:2379"
ETCD_LISTEN_PEER_URLS="http://0.0.0.0:2380"
ETCD_INITIAL_ADVERTISE_PEER_URLS="http://192.168.1.11:2380"
ETCD_ADVERTISE_CLIENT_URLS="http://192.168.1.11:2379"
ETCD_INITIAL_CLUSTER="node1=http://192.168.1.11:2380,node2=http://192.168.1.12:2380,node3=http://192.168.1.13:2380"
ETCD_INITIAL_CLUSTER_TOKEN="etcd-cluster-token"
ETCD_INITIAL_CLUSTER_STATE="new"

Restart and enable etcd:

sudo systemctl restart etcd
sudo systemctl enable etcd

Verify cluster health from any node:

etcdctl cluster-health

Step 2: Install PostgreSQL and Patroni

Install PostgreSQL and required dependencies on all three nodes:

sudo apt install -y postgresql-common
sudo install -d /usr/share/postgresql-common/pgdg
sudo curl -o /usr/share/postgresql-common/pgdg/apt.postgresql.org.asc --fail https://www.postgresql.org/media/keys/ACCC4CF8.asc
sudo sh -c 'echo "deb [signed-by=/usr/share/postgresql-common/pgdg/apt.postgresql.org.asc] http://apt.postgresql.org/pub/repos/apt $(lsb_release -cs)-pgdg main" > /etc/apt/sources.list.d/pgdg.list'

sudo apt update
sudo apt install -y postgresql-16 python3-pip python3-psycopg2
sudo pip3 install patroni[etcd3]

Stop and disable the default PostgreSQL service, as Patroni will manage the PostgreSQL process:

sudo systemctl stop postgresql
sudo systemctl disable postgresql

Step 3: Configure Patroni

Create a configuration file at /etc/patroni/patroni.yml on each node. Ensure you adjust the node name and IP addresses for each host:

scope: pg-cluster
namespace: /service
name: node1

restapi:
  listen: 192.168.1.11:8008
  connect_address: 192.168.1.11:8008

etcd3:
  hosts:
    - 192.168.1.11:2379
    - 192.168.1.12:2379
    - 192.168.1.13:2379

bootstrap:
  dcs:
    ttl: 30
    loop_wait: 10
    retry_timeout: 10
    maximum_lag_on_failover: 1048576
    postgresql:
      use_pg_rewind: true
      parameters:
        max_connections: 100
        wal_level: replica
        hot_standby: "on"
        max_wal_senders: 10
        max_replication_slots: 10

  initdb:
    - encoding: UTF8
    - data-checksums

  pg_hba:
    - host replication replicator 192.168.1.0/24 md5
    - host all all 0.0.0.0/0 md5

postgresql:
  listen: 0.0.0.0:5432
  connect_address: 192.168.1.11:5432
  data_dir: /var/lib/postgresql/16/main
  bin_dir: /usr/lib/postgresql/16/bin
  pgpass: /var/lib/postgresql/.pgpass
  authentication:
    replication:
      username: replicator
      password: ReplicatePassword123
    superuser:
      username: postgres
      password: SuperuserPassword123

tags:
  nofailover: false
  noloadbalance: false
  clonefrom: false
  nosync: false

Set appropriate ownership:

sudo mkdir -p /etc/patroni
sudo chown -R postgres:postgres /etc/patroni
sudo chown -R postgres:postgres /var/lib/postgresql

Step 4: Create a Systemd Service for Patroni

Create the systemd service file on all nodes at /etc/systemd/system/patroni.service:

[Unit]
Description=Patroni Orchestrator for PostgreSQL
After=network.target etcd.service
Requires=etcd.service

[Service]
Type=simple
User=postgres
Group=postgres
ExecStart=/usr/local/bin/patroni /etc/patroni/patroni.yml
ExecReload=/bin/kill -s HUP $MAINPID
KillMode=process
TimeoutSec=30
Restart=no

[Install]
WantedBy=multi-user.target

Reload systemd, enable, and start Patroni:

sudo systemctl daemon-reload
sudo systemctl enable patroni
sudo systemctl start patroni

Start the service on Node 1 first so it bootstraps the database, followed by Node 2 and Node 3 to join as replicas.

Step 5: Verify Cluster Topology

Check the status of the cluster using patronictl:

patronictl -c /etc/patroni/patroni.yml list

The output will display the primary node (Leader), replicas, their running states, and replication lag.

To test automatic failover:

sudo systemctl stop patroni # Run on the current Leader node

Run patronictl list on any surviving node to verify that an operational standby node has been automatically promoted to the new Leader.

Step 6: Route Traffic Using HAProxy

To expose a unified database endpoint, deploy HAProxy on an independent load-balancer node or across client machines:

sudo apt install -y haproxy

Append the configuration to /etc/haproxy/haproxy.cfg:

frontend pg_primary_in
    bind *:5000
    default_backend pg_primary_backend

backend pg_primary_backend
    option httpchk GET /primary
    http-check expect status 200
    default-server inter 3s fall 3 rise 2 on-marked-down shutdown-sessions
    server node1 192.168.1.11:5432 maxconn 100 check port 8008
    server node2 192.168.1.12:5432 maxconn 100 check port 8008
    server node3 192.168.1.13:5432 maxconn 100 check port 8008

frontend pg_replica_in
    bind *:5001
    default_backend pg_replica_backend

backend pg_replica_backend
    option httpchk GET /replica
    http-check expect status 200
    default-server inter 3s fall 3 rise 2
    server node1 192.168.1.11:5432 maxconn 100 check port 8008
    server node2 192.168.1.12:5432 maxconn 100 check port 8008
    server node3 192.168.1.13:5432 maxconn 100 check port 8008

Restart HAProxy:

sudo systemctl restart haproxy

Applications can now direct write traffic to port 5000 (automatically routed to the Patroni leader) and read-only queries to port 5001 (distributed across replicas).
