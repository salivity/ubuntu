Sync Passwords Across Ubuntu Using Pass Git Integration

The pass utility, known as the standard Unix password manager, uses Git integration to provide a secure, decentralized method for syncing encrypted credentials across multiple Ubuntu machines. By wrapping standard Git version-control commands directly into its command-line interface, pass tracks changes to your password store, automatically creates commits for additions or edits, and allows you to push and pull your encrypted data through remote repositories. This article explains the technical mechanics behind this Git integration, its security architecture, and how to effectively manage password synchronization on Ubuntu.

How the Git Integration Functions

At its foundation, pass organizes passwords as individual GPG-encrypted files inside a hidden directory located at ~/.password-store. When the Git integration is enabled, this directory is initialized as a local Git repository.

Every time a password is created, edited, generated, or deleted using the pass CLI, the utility automatically stages the affected .gpg file and generates a Git commit with a descriptive message (e.g., "Add given password for email/example to store.").

You can interact directly with the underlying repository by prefixing standard Git commands with pass git. For example, running pass git status or pass git log executes those operations directly inside ~/.password-store.

Security Architecture in Synchronization

The primary advantage of synchronizing pass via Git is that the remote repository never handles unencrypted data.

  1. At-Rest Encryption: Passwords are encrypted locally on your Ubuntu machine using asymmetric GPG keys before Git ever touches them.
  2. Safe Remote Hosting: Because Git only synchronizes the encrypted .gpg files, you can safely host your password repository on remote platforms such as GitHub, GitLab, or a private self-hosted Git server over SSH.
  3. Integrity and Auditability: Git's cryptographic commit hashing guarantees that no password files are modified or tampered with in transit without detection. Furthermore, Git maintains a complete historical record of all credential additions, modifications, and deletions.

Setting Up Synchronization on Ubuntu

To synchronize credentials between two Ubuntu systems, both machines must have pass, git, and gnupg installed via apt:

sudo apt update && sudo apt install pass git gnupg

1. Initialize Git on the Primary Machine

If you have an existing password store, initialize the Git repository and link it to an empty private remote repository:

pass git init
pass git remote add origin git@github.com:username/password-store.git
pass git push -u origin master

2. GPG Key Distribution

Because each file is encrypted with a specific GPG key, the secondary Ubuntu machine must possess the appropriate GPG private key to decrypt passwords, or its public key must be added as an authorized recipient via pass init.

To use the same private key, export it from the primary machine and import it onto the secondary machine:

# On primary machine
gpg --export-secret-keys --armor KEY_ID > private.key

# Transfer securely to secondary machine, then import
gpg --import private.key

3. Cloning to the Secondary Machine

On the target Ubuntu system, clone the remote password store directly into your local configuration:

git clone git@github.com:username/password-store.git ~/.password-store

Once cloned, the secondary machine can immediately read passwords using pass <path> or insert new ones.

Ongoing Synchronization Workflow

Once the initial setup is complete, maintaining parity across your Ubuntu machines relies on standard distributed version-control practices:

  • Pushing Updates: When you add or change a credential on one system, upload the automated commit using: 
    pass git push
  • Pulling Updates: Before querying or adding passwords on another system, fetch the latest changes using: 
    pass git pull

If simultaneous modifications create merge conflicts, standard Git conflict resolution applies. However, because pass stores each entry in its own isolated .gpg file within a filesystem hierarchy, file-level merge conflicts are rare compared to traditional monolithic database password managers.
