Adjust OOM Score to Prevent Process Kills in Ubuntu

When a system runs dangerously low on memory, the Ubuntu Linux kernel invokes the Out of Memory (OOM) Killer to terminate processes and protect system stability. This article explains how the kernel assigns memory priority and provides direct, actionable methods to adjust a critical process's oom_score_adj value. By lowering this value—either temporarily via the /proc virtual filesystem or permanently through systemd service configurations—you can protect vital applications like databases or web servers from unexpected termination.

How the OOM Score Works

The Linux kernel tracks each running process with two primary metrics:

  • oom_score: A calculated value between 0 and 1000 representing the likelihood of the process being selected by the OOM Killer. A higher value indicates a higher probability of termination.
  • oom_score_adj: An adjustment value ranging from -1000 to 1000. Setting this value to -1000 grants the process complete immunity from the OOM Killer, while 1000 marks it as the first candidate for termination.

Method 1: Check and Adjust a Running Process Temporarily

This approach takes effect immediately for an existing process by modifying the /proc interface. Changes revert once the process restarts.

1. Find the Process ID (PID)

Identify the PID of the target service:

pgrep -f process_name

2. View the Current Scores

Check the current calculated score and its adjustment factor:

cat /proc/<PID>/oom_score
cat /proc/<PID>/oom_score_adj

3. Apply the New Score

Write the desired adjustment value into /proc/<PID>/oom_score_adj using root privileges. To make the process immune to OOM termination:

echo -1000 | sudo tee /proc/<PID>/oom_score_adj

To give it a lower priority without total immunity, use a smaller negative value, such as -500:

echo -500 | sudo tee /proc/<PID>/oom_score_adj

Confirm the change:

cat /proc/<PID>/oom_score_adj

Method 2: Configure Persistent Protection Using systemd

For services managed by systemd, apply the adjustment permanently so that restarts do not wipe out your settings.

1. Edit the Service Configuration

Create a drop-in override for your service (for example, nginx):

sudo systemctl edit nginx

2. Add the OOMScoreAdjust Directive

In the editor that opens, insert the following block:

[Service]
OOMScoreAdjust=-1000

Save and exit the editor. Systemd will automatically store this configuration in /etc/systemd/system/<service_name>.service.d/override.conf.

3. Apply Changes

Reload the systemd manager configuration and restart the service:

sudo systemctl daemon-reload
sudo systemctl restart nginx

4. Verify the New Score

Confirm that the new setting was applied to the freshly spawned PID:

cat /proc/$(pgrep -f nginx | head -n 1)/oom_score_adj

The output should return -1000.

Important Operational Considerations

  • System Hangs: Assigning -1000 to high-memory processes eliminates the kernel's safety valve. If the system completely exhausts physical RAM and swap space without being able to terminate the offending process, the entire kernel may freeze (kernel panic).
  • Permission Limits: Unprivileged users cannot lower oom_score_adj below 0. Root privileges are strictly required to protect processes with negative values.
