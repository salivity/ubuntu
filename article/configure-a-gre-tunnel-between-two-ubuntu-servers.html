Configure a GRE Tunnel Between Two Ubuntu Servers

Setting up a Generic Routing Encapsulation (GRE) tunnel between two Ubuntu servers allows you to route network packets over an existing public or private IP network by encapsulating them inside IP packets. This guide outlines the complete step-by-step process for configuring a functional and persistent GRE tunnel between two remote Ubuntu systems, covering kernel module setup, temporary interface creation, Netplan configuration for persistence, and connectivity verification.

Scenario Assumptions

To follow this guide, assume the following network configuration details:

  • Server A (Local):
    • Public IP: 203.0.113.1
    • GRE Tunnel IP: 10.0.0.1/30
  • Server B (Remote):
    • Public IP: 198.51.100.1
    • GRE Tunnel IP: 10.0.0.2/30

Step 1: Enable the GRE Kernel Module

Before creating the tunnel, ensure the GRE kernel module (ip_gre) is loaded on both servers.

  1. Load the module immediately:

    sudo modprobe ip_gre

  2. Ensure the module loads automatically on boot:

    echo "ip_gre" | sudo tee -a /etc/modules

Step 2: Configure UFW (Firewall)

GRE uses IP protocol number 47 (not TCP/UDP port 47). Ensure your firewall allows GRE traffic on both servers.

If you use UFW, allow GRE traffic from the remote server's public IP:

On Server A:

sudo ufw allow proto gre from 198.51.100.1

On Server B:

sudo ufw allow proto gre from 203.0.113.1

Step 3: Temporary Tunnel Setup (Using ip CLI)

You can create a temporary tunnel using the ip command to test functionality before making changes persistent.

On Server A:

sudo ip tunnel add gre1 mode gre remote 198.51.100.1 local 203.0.113.1 ttl 255
sudo ip addr add 10.0.0.1/30 dev gre1
sudo ip link set gre1 up

On Server B:

sudo ip tunnel add gre1 mode gre remote 203.0.113.1 local 198.51.100.1 ttl 255
sudo ip addr add 10.0.0.2/30 dev gre1
sudo ip link set gre1 up

Step 4: Permanent Tunnel Setup (Using Netplan)

Ubuntu uses Netplan for network management. Defining the tunnel in Netplan ensures the configuration survives system reboots.

  1. Open or create a Netplan configuration file on both servers (e.g., /etc/netplan/60-gre-tunnel.yaml).

Configuration for Server A:

network:
  version: 2
  tunnels:
    gre1:
      mode: gre
      local: 203.0.113.1
      remote: 198.51.100.1
      addresses:
        - 10.0.0.1/30

Configuration for Server B:

network:
  version: 2
  tunnels:
    gre1:
      mode: gre
      local: 198.51.100.1
      remote: 203.0.113.1
      addresses:
        - 10.0.0.2/30

  1. Set proper permissions for the Netplan file on both servers:

    sudo chmod 600 /etc/netplan/60-gre-tunnel.yaml

  2. Test and apply the configuration:

    sudo netplan try
sudo netplan apply

Step 5: Verify the Tunnel

  1. Check Interface Status: Run ip link show gre1 to confirm that the gre1 interface is active and shows the state UP.

  2. Test Internal Connectivity:

    • From Server A, ping Server B's tunnel IP: 
      ping -c 4 10.0.0.2
    • From Server B, ping Server A's tunnel IP: 
      ping -c 4 10.0.0.1

If the pings receive successful replies, the GRE tunnel is successfully configured and routing traffic between the two Ubuntu servers.
