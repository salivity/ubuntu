SSSD Credential Caching for Offline Ubuntu Logins

The System Security Services Daemon (SSSD) enables Ubuntu systems to authenticate users against remote identity providers—such as Active Directory, FreeIPA, or OpenLDAP—and allows those users to log in even when the system is disconnected from the network. By acting as a mediator between local system authentication subsystems and remote directory services, SSSD securely caches credentials and identity metadata locally, ensuring seamless access for mobile workforces and during network outages.

How SSSD Offline Authentication Works

When an Ubuntu system is connected to the network, SSSD intercepts login requests routed through Pluggable Authentication Modules (PAM) and Name Service Switch (NSS). During a successful online authentication:

  1. Remote Verification: SSSD contacts the remote identity provider to verify the user’s credentials and retrieve their identity attributes (such as UID, GID, group memberships, and shell permissions).
  2. Local Caching: SSSD saves these identity attributes and stores a salted, cryptographic hash of the user’s password in its local database files, typically located in /var/lib/sss/db/ using the LDB format.
  3. State Tracking: SSSD continuously monitors the reachability of the remote servers. If network requests fail or time out, SSSD transitions into an offline state.

When the system goes offline, the login process changes:

  1. Interception: A user attempts to authenticate locally (via console, SSH, or a display manager like GDM).
  2. PAM/NSS Query: PAM invokes the pam_sss.so module to verify the password, while NSS queries SSSD for the user's account details.
  3. Cache Validation: Because the identity provider is unreachable, SSSD compares the hash of the supplied password against the locally cached hash. It also reads the cached user and group metadata to construct the user's local session.
  4. Session Creation: If the password matches and any cached access-control policies are satisfied, the login succeeds without reaching out to the remote server.

Key SSSD Configuration for Offline Support

On Ubuntu, SSSD behavior is governed by the /etc/sssd/sssd.conf configuration file. Credential caching relies on several core directives within the domain configuration section:

  • cache_credentials = true: Explicitly instructs SSSD to cache user credentials locally upon successful online logins.
  • offline_credentials_expiration: Defines the number of days cached credentials remain valid while the machine remains offline, preventing indefinitely stale access.
  • account_cache_expiration: Controls how long identity data (such as group memberships and user properties) persists before requiring synchronization with the remote directory.

Security Safeguards

To prevent tampering and unauthorized access to cached data:

  • The /etc/sssd/sssd.conf file strictly requires 0600 permissions and ownership by root:root; otherwise, the SSSD service refuses to start.
  • Database files in /var/lib/sss/db/ are restricted to root access.
  • Cached passwords are stored exclusively as strong one-way cryptographic hashes, ensuring that plain-text passwords are never recoverable from disk.
