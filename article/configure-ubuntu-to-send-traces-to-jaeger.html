Configure Ubuntu to Send Traces to Jaeger

This guide explains how to configure an Ubuntu server to capture and forward application telemetry to a Jaeger backend using the OpenTelemetry Collector. By installing the collector as a system service, mapping incoming trace traffic from your applications, and forwarding it via standard OTLP (OpenTelemetry Protocol), you create a reliable, production-ready distributed tracing pipeline on your Linux system.

Prerequisites

  • An Ubuntu 20.04 or 22.04 LTS server with sudo privileges.
  • An accessible Jaeger backend instance (with OTLP gRPC port 4317 or HTTP port 4318 open).
  • Basic networking access between the Ubuntu server and the Jaeger host.

Step 1: Install the OpenTelemetry Collector

The OpenTelemetry Collector receives, processes, and exports telemetry data. The contrib distribution provides full support for Jaeger and OTLP.

  1. Update your system package index and install curl:

    sudo apt update && sudo apt install -y curl

  2. Download the latest OpenTelemetry Collector Contrib .deb package (replace version as needed):

    VERSION="0.96.0"
curl -LO "https://github.com/open-telemetry/opentelemetry-collector-releases/releases/download/v${VERSION}/otelcol-contrib_${VERSION}_linux_amd64.deb"

  3. Install the package using dpkg:

    sudo dpkg -i otelcol-contrib_${VERSION}_linux_amd64.deb

Step 2: Configure the Collector for Jaeger

The configuration file defines how data enters the collector and where it is sent.

  1. Open the configuration file in a text editor:

    sudo nano /etc/otelcol-contrib/config.yaml

  2. Replace the existing content with the following configuration. Replace jaeger-server.example.com:4317 with the actual IP address or hostname and port of your Jaeger endpoint:

    receivers:
  otlp:
    protocols:
      grpc:
        endpoint: 0.0.0.0:4317
      http:
        endpoint: 0.0.0.0:4318

processors:
  batch:
    timeout: 1s
    send_batch_size: 1024

exporters:
  otlp:
    endpoint: "jaeger-server.example.com:4317"
    tls:
      insecure: true

service:
  pipelines:
    traces:
      receivers: [otlp]
      processors: [batch]
      exporters: [otlp]

    Note: If your Jaeger instance uses TLS certificates, change insecure: true to insecure: false and specify ca_file path under tls.

  3. Save the file and exit the editor.

Step 3: Start and Enable the Collector Service

  1. Start the service and configure it to launch automatically on system boot:

    sudo systemctl restart otelcol-contrib
sudo systemctl enable otelcol-contrib

  2. Verify that the service is running without errors:

    sudo systemctl status otelcol-contrib

  3. Confirm that the collector is listening locally on ports 4317 (gRPC) and 4318 (HTTP):

    sudo ss -tulpn | grep -E '4317|4318'

Step 4: Configure Your Applications

Applications running on the Ubuntu server must be pointed to the local collector instance using OpenTelemetry SDKs or agent exporters.

Set the standard OpenTelemetry environment variables in your application environment or service definition (such as /etc/environment or your application's systemd unit):

# Set the application name in Jaeger
export OTEL_SERVICE_NAME="my-ubuntu-service"

# Direct traces to the local OpenTelemetry Collector
export OTEL_EXPORTER_OTLP_ENDPOINT="http://127.0.0.1:4317"
export OTEL_EXPORTER_OTLP_PROTOCOL="grpc"

If your application uses HTTP instead of gRPC, update the configuration accordingly:

export OTEL_EXPORTER_OTLP_ENDPOINT="http://127.0.0.1:4318"
export OTEL_EXPORTER_OTLP_PROTOCOL="http/protobuf"

Step 5: Verify Trace Delivery

  1. Generate trace traffic by starting your application and triggering requests.

  2. Check the OpenTelemetry Collector logs to ensure spans are being received and processed:

    sudo journalctl -u otelcol-contrib -f

  3. Open your Jaeger UI in a browser, select your application name from the Service dropdown, and click Find Traces to view incoming spans.
