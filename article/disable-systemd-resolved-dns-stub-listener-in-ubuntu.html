Disable systemd-resolved DNS Stub Listener in Ubuntu

Disabling the systemd-resolved DNS stub listener in Ubuntu frees up port 53, allowing you to run your own custom DNS server, such as Pi-hole, AdGuard Home, or Unbound. By default, systemd-resolved binds to port 53 on the local loopback interface (127.0.0.53), which prevents other applications from using that port. This step-by-step guide walks you through editing the system configuration, re-linking the DNS resolver file, and restarting the service to release port 53 safely.

Step 1: Open the systemd-resolved Configuration File

Open the /etc/systemd/resolved.conf configuration file in a text editor with administrative privileges:

sudo nano /etc/systemd/resolved.conf

Step 2: Disable the DNS Stub Listener

Locate the line containing #DNSStubListener=yes.

Uncomment the line by removing the # symbol and change the value to no:

DNSStubListener=no

If you also want to set a custom upstream DNS server directly in this file, uncomment the DNS= line and add your preferred provider:

DNS=1.1.1.1 8.8.8.8

Save the file and exit the editor (in nano, press Ctrl+O, Enter, then Ctrl+X).

Step 3: Symlink /etc/resolv.conf

By default, /etc/resolv.conf points to the local stub file at /run/systemd/resolve/stub-resolv.conf. You must point it to the active systemd resolution file (/run/systemd/resolve/resolv.conf), which uses the actual upstream DNS servers instead of the local stub interface.

Remove the existing symlink:

sudo rm /etc/resolv.conf

Create a new symlink pointing to the direct resolution configuration:

sudo ln -s /run/systemd/resolve/resolv.conf /etc/resolv.conf

Step 4: Restart the systemd-resolved Service

Apply the configuration changes by restarting the systemd-resolved service:

sudo systemctl restart systemd-resolved

Step 5: Verify Port 53 is Free

To confirm that systemd-resolved is no longer listening on port 53, check the active listening ports on your system:

sudo ss -tulpn | grep :53

If the command returns no output, port 53 is now open and available for your custom DNS software.
