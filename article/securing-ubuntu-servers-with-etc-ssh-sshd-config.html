Securing Ubuntu Servers with /etc/ssh/sshd_config

The /etc/ssh/sshd_config file is the central configuration file for the OpenSSH SSH daemon on Ubuntu servers, responsible for defining the security policies and operational parameters of remote SSH connections. By customizing the settings within this file, system administrators can control authentication methods, restrict user access, enforce session limits, and harden the server against unauthorized entry and automated brute-force attacks.

Core Security Functions of sshd_config

The /etc/ssh/sshd_config file directly governs how the SSH daemon (sshd) behaves when receiving connection requests. Modifying its directives allows you to control several critical security layers:

1. Disabling Direct Root Login

By default, root access via SSH poses a major security risk. The PermitRootLogin directive controls whether the root account can log in directly. Setting this to no forces administrative users to log in using a standard account first and elevate privileges using sudo.

PermitRootLogin no

2. Enforcing Key-Based Authentication

Password-based authentication is vulnerable to credential stuffing and brute-force attacks. Disabling password access via the PasswordAuthentication directive ensures that only users with authorized SSH key pairs can establish a connection.

PasswordAuthentication no

3. Restricting User and Group Access

The file allows administrators to create explicit access control lists using directives such as AllowUsers, AllowGroups, DenyUsers, and DenyGroups. This prevents unauthorized local system accounts from accessing the server remotely.

AllowUsers sysadmin deployer

4. Mitigating Brute-Force and Scanning Attacks

  • Changing the Default Port: Changing the Port directive from the default port 22 to an unused high-numbered port helps avoid automated port scanners.
  • Limiting Authentication Attempts: The MaxAuthTries directive limits the number of failed login attempts per connection before the server drops the session, mitigating brute-force tools.
Port 2222
MaxAuthTries 3

5. Managing Idle Sessions

Unattended, open SSH sessions leave servers vulnerable to unauthorized local access. Directives like ClientAliveInterval and ClientAliveCountMax configure automatic session timeouts when a client becomes inactive.

ClientAliveInterval 300
ClientAliveCountMax 2

Applying and Validating Changes

Modifications made to /etc/ssh/sshd_config do not take effect automatically. To apply security changes safely on an Ubuntu server:

  1. Test the configuration syntax for errors:

    sudo sshd -t

  2. Restart the SSH service to enforce the new configuration:

    sudo systemctl restart ssh

Properly configuring /etc/ssh/sshd_config provides the foundational defense needed to secure remote access to Ubuntu infrastructure.
