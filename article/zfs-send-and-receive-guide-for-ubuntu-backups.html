ZFS Send and Receive Guide for Ubuntu Backups

In Ubuntu backup strategies, the zfs send and zfs receive commands provide a native, high-performance method for replicating data between ZFS storage pools. By converting ZFS snapshots into serialized data streams and reconstructing them at a target destination, these commands allow administrators to execute rapid, block-level full and incremental backups across local drives or remote servers with minimal system overhead.

Understanding the Core Mechanism

The zfs send command inspects a ZFS snapshot and converts its underlying blocks into a continuous data stream. Conversely, zfs receive (or zfs recv) takes this incoming stream and writes it into a target dataset or pool, reconstructing an exact, byte-for-byte replica of the original snapshot. Because this process operates directly at the OpenZFS file system layer rather than through the operating system's standard file-access APIs, it avoids the overhead of scanning directories and opening individual files.

Key Roles in an Ubuntu Backup Strategy

1. Efficient Incremental Replication

Traditional backup utilities like rsync must traverse directory trees to compare file timestamps and sizes, a process that can take hours on datasets containing millions of files. With ZFS, the file system constantly tracks which data blocks have changed. Using the incremental flag (-i or -I), zfs send extracts only the blocks that were modified between two snapshots. This enables near-instantaneous incremental backups, even on multi-terabyte pools.

2. Preservation of File System Properties

When transferring data with zfs send and zfs receive, the native ZFS attributes are completely preserved. This includes:

  • Native compression settings (saving bandwidth and disk space via the -c or raw send flag).
  • Native ZFS encryption (enabling raw sends where the remote target cannot read the encrypted data).
  • Access Control Lists (ACLs), extended attributes, permissions, and dataset properties (like mountpoint or quota).

3. Secure Remote Offsite Backups

Because zfs send generates standard output (stdout) and zfs receive reads standard input (stdin), they integrate seamlessly with standard Unix pipelines. On Ubuntu, administrators commonly pipe the data stream through SSH to achieve secure, encrypted offsite backups without requiring proprietary backup software:

zfs send -i pool/dataset@snap1 pool/dataset@snap2 | ssh user@remote-ubuntu "zfs receive backup-pool/dataset"

4. Fast Disaster Recovery

Restoring from a backup created with zfs receive requires no complex file-by-file extraction. The target dataset is immediately ready to be mounted or cloned. In disaster recovery scenarios on Ubuntu servers, an entire operating system or database volume can be rolled back or promoted to production within seconds.

Automated Implementation on Ubuntu

While zfs send and zfs receive can be run manually or scripted via cron jobs, they also serve as the underlying engine for dedicated Ubuntu ZFS automation tools such as Sanoid/Syncoid and zrepl. These utilities manage snapshot retention policies and handle network retries, providing enterprise-grade, automated replication pipelines built entirely on top of the native ZFS send/receive commands.
