Role of lxc-create in Ubuntu Legacy LXC

This article provides an overview of the lxc-create command, detailing its specific role, syntax, and functionality within legacy Linux Containers (LXC) on Ubuntu. Readers will learn how this utility initializes container environments, prepares file systems using templates, and sets up configuration metadata prior to container execution.

What is lxc-create?

In legacy LXC (the foundational containerization framework preceding modern managers like LXD), containers operate through direct, userspace system commands. Within this architecture, lxc-create serves as the primary provisioning tool. Its sole purpose is to allocate and assemble the root filesystem (rootfs) and configuration files required for a container before it is ever powered on.

Unlike modern container engines that pull pre-packaged images via background daemons, legacy LXC uses lxc-create to execute local shell scripts called templates. These scripts actively bootstrap a minimal Linux distribution inside the target host environment.

Core Functions of lxc-create

When executed on an Ubuntu host, lxc-create performs several critical tasks:

  1. Namespace and Resource Allocation: It registers the container under the default LXC directory structure (typically /var/lib/lxc/<container_name>).
  2. Template Execution: By calling a specified template, it downloads, de-bootstraps, or caches the base operating system packages necessary to form a functioning rootfs.
  3. Configuration File Generation: It generates the config file containing parameters for network bridging, cgroup constraints, storage mounts, and security permissions (such as AppArmor profiles and POSIX capabilities).
  4. Storage Backend Integration: It formats and attaches the rootfs to a designated storage system, supporting standard directory structures (dir), LVM logical volumes, Btrfs subvolumes, or ZFS filesystems.

Basic Syntax and Parameters

The standard command structure for lxc-create requires at least a container name and a template designation:

sudo lxc-create -n container_name -t template_name

Commonly used arguments include:

  • -n, --name: Designates the unique identifier for the container.
  • -t, --template: Specifies the template script found in /usr/share/lxc/templates/ (e.g., ubuntu, debian, or download). Using -t download connects to standard repositories to retrieve pre-built, lightweight root filesystems rather than bootstrapping from scratch.
  • -B, --bdev: Selects the underlying block device or filesystem type (e.g., lvm, zfs, btrfs, dir).
  • -- (Template Options): Passes specific flags directly to the template script, such as distribution release (-r focal) and architecture (-a amd64).

For example, provisioning an Ubuntu container on an Ubuntu host using the download template:

sudo lxc-create -n web-server -t download -- -d ubuntu -r jammy -a amd64

Role in the Container Lifecycle

lxc-create handles strictly the definition and build phase of a container. It does not run processes, isolate namespaces dynamically, or start network interfaces. Once lxc-create builds the environment, the operational lifecycle shifts to other utility commands:

  • lxc-start launches the container into active namespaces.
  • lxc-attach or lxc-console provides shell access.
  • lxc-stop terminates containerized processes.
  • lxc-destroy unlinks and deletes the filesystem constructed by lxc-create.

By decoupling the container creation step from execution, lxc-create provides fine-grained control over system-level virtualization, allowing administrators to customize the initial rootfs and configuration before any service runs.
