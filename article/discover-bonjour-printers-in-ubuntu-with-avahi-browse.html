Discover Bonjour Printers in Ubuntu with avahi-browse

In Ubuntu, network printers often announce their availability using Zeroconf and Apple Bonjour protocols, allowing for automatic setup without manual IP configuration. The avahi-browse command serves as an essential command-line utility for querying, discovering, and diagnosing these multicast DNS (mDNS) and DNS Service Discovery (DNS-SD) broadcasts on a local network. This article explains how avahi-browse works, the role it plays in printer identification, and how administrators can use it to troubleshoot printing services.

Understanding Zeroconf and Avahi in Ubuntu

Zeroconf (Zero Configuration Networking) relies on two key technologies to make devices discoverable: mDNS, which translates hostnames to IP addresses without a central DNS server, and DNS-SD, which advertises specific services offered by a device.

In Ubuntu, the Avahi daemon (avahi-daemon) provides the system-level implementation of Zeroconf and Bonjour. While the daemon works in the background to register and listen for network events, user-space utilities like avahi-browse provide a direct interface to inspect the real-time service announcements passing through the network.

The Role of avahi-browse in Printer Discovery

The primary role of avahi-browse in printer discovery is service inspection and resolution. When a modern network printer connects to a local subnet, it broadcasts service types indicating its printing capabilities.

Ubuntu's printing architecture (CUPS and cups-browsed) listens to the Avahi daemon to automatically create queues for driverless printing. When an administrator or user runs avahi-browse, the tool sends queries to the network and collects these broadcast packets. This allows users to:

  • Verify Service Advertisement: Confirm whether a printer is actively broadcasting its presence or if network barriers (such as mDNS-blocking switches or isolated VLANs) are suppressing the packets.
  • Identify Supported Protocols: Determine which specific protocols the printer supports, such as Internet Printing Protocol (IPP), IPP Everywhere, LPD, or raw socket printing.
  • Resolve Connection Details: Translate abstract service names into concrete connection parameters, including hostnames, IP addresses, port numbers, and specific queue paths.
  • Read Configuration Metadata: Access TXT records embedded in the broadcast, which contain critical driverless printing metadata like supported page description languages (PDF, PWG-Raster, PostScript), printer model names, and duplexing capabilities.

Key Print Services Scanned by avahi-browse

Network printers register different service subtypes depending on their firmware and enabled features. The most common service types targeted with avahi-browse include:

  • _ipp._tcp: Standard Internet Printing Protocol (used by modern IPP and driverless setups).
  • _ipps._tcp: Secure Internet Printing Protocol over TLS/SSL.
  • _printer._tcp: Legacy Line Printer Daemon (LPD) service.
  • _pdl-datastream._tcp: HP JetDirect / AppSocket raw port (typically port 9100).

Using avahi-browse to Locate Printers

The utility is provided by the avahi-utils package in Ubuntu:

sudo apt install avahi-utils

Discovering All Active Print Services

To scan the local network specifically for IPP-compatible printers, use the -r (resolve) and -t (terminate after dump) flags:

avahi-browse -rt _ipp._tcp

Understanding the Output

When resolving an IPP printer, avahi-browse returns several critical fields:

  • Service Name: The user-friendly name advertised by the device (e.g., HP Color LaserJet @ office).
  • Hostname and Address: The mDNS address (e.g., printer.local) and its resolved IPv4 or IPv6 address.
  • Port: The listening port (standard IPP is 631).
  • TXT Record Attributes: Crucial parameters used by CUPS, such as:
    • rp: The resource path or queue name (e.g., ipp/print).
    • ty: The exact make and model of the printer.
    • pdl: Supported MIME types and PDLs, confirming if the device supports driverless IPP Everywhere (image/urf, application/pdf).

Diagnostic Value in CUPS Troubleshooting

When a network printer fails to appear in Ubuntu's default printer settings panel, avahi-browse acts as the first line of diagnosis. If avahi-browse -rt _ipp._tcp returns the printer with valid host and TXT information, the issue lies within CUPS configuration or local firewall settings. If avahi-browse finds nothing, the problem is typically physical connectivity, printer firmware settings, or network routers blocking multicast UDP traffic on port 5353.
