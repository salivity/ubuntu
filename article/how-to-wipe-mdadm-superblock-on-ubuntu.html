How to Wipe mdadm Superblock on Ubuntu

When repurposing a drive previously used in a Linux software RAID array on Ubuntu, lingering RAID metadata—known as the superblock—can cause the operating system to automatically reassemble or misidentify the array. This guide explains how to properly and securely remove the mdadm superblock from a disk or partition, ensuring the drive is cleanly disassociated from the previous RAID configuration and ready for new use.

The Primary Command: mdadm --zero-superblock

The dedicated command to erase the RAID superblock from a drive or partition is:

sudo mdadm --zero-superblock /dev/sdX

Replace /dev/sdX with the specific drive identifier (for example, /dev/sdb) or the specific partition (such as /dev/sdb1) that contained the RAID metadata.

This command overwrites the RAID metadata block with zeros, preventing Ubuntu from detecting the drive as an active member of any mdadm array.

Step-by-Step Procedure

To ensure the superblock is wiped without errors, follow these steps:

1. Stop the Active RAID Array

If the array is running, you must stop it before clearing the metadata. Identify the array using cat /proc/mdstat, then stop it with:

sudo mdadm --stop /dev/md0

(Replace /dev/md0 with your array's device node.)

2. Zero the Superblock

Run the zeroing command on each partition or raw disk that belonged to the array:

sudo mdadm --zero-superblock /dev/sdb1

If the entire raw disk was added directly to the array without a partition table:

sudo mdadm --zero-superblock /dev/sdb

3. Completely Remove Signatures (Optional but Recommended)

To prevent modern partition managers and systemd from reading any conflicting residual signatures (such as filesystem or partition table signatures), run wipefs:

sudo wipefs --all --force /dev/sdb1
sudo wipefs --all --force /dev/sdb

4. Clean Configuration Files

Remove any obsolete references to the old array from the system configuration file:

  1. Open /etc/mdadm/mdadm.conf (or /etc/mdadm.conf) in a text editor and remove the line defining the old array.
  2. Update the initramfs image to ensure the system does not attempt to assemble the removed array during boot:
sudo update-initramfs -u
