How to Install and Configure SSSD on Ubuntu

This guide provides a straightforward walkthrough for installing and configuring the System Security Services Daemon (SSSD) on Ubuntu. SSSD allows local systems to connect to remote identity and authentication providers such as OpenLDAP, FreeIPA, or Microsoft Active Directory. By following the steps below, you will learn how to install the required packages, create an authentication profile, securely configure the /etc/sssd/sssd.conf file, and enable automatic home directory creation for remote users.

Step 1: Update Your System

Before installing new packages, ensure your system repository cache and installed packages are up to date:

sudo apt update && sudo apt upgrade -y

Step 2: Install SSSD Packages

Install SSSD along with common integration packages for PAM (Pluggable Authentication Modules) and NSS (Name Service Switch):

sudo apt install sssd sssd-tools libpam-sss libnss-sss -y

If you are joining an Active Directory domain, you may also want to install the realmd and adcli packages to automate domain enrollment:

sudo apt install realmd adcli -y

Step 3: Create the SSSD Configuration File

SSSD does not generate a default configuration file upon installation. You must create /etc/sssd/sssd.conf manually.

Open the file in a text editor:

sudo nano /etc/sssd/sssd.conf

Add your directory service details. Below is an example configuration for a standard LDAP directory:

[sssd]
services = nss, pam
config_file_version = 2
domains = default

[nss]
homedir_substring = /home

[pam]

[domain/default]
id_provider = ldap
auth_provider = ldap
ldap_uri = ldap://ldap.example.com
ldap_search_base = dc=example,dc=com
ldap_id_use_start_tls = True
ldap_tls_cacertdir = /etc/ssl/certs
cache_credentials = True
enumerate = False

Note: Replace ldap://ldap.example.com and dc=example,dc=com with the actual URI and search base of your directory service.

Step 4: Secure the Configuration File

SSSD will fail to start if the permissions on /etc/sssd/sssd.conf are too open. Set the ownership to root:root and restrict read and write permissions exclusively to the root user:

sudo chown root:root /etc/sssd/sssd.conf
sudo chmod 600 /etc/sssd/sssd.conf

Step 5: Enable Automatic Home Directory Creation

Centralized users often do not have a pre-existing /home/username directory on the local machine. Enable the PAM module to create home directories automatically upon first login:

sudo pam-auth-update --enable mkhomedir

Ensure the "Create home directory on login" option is selected, then press OK.

Step 6: Start and Enable SSSD

Restart the SSSD service to apply your changes, and enable it to launch automatically on system boot:

sudo systemctl restart sssd
sudo systemctl enable sssd

Verify that the service is running without errors:

sudo systemctl status sssd

Step 7: Test the Configuration

To confirm that SSSD communicates properly with your identity provider, query an existing user from your directory server using getent or id:

id <username>

or

getent passwd <username>

If configured correctly, the command will return the UID, GID, and group memberships retrieved from the remote directory.
