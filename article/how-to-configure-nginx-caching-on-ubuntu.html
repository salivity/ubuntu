How to Configure Nginx Caching on Ubuntu

Configuring Nginx caching on Ubuntu is one of the most effective ways to reduce server load, decrease latency, and speed up page load times for your web application. By storing static or dynamic responses in memory or on disk, Nginx can serve repeated requests directly without querying backend servers or executing resource-heavy scripts. This guide outlines the step-by-step process to set up Nginx proxy caching on an Ubuntu server, configure cache directives, test your configuration, and verify that cached content is being served correctly.

Step 1: Create the Cache Directory

Before configuring Nginx, create a dedicated directory on your Ubuntu server where Nginx will store the cached files.

Execute the following commands in your terminal:

sudo mkdir -p /var/cache/nginx
sudo chown -R www-data:www-data /var/cache/nginx

This ensures that the directory exists and that the Nginx user (www-data) has write permissions.

Step 2: Define the Cache Path in Nginx

Next, define the cache storage parameters in your main Nginx configuration file or within your specific server block context.

Open your site configuration file (usually located at /etc/nginx/sites-available/default or /etc/nginx/nginx.conf):

sudo nano /etc/nginx/sites-available/default

Add the proxy_cache_path directive outside the server block (at the http context level):

proxy_cache_path /var/cache/nginx levels=1:2 keys_zone=MY_CACHE:10m max_size=1g inactive=60m use_temp_path=off;

Key parameters explained:

  • levels=1:2: Sets up a two-tier directory hierarchy under /var/cache/nginx to prevent performance issues with thousands of files in a single folder.
  • keys_zone=MY_CACHE:10m: Defines a shared memory zone named MY_CACHE with a size of 10 megabytes to store cache keys and metadata.
  • max_size=1g: Limits the total cache size to 1 Gigabyte.
  • inactive=60m: Cache items not accessed for 60 minutes will be deleted.
  • use_temp_path=off: Writes cached files directly to the target cache directory to avoid unnecessary file copying.

Step 3: Enable Caching in the Server Block

Now, apply the cache settings inside your site's server or specific location block.

Update your configuration block as follows:

server {
    listen 80;
    server_name example.com;

    location / {
        proxy_pass http://127.0.0.1:8080;
        
        # Enable the defined cache zone
        proxy_cache MY_CACHE;
        
        # Define cache rules based on HTTP response status codes
        proxy_cache_valid 200 302 10m;
        proxy_cache_valid 404 1m;
        
        # Serve stale cache if the backend is down
        proxy_cache_use_stale error timeout invalid_header updating http_500 http_502 http_503 http_504;
        
        # Add a custom response header to track cache hits/misses
        add_header X-Cache-Status $upstream_cache_status;
    }
}

Step 4: Test and Reload Nginx

Always test your Nginx configuration syntax before restarting the service to avoid accidental downtime.

Run the configuration test:

sudo nginx -t

If the syntax is valid, reload Nginx to apply the changes:

sudo systemctl reload nginx

Step 5: Verify Nginx Caching

To check if caching is working properly, send a request to your server using curl and inspect the custom response header added in Step 3.

Run the following command twice:

curl -I http://example.com

Look for the X-Cache-Status header in the output:

  • First Request: X-Cache-Status: MISS (The response was fetched from the backend server).
  • Second Request: X-Cache-Status: HIT (The response was served directly from the Nginx cache).
