Purpose of the /run Directory in Ubuntu Linux

The /run directory in modern Ubuntu and Linux distributions is a temporary, volatile filesystem (tmpfs) used to store system state data that accumulates during runtime. Introduced to solve early-boot storage conflicts and standardize scattered temporary files like /var/run and /var/lock, /run holds critical live data such as process IDs, socket files, and lock files. Because it exists entirely in system memory (RAM), all contents in /run are automatically cleared when the system reboots or shuts down.

Why the /run Directory Was Created

Before the introduction of /run, Linux systems stored runtime data in /var/run and lock files in /var/lock. This setup created a fundamental problem during the boot process:

  • The Early-Boot Problem: System daemons and services starting early in the boot sequence needed a place to write process IDs and temporary state files. However, /var was frequently located on a separate drive partition that might not yet be mounted as read-write when these early processes started.
  • The Solution: The /run directory was placed on the root filesystem and mounted very early in the boot process as a tmpfs (RAM-backed filesystem). This ensured that a writable, temporary storage location was available to system services from the very beginning of boot.

To maintain backward compatibility with older software, modern Ubuntu releases use symbolic links (symlinks): * /var/run points to /run * /var/lock points to /run/lock

Key Functions and Contents of /run

The /run directory serves several critical functions for system services, background daemons, and user sessions:

1. Process ID Files (.pid)

When background services (daemons) start up, they write their process ID (PID) to files inside /run. These .pid files allow the system and administrative scripts to identify, monitor, and manage specific running services. For example, a web server like Nginx or an SSH daemon stores its PID in /run to signal that it is currently active.

2. Socket Files (.sock)

/run is heavily used for Inter-Process Communication (IPC). Programs write socket files to /run so that separate processes can communicate with one another quickly. Examples include: * System service sockets (like systemd sockets) * Container runtime sockets (such as Docker or Containerd) * Display server sockets (such as Wayland or X11)

3. Lock Files (/run/lock)

The /run/lock subdirectory prevents multiple software applications or system tasks from accessing the same hardware device, file, or resource simultaneously. If an application opens a device, it creates a lock file in /run/lock. Other applications check for this file before attempting to access the same resource to avoid data corruption.

4. Per-User Runtime Directories (/run/user/<UID>)

Modern Ubuntu systems using systemd create a specific directory for every logged-in user under /run/user/<UID> (where <UID> is the user’s numerical ID, such as 1000). This directory acts as a secure, RAM-backed space for user-specific runtime files, such as audio daemon sockets (PipeWire/PulseAudio), desktop environment session files, and temporary user environment variables.

Main Advantages of /run

  • High Performance: Because /run is mounted in RAM as a tmpfs filesystem, reading and writing runtime data is virtually instantaneous.
  • Automatic Cleanup: Since RAM loses its contents when unpowered, files in /run are automatically wiped upon reboot, preventing stale state files or orphaned PID files from persisting across system restarts.
  • Reduced Disk Wear: Writing temporary status updates to RAM avoids constant write operations to physical solid-state drives (SSDs) or hard drives (HDDs).
