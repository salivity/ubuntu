PostgreSQL Point-in-Time Recovery on Ubuntu

Point-in-Time Recovery (PITR) allows you to restore a PostgreSQL database to a specific moment in time using a physical base backup combined with archived Write-Ahead Logging (WAL) files. On Ubuntu, PITR is not executed through a single stand-alone command, but rather through a sequence of administrative commands centered around restoring the base data, signaling recovery with touch recovery.signal, configuring target parameters in postgresql.conf, and restarting the PostgreSQL service.

Step 1: Stop the PostgreSQL Service

Before modifying database files, stop the running PostgreSQL cluster:

sudo systemctl stop postgresql

Step 2: Clear Data Directory and Restore the Base Backup

Move your current data directory to a safe location or clear it, then restore your file system base backup. Replace 16 with your PostgreSQL version and main with your cluster name if different:

sudo mv /var/lib/postgresql/16/main /var/lib/postgresql/16/main_old
sudo mkdir -p /var/lib/postgresql/16/main
sudo tar -xvzf /path/to/basebackup.tar.gz -C /var/lib/postgresql/16/main
sudo chown -R postgres:postgres /var/lib/postgresql/16/main
sudo chmod 700 /var/lib/postgresql/16/main

Step 3: Create the Recovery Signal File

The crucial command that instructs PostgreSQL to enter recovery mode on startup is creating a recovery.signal file in the data directory:

sudo -u postgres touch /var/lib/postgresql/16/main/recovery.signal

Step 4: Configure the Recovery Parameters

Edit your PostgreSQL configuration file to define how WAL archives are retrieved and specify the exact target time:

sudo nano /etc/postgresql/16/main/postgresql.conf

Add or update the following recovery settings:

# Command to fetch WAL archives from your storage location
restore_command = 'cp /path/to/wal_archive/%f %p'

# Target timestamp for the recovery (UTC or specified timezone)
recovery_target_time = '2024-05-01 14:30:00 UTC'

# Action to take once the target is reached (promote opens the DB for writes)
recovery_target_action = 'promote'

Step 5: Start the PostgreSQL Service

Initiate the recovery process by starting the database service:

sudo systemctl start postgresql

Step 6: Verify Recovery

PostgreSQL will replay the WAL records up to the timestamp defined in recovery_target_time, remove the recovery.signal file automatically, and promote the instance to accept connections. You can monitor the process through the logs:

sudo tail -f /var/log/postgresql/postgresql-16-main.log
