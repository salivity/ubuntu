Role of /etc/nsswitch.conf in Ubuntu Name Resolution

The /etc/nsswitch.conf (Name Service Switch configuration) file in Ubuntu acts as a central dispatcher that determines the order and priority of sources the operating system queries when looking up various system databases. For network name resolution, this file dictates how Ubuntu resolves human-readable hostnames and domain names into IP addresses, controlling the fallback behavior and interaction between local static files, DNS servers, and system daemons.

How It Works

When an application on Ubuntu requests network address resolution (typically using standard C library functions like getaddrinfo or gethostbyname), the system reads /etc/nsswitch.conf to discover where to look.

The primary directive responsible for network name resolution is the hosts: line. A standard Ubuntu installation typically features an entry similar to:

hosts: files mdns4_minimal [NOTFOUND=return] resolve [!UNAVAIL=return] dns

The system evaluates these services sequentially from left to right.

Key Resolution Sources

Each keyword on the hosts: line corresponds to a specific service or NSS module:

  • files: Directs the system to consult the local /etc/hosts file first. If an IP and hostname mapping exists locally, it is used immediately without issuing a network request.
  • mdns4_minimal / mdns4: Provided by the Avahi daemon for Multicast DNS (mDNS). It handles zero-configuration networking, primarily resolving names ending in .local.
  • resolve: Integrates with systemd-resolved, the default local DNS caching and network management service in modern Ubuntu releases. It forwards queries to local or network-configured DNS servers via D-Bus.
  • dns: Acts as a fallback to traditional DNS resolution, directly querying the nameservers specified in /etc/resolv.conf.

Control Criteria and Execution Flow

Between the sources, bracketed parameters define control criteria that alter lookup flow based on query outcomes:

  • [NOTFOUND=return]: If the preceding service (such as mdns4_minimal) determines that a name does not exist, the search terminates immediately rather than continuing down the chain.
  • [!UNAVAIL=return]: If the service (such as resolve) is available—even if it returns that the host was not found—the query will not fall back to the subsequent direct dns lookup, preventing redundant network requests.

Purpose and Importance

The /etc/nsswitch.conf file provides modularity, security, and performance optimization. By ordering local sources like /etc/hosts ahead of remote network queries, Ubuntu minimizes unnecessary network traffic and speeds up local resolutions. Furthermore, it allows system administrators to customize name resolution behavior—such as prioritizing specific internal directory services, disabling mDNS, or adjusting how DNS fallbacks occur—without modifying application code.
