How to Use lsof Command for Ubuntu Troubleshooting

The lsof command, short for “List Open Files,” is an essential command-line utility in Ubuntu used to report a list of all currently open files and the processes that opened them. Because Unix-like systems treat almost everything—including network sockets, pipes, and devices—as files, lsof serves as a powerful diagnostic tool. This article covers the primary functions of lsof in Ubuntu troubleshooting, including identifying port conflicts, locating locked files, tracking network connections, and freeing up hidden disk space.

Key Troubleshooting Uses for lsof in Ubuntu

1. Identifying Processes Using Specific Network Ports

When a service fails to start due to a “port already in use” error, lsof can identify the exact process holding the port open.

lsof -i :80

This command displays the Process ID (PID), user, and command occupying port 80, allowing you to terminate or reconfigure the conflicting service.

2. Resolving “Device or Resource Busy” Errors

When attempting to unmount a drive or partition, Ubuntu may throw a “resource busy” error if a background process is accessing it. To locate the process blocking the unmount operation:

lsof /media/user/external_drive

Once you find the associated PID, you can save your work, stop the application, or terminate the process to unmount the device safely.

3. Finding Deleted Files Occupying Disk Space

Disk space may remain full even after deleting large log files if a running application still holds an open file handle to them. To display these deleted but open files:

lsof +L1

This lists open files with a link count of zero. Restarting the process listed by lsof releases the file handle and reclaims the lost disk space.

4. Inspecting Network Connections

lsof allows you to monitor active network connections to diagnose connectivity issues or security anomalies:

  • View all open network files: lsof -i
  • View active IPv4 connections: lsof -i 4
  • View established TCP connections: lsof -i tcp

5. Auditing Process and User File Access

To investigate application behavior or system performance issues, you can inspect all files opened by a specific process ID or system user:

  • Inspect by Process ID: lsof -p <PID>
  • Inspect by Username: lsof -u <username>

This capability helps you verify which configuration files, libraries, or log files an application is currently reading or writing to.
