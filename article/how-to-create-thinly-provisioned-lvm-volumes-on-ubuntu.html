How to Create Thinly-Provisioned LVM Volumes on Ubuntu

Thin provisioning in Logical Volume Manager (LVM) allows systems administrators to allocate virtual storage that exceeds the physical capacity of the underlying disks, a practice known as storage overcommitment. Instead of reserving all blocks upfront, physical blocks are allocated on-demand as data is written. This article provides a direct, step-by-step walkthrough for configuring an LVM thin pool and creating thinly-provisioned logical volumes to maximize storage efficiency on an Ubuntu system.

Prerequisites

Ensure you have administrative privileges (sudo) and an existing LVM Volume Group (VG) with available physical extents. You can check your available volume groups using:

sudo vgs

If you do not have an existing volume group, initialize a physical volume with pvcreate /dev/sdX and create a volume group with vgcreate my_vg /dev/sdX.

Step 1: Create a Thin Pool

A thin pool acts as a shared reservoir of physical storage from which thinly-provisioned volumes draw space as data is written.

To create a thin pool named my_thin_pool with a physical size of 20GB inside the volume group my_vg, run:

sudo lvcreate -L 20G -T my_vg/my_thin_pool
  • -L 20G: Specifies the actual physical space reserved for the pool.
  • -T: Designates that the logical volume being created is a thin pool.
  • my_vg/my_thin_pool: Specifies the volume group and the name of the new pool.

Step 2: Create a Thin Logical Volume (Overcommitting Space)

Once the thin pool is active, you can create virtual logical volumes that are larger than the thin pool itself.

To create a virtual volume named thin_vol1 with a virtual size of 50GB drawn from the 20GB pool:

sudo lvcreate -V 50G -T my_vg/my_thin_pool -n thin_vol1
  • -V 50G: Sets the virtual size exposed to the operating system.
  • -T my_vg/my_thin_pool: References the thin pool created in Step 1.
  • -n thin_vol1: Sets the name of the thin logical volume.

You can repeat this command to create multiple volumes (e.g., thin_vol2, thin_vol3), committing far more total virtual capacity than the 20GB physical limit.

Step 3: Format and Mount the Thin Volume

Format the new thin volume with your preferred filesystem, such as ext4 or XFS, and mount it to the directory tree.

sudo mkfs.ext4 /dev/my_vg/thin_vol1
sudo mkdir -p /mnt/thin_storage
sudo mount /dev/my_vg/thin_vol1 /mnt/thin_storage

The system will report a 50GB filesystem at /mnt/thin_storage, even though it currently consumes almost zero physical blocks in the underlying thin pool.

Step 4: Monitor Space Usage

Because overcommitting can lead to data write failures if the physical pool fills up completely, monitoring is essential. Use the lvs command to check usage:

sudo lvs my_vg

Pay attention to two key columns in the output:

  • Data%: The percentage of physical space currently consumed within the thin pool.
  • Meta%: The percentage of metadata space used to track block allocations.

To prevent sudden outages, you can configure automatic pool extension by editing /etc/lvm/lvm.conf and setting thin_pool_autoextend_threshold and thin_pool_autoextend_percent.
