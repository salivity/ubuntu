Using Ethtool to Troubleshoot Network Links on Ubuntu

The ethtool utility in Ubuntu is a command-line tool designed for querying and controlling network interface controllers (NICs) and their device drivers at the physical layer (OSI Layer 1) and data link layer (Layer 2). This article details how system administrators use ethtool to diagnose physical connectivity failures, detect cable and transceiver faults, identify speed and duplex mismatches, and review raw hardware performance metrics directly from the Linux terminal.

Verifying Physical Carrier Status

The primary role of ethtool during a network outage is confirming whether a physical link actually exists between the host NIC and the switch or router. Running ethtool <interface_name> provides direct hardware status through the Link detected field.

  • Link detected: yes: Indicates electrical or optical carrier signal presence. The cable is connected, powered, and communicating with the link partner.
  • Link detected: no: Points directly to a physical-layer failure, such as an unplugged cable, broken fiber strand, faulty SFP/transceiver module, or a disabled switch port.

Detecting Speed and Duplex Mismatches

Hardware link negotiations can fail if auto-negotiation fails or if one end of the connection is hardcoded. ethtool displays:

  • Supported link modes: The speeds and duplex settings supported by the local NIC.
  • Speed: The actual operating speed negotiated (e.g., 1000Mb/s, 10000Mb/s).
  • Duplex: Whether the link operates in Full or Half duplex.
  • Auto-negotiation: Indicates whether dynamic negotiation is active (on or off).

If an interface that should operate at 1000 Mbps drops to 100 Mbps or switches to half-duplex, ethtool reveals the issue immediately. These mismatches cause severe packet drops, high latency, and degraded throughput.

Inspecting Hardware-Level Error Counters

Standard tools like ip or ifconfig aggregate packet drops into generic counters. In contrast, ethtool -S <interface_name> reads registers directly from the physical controller to expose granular error types:

  • CRC errors (rx_crc_errors): Typically caused by bad cabling, electromagnetic interference (EMI), damaged RJ45 terminations, or faulty optical transceivers.
  • Frame errors (rx_frame_errors): Often indicative of duplex mismatches or framing issues at the physical interface.
  • FIFO/Ring buffer drops (rx_fifo_errors / rx_missed_errors): Show whether packets reach the physical layer but fail to enter host memory, ruling out external physical link problems.

Physical Port Identification

In multi-port server environments, mapping an operating system interface name (such as eth0 or enp3s0) to the correct physical port on the chassis can be difficult. The command ethtool -p <interface_name> [seconds] physically blinks the LED light on the target network port, allowing technicians to locate the exact port requiring cable replacement or inspection without disrupting other active interfaces.

Running Hardware Self-Tests

For supported network adapters, ethtool -t <interface_name> executes built-in hardware diagnostic routines (offline or online). This diagnostic checks the integrity of the physical loopback, internal memory registers, and hardware controller functions, determining whether persistent link dropouts stem from a physically degraded NIC rather than external network infrastructure.
