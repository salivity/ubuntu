How to Configure iSCSI Initiator on Ubuntu

Setting up an iSCSI initiator on Ubuntu allows a server to connect to block storage hosted on a Storage Area Network (SAN) across a standard IP network. This guide covers the end-to-end configuration process, which involves installing the open-iscsi package, retrieving your system's unique Initiator Qualified Name (IQN), discovering the SAN target, authenticating and logging in, and mounting the resulting block device with persistent settings for system reboots.

1. Install Open-iSCSI

Ubuntu utilizes the open-iscsi package to handle iSCSI protocol communications. Update your package index and install the software:

sudo apt update
sudo apt install open-iscsi

Ensure the iSCSI daemon is enabled and running:

sudo systemctl enable --now iscsid open-iscsi

2. Identify and Configure the Initiator Name

Your Ubuntu host identifies itself to the SAN using an iSCSI Qualified Name (IQN). View the auto-generated IQN:

cat /etc/iscsi/initiatorname.iscsi

You will see output similar to InitiatorName=iqn.2004-01.com.ubuntu:01:abcdef123456. Provide this IQN to your SAN administrator so they can map the appropriate LUNs (Logical Unit Numbers) to your host. If you must set a specific name mandated by your storage policy, edit this file and restart the iscsid service:

sudo systemctl restart iscsid

3. Discover the SAN Target

Query the SAN target IP address to discover the available storage nodes using iscsiadm:

sudo iscsiadm -m discovery -t sendtargets -p <SAN_IP_ADDRESS>

Replace <SAN_IP_ADDRESS> with the IP or hostname of your SAN. The output will list discovered targets in this format:

<SAN_IP_ADDRESS>:3260,1 iqn.2000-01.com.synology:storage.target1

4. Configure Authentication (Optional)

If your SAN requires CHAP (Challenge-Handshake Authentication Protocol), configure the credentials in /etc/iscsi/iscsid.conf or directly modify the target parameters:

sudo iscsiadm -m node -T <TARGET_IQN> -o update -n node.session.auth.authmethod -v CHAP
sudo iscsiadm -m node -T <TARGET_IQN> -o update -n node.session.auth.username -v <CHAP_USERNAME>
sudo iscsiadm -m node -T <TARGET_IQN> -o update -n node.session.auth.password -v <CHAP_PASSWORD>

5. Log in to the iSCSI Target

Connect to the discovered target:

sudo iscsiadm -m node -T <TARGET_IQN> -p <SAN_IP_ADDRESS> --login

To ensure the session establishes automatically during boot, configure the startup property:

sudo iscsiadm -m node -T <TARGET_IQN> -p <SAN_IP_ADDRESS> --op update -n node.startup -v automatic

6. Verify and Format the New Block Device

Check that the kernel recognizes the new block storage:

lsblk

Locate the new device (e.g., /dev/sdb). Create a filesystem on the device:

sudo mkfs.ext4 /dev/sdb

7. Mount the Storage with Network Dependencies

Create a mount directory and attach the drive:

sudo mkdir -p /mnt/san-storage
sudo mount /dev/sdb /mnt/san-storage

To maintain persistent access across system reboots, locate the UUID of the block device using sudo blkid /dev/sdb, then append an entry to /etc/fstab. You must include the _netdev mount option to ensure the operating system delays mounting the drive until network connectivity is online:

UUID=<YOUR_DEVICE_UUID>  /mnt/san-storage  ext4  defaults,_netdev  0  2
