Build Strictly Confined Snaps with Snapcraft

This guide provides a practical walkthrough for developers looking to package applications as strictly confined snaps on Ubuntu using the Snapcraft tool. You will learn how to set up the build environment, configure the snapcraft.yaml manifest for strict confinement, declare necessary interfaces, and compile and test your secure snap package locally.

1. Install Snapcraft and Build Providers

Snapcraft builds snaps inside isolated environments using either LXD or Multipass to ensure reproducibility. Install Snapcraft directly via the snap store with classic confinement:

sudo snap install snapcraft --classic

LXD is the recommended container provider on modern Ubuntu releases. Install and initialize it with default options:

sudo snap install lxd
sudo lxd init --auto

2. Initialize the Project

Navigate to your application's source directory and initialize a new Snapcraft project:

mkdir my-confined-app
cd my-confined-app
snapcraft init

This creates a snap/snapcraft.yaml template file that acts as the primary configuration manifest for the packaging process.

3. Configure snapcraft.yaml for Strict Confinement

Strict confinement isolates your application via AppArmor profiles, seccomp filters, and cgroups. To enforce this, set the confinement key to strict in snap/snapcraft.yaml.

Below is a complete, minimal example of a strictly confined application:

name: my-confined-app
base: core22
version: '1.0'
summary: A sample strictly confined snap
description: |
  This application runs in an isolated environment with restricted access
  to the host system.

grade: stable
confinement: strict

apps:
  my-confined-app:
    command: bin/app
    plugs:
      - network
      - home

parts:
  my-part:
    plugin: dump
    source: .
    stage:
      - bin/app

Key Elements of Strict Confinement

  • confinement: strict: Enforces complete sandboxing. The application cannot access system files, network adapters, or user directories unless explicitly granted.
  • base: core22: Specifies the base runtime environment (Ubuntu 22.04 LTS).
  • plugs: Interfaces that puncture controlled holes in the sandbox. In the example above, network grants outgoing internet access, while home grants access to non-hidden files in the user's home directory.

4. Build the Snap Package

With your snapcraft.yaml configured, execute the build command in your terminal:

snapcraft

Snapcraft launches an ephemeral LXD container, downloads the base runtime, installs build dependencies, applies your plugins, and packages the final artifacts into a .snap file (for example, my-confined-app_1.0_amd64.snap).

If you are developing inside an already isolated CI/CD container where nested virtualization is unavailable, you can bypass LXD by running:

snapcraft --destructive-mode

5. Install and Verify Confinement

Install your newly compiled snap locally using the --dangerous flag (required because the package is not signed by the Snap Store):

sudo snap install my-confined-app_1.0_amd64.snap --dangerous

Verify that the package is actively enforcing strict confinement:

snap list my-confined-app

The output will confirm strict under the Notes/Confinement column. You can also inspect the connected plugs and slots to ensure only the declared interfaces are linked:

snap connections my-confined-app

Run your application to verify its behavior within the sandbox:

my-confined-app

If the application attempts to read unpermitted files or access restricted system resources, AppArmor blocks the action. You can monitor sandbox denials by inspecting the system log with sudo dmesg | grep audit.
