Configure Apache SAML 2.0 Authentication on Ubuntu

This guide provides a step-by-step walkthrough for configuring an Apache web server on Ubuntu to authenticate users using SAML 2.0. By utilizing the libapache2-mod-auth-mellon module, you will learn how to install necessary dependencies, generate Service Provider (SP) metadata and keys, integrate with an Identity Provider (IdP), and protect specific directories using Single Sign-On (SSO).

Step 1: Install Apache and the Mellon Module

Update your local package index and install the Apache HTTP server alongside the Mellon SAML authentication module:

sudo apt update
sudo apt install apache2 libapache2-mod-auth-mellon -y

Ensure the module is enabled:

sudo a2enmod auth_mellon

Step 2: Create a Directory for SAML Metadata

Create a dedicated directory to store your SAML certificates and metadata files:

sudo mkdir -p /etc/apache2/saml2
cd /etc/apache2/saml2

Step 3: Generate Service Provider (SP) Metadata and Keys

Mellon provides a utility script to create the SP private key, certificate, and XML metadata file automatically. Run the script with your entity ID and the Mellon endpoint URL (replace example.com with your actual domain name):

sudo /usr/sbin/mellon_create_metadata.sh "https://example.com" "https://example.com/mellon"

This generates three files matching your domain prefix:

  • https_example.com.key (Private key)
  • https_example.com.cert (Certificate)
  • https_example.com.xml (SP Metadata file)

Rename them to simpler filenames for easier management:

sudo mv https_example.com.key sp-private-key.key
sudo mv https_example.com.cert sp-certificate.cert
sudo mv https_example.com.xml sp-metadata.xml

Secure the private key permissions:

sudo chmod 600 sp-private-key.key

Step 4: Import Identity Provider (IdP) Metadata

Obtain the SAML 2.0 metadata XML file from your Identity Provider (such as Okta, Azure AD, Keycloak, or Google Workspace). Save this file directly into your SAML directory:

/etc/apache2/saml2/idp-metadata.xml

Next, register your Service Provider with the IdP by uploading the sp-metadata.xml file generated in Step 3 to your IdP's administrative dashboard.

Step 5: Configure the Apache VirtualHost

Open your Apache site configuration file (e.g., /etc/apache2/sites-available/000-default.conf or your SSL configuration file):

sudo nano /etc/apache2/sites-available/default-ssl.conf

Inside the <VirtualHost *:443> block, configure the Mellon global directives and define a protected location:

<VirtualHost *:443>
    ServerName example.com
    DocumentRoot /var/www/html

    SSLEngine on
    SSLCertificateFile /etc/ssl/certs/ssl-cert-snakeoil.pem
    SSLCertificateKeyFile /etc/ssl/private/ssl-cert-snakeoil.key

    # Mellon SAML Configuration
    <Location />
        MellonEnable "info"
        MellonEndpointPath "/mellon/"
        MellonSPPrivateKeyFile /etc/apache2/saml2/sp-private-key.key
        MellonSPCertFile /etc/apache2/saml2/sp-certificate.cert
        MellonSPMetadataFile /etc/apache2/saml2/sp-metadata.xml
        MellonIdPMetadataFile /etc/apache2/saml2/idp-metadata.xml
    </Location>

    # Protected Directory
    <Location /protected>
        MellonEnable "auth"
        AuthType "Mellon"
        MellonRequire "valid-user"
        Require valid-user
    </Location>
</VirtualHost>
  • MellonEndpointPath: The base URL path where Mellon handles internal SAML endpoints (e.g., login, logout, and metadata processing).
  • MellonEnable "info": Populates environment variables with SAML attributes across the site without requiring authentication.
  • MellonEnable "auth": Enforces SAML authentication for resources within the /protected location.

Step 6: Test and Restart Apache

Validate the Apache configuration for syntax errors:

sudo apache2ctl configtest

If the syntax is verified as Syntax OK, restart Apache to apply the changes:

sudo systemctl restart apache2

Step 7: Verify Authentication

  1. Open a web browser and navigate to https://example.com/protected.
  2. Apache will intercept the request and redirect your browser to the IdP login page.
  3. Authenticate with your IdP credentials.
  4. Upon successful authentication, the IdP redirects you back to https://example.com/mellon/postResponse, which establishes your session and loads the /protected resource.
