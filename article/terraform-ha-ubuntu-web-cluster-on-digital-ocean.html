Terraform HA Ubuntu Web Cluster on DigitalOcean

This guide details how to automate the provisioning of a high-availability Ubuntu web server cluster on DigitalOcean using HashiCorp Terraform. You will configure the DigitalOcean Terraform provider, deploy multiple Ubuntu Droplets provisioned with an Nginx web server, and distribute incoming traffic across them using a managed DigitalOcean Load Balancer with health checks to ensure continuous uptime.

Prerequisites

Before beginning, ensure you have the following:

  • Terraform (v1.3+) installed on your local machine.
  • A DigitalOcean account with an active Personal Access Token.
  • An SSH key added to your DigitalOcean account.

Step 1: Configure the Terraform Provider

Create a working directory and a file named provider.tf to declare the DigitalOcean provider.

terraform {
  required_version = ">= 1.3.0"
  required_providers {
    digitalocean = {
      source  = "digitalocean/digitalocean"
      version = "~> 2.0"
    }
  }
}

variable "do_token" {
  description = "DigitalOcean API Token"
  type        = string
  sensitive   = true
}

variable "ssh_fingerprint" {
  description = "Fingerprint of the SSH key uploaded to DigitalOcean"
  type        = string
}

variable "region" {
  description = "DigitalOcean region"
  type        = string
  default     = "nyc3"
}

provider "digitalocean" {
  token = var.do_token
}

Step 2: Define Web Droplets and User Data

Create a file named main.tf. This configuration uses cloud-init via the user_data argument to install and start Nginx automatically on each Ubuntu instance.

data "digitalocean_ssh_key" "default" {
  fingerprint = var.ssh_fingerprint
}

resource "digitalocean_tag" "web_cluster" {
  name = "web-cluster"
}

resource "digitalocean_droplet" "web" {
  count              = 2
  name               = "ubuntu-web-${count.index + 1}"
  region             = var.region
  image              = "ubuntu-22-04-x64"
  size               = "s-1vcpu-1gb"
  ssh_keys           = [data.digitalocean_ssh_key.default.id]
  tags               = [digitalocean_tag.web_cluster.id]

  user_data = <<-EOF
              #!/bin/bash
              apt-get update -y
              apt-get install -y nginx
              echo "<h1>Served from $(hostname)</h1>" > /var/www/html/index.html
              systemctl enable nginx
              systemctl start nginx
              EOF
}

Using a tag (web-cluster) allows the load balancer to dynamically associate with all cluster members rather than managing individual Droplet IDs.

Step 3: Add the DigitalOcean Load Balancer

In main.tf, append the digitalocean_loadbalancer resource. The load balancer routes incoming port 80 traffic evenly across the Droplets and runs periodic health checks to remove failing nodes from rotation.

resource "digitalocean_loadbalancer" "public" {
  name   = "ha-web-lb"
  region = var.region

  forwarding_rule {
    entry_port     = 80
    entry_protocol = "http"

    target_port     = 80
    target_protocol = "http"
  }

  healthcheck {
    port     = 80
    protocol = "http"
    path     = "/"
    check_interval_seconds   = 10
    response_timeout_seconds = 5
    unhealthy_threshold      = 3
    healthy_threshold        = 2
  }

  droplet_tag = digitalocean_tag.web_cluster.name
}

Step 4: Define Output Variables

Create an outputs.tf file to display the external IP address of the load balancer upon deployment.

output "load_balancer_ip" {
  description = "The public IP address of the Load Balancer"
  value       = digitalocean_loadbalancer.public.ip
}

Step 5: Initialize and Deploy

Set your environment variables or provide a terraform.tfvars file containing your do_token and ssh_fingerprint. Then run:

  1. Initialize the working directory:

    terraform init

  2. Preview the execution plan:

    terraform plan

  3. Apply the changes:

    terraform apply -auto-approve

Verification and Scaling

Once the provisioning completes, Terraform outputs the public IP address of the load balancer. Open http://<load_balancer_ip> in your web browser and refresh repeatedly; you should see responses alternate between ubuntu-web-1 and ubuntu-web-2.

To scale the cluster, adjust the count attribute in digitalocean_droplet.web and re-run terraform apply. The new Droplets will automatically be tagged, pass health checks, and begin handling incoming traffic.
