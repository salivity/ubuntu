How to Configure Policy Routing with iproute2 in Ubuntu

Policy-based routing (PBR) in Ubuntu allows network traffic to be routed based on criteria such as source IP address, protocol, or port, rather than relying solely on the destination address. By utilizing the iproute2 suite, administrators can manage multiple routing tables and set rules to direct specific packets through designated gateways. This guide provides a step-by-step process for creating custom routing tables, defining IP rules, and making these settings persistent across system reboots.

1. Define a Custom Routing Table

Linux uses numerical IDs for routing tables. To make management easier, assign a name to a custom table ID in the /etc/iproute2/rt_tables configuration file.

Open the file in a text editor:

sudo nano /etc/iproute2/rt_tables

Add a custom table entry at the end of the file by specifying a unique number (between 1 and 252) and a name:

200 custom_table

Save and exit the file.

2. Add Routes to the Custom Table

Populate the custom table with default and subnet routes using the ip route command.

To add a default gateway to your custom table:

sudo ip route add default via 192.168.2.1 dev eth1 table custom_table

To add a local network route to the custom table:

sudo ip route add 192.168.2.0/24 dev eth1 proto kernel scope link src 192.168.2.10 table custom_table

3. Create Routing Rules

Use ip rule to dictate which traffic should utilize the custom routing table.

To route all traffic originating from a specific source IP address through the custom table:

sudo ip rule add from 192.168.2.10 table custom_table

To route traffic based on a specific incoming interface:

sudo ip rule add iif eth1 table custom_table

To assign a priority to the rule (lower numbers indicate higher priority):

sudo ip rule add from 192.168.2.10 table custom_table priority 500

4. Verify the Configuration

Verify that the rules and routes are applied correctly using the following commands:

View all active routing rules:

ip rule show

View routes inside your custom table:

ip route show table custom_table

Flush the routing cache to ensure the changes take effect immediately:

sudo ip route flush cache

5. Make Rules Persistent with Netplan

Commands executed via iproute2 are lost upon reboot. On modern Ubuntu systems using Netplan, configure persistence by adding routing rules directly to /etc/netplan/01-netcfg.yaml (or your active Netplan file):

network:
  version: 2
  ethernets:
    eth1:
      addresses:
        - 192.168.2.10/24
      routes:
        - to: default
          via: 192.168.2.1
          table: 200
      routing-policy:
        - from: 192.168.2.10
          table: 200
          priority: 500

Apply the updated Netplan configuration:

sudo netplan apply
