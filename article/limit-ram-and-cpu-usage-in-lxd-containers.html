Limit RAM and CPU Usage in LXD Containers

Managing system resources in LXD ensures that individual containers do not monopolize host memory and processing power. This guide demonstrates how to configure hard and soft resource limits for RAM and CPU on an Ubuntu host using LXD's built-in configuration tools. You will learn how to apply these constraints directly to running instances as well as how to enforce them across multiple containers using profiles.

Limiting RAM (Memory)

LXD allows you to set hard limits on the amount of physical memory an instance can consume. The changes take effect immediately without requiring a reboot of the container.

To set a maximum memory limit for a specific container, run:

lxc config set <container_name> limits.memory 2GiB

You can specify values in KiB, MiB, GiB, or as a percentage of the host system's total memory (e.g., 20%).

By default, LXD allows the container to use swap space once memory is exhausted. To disable swap entirely for the container to enforce strict boundaries, run:

lxc config set <container_name> limits.memory.swap false

Alternatively, you can assign a dedicated swap allocation:

lxc config set <container_name> limits.memory.swap 512MiB

Limiting CPU Usage

LXD offers multiple ways to restrict CPU resources, including setting the number of available cores, pinning containers to specific physical cores, or capping overall CPU execution time.

Option 1: Limit by Number of CPU Cores

To restrict a container to a specific number of virtual CPUs:

lxc config set <container_name> limits.cpu 2

Option 2: Pin to Specific CPU Cores

To bind the container strictly to specific CPU cores on the host:

lxc config set <container_name> limits.cpu 0,1

Or for a core range:

lxc config set <container_name> limits.cpu 0-3

Option 3: Limit by CPU Allowance (Percentage)

To restrict the percentage of total CPU time a container can use across its assigned cores:

lxc config set <container_name> limits.cpu.allowance 50%

You can also specify a time-slice budget, such as 25ms/100ms, which restricts the container to 25ms of execution time for every 100ms period.

Applying Limits Using Profiles

To apply CPU and memory limits automatically to new containers, apply the settings to an LXD profile rather than individual containers:

lxc profile set default limits.memory 1GiB
lxc profile set default limits.cpu 1

Any container assigned to the default profile will inherit these restrictions.

Verifying Applied Limits

To check that the settings are active on a container:

lxc config show <container_name>

You can also verify the resource visibility inside the container:

lxc exec <container_name> -- free -h
lxc exec <container_name> -- nproc

LXD utilizes the Linux kernel's cgroups (control groups) and lxcfs to expose these resource boundaries accurately within the guest environment.
