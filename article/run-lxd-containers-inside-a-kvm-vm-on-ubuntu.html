Run LXD Containers Inside a KVM VM on Ubuntu

Running LXD system containers inside a KVM virtual machine requires nested virtualization support on the host, host CPU feature pass-through to the guest, and proper kernel configuration within the Ubuntu virtual machine. This guide walks you through enabling nested virtualization on the KVM host, configuring the virtual machine processor settings, and initializing LXD inside the Ubuntu guest to run unprivileged containers efficiently.

1. Enable Nested Virtualization on the KVM Host

Nested virtualization allows the KVM hypervisor to pass virtualization extensions down to the guest operating system.

Check whether nested virtualization is currently enabled on your host:

# For Intel processors
cat /sys/module/kvm_intel/parameters/nested

# For AMD processors
cat /sys/module/kvm_amd/parameters/nested

If the output is Y or 1, nested virtualization is already enabled. If the output is N or 0, enable it persistently:

For Intel:

echo "options kvm_intel nested=1" | sudo tee /etc/modprobe.d/kvm.conf
sudo modprobe -r kvm_intel
sudo modprobe kvm_intel

For AMD:

echo "options kvm_amd nested=1" | sudo tee /etc/modprobe.d/kvm.conf
sudo modprobe -r kvm_amd
sudo modprobe kvm_amd

2. Configure the Guest VM CPU Model

LXD benefits from hardware virtualization and standard host CPU instruction sets. Set the guest CPU to pass-through mode on the host using virsh:

  1. Open the virtual machine configuration:

    virsh edit <vm-name>

  2. Locate the <cpu> block and change the mode to host-passthrough:

    <cpu mode='host-passthrough' check='none'>
  <topology sockets='1' dies='1' cores='4' threads='1'/>
</cpu>

  3. Save, exit, and start the virtual machine:

    virsh start <vm-name>

3. Install and Initialize LXD on the Ubuntu Guest

Log in to the Ubuntu KVM guest virtual machine.

  1. Ensure your system packages are up to date and install LXD via Snap:

    sudo apt update && sudo apt upgrade -y
sudo snap install lxd

  2. Add your current user to the lxd group to manage containers without sudo:

    sudo usermod -aG lxd $USER
newgrp lxd

  3. Initialize the LXD daemon:

    lxd init

    During initialization, accept the defaults for most options:

    • Clustering: No
    • Storage backend: Choose dir, btrfs, or zfs (choose dir if you do not have dedicated block devices or want minimum setup overhead inside the VM).
    • Network bridge: Create a new network bridge (default lxdbr0).
    • IPv4/IPv6: Accept default DHCP/NAT settings.

4. Adjust Guest Kernel and Security Settings

LXD containers rely heavily on cgroups and namespaces. Because the guest is inside a VM, check that AppArmor and necessary mount namespaces are fully operational.

If you encounter issues with unprivileged file mounts or permission errors inside containers, ensure nested AppArmor profiles are permitted in the guest:

sudo systemctl enable --now apparmor

To enable nesting specifically for workloads inside an LXD container, you can apply the nested security flag to containers or profiles:

lxc profile set default security.nesting true

5. Verify the Nested Deployment

Launch a test container inside the Ubuntu VM to confirm everything functions properly:

lxc launch ubuntu:24.04 test-container

Verify that the container is running and has acquired an IP address:

lxc list

Access the container shell to test operation:

lxc exec test-container -- uname -a

The container will execute using the kernel of the KVM guest, running as an isolated system container nested within your virtualized Ubuntu instance.
