How to Update CPU Microcode Securely in Ubuntu

Updating your CPU microcode is essential for patching critical hardware vulnerabilities such as Spectre, Meltdown, and Downfall at the processor level. This guide provides a straightforward method to identify your processor vendor, install officially signed microcode packages through Ubuntu's secure repository system, apply the updates to your bootloader, and verify that the security patches are active.

Step 1: Identify Your CPU and Current Microcode

Open your terminal and determine whether your machine runs on an Intel or AMD processor:

lscpu | grep "Vendor ID"

Next, check the microcode version currently loaded by your kernel:

dmesg | grep -i microcode

Note the current revision number displayed in the output so you can confirm changes after updating.

Step 2: Enable the Restricted Repository

Ubuntu distributes tested and cryptographically signed microcode binaries via its restricted and multiverse repositories. Ensure these repositories are enabled to prevent downloading unverified packages:

sudo add-apt-repository restricted
sudo apt update

Step 3: Install the Vendor-Specific Microcode Package

Install the relevant package based on your processor vendor. Ubuntu's Advanced Package Tool (APT) automatically verifies the cryptographic signature of the package against canonical keys before installation.

For Intel processors:

sudo apt install intel-microcode

For AMD processors:

sudo apt install amd64-microcode

Step 4: Apply Updates to the Initramfs

The installation process typically triggers an update to the initial RAM filesystem (initramfs) automatically. If it does not, or to ensure the new microcode loads at early boot before the kernel initializes, run:

sudo update-initramfs -u

Step 5: Reboot and Verify

Microcode fixes cannot be applied dynamically to running CPU execution units without a reboot. Restart your system:

sudo reboot

After the system boots up, verify that the updated microcode has been loaded:

dmesg | grep -i microcode

Look for lines indicating that the microcode was updated to a newer revision during early boot, confirming the hardware security patches are now in place.
