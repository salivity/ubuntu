Run Bash Scripts on Multiple Ubuntu Servers with Ansible

Managing operations across dozens of nodes manually is time-consuming and error-prone. This guide explains how to use Ansible to distribute and execute a local bash script across 50 remote Ubuntu servers simultaneously. By configuring an inventory file, adjusting Ansible's concurrency settings (forks), and leveraging the built-in script module, you can automate fleet-wide maintenance tasks in seconds without needing to manually copy files to each remote machine.

Prerequisites

Ensure you have the following requirements configured before running commands:

  • Control Node: Ansible installed on your local machine or administrative workstation.
  • Target Nodes: 50 Ubuntu servers reachable over SSH.
  • Authentication: SSH key-based authentication configured from the control node to the remote servers (passwordless sudo access is recommended).
  • Python: Python 3 installed on all target Ubuntu servers (standard on modern Ubuntu releases).

Step 1: Define the Inventory

Create an inventory file named hosts.ini listing your 50 Ubuntu servers. Group them together under a single label, such as [ubuntu_servers].

[ubuntu_servers]
server1.example.com
server2.example.com
server3.example.com
# Add remaining servers through server50
server50.example.com

[ubuntu_servers:vars]
ansible_user=ubuntu
ansible_ssh_private_key_file=~/.ssh/id_rsa
ansible_python_interpreter=/usr/bin/python3

You can also use IP addresses instead of domain names if preferred.

Step 2: Configure Concurrency (Forks)

By default, Ansible processes tasks across 5 remote servers at a time. To run your script across all 50 servers concurrently, increase the forks parameter to 50.

Create or edit an ansible.cfg file in the same directory as your inventory:

[defaults]
inventory = hosts.ini
forks = 50
host_key_checking = False

Alternatively, you can pass -f 50 directly in the command line.

Step 3: Prepare the Bash Script

Create the bash script you want to run on the control node. For example, create maintenance.sh:

#!/usr/bin/env bash
set -e

# Update package lists and perform tasks
apt-get update -y
apt-get autoremove -y

# Output confirmation
echo "Maintenance complete on $(hostname) at $(date)"

Make sure the script is executable locally:

chmod +x maintenance.sh

Step 4: Execute the Script

There are two primary methods to execute the script: using an ad-hoc command or using an Ansible playbook.

Method A: Ad-Hoc Command (Fastest)

The ansible.builtin.script module automatically copies your local script to a temporary directory on the remote targets, executes it, and collects the output.

Run the following command:

ansible ubuntu_servers -m ansible.builtin.script -a "maintenance.sh" --become
  • -m ansible.builtin.script: Tells Ansible to execute the local script on remote nodes.
  • -a "maintenance.sh": Path to your local script.
  • --become: Runs the script with administrative privileges (sudo).

Method B: Ansible Playbook (Recommended for Automation)

For reproducible workflows, define a playbook named run_script.yml:

---
- name: Execute Maintenance Script Across Fleet
  hosts: ubuntu_servers
  become: yes
  tasks:
    - name: Run local bash script remotely
      ansible.builtin.script: maintenance.sh
      register: script_output

    - name: Display script output
      ansible.builtin.debug:
        var: script_output.stdout_lines

Run the playbook:

ansible-playbook run_script.yml

Verification and Troubleshooting

  • Check Connectivity: Before executing heavy scripts, verify all 50 hosts respond by running ansible ubuntu_servers -m ping.
  • Resource Limits: Running 50 concurrent SSH connections requires adequate file descriptors on the control node. Check your limits with ulimit -n and increase if necessary.
  • Failures: If a server fails during execution, Ansible records it in the final summary. You can re-run against failed hosts only using the --limit @run_script.retry flag.
