How to Mask a Systemd Service on Ubuntu

Masking a systemd service on Ubuntu is the strongest method to ensure a service never starts, whether automatically at boot, manually by a user, or as a dependency triggered by another process. This guide explains the difference between disabling and masking a service, demonstrates how to mask an active or inactive service, verifies that the mask is working, and covers how to safely unmask the service when needed.

Why Mask Instead of Disable?

Using systemctl disable only removes the symlinks that trigger the service at boot time. A disabled service can still be started manually by an administrator or triggered automatically if another active service requires it.

Masking a service points its unit file directly to /dev/null. This makes it completely impossible for systemd to load or execute the service under any circumstance until it is explicitly unmasked.

Step 1: Stop the Running Service

Before masking a service, stop any currently active instances to ensure it does not continue running in the background.

sudo systemctl stop <service-name>

Replace <service-name> with the name of the service (for example, apache2 or nginx).

Step 2: Mask the Service

To mask the service, execute the mask command:

sudo systemctl mask <service-name>

The system will respond by creating a symbolic link pointing the unit file to /dev/null:

Created symlink /etc/systemd/system/<service-name>.service → /dev/null.

Step 3: Verify the Mask

Confirm that the service is masked by checking its status:

systemctl status <service-name>

The output will display Loaded: masked (Reason: Unit <service-name>.service is masked.).

You can also test the lock by attempting to start the service manually:

sudo systemctl start <service-name>

Systemd will block the execution and return an error:

Failed to start <service-name>.service: Unit <service-name>.service is masked.

How to Unmask the Service

If you need to restore the service to normal operation in the future, remove the /dev/null symlink using the unmask command:

sudo systemctl unmask <service-name>

After unmasking, the service returns to an inactive or disabled state. You can then enable or start it normally using sudo systemctl start <service-name> or sudo systemctl enable <service-name>.
