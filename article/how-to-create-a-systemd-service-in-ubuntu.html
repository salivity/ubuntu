How to Create a Systemd Service in Ubuntu

Managing custom applications on Ubuntu is most efficiently done using systemd, the default init system and service manager. This guide explains how to create, configure, and manage a custom systemd service file, ensuring your application starts automatically on boot, restarts upon failure, and can be easily controlled using standard systemctl commands.

Step 1: Create Your Application Script

Ensure your application or script is executable and placed in a standard directory, such as /usr/local/bin/.

For example, if you have a Python script located at /usr/local/bin/myapp.py, make sure it has execution permissions:

sudo chmod +x /usr/local/bin/myapp.py

Step 2: Create the Systemd Service File

Systemd service configuration files are stored in the /etc/systemd/system/ directory. Create a new service file using a text editor:

sudo nano /etc/systemd/system/myapp.service

Add the following structure to the file:

[Unit]
Description=My Custom Application Service
After=network.target

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/usr/local/bin
ExecStart=/usr/bin/python3 /usr/local/bin/myapp.py
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target

Key configuration directives explained:

  • Description: A human-readable name for the service.
  • After: Ensures the service starts only after the network interface is up.
  • User: Specifies the system user that runs the application (replace ubuntu with your actual username).
  • ExecStart: The exact command used to launch the application.
  • Restart: Automatically restarts the application if it crashes (on-failure).
  • WantedBy: Defines the boot target; multi-user.target is standard for non-graphical multi-user systems.

Save and close the file.

Step 3: Set File Permissions

Set the appropriate permissions on the service file so systemd can execute it properly:

sudo chmod 644 /etc/systemd/system/myapp.service

Step 4: Reload the Systemd Daemon

Whenever you create or modify a service file, you must tell systemd to reload its configuration files:

sudo systemctl daemon-reload

Step 5: Start and Enable the Service

Start your custom application service immediately:

sudo systemctl start myapp.service

Enable the service so that it automatically starts whenever the system boots up:

sudo systemctl enable myapp.service

Step 6: Verify Service Status and Logs

To verify that your application is running correctly, check its status:

sudo systemctl status myapp.service

To view real-time log output generated by your custom service, use journalctl:

sudo journalctl -u myapp.service -f
