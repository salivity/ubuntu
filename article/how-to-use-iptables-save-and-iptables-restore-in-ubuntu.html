How to Use iptables-save and iptables-restore in Ubuntu

This article explains how to capture, persist, and apply firewall and routing rules using the iptables-save and iptables-restore utilities on Ubuntu. You will learn the command syntax for dumping and importing rulesets, how to write a custom bash routing script that automatically loads these configurations, and how to execute the script during system startup.

Understanding the Commands

Linux kernel firewall rules configured via iptables exist only in memory and are wiped out upon reboot. The utilities iptables-save and iptables-restore handle persistence:

  • iptables-save: Dumps the current active packet filtering and routing table rules from kernel memory into a structured text format on standard output.
  • iptables-restore: Parses the structured text file generated by iptables-save and replaces or injects the rules directly into the kernel atomically, preventing partial configuration states.

Step 1: Exporting Existing Rules

Before writing an automation script, configure your routing or NAT rules manually, then save the current state to a persistent file location such as /etc/iptables/.

Create the directory if it does not exist:

sudo mkdir -p /etc/iptables

Dump the active IPv4 ruleset to a file:

sudo iptables-save > /etc/iptables/rules.v4

To export IPv6 rules, run:

sudo ip6tables-save > /etc/iptables/rules.v6

Step 2: Creating a Custom Routing Script

A custom routing script enables IP forwarding in the kernel, prepares interfaces, and restores the saved rules using iptables-restore.

Create a new script at /usr/local/bin/custom-routing.sh:

sudo nano /usr/local/bin/custom-routing.sh

Add the following logic:

#!/bin/bash
set -e

# Path to the saved rules
RULES_FILE="/etc/iptables/rules.v4"

# 1. Enable IPv4 packet forwarding in the kernel
sysctl -w net.ipv4.ip_forward=1 > /dev/null

# 2. Check if the rules file exists and restore it
if [ -f "$RULES_FILE" ]; then
    echo "Restoring iptables rules from $RULES_FILE..."
    iptables-restore < "$RULES_FILE"
else
    echo "Error: Rules file $RULES_FILE not found." >&2
    exit 1
fi

echo "Routing and firewall rules successfully applied."

Make the script executable:

sudo chmod +x /usr/local/bin/custom-routing.sh

Script Variations: Modifying Rules Inline

If your script applies dynamic rules based on environment variables or dynamic interfaces before saving or restoring, you can combine the commands using standard input/output redirection:

# Append rules dynamically and reload
iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
iptables-save > /etc/iptables/rules.v4
iptables-restore < /etc/iptables/rules.v4

Using iptables-restore with the -c (or --counters) option preserves packet and byte counters, while the -n (or --noflush) option prevents flushing existing table rules before loading the new set.

Step 3: Automating the Script at Boot via Systemd

To ensure the routing script runs automatically when Ubuntu boots, create a systemd service unit.

Create /etc/systemd/system/custom-routing.service:

sudo nano /etc/systemd/system/custom-routing.service

Add the following configuration:

[Unit]
Description=Apply Custom iptables Routing and Rules
After=network.target

[Service]
Type=oneshot
ExecStart=/usr/local/bin/custom-routing.sh
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target

Reload the systemd manager configuration, enable the service to start at boot, and run it immediately:

sudo systemctl daemon-reload
sudo systemctl enable custom-routing.service
sudo systemctl start custom-routing.service

Verification

To verify that the rules were successfully applied by your script, inspect the active NAT and forwarding tables:

sudo iptables -L -v -n
sudo iptables -t nat -L -v -n

Check the status of the systemd service to confirm proper execution:

sudo systemctl status custom-routing.service
