Configure 2FA for SSH Logins on Ubuntu

Securing an Ubuntu server with two-factor authentication (2FA) adds a critical second layer of security to your Secure Shell (SSH) access, requiring both a primary credential (password or SSH key) and a time-based one-time password (TOTP) from an authenticator app. This guide details the step-by-step process of installing the Google Authenticator PAM module, generating user secret keys, updating the SSH daemon configuration, and testing the setup safely.

Step 1: Update Packages and Install the PAM Module

Begin by updating your system package index and installing the Google Authenticator Pluggable Authentication Module (PAM).

sudo apt update
sudo apt install libpam-google-authenticator -y

Step 2: Generate the 2FA Secret Key

Run the initialization tool in your terminal to set up 2FA for your user account:

google-authenticator

Respond to the setup prompts:

  1. Make tokens time-based? Enter y.
  2. Scan the QR Code: Use an authenticator app (such as Google Authenticator, Authy, or 1Password) to scan the displayed QR code, or manually enter the secret key.
  3. Emergency Scratch Codes: Record the emergency recovery codes shown on the screen in a safe location.
  4. Update the configuration file? Enter y.
  5. Disallow multiple uses of the same token? Enter y.
  6. Increase time window to prevent sync issues? Enter n (or y if you frequently experience clock drift).
  7. Enable rate-limiting? Enter y.

Step 3: Configure PAM for SSH

Edit the SSH PAM configuration file to require the authentication module.

sudo nano /etc/pam.d/sshd

Add the following line to the bottom of the file:

auth required pam_google_authenticator.so nullok

Note: Adding nullok allows users who have not yet set up 2FA to log in using only their password or SSH key. Remove nullok once all users have configured 2FA to strictly enforce it across the server.

Save and close the file (Ctrl + O, Enter, then Ctrl + X).

Step 4: Configure the SSH Daemon

Modify the main SSH configuration file to enable interactive authentication challenges.

sudo nano /etc/ssh/sshd_config

Locate and update the following settings:

  1. Set keyboard-interactive authentication to yes:

    KbdInteractiveAuthentication yes

    (On older Ubuntu versions, look for ChallengeResponseAuthentication yes.)

  2. Optional (Require SSH Key + 2FA): If you use SSH keys and want to require both the key AND the 2FA code, add this line at the bottom of the file:

    AuthenticationMethods publickey,keyboard-interactive

Save and close the file.

Step 5: Restart the SSH Service

Apply the changes by restarting the SSH service:

sudo systemctl restart ssh

Step 6: Verify the Setup

Do not close your current terminal session. Open a new terminal window or tab and test logging in to your server via SSH.

ssh username@your_server_ip

Depending on your configuration, the server will prompt you for your SSH key passphrase/password, followed by Verification code:, where you must enter the 6-digit code generated by your authenticator app.
