Role of acpid Daemon in Managing Ubuntu Power Events

The Advanced Configuration and Power Interface daemon (acpid) is a background service in Ubuntu designed to capture and deliver hardware-level power events to user-space applications. This article explains the primary role of acpid on Ubuntu systems, how it intercepts events like laptop lid closures and power button presses, how event rules are processed, and how acpid coexists with modern init systems like systemd.

Understanding the Role of acpid

The primary responsibility of acpid is to monitor the system kernel for Advanced Configuration and Power Interface (ACPI) signals generated by hardware actions. When a user interacts with system power controls, the Linux kernel generates an ACPI event. acpid catches these events and translates them into actionable shell scripts or system commands.

Common power events handled by acpid include:

  • Power Button Presses: Shutting down or putting the system into sleep mode.
  • Lid Open/Close Events: Triggering suspend mode when a laptop lid is closed.
  • AC Adapter Plug/Unplug: Changing power profiles when switching between battery and wall power.
  • Sleep/Wake Buttons: Placing the computer in standby or hibernating.
  • Thermal/Fan Events: Responding to changes in system temperature.

How acpid Processes Events

The acpid service operates through a simple event-matching mechanism defined in configuration files located in the /etc/acpi/ directory structure.

  1. Event Interception: acpid opens /dev/input/evdev or /proc/acpi/event to listen continuously for incoming hardware events.
  2. Rule Matching: When an event occurs, acpid checks the configuration files located in /etc/acpi/events/. These files use regular expressions to match specific event strings.
  3. Action Execution: If an event matches a defined rule, acpid executes the associated action script, typically located in /etc/acpi/actions/ or /etc/acpi/.

Example Configuration Structure

An event configuration file in /etc/acpi/events/powerbtn generally looks like this:

event=button/power
action=/etc/acpi/powerbtn.sh

When the power button is pressed, acpid detects the button/power event and executes /etc/acpi/powerbtn.sh.

acpid vs. systemd-logind on Modern Ubuntu

In modern versions of Ubuntu, systemd-logind handles many common power management tasks by default (such as lid closures and power button actions). However, acpid remains valuable for specific use cases:

  • Custom Event Scripting: acpid allows administrators to easily write custom shell scripts for niche hardware events without modifying systemd configurations.
  • Legacy Hardware Support: Older systems or specialized embedded hardware often rely on acpid for full ACPI event handling.
  • Headless Servers: On servers without a desktop environment, acpid provides lightweight power event management without needing full desktop display managers.

When both services run simultaneously, systemd-logind typically handles standard power actions unless explicitly configured to ignore them, allowing acpid to manage custom behaviors.
