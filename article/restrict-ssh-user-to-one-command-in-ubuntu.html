Restrict SSH User to One Command in Ubuntu

Restricting an SSH user to execute only a specific command enhances server security by preventing interactive shell access and unauthorized tasks. On Ubuntu, this is achieved natively through OpenSSH by prepending the command option to the user's public key in the ~/.ssh/authorized_keys file. This guide covers how to locate the file, configure the directive, add hardening flags, and test the restricted connection.

1. Access the Target User's authorized_keys File

Log into your Ubuntu server as a user with administrative privileges, or directly as the user whose access you want to restrict.

Navigate to the user's .ssh directory and open the authorized_keys file:

nano /home/<username>/.ssh/authorized_keys

Ensure the correct file permissions are applied:

chmod 700 /home/<username>/.ssh
chmod 600 /home/<username>/.ssh/authorized_keys

2. Add the command Directive

In the authorized_keys file, prepend the command="..." attribute directly before the SSH key type (e.g., ssh-ed25519 or ssh-rsa). Use the absolute path to the executable or script.

Example format:

command="/usr/local/bin/backup-script.sh" ssh-ed25519 AAAAC3NzaC1lZDI1NTE5... user@client

When this key is used to authenticate, the server immediately executes /usr/local/bin/backup-script.sh and terminates the session upon completion.

3. Harden the Connection with Security Directives

By default, an SSH session may allow port forwarding, agent forwarding, or terminal allocation (PTY). To fully lock down the session, combine the command option with additional OpenSSH security flags separated by commas:

  • no-port-forwarding: Disables local and remote TCP port forwarding.
  • no-X11-forwarding: Disables X11 graphical forwarding.
  • no-agent-forwarding: Prevents forwarding the authentication agent.
  • no-pty: Prevents the allocation of a pseudo-terminal.

Updated configuration entry:

command="/usr/local/bin/backup-script.sh",no-port-forwarding,no-X11-forwarding,no-agent-forwarding,no-pty ssh-ed25519 AAAAC3NzaC1lZDI1NTE5... user@client

Save and exit the text editor.

4. Test the Configuration

From the client machine, connect to the Ubuntu server using the corresponding private key:

ssh -i ~/.ssh/id_ed25519 <username>@<server-ip>

Upon connection:

  • The specified command runs automatically.
  • Any command specified by the client (e.g., ssh user@server "ls -l") is ignored in favor of the configured command.
  • Once the command finishes executing, the connection closes automatically without offering an interactive shell.
