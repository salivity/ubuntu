Using Nohup for Long-Running SSH Tasks on Ubuntu

When managing an Ubuntu server remotely via SSH, closing the connection or experiencing an unexpected network drop will terminate any active commands running in that session. The nohup (short for "no hang up") command prevents this termination by allowing processes to continue executing in the background even after you log out. This article explains how nohup functions, why it is critical for long-running SSH tasks, and how to use it effectively on Ubuntu.

The Problem: SIGHUP Signals in SSH Sessions

When you establish an SSH connection to an Ubuntu machine, the operating system assigns a pseudo-terminal to your session. Every program you launch within that terminal runs as a child process of your shell.

When your SSH connection terminates—whether intentionally via exit, accidentally due to a dropped internet connection, or because of a timeout—the operating system sends a SIGHUP (Signal Hang Up, signal number 1) to the controlling shell. The shell immediately propagates this signal to all of its child processes, instructing them to abort immediately. This means that an unshielded command like a database migration, file backup, or compilation job will fail mid-execution if the session closes.

How nohup Solves the Problem

The primary purpose of the nohup command is to intercept and ignore the SIGHUP signal. By wrapping an executable with nohup, the resulting process becomes immune to hangup signals emitted when the terminal session ends. As a result, the command will continue running uninterrupted until it finishes its task or is explicitly terminated by a user or system shutdown.

Output Redirection

Because a disconnected process no longer has a terminal screen to print its output to, nohup automatically handles standard output (stdout) and standard error (stderr):

  • By default, if stdout is bound to a terminal, nohup redirects all output to a file named nohup.out in the current working directory.
  • If the current directory is not writable, nohup automatically writes the output to ~/nohup.out.
  • You can also manually redirect output to custom log files to keep track of multiple jobs.

Practical Usage Syntax

To run a persistent process over SSH, nohup is typically paired with the & operator, which places the job into the background so you can regain control of your shell prompt.

Basic execution:

nohup python3 long_script.py &

Custom logging execution:

nohup ./data_backup.sh > backup.log 2>&1 &

In this example:

  • nohup prevents the process from dying upon SSH exit.
  • > backup.log redirects standard output to a designated log file.
  • 2>&1 redirects standard error to the same location as standard output.
  • & sends the command to the background, freeing your terminal immediately.

After starting the command, you can safely type exit to close your SSH session. The process will persist on the Ubuntu server.

Monitoring and Managing nohup Processes

Once disconnected from the terminal, the process runs independently. To monitor or stop the task during a subsequent SSH session, you can locate its Process ID (PID) using standard process-management tools:

ps aux | grep script_name

To review the ongoing output of the backgrounded task in real-time:

tail -f nohup.out

To end the process manually:

kill -9 <PID>

By decoupling processes from the lifecycle of your remote terminal, nohup provides a lightweight, dependency-free solution for executing persistent, non-interactive tasks on remote Ubuntu servers.
