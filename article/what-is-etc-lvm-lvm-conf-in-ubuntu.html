What is /etc/lvm/lvm.conf in Ubuntu?

The /etc/lvm/lvm.conf file is the central configuration file for the Logical Volume Manager (LVM) in Ubuntu and other Linux distributions. It defines system-wide settings that govern how LVM detects physical storage devices, manages volume groups, allocates logical volumes, and handles automatic activation during system boot. This article breaks down the primary purpose of /etc/lvm/lvm.conf, its key configuration sections, common use cases, and best practices for modifying it.

Primary Purpose of /etc/lvm/lvm.conf

In Ubuntu, LVM abstracts physical hard drives and SSDs into flexible storage pools. The /etc/lvm/lvm.conf file controls the operational behavior of all LVM tools (such as pvcreate, vgcreate, lvcreate, and lvs). Without this file, LVM relies entirely on built-in default values, which may not suit specialized server environments, SAN attachments, or complex storage topologies.

By editing /etc/lvm/lvm.conf, administrators can: * Restrict which storage devices LVM scans for metadata. * Tune performance and extent allocation strategies. * Configure metadata backup and restore retention rules. * Adjust locking mechanisms to prevent data corruption in multi-node setups. * Control log verbosity for troubleshooting volume issues.

Key Configuration Sections

The file uses a structured syntax broken into functional sections. The most critical sections include:

1. devices

Controls how LVM interacts with underlying disk hardware. * filter: Defines rules for scanning specific block devices and ignoring others (e.g., ignoring loop devices or specific SAN paths). * global_filter: Similar to filter, but enforced globally across system services like udev. * multipath_component_detection: Prevents LVM from using raw underlying paths when multipathing software is managing the storage.

2. allocation

Determines how LVM places extents on physical volumes when creating or extending logical volumes. * Configures default policies (e.g., contiguous, cling, or normal). * Sets stripe size defaults and thin-pool allocation thresholds.

3. activation

Manages how logical volumes become active and accessible to the operating system. * auto_activation_volume_list: Specifies which volume groups or logical volumes automatically activate at boot. * thin_pool_autoextend_threshold: Defines when a thin-provisioned storage pool automatically expands to prevent running out of space.

4. global

Handles overall LVM system behavior. * locking_type: Sets file, local, or cluster locking mechanisms (sanlock or dlm). * use_lvmetad: Historical setting (mostly disabled or deprecated in newer Ubuntu releases) regarding metadata caching daemons.

5. backup and archive

Defines automatic backup settings for LVM metadata. * Specifies where automatic configuration backups are saved (typically /etc/lvm/backup/ and /etc/lvm/archive/). * Sets retention policies for how many historic volume layouts are kept.

Common Use Cases for Modifying /etc/lvm/lvm.conf

Excluding Drives from LVM (Device Filtering)

If a system has software RAID, multipath drives, or guest virtual machine drives, you may want LVM to ignore specific disks to avoid duplicate UUID conflicts or accidental overwrites.

Example filter setting:

devices {
    filter = [ "a|^/dev/sda.*|", "r|/dev/sdb.*|" ]
}

This rule explicitly accepts (a) /dev/sda partitions and rejects (r) /dev/sdb partitions.

Enabling Auto-Expansion for Thin Pools

For thin-provisioned logical volumes, you can configure LVM to automatically extend thin pools when they reach a certain capacity threshold:

activation {
    thin_pool_autoextend_threshold = 80
    thin_pool_autoextend_percent = 20
}

When a pool reaches 80% capacity, LVM automatically extends its size by 20%.

Best Practices When Editing /etc/lvm/lvm.conf

  1. Always Create a Backup: Before saving changes, create a copy of the active file:

    sudo cp /etc/lvm/lvm.conf /etc/lvm/lvm.conf.bak

  2. Validate Syntax: Test your configuration changes using lvmconfig or pvscan before rebooting the server.

  3. Update Initramfs: If your changes affect storage required during early boot (such as root volume filters), update the initial RAM disk:

    sudo update-initramfs -u
