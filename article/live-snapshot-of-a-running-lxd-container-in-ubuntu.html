Live Snapshot of a Running LXD Container in Ubuntu

This guide covers how to take a live snapshot of a running LXD container in Ubuntu, allowing you to capture the current state of your instance without shutting it down. You will learn the exact command syntax required to capture both the container's disk and active memory, as well as the prerequisites needed to support stateful snapshots.

The Command for a Live Stateful Snapshot

To take a true "live" snapshot that saves both the filesystem and the running memory state (RAM) of an LXD container, use the lxc snapshot command with the --stateful flag:

lxc snapshot <container-name> <snapshot-name> --stateful

For example, to take a live snapshot named backup-state of a running container named web-server, execute:

lxc snapshot web-server backup-state --stateful

Prerequisites for Stateful Snapshots

For the --stateful flag to work, LXD relies on CRIU (Checkpoint/Restore in Userspace). Ensure CRIU is installed and properly configured on your Ubuntu host:

sudo apt update
sudo apt install criu

If CRIU is not available or if the container configuration prevents live memory dumps, the command will return an error indicating that checkpointing failed.

Standard Snapshot of a Running Container

If you only need to capture the filesystem state of a running container without saving the volatile memory (RAM), omit the --stateful flag:

lxc snapshot web-server backup-disk-only

LXD leverages the underlying storage driver (such as ZFS or Btrfs) to create an instantaneous, point-in-time copy of the container's disk data without stopping the container.

Viewing and Restoring Snapshots

To verify that the snapshot was created, run:

lxc info web-server

The output will list all snapshots under the "Snapshots" section, indicating whether each snapshot is stateful.

To restore a stateful snapshot and resume execution from the exact point it was saved:

lxc restore web-server backup-state --stateful
