How Kdump Captures Kernel Crash Dumps on Ubuntu

This article explains the role of the kdump service in capturing kernel crash dumps on Ubuntu systems. It outlines the core mechanics of how kdump operates during a fatal system failure, highlights its reliance on kexec and secondary memory reservation, and covers the essential tools used to preserve, compress, and analyze system memory for post-mortem diagnostics.

What is Kdump?

Kdump is the standard kernel crash-dumping mechanism used in Linux environments, including Ubuntu. Its primary role is to reliably capture the contents of the system's memory (known as a vmcore) at the exact moment a kernel panic, hardware exception, or fatal crash occurs. This memory snapshot is crucial for system administrators and developers to determine the root cause of the failure using debugging utilities like crash or gdb.

How Kdump Works

Traditional crash-dumping methods often fail because attempting to write a dump file using the already corrupted or panicked kernel can lead to data corruption or a complete system freeze. Kdump circumvents this risk through a two-kernel architecture:

  1. Memory Reservation: During normal boot, Ubuntu reserves a dedicated region of physical memory via the crashkernel boot parameter in GRUB. The primary production kernel runs normally and cannot touch this reserved space.
  2. Kexec Mechanism: When a kernel panic triggers, kdump utilizes the kexec system call. kexec allows the system to instantly boot a new, lightweight capture kernel from the reserved memory space without passing through the BIOS or UEFI firmware initialization stages.
  3. Capture and Dump: The newly booted capture kernel accesses the primary kernel's memory space via /proc/vmcore in a read-only state. It copies this data to a persistent storage location, such as a local disk partition (/var/crash/) or a remote network server (NFS/SSH).
  4. Reboot: Once the dump collection is finished, the capture kernel automatically reboots the system back into the primary production environment, minimizing total downtime.

Key Kdump Components on Ubuntu

On Ubuntu, kdump functionality is primarily managed by the linux-crashdump package, which configures several interrelated tools:

  • kexec-tools: Provides the kexec binary required to load and boot the secondary capture kernel directly from memory.
  • kdump-tools: The Ubuntu-specific service layer that manages configuration, checks kernel reservation status, and initiates dump generation upon failure.
  • makedumpfile: A utility used by the capture kernel to optimize the dump file. It filters out unnecessary pages (such as free pages, zero-filled pages, and user-space cache) and compresses the remaining memory data to drastically reduce dump file size and save storage space.

Importance in Production Environments

The kdump service transforms unrecoverable kernel crashes into actionable diagnostic data. Without kdump, transient hardware faults, driver bugs, or kernel regressions would leave no trace other than an abrupt freeze or reboot. By isolating the capture process in a clean kernel environment, Ubuntu systems maintain dump integrity, ensuring high availability infrastructure can be quickly diagnosed and stabilized.
