Automate Ubuntu First Boot with Cloud-Init

Automating the initial setup of an Ubuntu cloud instance is essential for scalable and efficient infrastructure management. This article explains how to use cloud-init, the industry-standard tool for handling early initialization of cloud instances. You will learn how to create a user-data configuration file to automatically update packages, manage system users, configure SSH keys, and execute post-deployment scripts during the server’s very first boot.

Understanding Cloud-Init and User-Data

cloud-init is pre-installed on standard Ubuntu cloud images provided by AWS, Azure, Google Cloud, DigitalOcean, and OpenStack. When a new instance boots, cloud-init searches for metadata and custom user-provided configuration scripts called user-data.

User-data scripts are typically written in YAML using the #cloud-config directive on the very first line.

Creating a Cloud-Init Configuration File

Below is a practical #cloud-config example demonstrating common provisioning tasks: system updates, user creation, package installation, and custom script execution.

#cloud-config

# Update package repositories and upgrade installed packages on first boot
package_update: true
package_upgrade: true

# Install essential packages
packages:
  - curl
  - git
  - ufw
  - nginx

# Create a new non-root user with sudo privileges
users:
  - name: deployer
    gecos: Deploy User
    sudo: ALL=(ALL) NOPASSWD:ALL
    groups: sudo, www-data
    shell: /bin/bash
    ssh_authorized_keys:
      - ssh-rsa AAAAB3NzaC1yc2EAAAADAQABAAABAQC... user@example.com

# Disable root login via SSH for security
disable_root: true
ssh_pwauth: false

# Write custom files to disk
write_files:
  - path: /etc/motd
    content: |
      --------------------------------------------------
      Welcome to your automated Ubuntu Cloud Instance!
      Managed by cloud-init.
      --------------------------------------------------

# Run commands at the end of the initialization process
runcmd:
  - systemctl enable nginx
  - systemctl start nginx
  - ufw allow 'Nginx Full'
  - ufw allow OpenSSH
  - ufw --force enable

Essential Cloud-Init Directives Explained

  • package_update & package_upgrade: Refreshes the apt database and upgrades all installed packages to their latest versions.
  • packages: Accepts a list of Ubuntu package names to install via apt-get install.
  • users: Defines new system accounts, grants sudo privileges, and imports public SSH keys into the user’s ~/.ssh/authorized_keys file.
  • write_files: Generates text files on the target filesystem with specific permissions and paths.
  • runcmd: Executes shell commands sequentially in the late boot stage.

How to Pass User-Data to Your Cloud Instance

The exact method for passing your cloud-init file depends on the platform or cloud provider you use:

1. Cloud Management Consoles (AWS, DigitalOcean, GCP)

Most cloud dashboards provide a User Data or Advanced Options text field during the instance creation wizard. Simply paste the entire #cloud-config snippet into this field.

2. AWS CLI

Pass the configuration file using the --user-data flag:

aws ec2 run-instances \
    --image-id ami-0c55b159cbfafe1f0 \
    --count 1 \
    --instance-type t3.micro \
    --key-name MyKeyPair \
    --user-data file://cloud-config.yaml

3. Multipass (Local Ubuntu Testing)

You can test your configuration locally on your computer using Ubuntu’s official multipass VM manager:

multipass launch --name test-instance --cloud-init cloud-config.yaml

Verification and Debugging

Once your instance finishes launching, SSH into the machine to verify that your configuration ran successfully.

Check the overall status of cloud-init:

cloud-init status

Inspect execution logs to troubleshoot any failures: * /var/log/cloud-init.log: Detailed internal logs detailing cloud-init execution steps and module status. * /var/log/cloud-init-output.log: Captures stdout and stderr output from commands defined under runcmd or package installation steps.

If you edit /etc/cloud/cloud.cfg or user-data on a running system for testing purposes, force cloud-init to re-run using:

sudo cloud-init clean --logs
sudo cloud-init init
