Configure iSCSI Target with targetcli on Ubuntu

This guide outlines the process of configuring an iSCSI target on an Ubuntu server to export shared block storage across a cluster. By utilizing targetcli-fb (an administration shell for the Linux-IO Target subsystem), you will prepare a storage backstore, establish an iSCSI Qualified Name (IQN), map logical units (LUNs), and configure Access Control Lists (ACLs) to enable secure block-level access for cluster nodes.

Prerequisites

  • An Ubuntu server configured with root or sudo access.
  • A dedicated raw disk, partition, or LVM logical volume (e.g., /dev/sdb or /dev/vg_cluster/lv_shared).
  • Static IP networking configured on the target node.
  • The IQN names of the initiator nodes (clients) that will connect to this target.

Step 1: Install targetcli

Update your package repositories and install the targetcli-fb package:

sudo apt update
sudo apt install targetcli-fb -y

Verify and enable the target service to ensure configurations persist across reboots:

sudo systemctl enable --now target

Step 2: Open the targetcli Interface

Access the interactive configuration shell:

sudo targetcli

You will enter an interactive shell (/>). The interface uses a hierarchical filesystem-like structure. You can use standard commands such as ls, cd, and pwd to navigate.

Step 3: Define a Storage Backstore

A backstore defines the physical or logical storage device provided to clients. For high performance in a clustered environment, a block device or LVM volume is recommended.

From the targetcli shell:

cd /backstores/block
create name=cluster_block dev=/dev/vg_cluster/lv_shared

Replace /dev/vg_cluster/lv_shared with the path to your actual block device.

Step 4: Create the iSCSI Target

Next, create the target infrastructure. This generates an iSCSI Qualified Name (IQN) and a default Target Portal Group (TPG).

cd /iscsi
create

By default, this command generates an IQN automatically (e.g., iqn.2003-01.org.linux-iscsi.ubuntu.x8664:sn.123456789abc). You can also specify a custom IQN:

create iqn.2024-01.com.example:cluster-target

Navigate to the generated target's Target Portal Group:

cd /iscsi/iqn.2024-01.com.example:cluster-target/tpg1/

Step 5: Create a Logical Unit Number (LUN)

Link the backstore created in Step 3 to the target portal group:

cd luns
create /backstores/block/cluster_block
cd ..

This binds cluster_block as lun0 within tpg1.

Step 6: Configure Access Control Lists (ACLs)

By default, iSCSI targets reject unauthorized initiators. To allow cluster nodes to connect, register each node’s initiator IQN.

Run the following for each cluster initiator:

cd acls
create iqn.2024-01.com.example:node01-initiator
create iqn.2024-01.com.example:node02-initiator
cd ..

Note: The initiator IQN can typically be found inside /etc/iscsi/initiatorname.iscsi on each client node.

Step 7: Configure the Network Portal

The target automatically binds to 0.0.0.0:3260, listening on all interfaces. If you want to bind to a specific cluster storage subnet:

cd portals
delete 0.0.0.0 3260
create 192.168.10.50 3260
cd ..

Replace 192.168.10.50 with your dedicated storage network IP.

Step 8: Save and Verify Configuration

Review the completed hierarchy:

cd /
ls

The output displays the backstore, target, LUN, and ACL relationships.

Save the configuration to disk and exit:

saveconfig
exit

Step 9: Configure Firewall Rules

If UFW is active on the Ubuntu target server, allow incoming traffic on the default iSCSI port (3260):

sudo ufw allow from <CLUSTER_SUBNET>/24 to any port 3260 proto tcp
sudo ufw reload

The iSCSI block storage target is now fully configured and accessible to the authorized initiator nodes within the cluster.
