How to Run Privileged LXD Containers on Ubuntu

Running an LXD container in privileged mode allows the root user inside the container to map directly to the root user (UID 0) on the Ubuntu host. While unprivileged containers are the secure default in LXD, certain workloads—such as running Docker inside LXD, nesting containers, or accessing specific hardware devices—require elevated privileges. This guide provides the direct commands needed to launch a new privileged container or convert an existing unprivileged container on an Ubuntu server.

Creating a New Privileged Container

To launch a new container directly into privileged mode, pass the security.privileged=true configuration flag during the initialization or launch command.

Run the following command, replacing my-container with your desired container name and ubuntu:24.04 with your preferred image:

lxc launch ubuntu:24.04 my-container -c security.privileged=true

Once the container starts, it will operate with host-mapped root privileges.

Converting an Existing Container to Privileged Mode

If you already have an existing unprivileged container, you can update its configuration. Changing this setting requires stopping the container first.

  1. Stop the running container:

    lxc stop my-container

  2. Update the configuration to enable privileged mode:

    lxc config set my-container security.privileged true

  3. Start the container again:

    lxc start my-container

Enabling Privileged Mode via Profiles

If you need multiple containers to run in privileged mode, you can assign the configuration via an LXD profile.

  1. Create a new profile:

    lxc profile create privileged-profile

  2. Set the privileged key on the profile:

    lxc profile set privileged-profile security.privileged true

  3. Apply the profile to an existing container:

    lxc profile add my-container privileged-profile

Verifying Privileged Status

To confirm that the container is running in privileged mode, inspect its configuration:

lxc config get my-container security.privileged

If configured correctly, the command will output:

true

You can also verify the UID mapping by checking process IDs from the host system. Run top or ps aux inside the container, then search for that process on the host using ps -ef. On a privileged container, the process will display root as the owner on the host, rather than an unprivileged subuid (such as 1000000).
