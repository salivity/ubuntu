How to Install Vault as a Systemd Service on Ubuntu

This guide provides a straightforward walkthrough for installing HashiCorp Vault on Ubuntu using the standalone binary and configuring it to run securely as a systemd service. By following these steps, you will set up a dedicated system user, prepare storage directories, define a baseline HCL configuration, and manage the Vault service lifecycle using Ubuntu's native service manager.

Prerequisites

Ensure you have administrative (sudo) privileges and that essential utilities are installed:

sudo apt update
sudo apt install -y curl unzip

Step 1: Download and Install the Vault Binary

Fetch the desired Vault binary directly from HashiCorp's release registry, extract it, and move it to your system execution path.

  1. Export the desired version and system architecture:

    export VAULT_VERSION="1.15.6"
export ARCH="amd64"

  2. Download and unzip the archive:

    curl -remote-name https://releases.hashicorp.com/vault/${VAULT_VERSION}/vault_${VAULT_VERSION}_linux_${ARCH}.zip
unzip vault_${VAULT_VERSION}_linux_${ARCH}.zip

  3. Move the binary to /usr/local/bin/ and set proper ownership:

    sudo chown root:root vault
sudo mv vault /usr/local/bin/

  4. Verify the installation:

    vault --version

  5. Enable the binary to lock memory without running as full root (preventing secrets from being swapped to disk):

    sudo setcap cap_ipc_lock=+ep /usr/local/bin/vault

Step 2: Create a Dedicated System User and Directories

For security reasons, Vault must run under an unprivileged dedicated service account.

  1. Create a vault system group and user:

    sudo useradd --system --home /etc/vault.d --shell /bin/false vault

  2. Create directories for configuration and persistent data storage:

    sudo mkdir --parents /etc/vault.d
sudo mkdir --parents /opt/vault/data

  3. Set ownership and restrict permissions:

    sudo chown -R vault:vault /etc/vault.d /opt/vault/data
sudo chmod 700 /etc/vault.d /opt/vault/data

Step 3: Create the Vault Configuration File

Create the primary configuration file in HashiCorp Configuration Language (HCL).

  1. Open /etc/vault.d/vault.hcl in a text editor:

    sudo nano /etc/vault.d/vault.hcl

  2. Add the following basic configuration (adjust tls_disable = 1 to 0 and provide certificate paths for production environments):

    storage "file" {
  path = "/opt/vault/data"
}

listener "tcp" {
  address     = "127.0.0.1:8200"
  tls_disable = 1
}

api_addr     = "http://127.0.0.1:8200"
cluster_addr = "https://127.0.0.1:8201"
ui           = true
disable_mlock = false

  3. Secure the configuration file permissions:

    sudo chown vault:vault /etc/vault.d/vault.hcl
sudo chmod 640 /etc/vault.d/vault.hcl

Step 4: Configure the systemd Service

Create a systemd unit file to manage the Vault lifecycle.

  1. Create /etc/systemd/system/vault.service:

    sudo nano /etc/systemd/system/vault.service

  2. Paste the following unit definition:

    [Unit]
Description="HashiCorp Vault - A tool for managing secrets"
Documentation=https://developer.hashicorp.com/vault/docs
Requires=network-online.target
After=network-online.target
ConditionFileNotEmpty=/etc/vault.d/vault.hcl
StartLimitIntervalSec=60
StartLimitBurst=3

[Service]
Type=notify
User=vault
Group=vault
ProtectSystem=full
ProtectHome=read-only
PrivateTmp=yes
PrivateDevices=yes
SecureBits=keep-caps
AmbientCapabilities=CAP_IPC_LOCK
Capabilities=CAP_IPC_LOCK+ep
CapabilityBoundingSet=CAP_SYSLOG CAP_IPC_LOCK
NoNewPrivileges=yes
ExecStart=/usr/local/bin/vault server -config=/etc/vault.d/vault.hcl
ExecReload=/bin/kill --signal HUP $MAINPID
KillMode=process
KillSignal=SIGINT
Restart=on-failure
RestartSec=5
TimeoutStopSec=30
LimitNOFILE=65536
LimitMEMLOCK=infinity

[Install]
WantedBy=multi-user.target

Step 5: Start and Enable the Vault Service

  1. Reload systemd to recognize the new unit file:

    sudo systemctl daemon-reload

  2. Enable the service to start automatically at boot:

    sudo systemctl enable vault

  3. Start the service:

    sudo systemctl start vault

  4. Check the service status:

    sudo systemctl status vault

Step 6: Initialize the Vault Instance

Now that Vault is running, it must be initialized and unsealed before storing secrets.

  1. Configure your local shell environment:

    export VAULT_ADDR="http://127.0.0.1:8200"

  2. Run the initialization command:

    vault operator init

  3. Save the generated Unseal Keys and Initial Root Token in a secure password manager.

  4. Unseal the vault by running the following command three times using three distinct unseal keys:

    vault operator unseal

Once unsealed, authenticate using the root token to begin provisioning secrets:

vault login <INITIAL_ROOT_TOKEN>
