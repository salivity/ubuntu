How to Use mokutil for Secure Boot on Ubuntu

The mokutil command is a dedicated Linux utility used to manage Machine Owner Keys (MOK) within UEFI Secure Boot environments on Ubuntu. This article explains the role of mokutil, how it interfaces with the UEFI firmware and the Shim bootloader, and the practical commands needed to check Secure Boot status, enroll custom signing keys for third-party kernel modules, and manage key revocations.

Understanding the Role of mokutil

UEFI Secure Boot prevents unauthorized bootloaders and kernel drivers from running by verifying their digital signatures against a trusted keystore embedded in system firmware. Because canonical hardware vendors only include Microsoft-approved keys in firmware by default, standard Linux distributions use a signed intermediate first-stage bootloader known as "Shim."

Shim introduces the Machine Owner Key (MOK) architecture, which allows system owners to register their own trusted cryptographic keys. The mokutil utility runs in user space on Ubuntu and serves as the primary tool for preparing, configuring, and manipulating these MOK requests before handoff to the bootloader during system startup.

Checking Secure Boot and Key Status

mokutil can query the current state of Secure Boot and inspect keys that are currently active in the system.

  • Verify Secure Boot State: To verify whether UEFI Secure Boot is active and enforcing signature verification: 
    mokutil --sb-state
  • List Enrolled Keys: To display all public keys currently trusted by the MOK list: 
    mokutil --list-enrolled
  • Check Pending Requests: To see keys queued for enrollment on the next reboot: 
    mokutil --list-new

Enrolling Keys for Third-Party Modules

When compiling proprietary hardware drivers (such as NVIDIA GPU drivers) or virtualization modules (such as VirtualBox (DKMS)), the resulting binaries must be signed with a custom private key. To make the kernel trust this module under Secure Boot, the corresponding public certificate (typically in .der format) must be added to the MOK database.

  1. Import the Key: 
    sudo mokutil --import /path/to/public_key.der
  2. Set a Temporary Password: mokutil will prompt you to create a one-time password. This password is required to confirm physical access to the machine.
  3. Reboot the System: 
    sudo reboot
  4. Complete Enrollment in MOKManager: Upon reboot, the system will not boot directly into Ubuntu. Instead, the Shim bootloader launches a blue, text-based interface called "MOKManager." Select Enroll MOK, choose Continue, select Yes to confirm, enter the one-time password configured earlier, and then select Reboot.

Once restarted, the kernel will trust modules signed with that specific key.

Deleting and Resetting Keys

If a key is compromised, superseded, or no longer needed, mokutil allows administrators to remove individual keys or wipe the custom database.

  • Delete a Specific Key: 
    sudo mokutil --delete /path/to/public_key.der
    Like the import process, this stages a deletion request that must be authenticated with a password and confirmed in the MOKManager screen during the next system reboot.
  • Reset All MOK Keys: 
    sudo mokutil --reset
    This clears all user-enrolled keys from the MOK list, returning the bootloader to its default state.

Disabling Validation

In scenarios where unsigned modules must be loaded temporarily and signing is not immediately feasible, mokutil can instruct the Shim bootloader to disable kernel module validation entirely without changing the UEFI BIOS settings.

sudo mokutil --disable-validation

This sets a flag that, once confirmed via MOKManager on the next reboot, disables signature enforcement for the Shim layer while leaving system-level Secure Boot enabled in firmware. Validation can be re-enabled later using:

sudo mokutil --enable-validation
