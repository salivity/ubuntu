Linux TC Qdisc Explained: Network Traffic Shaping

In Linux-based operating systems like Ubuntu, a queueing discipline (qdisc) is the core mechanism responsible for organizing, scheduling, and regulating outbound network packets. Implemented inside the Linux kernel network stack and managed using the tc (traffic control) utility, a qdisc acts as a gatekeeper between the network protocol layers and the network interface card (NIC). By deciding when, how, and if packets are transmitted onto the wire, qdiscs enable precise bandwidth shaping, latency optimization, and congestion management.

The Function of a Qdisc

When the Linux kernel prepares to transmit a network packet, it does not send it directly to the physical interface. Instead, it places the packet into a queue managed by a qdisc attached to that interface. The primary roles of a qdisc include:

  • Rate Limiting and Shaping: Delaying packets that exceed predefined bandwidth thresholds to smooth out bursty traffic and enforce strict throughput limits.
  • Packet Scheduling: Reordering packets to ensure high-priority traffic (such as VoIP, gaming, or SSH) is transmitted ahead of bulk data transfers (such as backups or large file downloads).
  • Congestion Management: Deciding which packets to drop or mark when network buffers become full to prevent bufferbloat and signal endpoints to reduce transmission rates.

Classless vs. Classful Qdiscs

The traffic control framework divides qdiscs into two fundamental categories, depending on the complexity of the shaping required:

Classless Qdiscs

Classless qdiscs apply uniform rules to all packets passing through an interface without distinguishing between different traffic types. Common examples include:

  • pfifo_fast: The default First-In, First-Out queue divided into three priority bands.
  • fq_codel (Fair Queueing with Controlled Delay): The modern default on Ubuntu that combines fair queuing across flows with active queue management to minimize latency under load.
  • tbf (Token Bucket Filter): A simple, precise algorithm for slowing down traffic to an exact target rate by requiring packets to acquire "tokens" before transmission.

Classful Qdiscs

Classful qdiscs allow an interface's egress traffic to be subdivided into a hierarchical tree of classes. Each class can have its own bandwidth allocations, priorities, and child qdiscs.

  • htb (Hierarchical Token Bucket): The standard classful qdisc on Linux for complex traffic shaping. It allows network administrators to guarantee minimum bandwidth to specific services while permitting them to borrow unused capacity from parent classes.
  • hfsc (Hierarchical Fair Service Curve): A specialized classful qdisc that separates delay allocation from bandwidth allocation, ideal for strict latency guarantees.

Utilizing Qdiscs with tc on Ubuntu

On Ubuntu, administrators manipulate qdiscs via the tc command from the iproute2 package. A qdisc is mounted directly to the root of a network device or as an egress queue.

To shape traffic, a typical configuration attaches a classful qdisc (like HTB) to the root of an interface, defines classes with specific bandwidth limits under that qdisc, and applies filters to map incoming packets into the designated classes based on IP addresses, ports, or protocols.

By selecting and tuning the appropriate qdisc, Ubuntu administrators can prevent individual applications from monopolizing connections, enforce Service Level Agreements (SLAs), and maintain low round-trip times across constrained network links.
