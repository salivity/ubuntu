Efficient Blender CUDA Rendering on Ubuntu

Running Blender with CUDA on Ubuntu allows 3D artists to maximize their rendering performance by offloading complex Cycles computations to NVIDIA GPUs. This guide provides a direct, step-by-step walkthrough for configuring your Ubuntu environment, setting up the proprietary NVIDIA drivers, configuring Blender's CUDA preferences, and applying essential render optimizations to ensure maximum hardware efficiency and stability.

1. Install Proprietary NVIDIA Drivers

To use CUDA, you must use the proprietary NVIDIA graphics drivers instead of the open-source Nouveau drivers.

  1. Open your terminal and check for recommended drivers: 
    ubuntu-drivers devices
  2. Install the recommended proprietary driver: 
    sudo ubuntu-drivers autoinstall
  3. Reboot your system to apply the changes: 
    sudo reboot
  4. Verify the driver installation: 
    nvidia-smi
    Ensure the output displays your GPU model and the driver version.

2. Install Blender

To ensure full compatibility with CUDA libraries, install Blender via the official Snap package or directly from the official portable tarball, rather than standard APT repositories which may carry outdated packages.

Install Blender via Snap:

sudo snap install blender --classic

3. Enable CUDA in Blender

Once installed, Blender must be explicitly configured to use your NVIDIA GPU.

  1. Launch Blender.
  2. Navigate to Edit > Preferences.
  3. Select the System tab on the left.
  4. Under Cycles Render Devices, click the CUDA tab.
  5. Check the box next to your NVIDIA graphics card.
  6. (Optional) Uncheck your CPU if you only want the GPU to handle rendering; rendering on both can sometimes slow down CUDA performance due to CPU thread synchronization overhead.
  7. Close the Preferences window (settings save automatically).

4. Optimize Cycles Render Settings

Configure your project to fully utilize the GPU pipeline.

  • Render Engine: Set the Render Engine to Cycles and the Device to GPU Compute in the Render Properties tab.
  • OptiX vs. CUDA: If your GPU supports it (RTX series and newer GTX cards), consider selecting OptiX instead of CUDA in the System Preferences, as OptiX utilizes dedicated RT cores for faster ray tracing. However, pure CUDA remains the most stable configuration for older architectures.
  • Sampling: Enable Noise Threshold (typically set between 0.01 and 0.05) and activate Denoising using the OpenImageDenoise or OptiX denoiser. This drastically reduces the number of samples required for clean output.
  • Tile Size: For Cycles in modern Blender versions (3.0 and newer), tile rendering is largely automated. Leave the tile size at the default setting unless VRAM constraints require smaller boundaries.

5. Ubuntu OS Performance Tweaks

Maximize GPU availability and efficiency by fine-tuning Ubuntu:

  • Enable Persistence Mode: This keeps the NVIDIA driver loaded constantly, preventing initialization delays between renders: 
    sudo nvidia-smi -pm 1
  • Render via Command Line: To conserve VRAM used by the Ubuntu desktop environment, render final animations or heavy scenes in background mode: 
    blender -b project.blend -E CYCLES -o //render_output -a
    This frees up graphical memory otherwise reserved for the display server (Xorg/Wayland), preventing out-of-memory errors on high-poly scenes.
