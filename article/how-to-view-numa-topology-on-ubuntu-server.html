How to View NUMA Topology on Ubuntu Server

Understanding Non-Uniform Memory Access (NUMA) topology is essential for optimizing workload performance on multi-socket Ubuntu servers. This guide explains the primary commands used to inspect NUMA architecture, CPU core mapping, and memory distribution across sockets, focusing on the dedicated numactl utility along with native alternatives like lscpu and lstopo.

The Primary Command: numactl --hardware

The most comprehensive command for inspecting NUMA topology on a multi-socket Linux system is numactl --hardware (or numactl -H). It provides an inventory of available NUMA nodes, the specific CPU cores assigned to each node, memory capacity and availability per node, and the relative latency (distance) between nodes.

On Ubuntu, numactl is not always installed by default. Install it using the APT package manager:

sudo apt update
sudo apt install numactl

Run the command:

numactl --hardware

Output Details

  • Available Nodes: Displays the total count of NUMA nodes (typically matching the physical CPU sockets).
  • Node CPUs: Lists the logical CPU core IDs associated with each socket.
  • Node Size: Shows the total RAM physically wired to that specific socket and how much is currently free.
  • Node Distances: Displays a matrix showing memory access latencies. Accessing local memory typically has a distance value of 10, while accessing remote memory attached to another socket shows higher values (e.g., 20 or 21), representing increased latency.

Alternative Native Command: lscpu

If you cannot install third-party packages, lscpu is pre-installed on all Ubuntu systems via util-linux and provides immediate visibility into your NUMA configuration.

Run:

lscpu

Filter specifically for NUMA information:

lscpu | grep -i numa

The output will display:

  • NUMA node(s): The total number of nodes detected.
  • NUMA nodeX CPU(s): The ranges of logical CPU IDs assigned to each node (e.g., 0-15,32-47).

Visualizing Topology with lstopo

For a hierarchical, tree-based representation of sockets, caches (L1, L2, L3), and NUMA nodes, use the hwloc package:

sudo apt install hwloc-nox
lstopo --no-graphics

This text-based diagram maps out which PCI devices, memory banks, and cache levels belong to each physical socket.

Inspecting NUMA via sysfs

You can also read NUMA details directly from the Linux kernel virtual filesystem without specialized utilities:

ls -d /sys/devices/system/node/node*

To see which CPUs belong to node0:

cat /sys/devices/system/node/node0/cpulist

To see memory statistics for node0:

cat /sys/devices/system/node/node0/meminfo
