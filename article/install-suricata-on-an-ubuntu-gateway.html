Install Suricata on an Ubuntu Gateway

This guide demonstrates how to install and configure the Suricata network threat detection engine on an Ubuntu-based gateway. Suricata is a high-performance Network Intrusion Detection System (NIDS), Intrusion Prevention System (IPS), and network security monitoring engine. Following these instructions will allow you to deploy Suricata, configure it to monitor local network interfaces, update detection signatures, and inspect real-time traffic for malicious activity.

Step 1: Install Suricata

Ubuntu repositories may carry older versions of Suricata. To install the latest stable release, add the official Open Information Security Foundation (OISF) Personal Package Archive (PPA):

sudo apt update
sudo apt install -y software-properties-common
sudo add-apt-repository -y ppa:oisf/suricata-stable
sudo apt update
sudo apt install -y suricata jq

Verify the installation:

suricata --build-info

Step 2: Identify Network Interfaces

A gateway typically contains at least two interfaces: a WAN interface facing the internet and a LAN interface facing the internal network. Run the following command to identify your interface names:

ip -br link

Note the interface you wish to monitor (for example, eth0 or enp3s0).

Step 3: Configure Suricata

Open the primary configuration file:

sudo nano /etc/suricata/suricata.yaml

Define Network Variables

Locate the vars: section at the top of the file and configure HOME_NET to match your local subnet, while setting EXTERNAL_NET to encompass external traffic:

vars:
  address-groups:
    HOME_NET: "[192.168.1.0/24]"
    EXTERNAL_NET: "!$HOME_NET"

Set the Listening Interface

Scroll down to the af-packet: section. Replace the default interface with your target network interface:

af-packet:
  - interface: eth0
    cluster-id: 99
    cluster-type: cluster_flow
    defrag: yes

If monitoring both LAN and WAN traffic, you can duplicate this block and specify the additional interface name with a unique cluster-id.

Step 4: Update Threat Rules

Suricata relies on signature rule sets to detect malicious behavior. Use the built-in tool suricata-update to fetch the default Emerging Threats (ET) Open ruleset:

sudo suricata-update

The updated rules are compiled into /var/lib/suricata/rules/suricata.rules, which is automatically referenced by the default configuration.

Step 5: Test the Configuration

Before starting the engine, run a syntax test to ensure the configuration file contains no errors:

sudo suricata -T -c /etc/suricata/suricata.yaml -v

Look for the final confirmation message: Suricata: Configuration provided was successfully verified. Engine will now exit.

Step 6: Start and Enable the Service

Restart the Suricata systemd service and enable it to launch automatically at boot:

sudo systemctl restart suricata
sudo systemctl enable suricata

Verify its active state:

sudo systemctl status suricata

Step 7: Verify Threat Detection

Test if Suricata generates alerts properly by triggering an ET Open signature test rule:

curl http://testmyids.com

Next, inspect the fast-log alert file:

sudo tail -f /var/log/suricata/fast.log

If functioning correctly, Suricata will log an alert similar to:

[**] [1:2100498:7] GPL ATTACK_RESPONSE id check returned root [**] [Classification: Potentially Bad Traffic] [Priority: 2] {TCP} ...

Suricata is now actively inspecting network packets crossing your Ubuntu gateway. Detailed event logs, including metadata, DNS queries, and HTTP traffic, can be monitored through /var/log/suricata/eve.json.
