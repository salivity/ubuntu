Configure iSCSI Multipath on Ubuntu with Dual NICs

This guide provides a step-by-step walkthrough for configuring an iSCSI initiator on Ubuntu to use Multipath I/O (MPIO) across two separate network interface cards (NICs). By binding separate iSCSI interfaces to distinct physical adapters and managing the resulting block devices with the Device Mapper Multipath utility, you will establish a redundant, high-performance storage connection that provides automatic failover and load balancing.

Prerequisites

Ensure you have two physical network interfaces configured with static IP addresses, preferably on separate subnets corresponding to separate iSCSI target portals. For this guide, we assume:

  • Primary NIC (eth1): 192.168.10.50
  • Secondary NIC (eth2): 192.168.20.50
  • Target Portal 1: 192.168.10.100:3260
  • Target Portal 2: 192.168.20.100:3260

Step 1: Install the Required Packages

Install the iSCSI initiator and multipath management utilities:

sudo apt update
sudo apt install open-iscsi multipath-tools -y

Verify that the initiator name exists in /etc/iscsi/initiatorname.iscsi. If required by your storage array, register this InitiatorName (IQN) on your storage target.

Step 2: Define iSCSI Interfaces Bound to NICs

To force iSCSI traffic across both network interfaces independently, create and bind two iSCSI interface definitions (ifaces).

  1. Create and bind the first interface:
sudo iscsiadm -m iface -I iface_eth1 --op=new
sudo iscsiadm -m iface -I iface_eth1 --op=update -n iface.net_ifacename -v eth1
  1. Create and bind the second interface:
sudo iscsiadm -m iface -I iface_eth2 --op=new
sudo iscsiadm -m iface -I iface_eth2 --op=update -n iface.net_ifacename -v eth2
  1. Verify the bindings:
sudo iscsiadm -m iface

Step 3: Discover and Log into the Targets

Use the defined interfaces to discover and establish sessions to the storage target.

  1. Discover available targets through both interfaces:
sudo iscsiadm -m discovery -t sendtargets -p 192.168.10.100 -I iface_eth1
sudo iscsiadm -m discovery -t sendtargets -p 192.168.20.100 -I iface_eth2
  1. Set the sessions to log in automatically on boot:
sudo iscsiadm -m node --op=update -n node.startup -v automatic
  1. Log in to all discovered portals:
sudo iscsiadm -m node -l
  1. Verify that two distinct sessions are active:
sudo iscsiadm -m session -P 1

You should see separate sessions mapped to each interface, and running lsblk will show two separate SCSI block devices (such as /dev/sdb and /dev/sdc) representing the same remote LUN.

Step 4: Configure Multipath-Tools

Generate a configuration file to combine the duplicate SCSI devices into a single multipath device.

  1. Create or edit /etc/multipath.conf:
sudo nano /etc/multipath.conf
  1. Insert a standard configuration:
defaults {
    user_friendly_names yes
    find_multipaths yes
    path_grouping_policy multibus
    path_checker tur
    failback immediate
    no_path_retry queue
}

blacklist {
    devnode "^(ram|raw|loop|fd|md|dm-|sr|scd|st)[0-9]*"
    devnode "^hd[a-z]"
    devnode "^sda$"
}

Note: Adjust path_grouping_policy (e.g., to group_by_prio or failover) according to your storage vendor's recommendations (ALUA vs. Active/Active).

  1. Restart and enable the multipath service:
sudo systemctl restart multipathd
sudo systemctl enable multipathd

Step 5: Verify the Multipath Setup

Run the multipath status command:

sudo multipath -ll

The output will display the consolidated device (e.g., mpatha located at /dev/mapper/mpatha) along with the two underlying paths (sdb and sdc), showing both paths as active and ready. You can now format and mount /dev/mapper/mpatha for read/write operations with redundant path failover.
