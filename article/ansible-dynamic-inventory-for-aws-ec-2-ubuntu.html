Ansible Dynamic Inventory for AWS EC2 Ubuntu

Managing cloud infrastructure requires flexible configuration management, as cloud environments are dynamic and IP addresses change frequently. This guide demonstrates how to configure and use Ansible's official amazon.aws.aws_ec2 inventory plugin to automatically discover, group, and manage AWS EC2 Ubuntu instances. By replacing static hosts files with dynamic inventory scripts, you can reliably run playbooks across your fleet using AWS tags, instance states, and VPC attributes.

Prerequisites

Before beginning, ensure your control node has:

  • Ansible (version 2.9 or newer) installed.
  • Python 3 with the AWS SDK libraries boto3 and botocore.
  • AWS credentials with read permissions for EC2 instances (ec2:DescribeInstances).

Step 1: Install Required Python Libraries and Collections

Ansible relies on the amazon.aws collection and Python's boto3 library to communicate with the AWS API. Install them on your Ansible control node:

pip install boto3 botocore
ansible-galaxy collection install amazon.aws

Step 2: Configure AWS Credentials

Ansible automatically looks for standard AWS authentication methods. You can export credentials as environment variables:

export AWS_ACCESS_KEY_ID="your_access_key"
export AWS_SECRET_ACCESS_KEY="your_secret_key"
export AWS_REGION="us-east-1"

Alternatively, configure your credentials file at ~/.aws/credentials using the AWS CLI (aws configure) or attach an IAM role if the control node runs directly on an EC2 instance.

Step 3: Create the Dynamic Inventory Configuration File

Create a YAML configuration file. The file name must end in aws_ec2.yml or aws_ec2.yaml for Ansible to detect the proper plugin.

Create a file named my_aws_ec2.yaml:

---
plugin: amazon.aws.aws_ec2
regions:
  - us-east-1

# Filter instances by state and optional tags to isolate Ubuntu nodes
filters:
  instance-state-name: running
  tag:OS: Ubuntu

# Set which attribute to use as the Ansible inventory hostname
hostnames:
  - ip-address
  - dns-name

# Group instances based on tags or instance attributes
keyed_groups:
  - key: tags.Environment
    prefix: env
  - key: tags.Role
    prefix: role

# Set default variables for matched hosts
compose:
  ansible_user: "'ubuntu'"

In this configuration:

  • plugin: amazon.aws.aws_ec2 designates the inventory plugin.
  • filters restricts targets to running instances tagged with OS: Ubuntu.
  • hostnames determines what value is used as the inventory host name (typically public or private IP).
  • keyed_groups organizes nodes into groups like env_production or role_webserver based on your AWS tags.
  • compose automatically sets ansible_user: 'ubuntu', the default SSH user for official Ubuntu cloud images.

Step 4: Verify the Inventory Configuration

Ensure Ansible can pull instance metadata by running the ansible-inventory command:

ansible-inventory -i my_aws_ec2.yaml --graph

This command outputs a tree representation of your discovered EC2 instances categorized into groups defined by your tags.

To inspect detailed variables returned for all instances, run:

ansible-inventory -i my_aws_ec2.yaml --list

Step 5: Test Connectivity

Run an ad-hoc ping module across your discovered Ubuntu instances using your SSH private key:

ansible all -i my_aws_ec2.yaml --private-key /path/to/your-key.pem -m ping

Step 6: Use with an Ansible Playbook

You can now target specific dynamic groups directly in standard playbooks:

---
- name: Update and Configure Ubuntu EC2 Nodes
  hosts: role_webserver
  become: true
  tasks:
    - name: Update apt cache
      ansible.builtin.apt:
        update_cache: yes
        cache_valid_time: 3600

Execute the playbook referencing the dynamic inventory file:

ansible-playbook -i my_aws_ec2.yaml --private-key /path/to/your-key.pem site.yml
