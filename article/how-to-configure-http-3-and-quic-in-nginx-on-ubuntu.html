How to Configure HTTP/3 and QUIC in Nginx on Ubuntu

This guide provides a step-by-step walkthrough for compiling, installing, and configuring an experimental or bleeding-edge build of Nginx with HTTP/3 and QUIC support on Ubuntu. You will learn how to install the required build dependencies, compile Nginx with the --with-http_v3_module flag, configure your virtual host directives to listen on QUIC, update your firewall rules for UDP traffic, and verify that HTTP/3 is serving traffic properly.

Step 1: Install Build Dependencies

HTTP/3 requires an SSL library that supports the QUIC transport protocol, such as OpenSSL 3.0 (standard in Ubuntu 22.04 and later). Update your system and install the essential compilation packages:

sudo apt update
sudo apt install -y build-essential libpcre3-dev zlib1g-dev libssl-dev git mercurial cmake ninja-build

Step 2: Download and Compile Nginx with HTTP/3

Clone the official experimental Nginx repository (nginx-quic) or obtain the latest mainline source code:

hg clone https://hg.nginx.org/nginx-quic
cd nginx-quic

Configure the build with the HTTP/3 module enabled alongside standard SSL modules:

auto/configure \
    --prefix=/etc/nginx \
    --sbin-path=/usr/sbin/nginx \
    --conf-path=/etc/nginx/nginx.conf \
    --http-log-path=/var/log/nginx/access.log \
    --error-log-path=/var/log/nginx/error.log \
    --with-http_ssl_module \
    --with-http_v2_module \
    --with-http_v3_module \
    --with-stream \
    --with-stream_ssl_module \
    --with-cc-opt="-I/usr/include" \
    --with-ld-opt="-L/usr/lib"

Compile and install the binaries:

make -j$(nproc)
sudo make install

Verify that the installed binary includes the HTTP/3 module:

nginx -V

Ensure --with-http_v3_module appears in the output arguments.

Step 3: Configure Nginx for HTTP/3

Edit your virtual host configuration file (for example, /etc/nginx/conf.d/default.conf or inside /etc/nginx/nginx.conf).

To serve HTTP/3 alongside standard HTTPS (HTTP/1.1 and HTTP/2), you must:

  1. Listen on port 443 with the quic option.
  2. Ensure the reuseport directive is present on the QUIC listener.
  3. Announce HTTP/3 availability to connecting clients via the Alt-Svc header.
  4. Enforce TLS 1.3, which is mandatory for QUIC.
server {
    # Standard TCP listeners for HTTP/1.1 and HTTP/2
    listen 443 ssl;
    listen [::]:443 ssl;

    # UDP listeners for HTTP/3 over QUIC
    listen 443 quic reuseport;
    listen [::]:443 quic reuseport;

    server_name example.com;

    # SSL configuration
    ssl_certificate /path/to/fullchain.pem;
    ssl_certificate_key /path/to/privkey.pem;
    ssl_protocols TLSv1.3;

    # Advertise HTTP/3 support to clients
    add_header Alt-Svc 'h3=":443"; ma=86400';

    location / {
        root /var/www/html;
        index index.html;
    }
}

Test the configuration for syntax errors:

sudo nginx -t

If the test passes, start or restart Nginx:

sudo systemctl restart nginx || sudo nginx -s reload

Step 4: Open UDP Port 443 in Firewall

QUIC operates entirely over UDP rather than TCP. If you use UFW (Uncomplicated Firewall), open both TCP and UDP port 443:

sudo ufw allow 443/tcp
sudo ufw allow 443/udp
sudo ufw reload

If you use cloud provider security groups (e.g., AWS, GCP, or DigitalOcean), add an inbound rule allowing UDP traffic on port 443.

Step 5: Verify HTTP/3 Functionality

You can test your HTTP/3 implementation using curl built with HTTP/3 support:

curl --http3 -I https://example.com

Alternatively, open your website in a modern browser (such as Chrome or Firefox), open Developer Tools (Network tab), right-click the table header, enable the Protocol column, and reload the page. The protocol should display as h3.
