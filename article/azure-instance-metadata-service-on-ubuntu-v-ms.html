Azure Instance Metadata Service on Ubuntu VMs

The Azure Instance Metadata Service (IMDS) provides essential runtime data to virtual machines directly from within the operating system. When queried from an Ubuntu VM, IMDS acts as a secure, locally accessible REST endpoint that supplies real-time compute specifications, network configurations, scheduled maintenance alerts, and authentication tokens for Azure resources, all without requiring credentials or external internet connectivity.

How IMDS Works on Ubuntu

IMDS is accessed via a non-routable link-local IP address (169.254.169.254) that only the VM itself can communicate with. On an Ubuntu system, you typically interact with IMDS using tools like curl or system scripts by sending a GET request along with the required HTTP header Metadata: true.

A basic query to retrieve compute details looks like this:

curl -H "Metadata:true" "http://169.254.169.254/metadata/instance/compute?api-version=2021-02-01"

Primary Purposes of IMDS on Ubuntu

1. Dynamic System Configuration and Bootstrapping

When an Ubuntu VM launches, configuration utilities like cloud-init or custom shell scripts query IMDS to discover the VM's environment. IMDS supplies:

  • Compute metadata: VM size, resource ID, location/region, subscription ID, and assigned tags.
  • Custom data: Scripts or configuration files passed during deployment. Using this information, initialization tools can automate system setup, register nodes into clusters, or alter behavior based on dynamic tags without manual intervention.

2. Network Discovery

IMDS provides granular network parameters directly to the guest OS. This includes private and public IP addresses, subnet masks, MAC addresses, and load balancer configurations. Scripts can read these endpoints to set up static route tables, bind specific services to private interfaces, or manage secondary network interfaces attached to the Ubuntu system.

3. Acquiring Managed Identity Access Tokens

One of the most critical security uses of IMDS is token acquisition via Azure Managed Identities (formerly MSI). Instead of storing sensitive secrets or API keys on the Ubuntu file system, applications running on the VM can request short-lived Azure Active Directory (Microsoft Entra ID) access tokens from IMDS. These tokens enable secure interaction with Azure services such as Azure Key Vault, Azure Blob Storage, or Azure SQL Database.

4. Handling Scheduled Maintenance and Preemption

High-availability systems and workloads running on Spot instances rely on the Scheduled Events feature of IMDS. By polling the /metadata/scheduledevents endpoint, an Ubuntu service can receive advance warnings about upcoming host reboots, live migrations, or node preemptions. This allows applications to gracefully drain traffic, flush caches, save state, or alert orchestration platforms before the VM goes offline.

5. System Attestation and Security

For Ubuntu VMs using Confidential Computing or Trusted Launch, IMDS exposes attestation metadata. The guest operating system can verify that it is running on genuine, secure Azure hardware and extract measured boot logs to confirm platform integrity.
