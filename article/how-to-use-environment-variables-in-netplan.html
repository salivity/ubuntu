How to Use Environment Variables in Netplan

Ubuntu's native network configuration tool, Netplan, reads static YAML files and does not inherently support runtime environment variable expansion. To create dynamic, environment-driven network configurations, administrators must use an external templating step to inject variables into a Netplan template before applying the configuration. This guide outlines how to build a dynamic Netplan template, populate it using standard Linux utilities like envsubst, and automate the process across dynamic environments.

Step 1: Create a Netplan YAML Template

Because Netplan will throw a syntax error if it encounters raw shell variable syntax (such as $INTERFACE or ${IP_ADDRESS}), store your template outside of the standard /etc/netplan/ directory or use a distinct file extension that Netplan ignores.

Create a template file named /etc/netplan/01-netcfg.yaml.tmpl:

network:
  version: 2
  renderer: networkd
  ethernets:
    ${NET_IFACE}:
      dhcp4: false
      addresses:
        - ${NET_STATIC_IP}/${NET_PREFIX}
      routes:
        - to: default
          via: ${NET_GATEWAY}
      nameservers:
        addresses:
          - ${NET_DNS1}
          - ${NET_DNS2}

Step 2: Define Environment Variables

Export the required network parameters into your environment:

export NET_IFACE="eth0"
export NET_STATIC_IP="192.168.1.50"
export NET_PREFIX="24"
export NET_GATEWAY="192.168.1.1"
export NET_DNS1="1.1.1.1"
export NET_DNS2="8.8.8.8"

Step 3: Render the Configuration Using envsubst

The envsubst utility (part of the gettext-base package) replaces environment variable references with their values.

  1. Ensure gettext-base is installed:

    sudo apt-get update && sudo apt-get install -y gettext-base

  2. Process the template and write the output directly to /etc/netplan/01-netcfg.yaml:

    envsubst < /etc/netplan/01-netcfg.yaml.tmpl | sudo tee /etc/netplan/01-netcfg.yaml > /dev/null

  3. Ensure correct file permissions:

    sudo chmod 600 /etc/netplan/01-netcfg.yaml

  4. Apply the configuration:

    sudo netplan apply

Step 4: Automate the Substitution on Boot

To make the configuration dynamic upon machine initialization, container startup, or cloud-instance booting, run the substitution script via a systemd service before Netplan executes.

  1. Create a script at /usr/local/bin/netplan-env-gen.sh:
#!/usr/bin/env bash
set -e

# Load environment variables from a file if necessary
if [ -f /etc/default/network-vars ]; then
  # shellcheck source=/dev/null
  source /etc/default/network-vars
fi

# Substitute variables and generate the final netplan file
envsubst < /etc/netplan/01-netcfg.yaml.tmpl > /etc/netplan/01-netcfg.yaml
chmod 600 /etc/netplan/01-netcfg.yaml

# Generate Netplan backends
netplan generate

  1. Make the script executable:

    sudo chmod +x /usr/local/bin/netplan-env-gen.sh

  2. Create a systemd unit at /etc/systemd/system/netplan-env-generator.service:

[Unit]
Description=Generate Netplan Config from Environment Variables
DefaultDependencies=no
Before=netplan-generate.service systemd-networkd.service
After=local-fs.target

[Service]
Type=oneshot
ExecStart=/usr/local/bin/netplan-env-gen.sh
RemainAfterExit=yes

[Install]
WantedBy=network.target
  1. Enable the service: 
    sudo systemctl enable netplan-env-generator.service

Verification and Troubleshooting

To test whether the configuration was generated accurately:

  1. Inspect the generated file:

    cat /etc/netplan/01-netcfg.yaml

  2. Run a Netplan syntax test without applying changes:

    sudo netplan generate

If no errors are returned, the substituted file contains valid Netplan syntax and will correctly control your interfaces.
