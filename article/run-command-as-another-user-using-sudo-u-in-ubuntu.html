Run Command as Another User Using sudo -u in Ubuntu

This guide explains how to execute specific commands as a different user in Ubuntu using the sudo -u command. Running single commands under another user identity eliminates the need to switch interactive shells entirely, which reduces security risks and simplifies automation. Below, you will find the basic syntax, common usage examples, and methods for handling environment variables and file redirections properly.

Basic Syntax

To run a command as another user, specify the target username with the -u flag followed by the command you want to execute:

sudo -u <username> <command>

For example, to check the username of the account executing the command as the www-data user:

sudo -u www-data whoami

This returns www-data instead of your current username or root.

Practical Examples

Running commands as service accounts or specific users is common when managing web servers, databases, or shared directories.

Listing Files in a Restricted Directory

If a directory is only readable by a specific user, you can view its contents without switching your shell:

sudo -u webuser ls -la /home/webuser/private/

Running Application Scripts

To run an application or background script using a service account (such as www-data or postgres):

sudo -u postgres psql -c "SELECT version();"

Preserving the Target User's Home Directory

By default, sudo retains the current user's environment, including the $HOME variable. If the command requires access to the target user's home directory (such as checking configuration files in ~/.config), add the -H flag:

sudo -H -u <username> <command>

The -H option sets the HOME environment variable to the home directory specified in the target user's /etc/passwd entry.

Handling Pipes and Output Redirection

Shell redirections like > or | are evaluated by your current shell before sudo runs. This means output redirection will run with your current user's permissions, not the target user's.

To execute a command and redirect its output entirely under the target user's context, wrap the command in a shell using sh -c or bash -c:

sudo -u www-data bash -c "echo 'Test content' > /var/www/html/test.txt"

Alternatively, use tee to handle writes safely:

echo "Test content" | sudo -u www-data tee /var/www/html/test.txt > /dev/null

Sudoers Configuration

To run commands with sudo -u, your current user account must have permission in the /etc/sudoers file. A standard sudo group member in Ubuntu already has full permissions:

%sudo   ALL=(ALL:ALL) ALL

If you need to grant a specific user permission to run commands only as a specific service account, add a rule using visudo:

john ALL=(www-data) /usr/bin/git, /usr/bin/composer

This restricts the user john to only running /usr/bin/git and /usr/bin/composer as www-data.
