How mdadm Daemon Monitors Ubuntu Software RAID

The mdadm daemon plays a vital role in maintaining the reliability and availability of software RAID arrays on Ubuntu systems. Operating continuously in the background, it actively monitors the health of array drives, detects hardware failures, triggers automated recovery processes using spare drives, and alerts system administrators through system logs and email notifications. This article explains the primary responsibilities of the mdadm daemon in Ubuntu RAID management and how it ensures uninterrupted data integrity.

Continuous Health Polling

The mdadm daemon runs as a background service (typically managed via systemd as mdadm-monitor or mdmonitor) that constantly tracks the status of active Linux Multiple Device (MD) RAID arrays. It queries the kernel state by inspecting /proc/mdstat and listening for device event notifications. This continuous checking allows the daemon to detect drive disconnections, read errors, or array degradation immediately after an event occurs.

Automated Alerts and System Logging

When a disk fails or an array changes state, the mdadm daemon generates immediate alerts. It integrates with the system's local mail transfer agent to send email notifications to the address specified in the MAILADDR directive within /etc/mdadm/mdadm.conf. Additionally, state changes—such as Fail, DegradedArray, or RebuildStarted—are written directly to the system log (journalctl / syslog), providing an audit trail for system administrators.

Automatic Hot Spare Activation and Rebuilding

If a drive fails within a RAID array that has an assigned hot spare, the mdadm daemon automatically handles the recovery process. It instructs the Linux kernel MD driver to mark the faulty drive as failed, remove it from active operations, and rebuild the degraded array using the available hot spare. This automated failover reduces the time an array spends in a vulnerable, non-redundant state without requiring manual intervention.

Configuration and Service Control in Ubuntu

In Ubuntu, the daemon relies on /etc/mdadm/mdadm.conf for its runtime directives. Essential parameters include:

  • MAILADDR: Specifies the email address that receives failure and health reports.
  • PROGRAM: Allows execution of a custom script whenever a designated RAID event occurs.
  • DAEMONOPTIONS: Defines poll intervals and daemon behavior.

System administrators can manage and inspect the monitoring service using systemctl:

  • View daemon status: systemctl status mdadm-monitor
  • Restart monitoring service: sudo systemctl restart mdadm-monitor

By handling real-time health checks, event logging, email dispatch, and automated drive rebuilding, the mdadm daemon provides necessary proactive maintenance for Ubuntu software RAID arrays.
