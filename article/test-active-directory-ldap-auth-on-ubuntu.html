Test Active Directory LDAP Auth on Ubuntu

Testing LDAP authentication against Microsoft Active Directory (AD) from an Ubuntu system is most effectively done using the ldapsearch utility provided by the ldap-utils package. This guide outlines how to install the required tools, construct the command to perform a simple bind against an Active Directory domain controller, and verify successful authentication or troubleshoot credential errors.

Install LDAP Utilities

The core tools for interacting with LDAP directories from the command line are packaged in ldap-utils. Install them using the apt package manager:

sudo apt update
sudo apt install ldap-utils -y

The Command to Test Authentication

The standard command to test authentication against Active Directory is ldapsearch. You can authenticate using a User Principal Name (UPN), such as username@domain.com, or the Distinguished Name (DN) of the user.

Run the following command:

ldapsearch -x -H ldap://<AD_SERVER_IP_OR_FQDN> -D "user@domain.com" -W -b "dc=domain,dc=com" "(sAMAccountName=user)"

Parameter Breakdown

  • -x: Enables simple authentication instead of SASL.
  • -H ldap://<AD_SERVER_IP_OR_FQDN>: Specifies the LDAP URI of the Active Directory domain controller. For secure LDAPS over port 636, use ldaps://<AD_SERVER_IP_OR_FQDN>.
  • -D "user@domain.com": The Bind DN or UPN of the user account you are attempting to authenticate with.
  • -W: Prompts for the user's password interactively to avoid exposing it in the shell history.
  • -b "dc=domain,dc=com": Defines the base DN for the search. Adjust this to match your Active Directory domain components.
  • "(sAMAccountName=user)": The search filter executed after a successful bind.

Alternative: Using ldapwhoami

If you only need to verify credentials without querying directory objects, use ldapwhoami. This command attempts to bind and returns the identity of the authenticated user:

ldapwhoami -x -H ldap://<AD_SERVER_IP_OR_FQDN> -D "user@domain.com" -W

Interpreting the Output

  • Success: If the credentials are valid, ldapsearch returns directory entries along with result: 0 Success. ldapwhoami will return u:DOMAIN\user followed by Result: Success (0).
  • Invalid Credentials: An incorrect username or password will return ldap_bind: Invalid credentials (49) with an Active Directory data code such as data 52e.
  • Connection Issues: If the command hangs or returns ldap_result: Can't contact LDAP server (-1), verify network connectivity, firewall rules, and that TCP port 389 (LDAP) or port 636 (LDAPS) is reachable on the domain controller.
