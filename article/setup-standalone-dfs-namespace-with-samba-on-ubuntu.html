Setup Standalone DFS Namespace with Samba on Ubuntu

This guide outlines the process of configuring Samba on Ubuntu to host a standalone Microsoft Distributed File System (DFS) namespace. By utilizing Samba's MS-DFS capabilities, administrators can present multiple network shares distributed across different servers under a single, unified path without requiring an Active Directory domain.

Prerequisites

  • An Ubuntu server with administrative (sudo) access.
  • Target SMB/CIFS shares already configured and accessible on your local network.
  • Proper network connectivity and DNS resolution between clients, the DFS host, and the target servers.

Step 1: Install Samba

Update your package repositories and install the Samba packages:

sudo apt update
sudo apt install samba samba-common-bin -y

Verify that the Samba service is active:

sudo systemctl status smbd

Step 2: Configure Samba for DFS

Open the Samba configuration file:

sudo nano /etc/samba/smb.conf

Add the host msdfs parameter to the [global] section to enable DFS support:

[global]
   workgroup = WORKGROUP
   server string = %h Samba DFS Server
   netbios name = SAMBADFS
   security = user
   map to guest = Bad User
   dns proxy = no

   # Enable DFS hosting
   host msdfs = yes

At the bottom of the file, define the DFS root share:

[dfs]
   comment = DFS Root Directory
   path = /srv/samba/dfsroot
   browseable = yes
   read only = no
   guest ok = yes
   msdfs root = yes

Save and exit the file.

Step 3: Create the DFS Root Directory

Create the directory designated as the DFS path in the configuration:

sudo mkdir -p /srv/samba/dfsroot

Set permissions to allow the Samba daemon and connected users to read the namespace:

sudo chown -R nobody:nogroup /srv/samba/dfsroot
sudo chmod -R 0755 /srv/samba/dfsroot

Step 4: Create DFS Links (Symlinks)

Samba creates DFS links using symbolic links pointing to a specific URI scheme: msdfs:<server>\<share>.

Navigate to the DFS root directory:

cd /srv/samba/dfsroot

Create a symlink for each target share:

sudo ln -s 'msdfs:server1.local\documents' docs
sudo ln -s 'msdfs:192.168.1.50\backups' backups
  • docs and backups will appear as folders inside the dfs share.
  • When users access these folders, Samba sends a referral redirecting them to \\server1.local\documents or \\192.168.1.50\backups.

Step 5: Validate and Restart Services

Check the configuration for syntax errors:

testparm

Restart the Samba services to apply the changes:

sudo systemctl restart smbd
sudo systemctl restart nmbd

If you have a firewall enabled (such as UFW), ensure the Samba ports are allowed:

sudo ufw allow samba

Step 6: Connect to the Namespace

Clients can now connect to the standalone DFS namespace using standard UNC paths:

  • Windows: Open File Explorer and navigate to \\<Ubuntu_IP_or_Hostname>\dfs
  • Linux: Mount using SMB: mount -t cifs //192.168.1.10/dfs /mnt/dfs -o guest

Opening the link folders will seamlessly redirect client requests to the respective target file servers.
