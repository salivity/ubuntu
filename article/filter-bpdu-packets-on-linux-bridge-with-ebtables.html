Filter BPDU Packets on Linux Bridge with ebtables

This article provides a direct guide on how to filter Bridge Protocol Data Unit (BPDU) frames on a Linux bridge in Ubuntu using ebtables. Filtering these packets prevents unwanted Spanning Tree Protocol (STP) topology recalculations and blocks virtual machines or unauthorized connected hosts from injecting rogue BPDU frames into the physical network. The steps below cover installing the required packages, identifying the destination MAC addresses for BPDU frames, applying the drop rules, and making the configuration persistent across reboots.

Step 1: Install ebtables

Ubuntu systems require the ebtables utility to inspect and manipulate Ethernet frames on bridge interfaces. Install it using apt:

sudo apt update
sudo apt install ebtables

Step 2: Identify BPDU Destination MAC Addresses

Spanning Tree Protocol implementations rely on well-known multicast MAC addresses:

  • Standard IEEE 802.1D / RSTP / MSTP: 01:80:c2:00:00:00
  • Cisco PVST+ / Per-VLAN STP: 01:00:0c:cc:cc:cd

To block BPDU traffic completely, you can filter one or both addresses depending on the network environment.

Step 3: Apply the Filter Rules

Use ebtables to intercept frames traversing the bridge. The rules should be added to the FORWARD chain, or the INPUT chain if you need to protect the host itself.

To drop standard IEEE STP BPDU packets forwarded across the bridge:

sudo ebtables -A FORWARD -d 01:80:c2:00:00:00 -j DROP

To drop Cisco PVST+ packets:

sudo ebtables -A FORWARD -d 01:00:0c:cc:cc:cd -j DROP

If you only want to filter BPDU frames arriving on a specific physical interface (for example, eth1 attached to a bridge named br0):

sudo ebtables -A FORWARD -i eth1 -d 01:80:c2:00:00:00 -j DROP

To also prevent the Linux host's local bridge interface from processing incoming BPDUs, apply the same match to the INPUT chain:

sudo ebtables -A INPUT -d 01:80:c2:00:00:00 -j DROP

Step 4: Verify the Rules

Check the current active rules in ebtables to ensure the entries have been appended properly:

sudo ebtables -L --Lc

The output will display the chain details along with packet and byte counters, allowing you to monitor blocked BPDU traffic.

Step 5: Make Rules Persistent Across Reboots

By default, rules created via the ebtables command do not persist across system reboots. To preserve them, use iptables-persistent and the netfilter-persistent service:

  1. Install the persistence package:
sudo apt install iptables-persistent
  1. Save the active ebtables rules:
sudo netfilter-persistent save

Alternatively, you can dump the rules directly to the system configuration file:

sudo ebtables-save | sudo tee /etc/ebtables.filter

If using the manual dump approach, restore the rules at boot by adding ebtables-restore < /etc/ebtables.filter to a startup systemd unit or network interface post-up script.
