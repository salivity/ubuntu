Configure Static ARP on Ubuntu Server

Configuring a static Address Resolution Protocol (ARP) entry on an Ubuntu server binds an IP address permanently to a specific MAC address, effectively mitigating local network threats like ARP spoofing, poisoning, and MAC address impersonation. By default, operating systems dynamically resolve and cache these associations, leaving them vulnerable to malicious overwrite by rogue hosts broadcasting falsified ARP replies. This guide explains how to identify your network parameters, temporarily apply a static ARP mapping, and configure it persistently across system reboots.

1. Identify Network Parameters

Before creating a static ARP entry, gather the target IP address, its verified hardware (MAC) address, and the server's active network interface. Typically, static mappings are applied to critical endpoints such as the default gateway.

Find the current gateway IP address and interface:

ip route show default

Check the currently cached MAC address for that IP:

ip neigh show

Note the interface name (e.g., eth0 or enp3s0), the IP address, and the corresponding MAC address.

2. Configure a Temporary Static ARP Entry

You can immediately bind the IP to the MAC address using the modern iproute2 utility suite. The entry must be marked with the permanent Neighbor Unreachability Detection (NUD) flag, which prevents dynamic ARP responses from modifying the table.

Run the following command, replacing <IP_ADDRESS>, <MAC_ADDRESS>, and <INTERFACE> with your target values:

sudo ip neigh replace <IP_ADDRESS> lladdr <MAC_ADDRESS> dev <INTERFACE> nud permanent

Verify that the entry is set as permanent:

ip neigh show <IP_ADDRESS>

The output should display PERMANENT at the end of the line, confirming that the kernel will ignore any incoming gratuitous ARP packets attempting to spoof this address.

3. Make the Static ARP Entry Persistent

Temporary entries added via the command line do not survive a system reboot. Because modern Ubuntu releases utilize systemd-networkd alongside Netplan, the most reliable way to enforce static ARP configurations on startup is through networkd-dispatcher.

Create a new script in the routable.d directory to execute the static mapping whenever the network interface becomes active:

sudo nano /etc/networkd-dispatcher/routable.d/50-static-arp.sh

Insert the following script, updating the placeholders accordingly:

#!/bin/bash
if [ "$IFACE" = "<INTERFACE>" ]; then
    /usr/sbin/ip neigh replace <IP_ADDRESS> lladdr <MAC_ADDRESS> dev <INTERFACE> nud permanent
fi

Save and exit the file. Next, grant execution permissions to the script:

sudo chmod +x /etc/networkd-dispatcher/routable.d/50-static-arp.sh

4. Verify Persistence

Test the configuration by restarting the server or triggering the dispatcher:

sudo reboot

Once the server comes back online, verify that the entry was loaded properly:

ip neigh show <IP_ADDRESS>

If the record indicates PERMANENT, the static ARP configuration is active, and the server is protected against MAC spoofing directed at that IP address.
