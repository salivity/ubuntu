Restart Display Manager in Ubuntu

This guide explains how to reload and restart the X11 or Wayland display manager service in Ubuntu. You will learn the universal systemd commands to manage the active display service, how to identify your current display manager (such as GDM3, LightDM, or SDDM), and how to apply these commands safely without causing persistent system issues.

Identify Your Active Display Manager

Before running a command, you should identify which display manager your Ubuntu system is currently running. Run the following command in your terminal:

systemctl status display-manager

Alternatively, you can check the default display manager file directly:

cat /etc/X11/default-display-manager

Default Ubuntu desktop installations generally use gdm3 (GNOME Display Manager), while flavors like Kubuntu use sddm, and Lubuntu or Xubuntu often use lightdm.

The Universal Restart Command

Ubuntu uses systemd to manage graphical sessions. You do not need to specify whether you are running X11 or Wayland, as the display manager handles the protocol initialization automatically.

To reload and restart the display manager regardless of which specific software is installed, run:

sudo systemctl restart display-manager

Note: Restarting the display manager will terminate your current graphical session, close all running GUI applications, and return you to the login screen.

Service-Specific Restart Commands

If you prefer to target your specific display manager service directly, use one of the following commands based on your setup:

For GDM3 (Default Ubuntu Desktop)

sudo systemctl restart gdm3

For LightDM

sudo systemctl restart lightdm

For SDDM (KDE Plasma)

sudo systemctl restart sddm

Reloading Configuration Without Full Termination

True in-place reloading without ending the user session is generally unsupported by modern display managers because the display server (X11 or Wayland compositor) is directly tied to the service lifecycle. However, if you only need the service daemon to reload its configuration files without dropping the session immediately, you can attempt:

sudo systemctl reload display-manager

If the display manager does not support native reloading, systemd will return an error, requiring a full restart to apply configuration updates.
