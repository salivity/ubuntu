How to Migrate LXD Containers Between Ubuntu Hosts

Migrating an LXD container from one Ubuntu host to another over a network can be accomplished seamlessly using LXD's built-in remote management capabilities. This guide outlines how to expose the LXD API on the target server, establish a trusted remote connection between both hosts, and transfer a container directly using the lxc copy or lxc move command without needing to manually export and import image tarballs.

Step 1: Configure the Target Host

To allow the source server to transfer data, the target Ubuntu host must expose its LXD daemon to the network and define a trust password for authentication.

Run the following commands on the destination (target) host:

  1. Bind the LXD daemon to an HTTPS port (default is 8443):

    lxc config set core.https_address "[::]:8443"

  2. Set a temporary trust password to allow new clients to authenticate:

    lxc config set core.trust_password YourSecurePasswordHere

  3. Ensure port 8443 is open on the target firewall:

    sudo ufw allow 8443/tcp

Step 2: Add the Remote on the Source Host

Once the target host is listening, configure the source host to recognize the target as a valid remote destination.

Run the following commands on the source host:

  1. Add the target host to your LXD remotes list:

    lxc remote add target-server <TARGET_IP>:8443

    Replace <TARGET_IP> with the actual IP address or hostname of your destination server.

  2. When prompted, verify the target server's certificate fingerprint by typing yes.

  3. Enter the trust password configured in Step 1.

  4. Verify that the connection is active:

    lxc remote list

    The target-server should now appear in the list of available remotes.

Step 3: Migrate the Container

LXD supports copying (preserving the source container) or moving (deleting the source container after transfer).

Option A: Copy the Container

To duplicate the container to the remote host while leaving the original intact:

lxc copy my-container target-server:my-container

If the container is actively running and you want to minimize downtime, use the --mode=relay flag (if network routing requires it) or specify live migration using CRIU (if configured):

lxc copy my-container target-server:my-container --mode=pull

Option B: Move the Container

To completely transfer and delete the container from the source host:

  1. Stop the container first for the cleanest migration:

    lxc stop my-container

  2. Execute the move command:

    lxc move my-container target-server:my-container

Step 4: Verify and Start the Container

On the target host, verify that the container is present:

lxc list

Start the migrated container:

lxc start my-container

Verify that the network configurations, storage pools, and profiles assigned to the container on the source match those available on the target to ensure the container initializes properly.

Step 5: Post-Migration Security Cleanup

After completing the transfer, remove the trust password from the target host to prevent unauthorized authentication attempts:

lxc config unset core.trust_password

If you do not intend to perform further remote operations, you can also stop listening on the public port:

lxc config unset core.https_address
