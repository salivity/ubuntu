How to Install and Secure a Redis Cluster on Ubuntu

This guide provides a comprehensive walkthrough for deploying and securing a distributed Redis cluster across multiple Ubuntu servers to achieve high availability and horizontal scalability. You will learn how to prepare your Ubuntu environments, configure individual Redis instances for clustering, enforce authentication, enable TLS encryption for data-in-transit, and initialize the cluster using the Redis CLI.

Prerequisites and Architecture

A production-ready Redis cluster requires at least three master nodes for high availability, alongside three replica nodes (one for each master). This setup uses three Ubuntu servers, running two Redis instances on distinct ports (e.g., 7000 and 7001) on each machine:

  • Node 1: 192.168.1.11 (Ports 7000, 7001)
  • Node 2: 192.168.1.12 (Ports 7000, 7001)
  • Node 3: 192.168.1.13 (Ports 7000, 7001)

Every node requires communication on two ports: the client port (e.g., 7000) and the cluster bus port, which is always the client port plus 10000 (e.g., 17000).

Step 1: Install Redis on All Nodes

Execute the following commands on every Ubuntu server to install Redis and the required build utilities:

sudo apt update
sudo apt install -y redis-server redis-tools
sudo systemctl stop redis-server
sudo systemctl disable redis-server

Disabling the default service prevents it from interfering with custom clustered instances.

Step 2: Generate TLS Certificates

To secure cluster communication and client-to-server traffic across the network, generate TLS certificates using OpenSSL. Perform this on your management machine or Node 1, then distribute the certificates to all nodes.

mkdir -p ~/redis-tls
cd ~/redis-tls

# Generate CA key and certificate
openssl genrsa -out ca.key 4096
openssl req -x509 -new -nodes -sha256 -key ca.key -days 365 -subj "/CN=Redis-CA" -out ca.crt

# Generate Server key and certificate
openssl genrsa -out redis.key 2048
openssl req -new -key redis.key -subj "/CN=redis-node" -out redis.csr
openssl x509 -req -in redis.csr -CA ca.crt -CAkey ca.key -CAcreateserial -out redis.crt -days 365 -sha256

Copy ca.crt, redis.crt, and redis.key to /etc/redis/tls/ on each server:

sudo mkdir -p /etc/redis/tls
sudo cp ca.crt redis.crt redis.key /etc/redis/tls/
sudo chown -R redis:redis /etc/redis/tls
sudo chmod 600 /etc/redis/tls/*

Step 3: Configure Redis Instances

Create distinct directories and configuration files for both instances on each node.

Create working directories:

sudo mkdir -p /var/lib/redis/7000 /var/lib/redis/7001
sudo chown -R redis:redis /var/lib/redis

Create /etc/redis/redis_7000.conf on each machine (adjust bind to the local node's private IP):

# Network and Port
bind 127.0.0.1 192.168.1.11
protected-mode yes
port 0
tls-port 7000

# TLS Configuration
tls-cert-file /etc/redis/tls/redis.crt
tls-key-file /etc/redis/tls/redis.key
tls-ca-cert-file /etc/redis/tls/ca.crt
tls-auth-clients yes
tls-replication yes
tls-cluster yes

# Cluster Settings
cluster-enabled yes
cluster-config-file nodes_7000.conf
cluster-node-timeout 5000

# Security Settings
requirepass StrongClusterPassword123!
masterauth StrongClusterPassword123!

# General Settings
daemonize yes
dir /var/lib/redis/7000
pidfile /var/run/redis_7000.pid
logfile /var/log/redis/redis_7000.log

Duplicate this file for port 7001:

sudo cp /etc/redis/redis_7000.conf /etc/redis/redis_7001.conf

In /etc/redis/redis_7001.conf, replace 7000 with 7001 across all directives (tls-port, cluster-config-file, dir, pidfile, and logfile).

Repeat this process across all nodes, ensuring the bind IP reflects the respective server's local network address.

Step 4: Configure the Firewall

Configure Uncomplicated Firewall (ufw) on each machine to only allow incoming traffic from participating cluster nodes:

# Allow communication from cluster peer IPs
for ip in 192.168.1.11 192.168.1.12 192.168.1.13; do
  sudo ufw allow from $ip to any port 7000 proto tcp
  sudo ufw allow from $ip to any port 7001 proto tcp
  sudo ufw allow from $ip to any port 17000 proto tcp
  sudo ufw allow from $ip to any port 17001 proto tcp
done

sudo ufw enable

Step 5: Start Redis Instances

Create systemd service definitions to manage the instances, or start them directly using the Redis binary:

sudo -u redis redis-server /etc/redis/redis_7000.conf
sudo -u redis redis-server /etc/redis/redis_7001.conf

Verify both processes are running on all servers:

ps aux | grep redis-server

Step 6: Initialize the Secured Cluster

Run the cluster creation command using redis-cli from any node. Supply the TLS parameters and cluster password:

redis-cli --cluster create \
  192.168.1.11:7000 192.168.1.12:7000 192.168.1.13:7000 \
  192.168.1.11:7001 192.168.1.12:7001 192.168.1.13:7001 \
  --cluster-replicas 1 \
  --tls \
  --cacert /etc/redis/tls/ca.crt \
  --cert /etc/redis/tls/redis.crt \
  --key /etc/redis/tls/redis.key \
  -a 'StrongClusterPassword123!'

Type yes when prompted to accept the proposed slot allocation.

Step 7: Verify Cluster Status

Verify that the cluster is operational and securely communicating:

redis-cli --tls \
  --cacert /etc/redis/tls/ca.crt \
  --cert /etc/redis/tls/redis.crt \
  --key /etc/redis/tls/redis.key \
  -a 'StrongClusterPassword123!' \
  -p 7000 cluster info

Look for cluster_state:ok in the output. To inspect the topology, role assignments, and slot distributions, run:

redis-cli --tls \
  --cacert /etc/redis/tls/ca.crt \
  --cert /etc/redis/tls/redis.crt \
  --key /etc/redis/tls/redis.key \
  -a 'StrongClusterPassword123!' \
  -p 7000 cluster nodes
