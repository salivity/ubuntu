Run Commands After Logout in Ubuntu Using nohup

When working on a remote Ubuntu server via SSH, closing your terminal session or losing your network connection normally terminates any active processes. The nohup command solves this problem by intercepting the hangup signal (SIGHUP), allowing scripts, commands, and long-running tasks to continue executing uninterrupted in the background even after you log out. This article provides a clear, step-by-step guide on how to use the nohup command in Ubuntu, manage process outputs, and monitor background tasks.

Basic Syntax of nohup

The term nohup stands for “no hangup.” To use it, place nohup before the command you wish to run, and append an ampersand (&) at the end of the line. The ampersand instructs the system to run the process in the background, freeing up your command line.

nohup command_name [arguments] &

When executed, nohup detaches the process from your terminal session. By default, it redirects both standard output (stdout) and standard error (stderr) into a file named nohup.out located in your current working directory.

Running a Command in the Background

To run a long script or command that will persist after logging out, use the following structure:

nohup python3 long_script.py &

After executing the command, terminal output similar to this will appear:

[1] 12345
appending output to nohup.out

The number 12345 represents the Process ID (PID). At this point, you can safely type exit or close your terminal, and long_script.py will continue running on the Ubuntu server.

Customizing Output Redirection

If you prefer not to use the default nohup.out file, you can manually redirect the output and error logs to specific locations.

Redirecting Output to a Custom Log File

To write standard output and standard error to a custom log file:

nohup ./backup.sh > my_output.log 2>&1 &
  • > my_output.log redirects standard output to my_output.log.
  • 2>&1 redirects standard error (channel 2) to the same place as standard output (channel 1).

Discarding Output Entirely

If the process generates heavy logging that you do not need to save, redirect all output to /dev/null:

nohup ./backup.sh > /dev/null 2>&1 &

How to Verify and Stop a nohup Process

After logging back into your Ubuntu system, you can check the status of your process or terminate it using standard Linux management commands.

Checking Running Processes

To verify if your command is still active, search for it using ps and grep:

ps aux | grep long_script.py

Alternatively, use pgrep to quickly find the Process ID:

pgrep -fl long_script.py

Viewing Log Files

To view real-time log updates generated by your process, use the tail command:

tail -f nohup.out

Terminating a nohup Process

To stop a process running under nohup, locate its PID and pass it to the kill command:

kill 12345

If the process does not respond to a standard termination request, force-kill it:

kill -9 12345
