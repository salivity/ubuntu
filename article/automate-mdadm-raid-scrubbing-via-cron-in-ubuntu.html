Automate mdadm RAID Scrubbing via Cron in Ubuntu

Regularly scrubbing an mdadm software RAID array ensures data integrity by scanning all disk blocks to detect and correct silent data corruption or read errors before drive failures happen. This guide covers how to identify your array, configure an automated cron job to perform routine integrity checks using Ubuntu's built-in tools, and monitor the scrub status.

Step 1: Identify Your RAID Array

Before creating the schedule, determine the device name and status of your active RAID array by checking /proc/mdstat:

cat /proc/mdstat

Look for the array identifier, such as md0 or md127, and ensure all expected drives are marked active without degradation.

Step 2: Test the Scrub Command

Ubuntu includes an official script specifically designed to manage RAID checks safely: /usr/share/mdadm/checkarray. It initiates a non-destructive read check across the array.

Test the command manually as root, replacing /dev/md0 with your array identifier:

sudo /usr/share/mdadm/checkarray /dev/md0

To run a check on all active arrays simultaneously:

sudo /usr/share/mdadm/checkarray --all

Alternatively, you can trigger a scrub directly via the Linux sysfs interface:

echo check | sudo tee /sys/block/md0/md/sync_action

Step 3: Configure the Automated Cron Job

To run the scrub automatically, create a scheduled entry in the system crontab. Scrubbing introduces I/O overhead, so it is best scheduled during low-traffic periods, such as early Sunday morning once per month.

  1. Open the root user's crontab editor:
sudo crontab -e
  1. Add a schedule entry. For example, to run a scrub on /dev/md0 at 02:00 AM on the first Sunday of every month, add the following line:
0 2 1-7 * * [ $(date +\%u) -eq 7 ] && /usr/share/mdadm/checkarray -a /dev/md0 > /dev/null 2>&1

If you prefer a simple monthly schedule running on the 1st of every month at 03:00 AM across all arrays:

0 3 1 * * /usr/share/mdadm/checkarray --all > /dev/null 2>&1
  1. Save and close the editor.

Step 4: Monitor and Verify the Scrub Process

Once a scrub has started, you can track its real-time progress and estimated completion time:

cat /proc/mdstat

The output will display a progress bar, completion percentage, and current speed.

After the check finishes, verify whether any data discrepancies were found:

cat /sys/block/md0/md/mismatch_cnt

A value of 0 indicates no parity errors were encountered. If non-zero values appear on RAID 5 or RAID 6, it may indicate silent corruption or hardware issues requiring investigation.

Step 5: Stopping a Scrub (Optional)

If high disk I/O from an active scrub interferes with critical tasks, you can abort the scan immediately by resetting the sync action:

echo idle | sudo tee /sys/block/md0/md/sync_action
