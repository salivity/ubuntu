Recover Corrupted Partition Table with GParted Live

A corrupted partition table can render an Ubuntu installation unbootable and make your storage drives appear completely unallocated. This guide provides a direct, step-by-step walkthrough for recovering lost or damaged partition tables using the GParted Live CD environment. By leveraging the recovery utilities bundled within GParted Live—specifically the command-line tool TestDisk—you can scan the physical disk structure, locate original partition boundaries, and rewrite a functional partition table to restore access to your Ubuntu system.

Step 1: Boot into the GParted Live Environment

  1. Download the official GParted Live ISO and create a bootable USB flash drive using a tool such as Ventoy, Rufus, or BalenaEtcher.
  2. Insert the bootable media into the affected computer and boot into it via your system's boot menu (commonly accessed via F12, F11, or Del during startup).
  3. On the boot screen, select GParted Live (Default settings).
  4. When prompted, select Don't touch keymap, choose your preferred language, and press Enter at the video mode prompt to load the default graphical environment.

Step 2: Identify the Target Drive

Once the desktop loads, open the GParted graphical interface if it does not launch automatically.

  1. Use the drop-down menu in the top-right corner of the GParted window to identify your drive's device path (for example, /dev/sda for SATA drives or /dev/nvme0n1 for NVMe drives).
  2. Note whether the drive space is reported as "unallocated" or displays an unrecognized partition scheme.
  3. Close the GParted graphical window, as the recovery tool requires exclusive access to the storage device.

Step 3: Launch TestDisk via Terminal

GParted Live bundles TestDisk, a specialized utility for searching and restoring lost partition structures.

  1. Double-click the Terminal icon on the GParted desktop.
  2. Launch TestDisk with administrative privileges: 
    sudo testdisk
  3. Use the arrow keys to select Create to start a new log file, then press Enter.

Step 4: Scan for Lost Partitions

  1. Highlight the corrupted drive you identified in Step 2 and select Proceed.
  2. Select your partition table type:
    • Choose EFI GPT for modern systems using UEFI.
    • Choose Intel for older systems using legacy BIOS and MBR.
    • TestDisk usually detects the original type automatically; accept its default if unsure.
  3. Select Analyse, then choose Quick Search.
  4. TestDisk will scan the disk sectors for known file system headers (such as ext4, swap, or fat32 for the EFI system partition).

Step 5: Verify and Inspect Partitions

  1. Review the list of partitions discovered by the scan.
  2. Highlight each partition and press P to list its files. Verifying that your Ubuntu directories (such as /home, /etc, or /var) are visible confirms that the partition boundary is accurate.
  3. Press Q to exit the file listing.
  4. Ensure the partition status flags on the left are correct:
    • * indicates a primary bootable partition.
    • P indicates a primary partition.
    • L indicates a logical partition.
  5. If the Quick Search did not locate all partitions, press Enter and select Deeper Search to perform a thorough, sector-by-sector scan.

Step 6: Write the Restored Partition Table

  1. Once the correct partition layout is displayed in the list, press Enter to proceed.
  2. Select the Write option at the bottom of the screen.
  3. Type Y and press Enter to confirm that you want to write the recovered partition table to disk.
  4. If prompted to reboot for the changes to take effect, acknowledge the message.
  5. Select Quit repeatedly until you exit TestDisk, then close the terminal.

Step 7: Reboot into Ubuntu

  1. Double-click the Exit icon on the GParted desktop.
  2. Choose Reboot, remove the GParted Live USB drive when prompted, and press Enter.
  3. Allow the machine to boot directly into your local Ubuntu installation. The operating system should now recognize the recovered partitions and boot normally.
