Ubuntu Batch Command for Low System Load Tasks

The batch command in Ubuntu provides an automated way to schedule and execute resource-intensive tasks exclusively when system resource demands are low. Part of the standard at scheduling suite, batch defers command execution until the operating system's load average drops below a predefined threshold. This article explains how the batch command operates, how to configure its system load limits, and how to queue, monitor, and manage heavy background jobs without degrading overall system performance.

How the Batch Command Works

Unlike tools like cron or at, which trigger tasks at strictly defined times or calendar intervals, batch schedules one-off tasks dynamically based on system health.

When a job is submitted to batch, the underlying atd daemon reads the system's current load average—typically via /proc/loadavg. By default on Ubuntu, batch holds the execution of queued jobs until the system load average falls below 1.5. If the system is under heavy load, the job remains in the queue. Once the load stabilizes below the threshold, the daemon initiates the command.

Installing and Enabling the Required Service

The batch command is bundled with the at package. If it is not pre-installed on your Ubuntu system, install it using apt:

sudo apt update
sudo apt install at

Ensure the scheduling daemon (atd) is active and enabled to start automatically on boot:

sudo systemctl enable --now atd

Running Commands with Batch

There are two primary ways to submit tasks to the batch queue: interactively and via standard input.

1. Interactive Mode

Running batch by itself opens an interactive prompt (at>) where you can enter one or more commands:

batch

At the prompt, type the commands you wish to execute, then press Ctrl + D to save and exit:

at> tar -czf /backup/large_dataset.tar.gz /var/data
at> python3 /opt/scripts/data_processing.py
at> <EOT>

2. Piping Commands or Scripts

For automation or simple inline execution, pass commands directly using standard input:

echo "/usr/bin/python3 /scripts/render_video.py" | batch

To queue an entire bash script:

batch < heavy_calculation.sh

Any standard output (stdout) or error output (stderr) generated by the command is typically emailed to the local user executing the task, unless redirected inside the command itself (e.g., command > /path/to/log.txt 2>&1).

Managing the Batch Queue

Because jobs run asynchronously based on load, monitoring the queue is essential.

  • View Queued Jobs: Run atq to view pending jobs awaiting execution. The output displays the job ID, scheduling date/time, and queue name (batch jobs typically use queue b).
  • Inspect a Queued Job: Run at -c [job_id] to view the environment and commands registered for a specific job number.
  • Cancel a Queued Job: Use atrm [job_id] to remove a task from the queue before it begins executing.

Customizing the Load Threshold

The default threshold of 1.5 may not suit multi-core servers, where a load average of 1.5 represents relatively low CPU utilization. You can adjust this limit by passing the -l (load limit) flag to the atd daemon.

  1. Edit the systemd service file for atd: 
    sudo systemctl edit atd
  2. Add the custom load limit configuration. For example, to set the load threshold to 4.0: 
    [Service]
ExecStart=
ExecStart=/usr/sbin/atd -l 4.0 -b 60
    (The -b flag defines the minimum interval in seconds between the start of two batch jobs, which defaults to 60.)
  3. Restart the service to apply the change: 
    sudo systemctl restart atd

With this configuration, tasks submitted via batch will wait until the system load average drops below 4.0, ensuring multi-threaded workloads utilize spare hardware capacity efficiently.
