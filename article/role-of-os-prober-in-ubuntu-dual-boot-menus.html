Role of OS-Prober in Ubuntu Dual-Boot Menus

The os-prober package is a core utility responsible for detecting existing operating systems on a computer's storage drives when configuring the bootloader. This article explains how os-prober identifies secondary operating systems—such as Windows or other Linux distributions—and integrates them into Ubuntu's GRUB boot menu to enable a seamless dual-boot environment.

What Is os-prober?

os-prober is a lightweight diagnostic tool designed to scan all available disk partitions for installed operating systems other than the currently running Ubuntu installation. It functions primarily as a helper script for GRUB (GRand Unified Bootloader), the default bootloader used by Ubuntu.

How os-prober Functions

When Ubuntu updates its bootloader configuration, os-prober operates through a sequence of steps:

  1. Partition Scanning: The utility scans all mounted and unmounted block devices connected to the system.
  2. Signature Detection: It inspects each partition's filesystem for known files and boot signatures. For example, it searches for files like bootmgr or ntldr to detect Microsoft Windows, or specific directory structures and kernels to detect other Linux installations.
  3. Information Passing: Once detected, os-prober formats the discovered operating system details (partition label, OS type, and boot file paths) and sends them to the GRUB configuration generation script located at /etc/grub.d/30_os-prober.
  4. Menu Entry Generation: The GRUB scripts append these entries into /boot/grub/grub.cfg, the master configuration file that creates the interactive boot menu visible when the computer starts up.

The update-grub Process

os-prober rarely runs as a standalone command by the user. Instead, it is automatically invoked whenever the system runs:

sudo update-grub

During this command, GRUB reads system settings, executes os-prober, and outputs terminal lines confirming the detection of external systems, such as Found Windows Boot Manager on /dev/nvme0n1p1@/EFI/Microsoft/Boot/bootmgfw.efi.

Security and Recent Behavior Changes

In upstream GRUB versions (specifically version 2.06 and later), os-prober was disabled by default due to security concerns regarding the execution of arbitrary code when mounting untrusted file systems.

To ensure other operating systems appear in the boot menu if they are missing, users must ensure os-prober is enabled in /etc/default/grub by setting:

GRUB_DISABLE_OS_PROBER=false

Running sudo update-grub after modifying this setting forces os-prober to scan the disks again and re-populate the dual-boot menu entries.
