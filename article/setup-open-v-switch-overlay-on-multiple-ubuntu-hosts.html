Setup Open vSwitch Overlay on Multiple Ubuntu Hosts

This guide provides a straightforward walkthrough for setting up an Open vSwitch (OVS) overlay network across multiple physical Ubuntu servers using VXLAN tunnels. By encapsulating Layer 2 Ethernet frames inside Layer 3 UDP packets, an OVS overlay allows virtual machines, containers, or network namespaces running on separate physical hosts to communicate seamlessly within the same private virtual subnet without requiring hardware reconfiguration of the underlying physical network.

Prerequisites

Before beginning, ensure you have:

  • Two or more physical servers running Ubuntu (20.04 LTS, 22.04 LTS, or newer).
  • Sudo or root privileges on all machines.
  • Static IP connectivity between the physical hosts over the existing network (underlay).

For this guide, assume the following host configuration:

  • Host 1 (Underlay IP): 192.168.1.10
  • Host 2 (Underlay IP): 192.168.1.20
  • Target Overlay Subnet: 10.0.0.0/24

Step 1: Install Open vSwitch on All Hosts

Run the following commands on both Ubuntu hosts to install and enable the Open vSwitch service:

sudo apt update
sudo apt install -y openvswitch-switch
sudo systemctl enable --now openvswitch-switch

Verify that the service is active and the CLI tool is functional:

sudo ovs-vsctl show

Step 2: Create the OVS Bridge

Create an integration bridge on both hosts. This virtual bridge will handle traffic for the overlay network.

On Host 1 and Host 2, execute:

sudo ovs-vsctl add-br br-overlay

Step 3: Configure the VXLAN Tunnel

Establish a VXLAN tunnel port on each host pointing to the remote host's underlay IP address. The default VXLAN port (UDP 4789) is used automatically.

On Host 1:

Create a tunnel interface targeting Host 2:

sudo ovs-vsctl add-port br-overlay vxlan0 -- set interface vxlan0 type=vxlan options:remote_ip=192.168.1.20

On Host 2:

Create a tunnel interface targeting Host 1:

sudo ovs-vsctl add-port br-overlay vxlan0 -- set interface vxlan0 type=vxlan options:remote_ip=192.168.1.10

Step 4: Configure Overlay Endpoints

To test and utilize the overlay network directly on the hosts, create an internal OVS port on each host and assign an IP address from the overlay subnet (10.0.0.0/24).

On Host 1:

# Add internal port
sudo ovs-vsctl add-port br-overlay int-port -- set interface int-port type=internal

# Assign IP and bring interface up
sudo ip addr add 10.0.0.1/24 dev int-port
sudo ip link set int-port up

On Host 2:

# Add internal port
sudo ovs-vsctl add-port br-overlay int-port -- set interface int-port type=internal

# Assign IP and bring interface up
sudo ip addr add 10.0.0.2/24 dev int-port
sudo ip link set int-port up

Step 5: Configure Firewall Rules

If UFW or an external firewall is enabled on your hosts, allow UDP traffic on port 4789 between the physical underlay IPs.

On Host 1:

sudo ufw allow from 192.168.1.20 proto udp to any port 4789

On Host 2:

sudo ufw allow from 192.168.1.10 proto udp to any port 4789

Step 6: Verify Network Connectivity

Verify that Layer 2 traffic travels across the Layer 3 underlay by testing connectivity between the overlay endpoints.

From Host 1, ping Host 2's overlay IP:

ping -c 4 10.0.0.2

From Host 2, ping Host 1's overlay IP:

ping -c 4 10.0.0.1

To inspect the Open vSwitch port configuration and active flow entries:

sudo ovs-vsctl show
sudo ovs-ofctl dump-flows br-overlay

Once connectivity is confirmed, virtual machines (via KVM/QEMU) or container network interfaces can be attached directly to the br-overlay bridge to participate in the multi-host network.
