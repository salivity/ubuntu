Using Conntrack to View Firewall States on Ubuntu

The conntrack utility provides a direct interface to inspect and manage the Netfilter connection tracking subsystem inside the Linux kernel on Ubuntu systems. This article explains the purpose of conntrack, details how it monitors active stateful network sessions—such as TCP handshakes, UDP streams, and ICMP exchanges—and demonstrates how network administrators use it to troubleshoot firewall rules, Network Address Translation (NAT), and state table capacity issues in real time.

The Purpose of Connection Tracking

The Linux kernel uses Netfilter to enforce stateful firewalling via tools like UFW, iptables, and nftables. To decide whether incoming or outgoing packets belong to an existing session, the kernel stores flow metadata in a dedicated memory structure called the connection tracking table (nf_conntrack).

Standard firewall management commands usually show the rules, not the actual active network sessions. The conntrack userspace tool fills this gap. It allows administrators to query, filter, update, and flush the kernel's live connection tracking entries without altering the persistent firewall configuration.

Installing Conntrack on Ubuntu

The utility is not installed by default on Ubuntu server or desktop installations. It is available directly from the standard repositories:

sudo apt update
sudo apt install conntrack

Viewing Active Firewall Connections

The primary function of conntrack is inspecting the live table to determine how the firewall treats current traffic.

To list all currently tracked connections:

sudo conntrack -L

This output displays the protocol, timeout values, connection state (e.g., ESTABLISHED, TIME_WAIT), source and destination IP addresses, port numbers, and packet/byte counters. It also reveals whether bidirectional NAT has altered the source or destination endpoints.

To filter results to a specific protocol or IP address:

# Filter by TCP traffic
sudo conntrack -L -p tcp

# Filter by source IP
sudo conntrack -L -s 192.168.1.50

To display real-time connection events as they happen (new connections, state transitions, and destroyed flows):

sudo conntrack -E

Key Administrative Use Cases

  • NAT and Port-Forwarding Verification: When troubleshooting masquerading or port forwarding, conntrack shows the original packet parameters alongside the translated reply parameters, proving whether address translation succeeded.
  • Detecting Connection Table Exhaustion: High-traffic servers can exhaust the nf_conntrack_max limit, causing dropped packets. Running conntrack -C displays the current count of tracked sessions, helping operators monitor capacity before exhaustion occurs.
  • Session Termination: Unlike basic packet filters, conntrack can manually clear stuck or malicious sessions using the -D flag (to delete specific entries) or -F (to flush the entire table), forcing clients to re-negotiate states against current firewall policies.
