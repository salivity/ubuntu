Using Multipass Mount to Share Files with Ubuntu VMs

This article explores the purpose, functionality, and practical usage of the multipass mount command when working with Canonical's Multipass tool. It explains how this command bridges the host operating system with an Ubuntu virtual machine, enabling seamless, bi-directional file access without manual transfers. Readers will learn the core benefits of directory mounting, the basic syntax required, and how it simplifies software development and administration workflows.

The Purpose of multipass mount

The primary purpose of the multipass mount command is to map a directory from your host operating system (Windows, macOS, or Linux) directly into an active Multipass Ubuntu virtual machine. Instead of copying files back and forth using protocols like SSH, FTP, or multipass transfer, mounting creates a live, persistent link between the host storage and the guest filesystem.

Real-Time Synchronization

When a directory is mounted, changes made on the host are immediately visible inside the Ubuntu VM, and vice versa. This eliminates latency in workflows and prevents data divergence. For developers, this means code can be written using native host text editors and IDEs (like Visual Studio Code or IntelliJ), while execution, compilation, and testing happen inside the isolated Ubuntu guest environment.

Syntax and Implementation

To mount a folder, you specify the local host directory, the name of the target virtual machine, and the desired path inside the VM.

multipass mount /path/on/host <instance-name>[:/path/in/guest]
  • If you omit the guest path, Multipass automatically mounts the directory to a matching path or under the /home/ubuntu hierarchy.
  • If the target directory inside the guest does not exist, Multipass creates it automatically.

For example, to share a local project folder named my-project with an instance named dev-vm:

multipass mount ~/projects/my-project dev-vm:/home/ubuntu/project

Key Advantages

  1. Storage Efficiency: Files are not duplicated across systems, saving disk space.
  2. Persistence: Data remains stored safely on the host machine even if the virtual machine is stopped or destroyed.
  3. Workflow Integration: Allows heavy graphical tools to run natively on the host while keeping runtime environments and dependencies isolated within Ubuntu.

Managing and Removing Mounts

You can inspect existing mounts using:

multipass info <instance-name>

When file access is no longer required, the connection is severed cleanly using the multipass unmount command:

multipass unmount <instance-name>[:/path/in/guest]

This detaches the host folder without deleting the underlying files on either the host or the VM.
