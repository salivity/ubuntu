Analyze Ubuntu Kernel Crash Dump with Crash Utility

When an Ubuntu system experiences a critical kernel panic, it can automatically capture the system memory state into a crash dump (vmcore) file using kdump. This guide explains how to inspect and analyze an Ubuntu kernel crash dump using the crash debugging utility. By setting up the necessary debug symbols, pointing the tool to the appropriate uncompressed kernel image and dump file, and using targeted commands, administrators can identify the exact kernel function, process, or hardware fault that triggered the crash.

1. Install the Crash Utility and Kernel Debug Symbols

To analyze a dump, the crash tool requires the unstripped kernel binary (vmlinux) containing debugging symbols (dbgsym) corresponding exactly to the kernel version that generated the dump.

Install the crash package:

sudo apt update
sudo apt install -y crash

Enable the Ubuntu debug symbol repositories:

sudo apt install -y ubuntu-dbgsym-keyring
echo "deb http://ddebs.ubuntu.com $(lsb_release -cs) main restricted universe multiverse
deb http://ddebs.ubuntu.com $(lsb_release -cs)-updates main restricted universe multiverse" | \
sudo tee /etc/apt/sources.list.d/ddebs.list

sudo apt update

Install the debug symbols matching the kernel version that crashed (replace <kernel-version> with your target version, e.g., 5.15.0-88-generic):

sudo apt install -y linux-image-<kernel-version>-dbgsym

The unstripped vmlinux binary will be installed to /usr/lib/debug/boot/vmlinux-<kernel-version>.

2. Locate the Crash Dump

Ubuntu typically saves kernel dumps managed by kdump-tools in the /var/crash/ directory. Each crash event usually generates a timestamped directory containing the dump file:

ls -lh /var/crash/

The dump file is often named dump.<timestamp> or vmcore.

3. Launch the Crash Utility

Start the interactive crash session by providing the debug kernel image and the path to the crash dump:

crash /usr/lib/debug/boot/vmlinux-<kernel-version> /var/crash/<timestamp>/dump.<timestamp>

Once the environment loads, you will enter the interactive crash> shell prompt displaying system metadata and the panic message.

4. Essential Crash Commands for Analysis

Execute the following commands within the crash> prompt to determine the root cause of the crash:

  • sys: Displays high-level system information, including the hostname, kernel release, system uptime, and the specific panic string (e.g., "Kernel panic - not syncing: Fatal exception").
  • bt: Prints the kernel stack backtrace of the active task at the time of the crash. To view the backtrace of a specific PID or task, use bt <PID>. This pinpointed trace reveals the sequence of function calls leading to the failure.
  • log: Outputs the kernel ring buffer (dmesg). This allows you to inspect the log messages, call traces, and hardware warnings logged immediately prior to the crash.
  • ps: Lists all active processes at the time of the panic. The process running on the CPU that crashed is typically highlighted or marked with an asterisk (>).
  • kmem -i: Displays kernel and system memory utilization statistics, helping determine if memory exhaustion or slab leaks caused the panic.
  • dis -l <address>: Disassembles the machine instructions at a specific memory address or function name, mapping assembly code back to source line numbers when debug symbols are present.

Once the faulting instruction, offending driver, or invalid memory dereference is identified, exit the utility:

crash> exit
