How to Purge Varnish Cache Using Custom VCL on Ubuntu

This guide explains how to configure a custom Varnish Configuration Language (VCL) rule to purge cached content on an Ubuntu server. You will learn how to secure the purge mechanism using an Access Control List (ACL), intercept HTTP PURGE requests in the VCL workflow, apply the changes, and verify that cached pages are successfully cleared using curl.

Step 1: Open the Varnish Configuration File

On Ubuntu, the default VCL file is located in the /etc/varnish/ directory. Open it using your preferred text editor with administrative privileges:

sudo nano /etc/varnish/default.vcl

Step 2: Define an Access Control List (ACL)

To prevent unauthorized users from clearing your cache and degrading server performance, restrict the purge command to trusted IP addresses. Add the following ACL block near the top of /etc/varnish/default.vcl:

acl purge {
    "localhost";
    "127.0.0.1";
    "::1";
}

Add any additional IP addresses that require permission to trigger purges inside this block.

Step 3: Configure the vcl_recv Subroutine

Locate the sub vcl_recv block (or create it if it does not exist) and add logic to evaluate incoming HTTP requests. If a request uses the PURGE method, verify the client's IP against the ACL and call the built-in purge action:

sub vcl_recv {
    if (req.method == "PURGE") {
        if (!client.ip ~ purge) {
            return (synth(405, "Method not allowed"));
        }
        return (purge);
    }
}

Step 4: Handle the Purge Response (Optional)

You can define custom responses to confirm whether the purge succeeded or failed by implementing the vcl_purge and vcl_synth subroutines:

sub vcl_purge {
    set req.http.X-Purge = "True";
    return (synth(200, "Purged"));
}

Step 5: Validate and Reload Varnish

Save and close the file. Test the VCL syntax to ensure there are no compilation errors before restarting the service:

varnishd -C -f /etc/varnish/default.vcl

If the compilation succeeds without errors, reload or restart the Varnish systemd service to apply the configuration:

sudo systemctl reload varnish

If reloading is not supported by your specific Varnish package build, use sudo systemctl restart varnish.

Step 6: Test the Purge Rule

To clear the cache for a specific URL, send an HTTP PURGE request using curl from a machine defined in your ACL:

curl -X PURGE http://127.0.0.1/example-page

If the configuration is correct, Varnish will return an HTTP 200 Purged status code, removing the cached object and forcing Varnish to fetch a fresh version from your backend server on the next request.
