How to Hibernate or Sleep Ubuntu from Terminal

This article explains how to place an Ubuntu system into deep sleep (suspend) or hibernation directly from the command line. You will learn the exact systemd commands used to trigger these low-power states, the difference between suspending to RAM and hibernating to disk, and the prerequisites required to ensure hibernation works properly on your system.

The Commands for Sleep and Hibernation

Modern versions of Ubuntu utilize systemd to control power management. You can trigger low-power states directly using the systemctl utility.

1. Putting Ubuntu into Deep Sleep (Suspend)

To place Ubuntu into a standard sleep state (Suspend-to-RAM), run the following command:

systemctl suspend

This cuts power to most components while keeping RAM active, allowing the system to resume instantly when you press a key or the power button.

2. Putting Ubuntu into Hibernation (Suspend-to-Disk)

To put Ubuntu into hibernation, run:

sudo systemctl hibernate

Hibernation writes the entire contents of your active RAM into swap space on your drive and powers off the machine completely. When the machine powers back on, the state is restored from disk.

3. Using Hybrid Sleep

Ubuntu also supports a hybrid state that writes the system state to disk while keeping RAM powered:

sudo systemctl hybrid-sleep

If the battery dies or power is lost, the system can still recover from the disk. If power remains intact, it wakes up instantly from RAM.

Hibernation Prerequisites in Ubuntu

Ubuntu disables hibernation by default on many installations. For systemctl hibernate to work successfully, your system must meet specific requirements:

  1. Adequate Swap Space: Your swap partition or swap file must be at least equal to or larger than your total installed RAM.
  2. Kernel Resume Support: The kernel needs to know where the swap space is located. This requires setting the resume parameter in /etc/default/grub pointing to your swap partition's UUID, followed by updating GRUB: 
    sudo update-grub
  3. Secure Boot: On many systems, UEFI Secure Boot restricts hibernation to protect system integrity. If hibernation fails or is locked down, Secure Boot may need to be disabled in the motherboard UEFI settings.

To check if hibernation is supported and enabled on your installation before running the command, execute:

sudo systemctl status sleep.target
