How vnStat Daemon Tracks Network Bandwidth on Ubuntu

This article explains the role of the vnStat daemon (vnstatd) in logging and preserving historical network bandwidth usage on Ubuntu systems. It covers how the background service collects traffic metrics from the Linux kernel, stores historical records in a persistent database without packet sniffing, and enables administrators to analyze hourly, daily, and monthly usage trends reliably across system reboots.

What is the vnStat Daemon?

The vnStat tool is split into two primary components: the command-line utility (vnstat) used to query and view reports, and the background daemon (vnstatd) responsible for the actual continuous data collection.

Unlike traditional packet-sniffing monitors that intercept and inspect individual network packets—consuming significant CPU and memory—vnstatd operates as a lightweight metric collector. It periodically reads the standard network interface counters exposed by the Linux kernel via the /proc/net/dev virtual filesystem.

Core Roles of vnstatd in Bandwidth Logging

1. Periodic Metric Sampling

The daemon runs continuously in the background, waking at regular intervals defined in its configuration file (/etc/vnstat.conf). During each cycle, it queries the bytes received (RX) and transmitted (TX) for all monitored interfaces. Because it samples kernel counters rather than intercepting live traffic, it introduces virtually zero CPU overhead, making it ideal for low-powered virtual private servers (VPS) and high-throughput servers alike.

2. Historical Data Aggregation

Kernel counters reset to zero whenever an interface goes down or the server reboots. The primary responsibility of vnstatd is to maintain continuity despite these resets. It computes the delta (the difference between the current and previous sample) and aggregates these figures into structured historical categories:

  • Five-minute and hourly intervals: Captures short-term spikes and intraday trends.
  • Daily summaries: Retains standard day-by-day transfer totals.
  • Monthly and yearly archives: Consolidates daily totals to help monitor long-term trends and billing-cycle data caps.
  • Top usage days: Automatically records peak bandwidth consumption events.

3. Persistent Database Storage

Modern versions of vnStat on Ubuntu store traffic logs in an SQLite database (typically located at /var/lib/vnstat/vnstat.db). To protect solid-state drives and storage media from excessive write wear, vnstatd keeps current counters in memory and periodically flushes aggregated changes to the disk. It also ensures an immediate flush occurs when the system signals a clean shutdown or reboot.

Managing the Service on Ubuntu

On Ubuntu systems, vnstatd runs as a systemd background service named vnstat.service. Once installed via the apt package manager, the daemon starts automatically and enables monitoring on all active interfaces by default.

Administrators can control the daemon using standard system commands:

  • Check daemon status: sudo systemctl status vnstat
  • Restart the service: sudo systemctl restart vnstat
  • Force an immediate write to disk: sudo killall -HUP vnstatd

Once vnstatd is running and collecting data, administrators invoke the front-end vnstat command with various flags (such as -h for hourly, -d for daily, or -m for monthly) to render the historical logs managed by the background daemon.
