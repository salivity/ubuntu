Purpose of /etc/netplan/99-custom.yaml in Ubuntu

The /etc/netplan/99-custom.yaml file in Ubuntu is a user-created configuration file used by Netplan to define or override network interface settings. Netplan parses files in /etc/netplan/ in alphabetical and numerical order, meaning the 99- prefix ensures that settings within this file take highest priority over default system configurations like 01-netcfg.yaml or 50-cloud-init.yaml. This article explains the role of file precedence in Netplan, the main use cases for 99-custom.yaml, and how it prevents configuration loss during system updates.

Netplan Precedence and the "99" Prefix

Netplan serves as an abstraction layer for Ubuntu network configuration, generating low-level configurations for backends such as systemd-networkd or NetworkManager.

When Netplan loads settings, it reads all files matching /etc/netplan/*.yaml. Files are processed in lexicographical order. When duplicate directives exist for the same network interface across multiple files, the last file read wins.

By prefixing a file with 99-, administrators ensure that their custom definitions are loaded last, successfully overriding any standard configurations supplied by the OS installer, cloud providers, or default packages.

Primary Use Cases

Creating a /etc/netplan/99-custom.yaml file is useful for several key tasks:

  • Overriding Cloud-Init Configurations: On cloud platforms (such as AWS, Azure, or DigitalOcean), system settings are often managed by cloud-init, which generates files like 50-cloud-init.yaml. Defining settings in 99-custom.yaml ensures your changes persist even if cloud-init runs again.
  • Setting Static IP Addresses: It allows you to switch an interface from dynamic DHCP to a static IP address without modifying original system files.
  • Custom DNS and Routing: You can specify custom DNS nameservers, search domains, and custom static routes for specific interfaces.
  • Advanced Networking: It provides a safe space to configure advanced network topologies, such as VLANs, network bonding (LACP), or software bridges for virtual machines.
  • Safe Configuration Management: Keeping personal or organization-specific changes in a distinct file makes auditing and backups straightforward, while avoiding conflicts during package upgrades.

Basic Structure Example

A standard /etc/netplan/99-custom.yaml file overriding an interface to use a static IP address follows this format:

network:
  version: 2
  renderer: networkd
  ethernets:
    enp0s3:
      dhcp4: no
      addresses:
        - 192.168.1.150/24
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses:
          - 1.1.1.1
          - 8.8.8.8

Applying the Configuration

After editing or creating /etc/netplan/99-custom.yaml, strict YAML formatting rules (including spaces instead of tabs for indentation) must be followed.

To test and apply the configuration safely:

  1. Test the setup: Run sudo netplan try. This command checks for syntax errors and reverts changes automatically if you do not confirm them within a timeout period.
  2. Apply permanently: Run sudo netplan apply to enforce the network settings directly into the system backend.
