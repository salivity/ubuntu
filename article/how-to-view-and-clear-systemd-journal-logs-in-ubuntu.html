How to View and Clear Systemd Journal Logs in Ubuntu

Systemd uses the journalctl utility to store and manage system logs in Ubuntu. This article covers how to view active system logs, filter them by service or time frame, check disk usage, and safely clear accumulated log data to free up disk space.

Viewing Systemd Journal Logs

To view all systemd journal logs, run the default journalctl command:

sudo journalctl

Useful Viewing Filters

  • View real-time (live) logs:

    sudo journalctl -f

  • View logs from the current boot:

    sudo journalctl -b

  • View logs for a specific service (e.g., NGINX or SSH):

    sudo journalctl -u nginx

  • View logs within a specific time range:

    sudo journalctl --since "1 hour ago"
sudo journalctl --since "2023-10-01" --until "2023-10-15"

  • View priority logs (errors, critical, or emergency only):

    sudo journalctl -p err..emerg

Checking Log Disk Usage

Before deleting logs, check how much disk space the journal logs are currently using:

journalctl --disk-usage

Clearing Systemd Journal Logs

Systemd logs should not be deleted manually using rm. Instead, use the built-in --vacuum options to remove old logs safely.

1. Clear Logs Older Than a Specific Time

To delete logs older than a specific duration (e.g., 7 days):

sudo journalctl --vacuum-time=7d

2. Retain Logs Up to a Maximum Size

To reduce total log volume down to a specific size (e.g., 500 MB):

sudo journalctl --vacuum-size=500M

3. Retain a Maximum Number of Log Files

To limit the journal to a specific number of archived files:

sudo journalctl --vacuum-files=5

Limiting Log Size Permanently

To prevent journal logs from filling up your disk in the future, set a permanent size limit in the systemd configuration file.

  1. Open the configuration file:

    sudo nano /etc/systemd/journald.conf

  2. Locate or add the SystemMaxUse parameter and define a limit:

    SystemMaxUse=500M

  3. Save the file and restart the systemd journal service:

    sudo systemctl restart systemd-journald
