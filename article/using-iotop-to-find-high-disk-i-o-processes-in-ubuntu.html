Using iotop to Find High Disk I/O Processes in Ubuntu

The iotop command in Ubuntu is an essential real-time monitoring tool designed to identify specific processes causing high disk read and write activity. Similar to how the standard top command monitors CPU and memory usage, iotop provides an interactive, top-like UI that isolates storage operations per process or thread. This makes it an indispensable utility for system administrators looking to diagnose system slowdowns, pinpoint disk bottlenecks, and maintain server performance.

Understanding the Role of iotop

When a system experiences sluggish responsiveness or high load averages while CPU usage remains low, the culprit is often an I/O bottleneck. Linux kernels log storage activity for every process, and iotop collects this data directly from the system kernel to present a live summary of storage throughput. It shows exact read and write speeds alongside the percentage of time a process spent waiting for disk operations to complete.

How to Install and Run iotop in Ubuntu

Because iotop relies on kernel-level task statistics, it requires administrative privileges to run correctly.

To install iotop on Ubuntu, run:

sudo apt update
sudo apt install iotop

To launch the basic real-time interface:

sudo iotop

Essential Techniques to Isolate High Disk I/O

While launching iotop without flags shows all active processes, several built-in parameters streamline the process of identifying heavy disk users:

  1. Filter Active Processes Only (-o or --only)
    By default, iotop lists all running processes, even if they are idle. Passing the -o flag hides idle tasks and displays only processes actively performing disk I/O:

    sudo iotop --only

  2. Sort by Disk Read or Write Rates
    Inside the interactive interface, use the left and right arrow keys to change the sorting column, or press r to reverse the sort order. Sorting by DISK READ or DISK WRITE instantly places the highest consumer at the top of the list.

  3. Check I/O Wait Percentage (IO>)
    The IO> column shows the percentage of time a process spent in the I/O wait state. A consistently high percentage indicates that the process is bottlenecked by drive performance.

  4. Batch Mode for Logging (-b)
    For non-interactive monitoring or capturing transient I/O spikes over time, use batch mode combined with a specified number of iterations and interval delays:

    sudo iotop -b -n 5 -d 2

Key Output Columns Explained

To effectively troubleshoot disk performance using iotop, monitor these primary display fields:

  • TID / USER: The Thread ID and the user account executing the operation.
  • DISK READ: The real-time rate at which the process reads data from storage (e.g., KB/s or MB/s).
  • DISK WRITE: The real-time rate at which the process writes data to storage.
  • SWAPIN: The percentage of time spent bringing swap memory back into RAM. High values usually indicate a shortage of physical memory.
  • IO>: The percentage of time the process spent waiting for storage I/O to complete.
  • COMMAND: The exact command or binary responsible for the activity.

By leveraging iotop to filter idle processes and monitor read, write, and wait metrics, Ubuntu administrators can quickly resolve disk contention and stabilize system performance.
