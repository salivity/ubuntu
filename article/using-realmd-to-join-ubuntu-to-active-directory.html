Using realmd to Join Ubuntu to Active Directory

The realmd tool significantly streamlines the integration of Ubuntu systems into enterprise identity domains such as Microsoft Active Directory and FreeIPA. By acting as an orchestration layer, it automatically detects domain settings, installs necessary dependencies, and configures authentication clients without requiring administrators to manually edit complex configuration files. This guide explains the core role of realmd, how it simplifies enrollment, and why it is the preferred utility for domain management on modern Ubuntu environments.

The Challenge of Traditional Domain Joins

Historically, joining an Ubuntu machine to an Active Directory domain required administrators to manually install, configure, and coordinate multiple disparate services:

  • Samba and Winbind or SSSD (System Security Services Daemon) for identity mapping.
  • Kerberos (krb5.conf) for network authentication and ticket handling.
  • Name Service Switch (nsswitch.conf) to resolve domain users and groups.
  • PAM (Pluggable Authentication Modules) to handle authentication policies, session creation, and home directory generation.

A single syntax error in any of these configuration files could prevent authentication or leave the system inaccessible.

How realmd Simplifies the Process

realmd abstracts this complexity by providing a unified, high-level command-line interface and DBus API. Instead of handling Kerberos and SSSD directly, the administrator interacts almost exclusively with realmd.

1. Automatic Domain Discovery

Before joining, realmd can probe the network via DNS SRV records to discover available domain controllers, the domain type, and supported authentication mechanisms:

realm discover example.com

This output identifies the realm name, domain software, and lists the exact packages Ubuntu requires to complete the join.

2. Automatic Dependency Resolution and Configuration

When executing the join command, realmd invokes package managers to install required software (such as sssd, adcli, and realmd packages) if they are missing. It then generates the proper configurations for SSSD and Kerberos based on the parameters discovered from the domain controller.

Joining typically requires a single command:

sudo realm join -U Administrator example.com

realmd authenticates with the domain, creates the computer account in Active Directory, retrieves the machine keytab, updates /etc/sssd/sssd.conf, and starts the necessary background services.

3. Streamlined Access Control

Managing which domain accounts are allowed to log into the Ubuntu machine is controlled directly through realmd. By default, joining allows all domain users to log in, but administrators can restrict access immediately:

  • Deny all domain logins: sudo realm deny --all
  • Permit specific users: sudo realm permit user@example.com
  • Permit specific domain groups: sudo realm permit -g "Domain Admins"

These commands automatically modify SSSD’s access provider configurations behind the scenes.

4. Clean System Leaves

Leaving a domain is equally direct. Running realm leave unregisters the machine from the domain, updates Active Directory (if credentials are provided), disables domain-based authentication in PAM and NSS, and resets local configuration files to prevent authentication lockouts.

Summary

The realmd command acts as an automation framework on Ubuntu, replacing error-prone manual configuration with simple commands for discovering, joining, managing, and leaving enterprise identity domains. By orchestrating SSSD, Kerberos, and PAM under a standardized interface, it ensures fast, repeatable, and secure domain integration.
