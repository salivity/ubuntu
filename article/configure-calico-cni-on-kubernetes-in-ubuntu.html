Configure Calico CNI on Kubernetes in Ubuntu

This guide provides a straightforward walkthrough for configuring the Calico Container Network Interface (CNI) plugin on a Kubernetes cluster running on Ubuntu. You will learn the network prerequisites, how to deploy the Calico operator and custom resources, how to match your cluster's pod CIDR, and how to verify that your cluster nodes transition to a functional, ready state.

1. Prerequisites and System Preparation

Before configuring Calico, ensure your Kubernetes control plane and worker nodes are running on Ubuntu with container runtimes (such as containerd) active.

Calico requires specific network ports to communicate across Ubuntu nodes:

  • TCP 179: Calico BGP driver (if using BGP routing)
  • IP Protocol 4: IP-in-IP encapsulation (if using IP-in-IP overlay)
  • UDP 4789: VXLAN encapsulation (if using VXLAN overlay)
  • TCP 5473: Typha daemon (used in larger clusters)

If Ubuntu's Uncomplicated Firewall (UFW) is active, allow traffic for the CNI or disable UFW entirely across all nodes:

sudo ufw disable

Ensure packet forwarding is enabled by setting net.ipv4.ip_forward = 1 in /etc/sysctl.conf:

sudo sysctl -w net.ipv4.ip_forward=1

2. Verify Kubernetes Cluster Initialization

Calico relies on your cluster's designated Pod Network CIDR. If you used kubeadm, your cluster was likely initialized with a command matching:

sudo kubeadm init --pod-network-cidr=192.168.0.0/16

If a different CIDR was defined (such as 10.244.0.0/16), note it down, as you will need to update the Calico manifest to match.

3. Install the Tigera Calico Operator

The recommended method to deploy Calico is via the Tigera Operator, which manages the lifecycle and components of Calico automatically.

From your Ubuntu control plane node, deploy the operator manifest:

kubectl create -f https://raw.githubusercontent.com/projectcalico/calico/v3.27.3/manifests/tigera-operator.yaml

4. Configure the Calico Custom Resources

Download the custom resources definition:

curl -O https://raw.githubusercontent.com/projectcalico/calico/v3.27.3/manifests/custom-resources.yaml

Open custom-resources.yaml in a text editor to verify the pod CIDR:

apiVersion: operator.tigera.io/v1
kind: Installation
metadata:
  name: default
spec:
  calicoNetwork:
    ipPools:
    - name: default-ipv4-ippool
      beans:
      cidr: 192.168.0.0/16
      encapsulation: VXLANCrossSubnet
      natOutgoing: Enabled
      nodeSelector: all()

If your cluster uses a CIDR other than 192.168.0.0/16, update the cidr: field. You can also change the encapsulation mode to VXLAN, IPIP, or None (for native unencapsulated BGP routing).

Apply the configuration:

kubectl create -f custom-resources.yaml

5. Verify the Calico Installation

Watch the Calico system pods spin up. The operator installs the primary networking pods inside the calico-system namespace:

kubectl get pods -n calico-system -w

Wait until all pods (calico-node, calico-kube-controllers, and calico-typha) enter the Running status.

Check the status of your Ubuntu Kubernetes nodes:

kubectl get nodes

Once Calico is operational, the nodes will shift from NotReady to Ready.

6. Install the Calicoctl CLI Tool (Optional)

To manage network policies, IP pools, and BGP configurations directly on Ubuntu, install the calicoctl binary on the control plane node:

curl -L https://github.com/projectcalico/calico/releases/download/v3.27.3/calicoctl-linux-amd64 -o calicoctl
chmod +x calicoctl
sudo mv calicoctl /usr/local/bin/

Verify calicoctl can interact with the cluster:

DATASTORE_TYPE=kubernetes KUBECONFIG=~/.kube/config calicoctl get nodes
