How to Use Btrfs Property Set Compression on Ubuntu

This article explores the specific role of the btrfs property set command in managing transparent data compression on an Ubuntu system running the Btrfs filesystem. It details how this command provides granular, object-level compression control over individual files, directories, and subvolumes as an alternative or complement to global mount options, and covers practical command syntax for implementing and verifying these settings.

Granular Compression Without Remounting

On Ubuntu, Btrfs compression is traditionally enabled at mount time using options such as compress=zstd in /etc/fstab. While effective, mount options apply globally to all data written to that specific filesystem mount.

The btrfs property set command allows administrators to control compression settings on a per-subvolume, per-directory, or per-file basis. This command modifies the underlying metadata property of the targeted filesystem object without requiring the filesystem to be unmounted, remounted, or adjusted in the system's mount configuration files.

Inheritance and Directory-Level Rules

When btrfs property set is applied to a directory or a subvolume root, it sets an inheritable property. Any new files or child directories created within that directory automatically inherit the designated compression algorithm.

This enables hybrid storage strategies on Ubuntu servers and desktops. For instance, high-write or latency-sensitive directories can remain uncompressed, while log directories, document stores, or virtual machine images can have compression explicitly defined via properties.

Command Syntax and Usage

To enable compression on a specific file, directory, or subvolume path on Ubuntu, use the following syntax with root privileges:

sudo btrfs property set /path/to/target compression zstd

Btrfs supports several compression algorithms through this property:

  • zstd: Modern standard balancing high compression ratios with fast decompression speeds.
  • lzo: Optimized for low CPU overhead and high throughput.
  • zlib: Legacy algorithm offering higher compression ratios at the cost of higher CPU usage.

To verify the current compression property applied to an object:

sudo btrfs property get /path/to/target compression

To remove the explicit compression property and revert to the filesystem default or global mount settings:

sudo btrfs property set /path/to/target compression ""

Behavior with Existing Data

Setting the compression property does not retroactively compress data that already exists inside the file or directory. The compression algorithm is only applied to data written after the property has been set.

To apply compression to existing files after updating the property, the data must be rewritten or defragmented using the Btrfs defragmentation utility:

sudo btrfs filesystem defragment -r -czstd /path/to/target

Using btrfs property set alongside targeted defragmentation provides complete administrative control over disk space optimization on Ubuntu without impacting unaffected partitions or workloads.
