Restrict Linux System Calls Using Seccomp in Ubuntu

Secure Computing Mode (seccomp) is a Linux kernel security facility designed to limit the system calls an application can make, significantly reducing the potential attack surface if the process is compromised. This guide demonstrates how to audit, write, and enforce seccomp filters on Ubuntu using both low-level C programming with the libseccomp library and high-level configuration directives using systemd service units.

Prerequisites and Setup

Before implementing seccomp filters, install the necessary development headers, utilities, and tracing tools on Ubuntu:

sudo apt update
sudo apt install -y libseccomp-dev seccomp strace build-essential

Step 1: Identifying Application System Calls

To create an effective whitelist filter, you must first profile the target application to identify every system call it requires during normal operation.

Use strace to log all syscalls invoked by a binary:

strace -c -f -S name ./your_program

This command runs the binary and outputs a summary of syscalls made, sorted by name. Ensure you run the application through its standard workflows to capture all necessary calls, such as file read/writes, network operations, and memory allocations.

Step 2: Implementing Seccomp Filters with libseccomp in C

The libseccomp library allows developers to integrate custom Berkeley Packet Filter (BPF) rules directly into an application's codebase.

The standard approach uses a default-deny policy (whitelisting):

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <seccomp.h>
#include <sys/syscall.h>

int main() {
    // 1. Initialize the filter context with default action KILL
    scmp_filter_ctx ctx = seccomp_init(SCMP_ACT_KILL);
    if (ctx == NULL) {
        perror("seccomp_init failed");
        return 1;
    }

    // 2. Allow essential system calls
    // Allow stdout/stderr output (write)
    if (seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(write), 0) < 0) {
        goto filter_err;
    }

    // Allow program exit
    if (seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(exit_group), 0) < 0) {
        goto filter_err;
    }

    // 3. Load the seccomp filter into the kernel
    if (seccomp_load(ctx) < 0) {
        goto filter_err;
    }

    // Clean up memory allocated for filter definition
    seccomp_release(ctx);

    // Filter is now active
    printf("Seccomp filter applied successfully.\n");

    // Attempting an unapproved syscall will result in immediate termination:
    // getpid() is not in the whitelist:
    printf("Process PID: %d\n", getpid());

    return 0;

filter_err:
    perror("Seccomp configuration error");
    seccomp_release(ctx);
    return 1;
}

Compile and run the program:

gcc seccomp_demo.c -lseccomp -o seccomp_demo
./seccomp_demo

Because getpid was not included in the whitelist, the kernel kills the process with a Bad system call (core dumped) error.

Step 3: Restricting Syscalls via systemd Services

If you manage applications as systemd services on Ubuntu, you can enforce seccomp filters declaratively without altering the application source code.

  1. Open or create an override file for the target service:
sudo systemctl edit your_service.service
  1. Add the SystemCallFilter directive under the [Service] section:
[Service]
# Whitelist only base system service calls and specific required syscalls
SystemCallFilter=@system-service
SystemCallFilter=write read openat fstat close exit_group

# Optional: Set the action on a blocked syscall to return an error instead of killing the process
SystemCallErrorNumber=EPERM

To create a blacklist instead, use the tilde (~) prefix:

[Service]
# Block network-related syscalls and raw memory execution
SystemCallFilter=~@network-io @privileged
  1. Reload the systemd daemon and restart the service:
sudo systemctl daemon-reload
sudo systemctl restart your_service.service

Step 4: Auditing and Debugging Blocked Calls

When tuning filters, changing the action from SCMP_ACT_KILL to SCMP_ACT_LOG (in C) or using SystemCallErrorNumber=EPERM (in systemd) prevents process termination while logging violations.

To view seccomp violations captured by the Linux audit daemon or kernel log, run:

sudo journalctl -k --grep="audit.*type=1326"

Look for syscall= fields in the logs, which display the numeric identifier of the blocked call. Convert the syscall number to a name using the ausyscall utility:

ausyscall <number>
