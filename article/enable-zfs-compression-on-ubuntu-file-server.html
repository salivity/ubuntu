Enable ZFS Compression on Ubuntu File Server

Enabling transparent compression in ZFS allows your Ubuntu file server to automatically compress data before writing it to disk and decompress it on the fly when read, dramatically saving storage capacity while often improving read/write performance. This guide demonstrates how to check current compression settings, select the best algorithm for your workload, apply transparent compression to a ZFS pool or dataset, and verify the resulting disk space savings.

Step 1: Check Current Compression Settings

Before making any changes, inspect the current compression status of your ZFS storage pools and datasets. Open a terminal and run:

zfs get compression

To view the setting for a specific pool or dataset, specify its name:

zfs get compression poolname/dataset

By default, ZFS datasets may have compression set to off.

Step 2: Choose a Compression Algorithm

ZFS supports multiple compression algorithms. The two most common and effective choices are:

  • lz4: The recommended default for most systems. It offers extremely fast compression and decompression speeds with very low CPU overhead. If a block cannot be compressed, LZ4 skips it without wasting CPU cycles.
  • zstd: Provides a higher compression ratio than LZ4, making it ideal for servers where maximizing storage savings is more important than absolute raw speed. It also supports customizable compression levels (from zstd-1 to zstd-19, with zstd defaulting to level 3).

Step 3: Enable Transparent Compression

You can apply compression to an entire storage pool (which inherits down to all child datasets) or to a specific dataset.

To enable LZ4 compression on a dataset:

sudo zfs set compression=lz4 poolname/dataset

To enable ZSTD compression on a dataset:

sudo zfs set compression=zstd poolname/dataset

To enable it across the entire pool:

sudo zfs set compression=lz4 poolname

The change takes effect immediately for all subsequent writes.

Step 4: Handling Existing Data

ZFS does not retroactively compress data already written to disk. Only newly created or modified files will be compressed. To compress existing data, you must rewrite it so ZFS processes it through the new compression engine:

cp -a /path/to/mountpoint/data /path/to/mountpoint/data-temp
rm -rf /path/to/mountpoint/data
mv /path/to/mountpoint/data-temp /path/to/mountpoint/data

Step 5: Verify Space Savings

To verify that compression is functioning and to view your storage savings, check the compressratio property:

zfs get compressratio poolname/dataset

A ratio of 1.00x indicates no compression, while a ratio of 1.50x means your data consumes roughly 33% less physical disk space than its uncompressed size. You can also view overall pool savings using:

zpool list
