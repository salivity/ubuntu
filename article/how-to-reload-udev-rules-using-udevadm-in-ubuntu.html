How to Reload udev Rules Using udevadm in Ubuntu

Managing hardware devices on Ubuntu often requires creating or modifying custom udev rules. Instead of rebooting your entire system to apply these changes, you can use the udevadm utility to instantly reload and trigger new configuration rules. This guide demonstrates the exact commands needed to force Ubuntu to recognize your updated udev rules immediately without interrupting your workflow.

Step 1: Reload the udev Rules

After creating or modifying your rule files inside the /etc/udev/rules.d/ directory, you must instruct the udev daemon to reload the configuration files into memory.

Run the following command:

sudo udevadm control --reload-rules

Or you can use the shorter equivalent command:

sudo udevadm control --reload

Step 2: Trigger the Updated Rules

Reloading the rules alerts the system to the changes, but it will not automatically apply them to hardware that is already plugged in. To apply the new rules to currently connected devices without unplugging and reconnecting them, run:

sudo udevadm trigger

Targeting Specific Devices

Running sudo udevadm trigger applies changes to all devices on your system. If you want to limit the trigger to a specific device or class of hardware, use one of the following variations:

  • Target a specific subsystem (e.g., USB devices):

    sudo udevadm trigger --subsystem-match=usb

  • Target a specific block device:

    sudo udevadm trigger --subsystem-match=block

  • Target a specific device path:

    sudo udevadm trigger /dev/ttyUSB0

Step 3: Verify Rule Execution

To test whether your rule parses correctly and applies the expected attributes, you can dry-run an event for a specific device using the following command:

udevadm test $(udevadm info -q path -n /dev/ttyUSB0)

Replace /dev/ttyUSB0 with your target device node. The output will display how udev processes the device and show if your custom rule was successfully triggered.
