How to Configure radvd for IPv6 SLAAC on Ubuntu

Setting up IPv6 Stateless Address Autoconfiguration (SLAAC) on Ubuntu allows networked devices to automatically obtain routable IPv6 addresses and default gateway routes without a stateful DHCPv6 server. This guide covers enabling kernel-level IPv6 packet forwarding, installing the Router Advertisement Daemon (radvd), configuring interface prefixes and flags, and verifying service operation to establish automated network configuration.

Prerequisites

  • An Ubuntu server with root or sudo privileges.
  • At least two network interfaces (or one interface serving a downstream LAN).
  • A statically assigned IPv6 address and /64 prefix configured on the downstream network interface (e.g., eth1 or enp3s0).

Step 1: Enable IPv6 Packet Forwarding

For an Ubuntu system to broadcast router advertisements and route traffic, IPv6 forwarding must be enabled at the kernel level.

  1. Open /etc/sysctl.conf in a text editor:

    sudo nano /etc/sysctl.conf

  2. Uncomment or add the following line:

    net.ipv6.conf.all.forwarding=1

  3. Apply the changes immediately:

    sudo sysctl -p

Step 2: Install radvd

The Router Advertisement Daemon is available in standard Ubuntu repositories. Install it using apt:

sudo apt update
sudo apt install radvd -y

Step 3: Configure radvd

The configuration file /etc/radvd.conf defines which network interfaces broadcast advertisements and which IPv6 prefixes are distributed to clients.

  1. Create or edit /etc/radvd.conf:

    sudo nano /etc/radvd.conf

  2. Add the configuration block for your local interface (replace eth1 with your interface name and 2001:db8:1::/64 with your assigned prefix):

    interface eth1 {
    AdvSendAdvert on;
    MinRtrAdvInterval 30;
    MaxRtrAdvInterval 100;

    prefix 2001:db8:1::/64 {
        AdvOnLink on;
        AdvAutonomous on;
        AdvRouterAddr on;
    };

    RDNSS 2001:4860:4860::8888 2001:4860:4860::8844 {
        AdvRDNSSLifetime 300;
    };
};
    • AdvSendAdvert on: Directs radvd to actively transmit Router Advertisements (RAs) on this interface.
    • AdvOnLink on: Informs clients that addresses sharing this prefix are reachable directly on the local link.
    • AdvAutonomous on: Tells clients to use SLAAC to self-generate an IPv6 address using this prefix.
    • RDNSS: (Optional) Supplies IPv6 DNS servers to supporting clients via the Router Advertisement.

Step 4: Start and Enable the radvd Service

Enable the service to start automatically on system boot and apply the new configuration:

sudo systemctl restart radvd
sudo systemctl enable radvd

Verify that the daemon is running without errors:

sudo systemctl status radvd

Step 5: Verify Router Advertisements

  1. Monitor Local Advertisements: Use the radvdump utility on the Ubuntu server to listen for and display outgoing advertisements:

    sudo radvdump

    The output should display the interface settings, prefix, and valid lifetimes configured in /etc/radvd.conf.

  2. Verify Client Address Assignment: Connect a client device to the target subnet. Check the client network interface settings to ensure it has derived an IPv6 address matching the configured /64 prefix and received the default IPv6 route pointing to the Ubuntu server's link-local address.
