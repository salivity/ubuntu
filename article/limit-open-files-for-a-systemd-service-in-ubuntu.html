Limit Open Files for a Systemd Service in Ubuntu

Managing resource consumption on Ubuntu servers is essential for maintaining application performance and stability. This guide explains how to configure the maximum number of open files (file descriptors) for an individual service managed by systemd using the LimitNOFILE directive. Following these steps, you will learn how to check existing limits, create a persistent drop-in configuration override, and verify that the new open file limits are active.

1. Check the Current Open File Limit

Before modifying limits, determine what the target service is currently using. Replace <service-name> with your actual service (for example, nginx or mysql):

systemctl show <service-name> -p LimitNOFILE

Alternatively, find the process ID (PID) of the running service and inspect its runtime limits directly from the proc filesystem:

cat /proc/$(pgrep -o <service-name>)/limits | grep "Max open files"

2. Create a Systemd Override File

Modifying default unit files under /lib/systemd/system/ is discouraged because package updates will overwrite your changes. Instead, use systemctl edit to create a drop-in override:

sudo systemctl edit <service-name>

This command opens a text editor. Add the following lines:

[Service]
LimitNOFILE=65536

Specifying Soft and Hard Limits

You can configure separate soft and hard limits by separating the values with a colon (soft:hard):

[Service]
LimitNOFILE=8192:65536

To remove the file descriptor constraint entirely, you can set the value to infinity:

[Service]
LimitNOFILE=infinity

Save and exit the editor. The override file is saved automatically under /etc/systemd/system/<service-name>.service.d/override.conf.

3. Apply the Changes

If you created the override file manually instead of using systemctl edit, reload the systemd configuration:

sudo systemctl daemon-reload

Restart the service to apply the new file descriptor limits:

sudo systemctl restart <service-name>

4. Verify the New File Limits

Confirm that systemd has registered the updated directive:

systemctl show <service-name> -p LimitNOFILE

Finally, inspect the running process to ensure the kernel has applied the new Max open files values:

cat /proc/$(pgrep -o <service-name>)/limits | grep "Max open files"

The output will display the updated Soft and Hard limits for the running service.
