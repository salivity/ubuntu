How to Install and Configure auditd on Ubuntu

The Linux Audit Daemon (auditd) is a vital tool for tracking security-relevant events, monitoring file changes, and auditing system calls on Ubuntu systems. This guide provides a step-by-step walk-through on installing the auditd package, configuring essential auditing rules, managing the service, and analyzing log files using built-in utilities like ausearch and aureport.

Step 1: Install auditd

Update your local package index and install auditd along with its plugin library using the apt package manager:

sudo apt update
sudo apt install auditd audispd-plugins -y

Step 2: Start and Enable the Service

Once installed, enable the service to ensure it starts automatically upon system boot, then start the daemon:

sudo systemctl enable auditd
sudo systemctl start auditd

Verify that the service is active and running:

sudo systemctl status auditd

Step 3: Understand the Configuration Files

The behavior of auditd is managed primarily through two locations:

  • /etc/audit/auditd.conf: Configures daemon-specific operational parameters, such as log file locations, log rotation policies, disk space limits, and security actions.
  • /etc/audit/rules.d/: Contains rule files (such as audit.rules) that define what events, files, and system calls auditd should monitor.

To edit general performance or logging limits, modify /etc/audit/auditd.conf:

sudo nano /etc/audit/auditd.conf

Key directives to review include:

  • log_file: The default storage path (/var/log/audit/audit.log).
  • max_log_file: Maximum log size in megabytes before rotating.
  • max_log_file_action: Action taken when the log size limit is reached (e.g., ROTATE).

Step 4: Configure Audit Rules

Audit rules dictate what gets logged. Rules should be added to files inside the /etc/audit/rules.d/ directory.

Open the default rules file:

sudo nano /etc/audit/rules.d/audit.rules

File Monitoring Examples

To log write and attribute changes (wa) to sensitive system files, append lines using the following syntax:

# Monitor changes to the user password database
-w /etc/passwd -p wa -k identity_changes

# Monitor changes to the sudoers file
-w /etc/sudoers -p wa -k sudoers_changes
  • -w: Specifies the file or directory to watch.
  • -p: Specifies permissions to trigger on (r=read, w=write, e=execute, a=attribute change).
  • -k: Assigns a key (label) to the log entry for easier searching later.

System Call Monitoring Example

To log command executions by users with specific execution calls:

# Log execution of commands for 64-bit systems
-a always,exit -F arch=b64 -S execve -k command_execution

Step 5: Apply the Audit Rules

After saving your custom rules, load them into the running audit framework:

sudo augenrules --load

To view all currently loaded active rules, run:

sudo auditctl -l

Step 6: Query and Analyze Audit Logs

Raw logs located in /var/log/audit/audit.log can be difficult to read. Use the following utilities to process the output:

Using ausearch

Search for logs matching a specific key defined in your rules:

sudo ausearch -k identity_changes

Search for events triggered by a specific executable:

sudo ausearch -x /usr/bin/sudo

Using aureport

Generate a summary report of system security events:

sudo aureport --summary

Generate a report focused on failed authentication events:

sudo aureport --auth --failed
