Set Up a Kubernetes Cluster with Kubeadm on Ubuntu

This guide provides a step-by-step walkthrough for configuring a multi-node Kubernetes cluster locally using kubeadm on Ubuntu machines. You will prepare the operating systems by configuring kernel modules and disabling swap, install a container runtime, install the core Kubernetes components (kubeadm, kubelet, and kubectl), initialize the control plane node, deploy a Container Network Interface (CNI), and join worker nodes to complete the cluster.

Prerequisites

Ensure you have at least two Ubuntu 22.04 or 24.04 nodes (one control plane and one or more worker nodes). Each node requires:

  • At least 2 GB of RAM and 2 CPUs for the control plane node.
  • At least 1 GB of RAM and 1 CPU for worker nodes.
  • Unique hostnames, MAC addresses, and IP addresses across all nodes.
  • Network connectivity between all nodes.

Step 1: Prepare All Nodes

Execute the following commands on all nodes (control plane and workers).

1. Disable Swap

Kubernetes requires swap memory to be disabled.

sudo swapoff -a
sudo sed -i '/ swap / s/^\(.*\)$/#\1/g' /etc/fstab

2. Load Kernel Modules and Enable IPv4 Packet Forwarding

Configure the required kernel modules and network parameters for container networking.

cat <<EOF | sudo tee /etc/modules-load.d/k8s.conf
overlay
br_netfilter
EOF

sudo modprobe overlay
sudo modprobe br_netfilter

cat <<EOF | sudo tee /etc/sysctl.d/k8s.conf
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF

sudo sysctl --system

Step 2: Install Container Runtime (containerd)

Execute the following on all nodes to install and configure containerd.

sudo apt-get update
sudo apt-get install -y ca-certificates curl gnupg lsb-release

# Install containerd
sudo apt-get install -y containerd

# Generate default configuration and enable systemd cgroup driver
sudo mkdir -p /etc/containerd
containerd config default | sudo tee /etc/containerd/config.toml >/dev/null
sudo sed -i 's/SystemdCgroup = false/SystemdCgroup = true/g' /etc/containerd/config.toml

# Restart containerd
sudo systemctl restart containerd
sudo systemctl enable containerd

Step 3: Install Kubeadm, Kubelet, and Kubectl

Execute the following commands on all nodes to install the Kubernetes components from the official community repository.

sudo apt-get update
sudo apt-get install -y apt-transport-https ca-certificates curl gpg

# Download the public signing key
curl -fsSL https://pkgs.k8s.io/core:/stable:/v1.30/deb/Release.key | sudo gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg

# Add the repository
echo 'deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.30/deb/ /' | sudo tee /etc/apt/sources.list.d/kubernetes.list

# Install packages
sudo apt-get update
sudo apt-get install -y kubelet kubeadm kubectl
sudo apt-mark hold kubelet kubeadm kubectl

sudo systemctl enable --now kubelet

Step 4: Initialize the Control Plane

Execute this step only on the control plane node.

  1. Initialize the cluster using a standard Pod CIDR network:
sudo kubeadm init --pod-network-cidr=10.244.0.0/16
  1. Once the command completes, set up regular user access to kubectl:
mkdir -p $HOME/.kube
sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config
  1. Note the kubeadm join command printed at the end of the initialization output. You will use this token and hash to connect your worker nodes.

Step 5: Install a Pod Network Add-on (CNI)

Run this step only on the control plane node. Flannel is used here to match the 10.244.0.0/16 CIDR.

kubectl apply -f https://github.com/flannel-io/flannel/releases/latest/download/kube-flannel.yml

Verify that the control plane node reaches the Ready state:

kubectl get nodes

Step 6: Join Worker Nodes to the Cluster

On each worker node, run the kubeadm join command generated during Step 4. The command structure looks like this:

sudo kubeadm join <control-plane-ip>:6443 --token <token> \
    --discovery-token-ca-cert-hash sha256:<hash>

Note: If the token has expired, generate a new one on the control plane node by running kubeadm token create --print-join-command.

Step 7: Verify the Cluster

Return to the control plane node and verify that all nodes have joined and are in the Ready status:

kubectl get nodes

You should see your control plane node and all joined worker nodes listed with the Ready status. Deployments and Pods can now be scheduled across the cluster.
