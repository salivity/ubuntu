Run ASP.NET Core as a systemd Service on Ubuntu

Running an ASP.NET Core application as a systemd background service on Ubuntu allows your web app to run continuously in the background, automatically start on system boots, and recover automatically from crashes. This guide provides a direct, step-by-step walkthrough for publishing your application, creating a dedicated system user, configuring a systemd service unit file, and managing the application lifecycle using native Linux tools.

1. Publish and Deploy Your Application

Publish your ASP.NET Core application locally or on your build server using the Release configuration:

dotnet publish -c Release -o ./publish

Copy the published files to a directory on your Ubuntu server, such as /var/www/myapp:

sudo mkdir -p /var/www/myapp
sudo cp -r ./publish/* /var/www/myapp/

Ensure the .NET runtime is installed on the Ubuntu host:

sudo apt-get update
sudo apt-get install -y dotnet-runtime-8.0

(Replace 8.0 with the version matching your target framework.)

2. Create a Dedicated Service User

For security reasons, do not run your application under the root account. Create a non-privileged system user without login privileges:

sudo useradd -r -s /bin/false www-aspnet
sudo chown -R www-aspnet:www-aspnet /var/www/myapp

3. Create the systemd Service Unit File

Create a new configuration file in the /etc/systemd/system/ directory:

sudo nano /etc/systemd/system/myapp.service

Add the following configuration:

[Unit]
Description=ASP.NET Core Application - MyApp
After=network.target

[Service]
WorkingDirectory=/var/www/myapp
ExecStart=/usr/bin/dotnet /var/www/myapp/MyApp.dll
Restart=always
# Restart service after 10 seconds if the dotnet service crashes
RestartSec=10
KillSignal=SIGINT
SyslogIdentifier=myapp
User=www-aspnet
Environment=ASPNETCORE_ENVIRONMENT=Production
Environment=DOTNET_PRINT_TELEMETRY_MESSAGE=false
Environment=ASPNETCORE_URLS=http://localhost:5000

[Install]
WantedBy=multi-user.target

Note: Update MyApp.dll with your project's actual entry point filename and verify the path to the dotnet binary using which dotnet.

4. Enable and Start the Service

Reload the systemd daemon to register the new unit file:

sudo systemctl daemon-reload

Enable the service so it starts automatically when the system boots:

sudo systemctl enable myapp.service

Start the service immediately:

sudo systemctl start myapp.service

5. Verify the Status and Check Logs

Check if the application is actively running:

sudo systemctl status myapp.service

You should see an active (running) status. To view real-time application output and Kestrel logs, use journalctl:

sudo journalctl -fu myapp.service

To test the application locally on the server, issue an HTTP request:

curl http://localhost:5000

Common Management Commands

  • Stop the application: sudo systemctl stop myapp.service
  • Restart the application: sudo systemctl restart myapp.service
  • Disable auto-start on boot: sudo systemctl disable myapp.service
