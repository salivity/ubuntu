How to Create a Read-Only Btrfs Snapshot on Ubuntu

Creating a read-only Btrfs subvolume snapshot provides an immutable, point-in-time copy of your filesystem, making it an ideal foundation for consistent, corruption-free backups on Ubuntu. This guide walks you through identifying your target subvolumes, generating a read-only snapshot using the native Btrfs command-line utilities, verifying its immutability, and preparing it for external backup operations.

Step 1: Identify Your Subvolumes

Before creating a snapshot, locate the path of the source subvolume you want to back up. Run the following command:

sudo btrfs subvolume list /

Note the path or mount point of the subvolume (for example, / or @).

Step 2: Create a Destination Directory

Create a dedicated directory to store your snapshots if one does not already exist. It is common practice to place them in a dedicated snapshots directory:

sudo mkdir -p /.snapshots

Step 3: Create the Read-Only Snapshot

To take a snapshot, use the btrfs subvolume snapshot command with the -r flag. The -r flag marks the snapshot as strictly read-only, preventing any subsequent modifications.

Run the following command, replacing the source and destination paths with your own:

sudo btrfs subvolume snapshot -r / /.snapshots/backup-$(date +%Y%m%d-%H%M%S)

This creates a new read-only snapshot named with the current timestamp inside /.snapshots.

Step 4: Verify the Read-Only Status

Confirm that the snapshot was created successfully and is set to read-only mode by inspecting its subvolume details:

sudo btrfs subvolume show /.snapshots/backup-<timestamp>

Look for the line displaying flags. It should confirm:

Flags: readonly

Alternatively, you can test the read-only enforcement by attempting to create a file inside the snapshot:

sudo touch /.snapshots/backup-<timestamp>/testfile

The system should return an error: touch: cannot touch '...': Read-only file system.

Step 5: Using the Snapshot for Backups

Because the snapshot is immutable, you can safely send it to an external drive or remote server using the native btrfs send command without risk of data altering mid-transfer:

sudo btrfs send /.snapshots/backup-<timestamp> | sudo btrfs receive /path/to/external/backup/mount

You can also use standard file-based backup utilities such as rsync or borgbackup targeting the snapshot path rather than your live, mutating root filesystem.
