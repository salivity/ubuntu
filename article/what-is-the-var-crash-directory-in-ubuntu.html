What is the /var/crash Directory in Ubuntu?

The /var/crash directory in Ubuntu serves as the default storage location for system crash reports, memory dumps, and diagnostic information generated when an application or system component fails. Managed primarily by Ubuntu's crash reporting service, Apport, this directory helps developers and system administrators analyze the root causes of software instabilities. This article covers the core purpose of /var/crash, the types of files stored within it, and how to safely manage or clear its contents to free up disk space.

The Role of /var/crash in Ubuntu

When a program crashes on an Ubuntu system, the kernel triggers an event handled by Apport (Ubuntu's crash reporting system). Apport collects debugging details about the state of the software at the exact moment of failure and writes this data to the /var/crash directory.

The primary goal of this directory is to aggregate useful diagnostic metrics so that users can report bugs directly to Canonical developers via Launchpad.

What Files Are Stored in /var/crash?

Files inside /var/crash typically end with specific extensions indicating their status and contents:

  • .crash files: These are main crash reports. They are plain-text files containing system details, backtraces, environment variables, register contents, and sometimes base64-encoded core dumps of the crashed application.
  • .upload / .uploaded files: These are zero-byte marker files created when a report has been sent or processed by the system's crash reporting tool.
  • Core dumps: In some configurations, raw binary files representing the process's allocated memory at the time of the crash are stored here.

Because core dumps and full system reports contain detailed memory contents, individual .crash files can occasionally grow to several hundred megabytes or even gigabytes in size.

How to Safely Clean /var/crash

Since the files in /var/crash are used strictly for post-mortem debugging, deleting them will not harm your operating system or affect running programs. If you are low on disk space, you can safely clear the directory.

To remove all crash reports in the directory, run:

sudo rm -rf /var/crash/*

Ubuntu also includes an automated mechanism via systemd-tmpfiles that automatically cleans old files out of /var subdirectories periodically, but manual deletion is safe whenever immediate storage recovery is needed.

Disabling Crash Reports (Optional)

If you operate a headless server or do not intend to submit crash reports to Ubuntu developers, you can disable Apport to prevent files from being written to /var/crash altogether.

  1. Open the Apport configuration file in a text editor: 
    sudo nano /etc/default/apport
  2. Change the enabled line from 1 to 0: 
    enabled=0
  3. Save the file and restart the Apport service: 
    sudo systemctl stop apport

Disabling Apport keeps the /var/crash directory empty and prevents unexpected disk consumption from recurring software crashes.
