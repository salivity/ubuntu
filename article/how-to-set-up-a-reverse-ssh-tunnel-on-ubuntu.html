How to Set Up a Reverse SSH Tunnel on Ubuntu

Setting up a reverse SSH tunnel allows you to access an Ubuntu machine that is hidden behind a NAT, firewall, or router without a public IP address. By establishing an outgoing SSH connection from the NAT-restricted local machine (the target) to a publicly accessible remote server (the relay), you create a secure path to SSH back into your local machine from anywhere. This step-by-step guide explains how to configure both the public server and the target machine, test the connection, and maintain a persistent connection.

Prerequisites

Before starting, ensure you have:

  • Target Machine: An Ubuntu machine behind a NAT/firewall with SSH server installed (sudo apt install openssh-server).
  • Relay Server: A remote VPS or server with a public IP address and SSH access.

Step 1: Configure the Public Relay Server

To allow the relay server to properly forward connections, edit its SSH configuration.

  1. SSH into your public relay server:

    ssh user@relay_server_ip

  2. Open the SSH daemon configuration file:

    sudo nano /etc/ssh/sshd_config

  3. Ensure the following line is set to yes (uncomment it if necessary):

    GatewayPorts yes

    Note: Setting GatewayPorts yes allows external machines to connect to the reverse port forwarded on the relay server. If you only plan to connect from inside the relay server itself, you can leave this set to no.

  4. Save the file and restart the SSH service:

    sudo systemctl restart sshd

Step 2: Create SSH Keys for Passwordless Login

To maintain an uninterrupted tunnel, set up SSH key authentication from the target Ubuntu machine to the relay server.

  1. On the target Ubuntu machine, generate an SSH key pair (press Enter for defaults and leave the passphrase empty for automated connections):

    ssh-keygen -t ed25519

  2. Copy the public key to the public relay server:

    ssh-copy-id user@relay_server_ip

Step 3: Initiate the Reverse SSH Tunnel

From the target Ubuntu machine, initiate the reverse tunnel connection to the relay server:

ssh -f -N -R 2222:localhost:22 user@relay_server_ip

Command Flags Breakdown:

  • -f: Requests SSH to go to the background just before command execution.
  • -N: Tells SSH not to execute a remote command (useful for just forwarding ports).
  • -R 2222:localhost:22: Maps port 2222 on the relay server to port 22 (SSH) on your local Ubuntu machine.

Step 4: Connect to the Target Machine

You can now connect to your local, NAT-restricted Ubuntu machine from anywhere.

Option A: From the Relay Server

SSH into the relay server, then execute:

ssh local_user@localhost -p 2222

Option B: Directly from a Remote Client

If GatewayPorts yes was enabled on the relay server, connect directly from any computer:

ssh local_user@relay_server_ip -p 2222

Step 5: Automate the Connection with AutoSSH

Standard SSH tunnels drop if the internet connection interrupts. Use autossh to automatically restart the connection if it drops.

  1. Install autossh on the target Ubuntu machine:

    sudo apt update && sudo apt install autossh -y

  2. Test the connection using autossh:

    autossh -M 0 -f -N -o "ServerAliveInterval 30" -o "ServerAliveCountMax 3" -R 2222:localhost:22 user@relay_server_ip

  3. To ensure the tunnel starts automatically at boot, create a systemd service on the target machine:

    sudo nano /etc/systemd/system/reverse-ssh.service

  4. Add the following configuration:

    [Unit]
Description=Reverse SSH Tunnel
After=network.target

[Service]
User=your_local_ubuntu_username
ExecStart=/usr/bin/autossh -M 0 -N -o "ServerAliveInterval 30" -o "ServerAliveCountMax 3" -o "ExitOnForwardFailure=yes" -R 2222:localhost:22 user@relay_server_ip
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target

  5. Enable and start the service:

    sudo systemctl daemon-reload
sudo systemctl enable reverse-ssh
sudo systemctl start reverse-ssh

Your reverse SSH tunnel is now fully configured and will automatically reconnect whenever the network drops or the machine reboots.
