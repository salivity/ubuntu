Using deborphan to Find Unused Libraries on Ubuntu

This article explains the purpose and operation of the deborphan tool on Ubuntu systems. Over time, installing and removing software can leave behind lingering shared libraries that waste disk space and clutter your package database. Below, you will learn what deborphan is, why orphaned libraries occur, how the tool detects them, and how to safely inspect and remove unnecessary packages from your system.

The Purpose of deborphan

The primary purpose of deborphan is to identify packages—specifically shared libraries—that have no other packages depending on them. When you install an application via the package manager, it often brings along several library dependencies. If you later remove that application using a basic command like dpkg -r or without the proper flags in apt, those auxiliary libraries may remain on the disk.

While modern versions of APT include the apt autoremove command to clean up unneeded dependencies tracked by APT's automatic installation flags, deborphan operates independently by directly examining the system's package status database. It acts as a safety check and a deeper cleaning tool, detecting orphaned libraries that apt may overlook, particularly those installed manually or left behind by older packaging tools.

How deborphan Identifies Orphaned Libraries

By default, deborphan inspects the libs and oldlibs sections within /var/lib/dpkg/status. It evaluates the dependency tree of every installed package and determines whether any other installed package lists a given library in its Depends or Pre-Depends fields.

If a library package has zero reverse dependencies, deborphan flags it as an "orphan." Because libraries are typically meant to serve other programs rather than be executed directly by users, a library with no reverse dependencies is almost always safe to remove.

Installing and Running deborphan

The deborphan package is available in the standard Ubuntu repositories and can be installed via the terminal:

sudo apt update
sudo apt install deborphan

To run a basic scan and output a list of orphaned libraries, execute:

deborphan

If any orphaned libraries are present, the command outputs their package names one per line. If no packages are listed, your system is free of unused library packages in the monitored sections.

Useful Command Options

  • Show Package Sizes: Run deborphan -s to view the package names alongside their estimated installed sizes.
  • Scan All Sections: While libraries are the default focus, running deborphan -a scans all package sections, not just libs and oldlibs. Use caution with this flag, as it will report user-facing applications and metapackages that do not have dependencies relying on them.
  • Predict Further Orphans: Running deborphan --guess-all employs heuristic checks to find non-library packages that might also be unneeded.

Removing Orphaned Packages Safely

Before removing any package identified by deborphan, review the list to confirm that no manually required development files or custom configurations depend on them. Once verified, you can pass the output of deborphan to apt to purge the packages and their configuration files:

sudo apt-get purge $(deborphan)

Because removing one set of libraries can cause higher-level dependent libraries to become orphaned in turn, you may need to run deborphan iteratively until it returns no more results. Alternatively, you can use orphaner, a menu-driven text interface bundled with deborphan, which lets you selectively review and delete unused packages interactively:

sudo orphaner
