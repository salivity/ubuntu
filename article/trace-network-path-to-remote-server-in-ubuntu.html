Trace Network Path to Remote Server in Ubuntu

Tracing the network path from an Ubuntu system to a remote server allows administrators and users to identify connection bottlenecks, packet loss, and routing issues. This article covers the standard traceroute command, how to install and use it on Ubuntu, and alternative tools like tracepath and mtr for detailed network diagnostics.

Using the traceroute Command

The primary command used to trace the network path in Ubuntu is traceroute. It tracks the journey of packets from your local machine through intermediate routers (hops) until they reach the destination IP address or domain name.

Step 1: Install Traceroute

By default, traceroute may not be installed on fresh Ubuntu installations. You can install it using the APT package manager:

sudo apt update
sudo apt install traceroute

Step 2: Run a Basic Trace

To trace the route to a remote server, pass the domain name or IP address as an argument:

traceroute example.com

Or using an IP address:

traceroute 192.0.2.1

Step 3: Interpret the Output

The output displays each hop on a new line with the following details:

  • Hop Number: The sequential order of routers the packet passes through.
  • Hostname/IP: The address of the router at that hop.
  • Round-Trip Times (RTT): Three latency measurements in milliseconds showing how long it took packets to return from that router.
  • Asterisks (* * *): Indicates a timed-out request, usually caused by a firewall blocking UDP or ICMP traffic at that specific hop.

Alternative Built-in Command: tracepath

If you prefer not to install additional packages, Ubuntu includes tracepath by default. It functions similarly to traceroute but does not require superuser privileges and automatically tracks the Maximum Transmission Unit (MTU).

Run the command with your target destination:

tracepath example.com

Advanced Diagnostic Tool: mtr

For real-time network path monitoring, mtr (My Traceroute) combines the functionality of traceroute and ping into a single report.

Step 1: Install MTR

sudo apt install mtr

Step 2: Run MTR

mtr example.com

This launches an interactive interface that continuously updates latency and packet loss statistics for every hop along the route.

Useful traceroute Flags

  • Disable DNS Name Resolution (-n): Displays IP addresses instead of resolving hostnames, speeding up the trace process. 
    traceroute -n example.com
  • Use ICMP ECHO Requests (-I): Uses ICMP packets instead of default UDP probes, which helps bypass routers blocking UDP traffic. 
    sudo traceroute -I example.com
  • Specify Maximum Hops (-m): Sets the maximum number of hops (default is 30) before stopping the trace. 
    traceroute -m 15 example.com
