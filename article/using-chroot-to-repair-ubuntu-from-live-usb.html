Using Chroot to Repair Ubuntu from Live USB

The chroot (change root) command plays a critical role in system recovery by allowing you to change the active root directory to a different disk partition. When an Ubuntu system fails to boot, booting into a Live USB environment provides a functional operating system in RAM. By using chroot to bridge the Live USB environment and your broken installation on the hard drive, you can execute commands, install packages, and repair system configurations as if you were booted directly into your installed OS.

Understanding the Role of Chroot in System Recovery

When you boot an Ubuntu Live USB, any command you execute in the terminal affects the temporary environment running in memory, not your actual hard drive. The chroot tool solves this by shifting the operational root directory (/) from the Live USB environment to the mounted partition where your target Ubuntu system resides.

Once inside the chroot environment: * Commands run directly within the context of the installed system. * System updates, package installations, and configurations apply to the hard drive. * The system uses the installed OS’s binaries, user accounts, and configuration files.

Primary Uses of Chroot During Ubuntu Repair

1. Reinstalling or Repairing the GRUB Bootloader

If the GRUB bootloader is corrupted or missing—often caused by bad updates or dual-boot installations—you cannot boot into Ubuntu. Inside a chroot environment, you can run grub-install and update-grub to rewrite the boot records directly to the correct drive.

2. Fixing Broken Packages and Updates

Interrupted system updates or corrupted dependencies can leave Ubuntu in an unbootable state. Once chrooted into the installation, you can run package management commands such as apt update, apt upgrade, or apt --fix-broken install to resolve package conflicts and complete failed installations.

3. Rebuilding the Initramfs and Kernel

If a kernel update fails or the initial RAM file system (initramfs) is corrupted, the system will panic on startup. chroot allows you to generate a new initial ramdisk using update-initramfs -u or reinstall working kernel packages.

4. Resetting Passwords and Fixing User Configuration

If you locked yourself out of your system or corrupt critical user files like /etc/sudoers or /etc/fstab, chroot gives you full root access to edit system configuration files or run the passwd command to reset credentials.

Standard Workflow for Repairing Ubuntu via Chroot

  1. Boot the Live USB: Start your computer using an Ubuntu Live USB and select “Try Ubuntu.”

  2. Identify the Partition: Open the terminal and locate your installed root partition using lsblk or sudo fdisk -l.

  3. Mount the Installed System: Mount the target root partition to /mnt:

    sudo mount /dev/sdXn /mnt

  4. Bind Essential Virtual Filesystems: Link the Live system’s hardware processes and devices to the mounted system:

    for dir in /dev /dev/pts /proc /sys /run; do sudo mount --bind $dir /mnt$dir; done

  5. Enter the Chroot Environment: Access your target system:

    sudo chroot /mnt

  6. Perform Repairs: Run the necessary terminal commands to fix bootloader issues, update packages, or edit configuration files.

  7. Exit and Cleanup: Exit the environment and unmount the drives before restarting:

    exit
sudo umount -R /mnt
sudo reboot
