How to Parse Nginx Logs with Logstash on Ubuntu

This guide provides a step-by-step walkthrough for configuring Logstash to ingest, parse, and structure Nginx access logs on an Ubuntu server. You will learn how to install Logstash, configure Grok filters to transform unstructured log lines into queryable data fields, grant proper system permissions, and verify the pipeline output to prepare your data for analysis in Elasticsearch or OpenSearch.

Step 1: Install Logstash on Ubuntu

Logstash requires Java to run. First, update your package index and install the OpenJDK runtime:

sudo apt update
sudo apt install -y default-jre

Next, add the Elastic repository and signing key to install Logstash:

wget -qO - https://artifacts.elastic.co/GPG-KEY-elasticsearch | sudo gpg --dearmor -o /usr/share/keyrings/elastic-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/elastic-keyring.gpg] https://artifacts.elastic.co/packages/8.x/apt stable main" | sudo tee /etc/apt/sources.list.d/elastic-8.x.list
sudo apt update
sudo apt install -y logstash

Step 2: Configure File Permissions

By default, Ubuntu restricts access to /var/log/nginx/ to the adm or root group. The logstash service user needs read access to ingest the logs:

sudo usermod -aG adm logstash
sudo chmod 755 /var/log/nginx
sudo chmod 644 /var/log/nginx/access.log

Step 3: Create the Logstash Pipeline Configuration

Nginx uses the standard combined log format by default, which maps directly to Logstash's built-in COMBINEDAPACHELOG grok pattern.

Create a new configuration file at /etc/logstash/conf.d/nginx-access.conf:

sudo nano /etc/logstash/conf.d/nginx-access.conf

Add the following pipeline configuration:

input {
  file {
    path => "/var/log/nginx/access.log"
    start_position => "beginning"
    sincedb_path => "/var/lib/logstash/sincedb_nginx"
    type => "nginx-access"
  }
}

filter {
  if [type] == "nginx-access" {
    grok {
      match => { "message" => "%{COMBINEDAPACHELOG}" }
      remove_field => "message"
    }

    date {
      match => [ "timestamp", "dd/MMM/yyyy:HH:mm:ss Z" ]
      target => "@timestamp"
      remove_field => "timestamp"
    }

    mutate {
      convert => {
        "response" => "integer"
        "bytes" => "integer"
      }
    }
  }
}

output {
  # Output to Elasticsearch (adjust hosts and credentials as needed)
  elasticsearch {
    hosts => ["http://localhost:9200"]
    index => "nginx-access-%{+YYYY.MM.dd}"
  }

  # Optional: Print parsed events to the console or log file for debugging
  stdout {
    codec => rubydebug
  }
}

Step 4: Validate and Test the Configuration

Before starting the service, test your configuration file for syntax errors using the Logstash binary:

sudo -u logstash /usr/share/logstash/bin/logstash --config.test_and_exit -f /etc/logstash/conf.d/nginx-access.conf

A response of Configuration OK confirms the syntax and patterns are valid.

Step 5: Start and Enable the Logstash Service

Enable Logstash to start automatically at system boot, then launch the service:

sudo systemctl enable logstash
sudo systemctl start logstash

Monitor the Logstash logs to ensure the pipeline is running without errors:

sudo tail -f /var/log/logstash/logstash-plain.log

Once active, Logstash will read the records from /var/log/nginx/access.log, extract individual components such as client IP, HTTP status, request verb, and URI into distinct fields, and forward the structured data to your designated output.
