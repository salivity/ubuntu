Setup Samba Active Directory DC on Ubuntu

This guide provides a comprehensive, step-by-step walkthrough for configuring an Ubuntu server as a Samba Active Directory Domain Controller (AD DC). You will learn how to prepare the network environment, install the required packages, provision the domain, configure Kerberos authentication, and verify that the domain controller and its integrated DNS service are functioning properly.

Prerequisites and Network Configuration

A Samba Active Directory Domain Controller requires a static IP address and a fully qualified domain name (FQDN).

  1. Set your server's hostname (e.g., dc1.example.lan):

    sudo hostnamectl set-hostname dc1.example.lan

  2. Edit /etc/hosts to map the static IP address to your FQDN and short hostname:

    127.0.0.1       localhost
192.168.1.10    dc1.example.lan    dc1

  3. Configure a static IP address in /etc/netplan/ using your network interface name. Ensure the nameserver points to 127.0.0.1 and your gateway's IP:

    network:
  version: 2
  renderer: networkd
  ethernets:
    eth0:
      dhcp4: no
      addresses:
        - 192.168.1.10/24
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses: [127.0.0.1, 192.168.1.1]

    Apply the changes:

    sudo netplan apply

Disable systemd-resolved DNS Stub Listener

Samba provides its own internal DNS server on port 53. Ubuntu’s default systemd-resolved service must be adjusted to prevent port conflicts.

  1. Edit /etc/systemd/resolved.conf:

    [Resolve]
DNS=127.0.0.1
DNSStubListener=no

  2. Link the resolved file and restart the service:

    sudo rm /etc/resolv.conf
sudo ln -s /run/systemd/resolve/resolv.conf /etc/resolv.conf
sudo systemctl restart systemd-resolved

Install Samba and Kerberos Packages

Update repository lists and install the required software suites:

sudo apt update
sudo apt install -y samba smbclient winbind libpam-winbind libnss-winbind krb5-user krb5-config

During installation, prompt screens will ask for the Kerberos default realm. Enter your realm in all uppercase (e.g., EXAMPLE.LAN). For the administrative server, enter your domain controller hostname (e.g., dc1.example.lan).

Provision the Domain

Before provisioning, you must stop any standard Samba services and remove the default configuration file.

  1. Stop and disable standard services:

    sudo systemctl stop smbd nmbd winbind
sudo systemctl disable smbd nmbd winbind
sudo systemctl mask smbd nmbd winbind

  2. Remove or rename the default Samba configuration:

    sudo mv /etc/samba/smb.conf /etc/samba/smb.conf.bak

  3. Provision the domain interactively using samba-tool:

    sudo samba-tool domain provision --use-rfc2307 --interactive
    • Realm: EXAMPLE.LAN
    • Domain: EXAMPLE
    • Server Role: dc
    • DNS backend: SAMBA_INTERNAL
    • DNS forwarder IP: Upstream DNS IP (e.g., 192.168.1.1 or 8.8.8.8)
    • Administrator password: Choose a strong password meeting complex criteria.

Configure Kerberos

Replace the default Kerberos configuration with the configuration generated by Samba:

sudo cp /var/lib/samba/private/krb5.conf /etc/krb5.conf

Start the Samba Active Directory Domain Controller

  1. Unmask and start the samba-ad-dc service:

    sudo systemctl unmask samba-ad-dc
sudo systemctl start samba-ad-dc
sudo systemctl enable samba-ad-dc

  2. Verify that the service is running:

    sudo systemctl status samba-ad-dc

Verification and Testing

  1. Verify Kerberos Authentication: Request a ticket-granting ticket for the Administrator account:

    kinit administrator@EXAMPLE.LAN

    Check that the ticket is active:

    klist

  2. Verify DNS Records: Ensure Samba internal DNS is resolving domain records:

    host -t A example.lan
host -t SRV _ldap._tcp.example.lan
host -t SRV _kerberos._udp.example.lan

  3. Verify SMB Shares: List the shares hosted on the domain controller:

    smbclient -L localhost -U%

    You should see default Active Directory shares such as sysvol and netlogon.
