Change IO Scheduler Dynamically in Ubuntu

This guide explains how to dynamically change the input/output (I/O) scheduling algorithm for a storage drive in Ubuntu without rebooting the system. By adjusting the scheduler in real time via the sysfs interface, you can optimize disk performance for specific workloads, whether you are running a database on high-speed NVMe drives or managing bulk throughput on mechanical hard disks.

1. Identify Your Storage Device

First, locate the identifier of the block device you want to configure (such as sda, sdb, or nvme0n1). You can list available block devices using:

lsblk

2. Check the Current I/O Scheduler

To see which schedulers are supported by your kernel for that device and which one is currently active, read the scheduler file in /sys/block/<device>/queue/:

cat /sys/block/sda/queue/scheduler

The output will display the available schedulers (commonly mq-deadline, none, bfq, or kyber). The currently active scheduler is enclosed in brackets, for example: [mq-deadline] none.

3. Change the I/O Scheduler Dynamically

To change the algorithm on the fly, write the desired scheduler name directly into the /sys/block/<device>/queue/scheduler file. Because this requires administrative privileges, use tee with sudo:

echo <scheduler-name> | sudo tee /sys/block/<device>/queue/scheduler

For example, to switch a drive named sda to the bfq scheduler:

echo bfq | sudo tee /sys/block/sda/queue/scheduler

For fast NVMe or high-end solid-state drives where the hardware handles queuing, setting the scheduler to none often yields the lowest latency:

echo none | sudo tee /sys/block/nvme0n1/queue/scheduler

4. Verify the Change

Confirm that the new scheduler is active by checking the file again:

cat /sys/block/sda/queue/scheduler

The brackets should now surround your chosen algorithm (e.g., none [bfq]). The change takes effect immediately without interrupting disk operations. Note that changes made via sysfs are temporary and will reset upon system reboot unless made permanent using a udev rule or kernel boot parameter.
