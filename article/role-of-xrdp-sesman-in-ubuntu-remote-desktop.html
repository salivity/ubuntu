Role of xrdp-sesman in Ubuntu Remote Desktop

The xrdp-sesman daemon is the session manager component of the xrdp remote desktop protocol server on Ubuntu. While the primary xrdp service manages incoming network connections and RDP protocol translation, xrdp-sesman handles user authentication, session creation, display server allocation, and lifecycle management for active user sessions. This article explains the fundamental responsibilities of xrdp-sesman, how it coordinates with the main xrdp service, and its role in maintaining remote desktop environments.

Core Responsibilities of xrdp-sesman

1. User Authentication

When a user attempts to log in remotely via RDP, xrdp collects the credentials and passes them to xrdp-sesman. The session manager uses Ubuntu's Pluggable Authentication Modules (PAM) system to verify username and password details against local or domain accounts.

2. Session Creation and Reconnection

Once authentication succeeds, xrdp-sesman determines whether to launch a new session or reconnect to an existing one:

  • New Session: If no active session exists for the user, xrdp-sesman requests an available display number (e.g., :10) and spawns an X server backend, such as Xorg or Xvnc.
  • Existing Session: If a session is already running for the user, xrdp-sesman redirects the incoming connection to the existing display session, allowing users to resume interrupted work.

3. Environment and Desktop Initialization

After starting the X server backend, xrdp-sesman executes startup scripts (typically /etc/xrdp/startwm.sh or user-specific .xsession files) to launch the graphical desktop environment (such as GNOME, XFCE, or MATE) and set up required user environment variables.

4. Session Termination and Cleanup

When a user logs out, xrdp-sesman terminates the associated desktop processes, stops the backend X server, releases the allocated display number, and cleans up temporary session files to free server resources.

How xrdp and xrdp-sesman Work Together

  1. Connection Request: The RDP client connects to xrdp on port 3389.
  2. Credential Handshake: xrdp requests authentication details from the client and forwards them to xrdp-sesman over an internal local socket (typically port 3350).
  3. Session Allocation: xrdp-sesman validates the credentials via PAM, allocates a display server, and starts the desktop session.
  4. Data Redirection: xrdp-sesman passes connection details back to xrdp, which then bridges the network RDP traffic directly to the underlying X session display.

Configuration

The behavior of xrdp-sesman is controlled through its configuration file located at /etc/xrdp/sesman.ini. Key settings managed in this file include:

  • Maximum allowable concurrent sessions.
  • Allowed session types (e.g., Xorg, Xvnc).
  • Inactivity timeouts and session limits.
  • Security parameters and PAM service definitions.
