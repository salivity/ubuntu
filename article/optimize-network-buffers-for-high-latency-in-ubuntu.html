Optimize Network Buffers for High Latency in Ubuntu

High-latency network connections, such as satellite links or long-distance transcontinental routes, often suffer from poor TCP throughput due to default operating system buffer limits. This guide demonstrates how to calculate the required Bandwidth-Delay Product (BDP) and adjust Ubuntu's network stack buffer limits using sysctl to maximize throughput across high-latency, high-bandwidth networks.

Understanding the Bandwidth-Delay Product (BDP)

Standard TCP throughput is heavily constrained by the TCP receive window size. To saturate a high-latency link, the network buffer must be at least as large as the Bandwidth-Delay Product (BDP):

\[\text{BDP (bytes)} = \text{Bandwidth (bytes/sec)} \times \text{Round-Trip Time (seconds)}\]

For example, a 1 Gbps link with a 150 ms Round-Trip Time (RTT):

  • Bandwidth: \(1{,}000{,}000{,}000 \text{ bits/sec} = 125{,}000{,}000 \text{ bytes/sec}\)
  • RTT: \(0.150 \text{ seconds}\)
  • BDP: \(125{,}000{,}000 \times 0.150 = 18{,}750{,}000 \text{ bytes}\) (approx. 18.75 MB)

Ubuntu’s default maximum buffer size is typically set between 4 MB and 6 MB, which throttles a connection requiring an 18.75 MB window.

Step 1: Open the Sysctl Configuration

To make buffer adjustments persistent across reboots, edit or create a configuration file in the /etc/sysctl.d/ directory:

sudo nano /etc/sysctl.d/99-network-tuning.conf

Step 2: Define Buffer Limits and Kernel Parameters

Add the following configuration parameters. These settings increase the global core buffers, expand the TCP dynamic auto-tuning boundaries, enable TCP window scaling, and enable modern congestion control:

# Enable TCP Window Scaling (RFC 1323)
net.ipv4.tcp_window_scaling = 1

# Increase the maximum socket receive and send buffer sizes (in bytes)
# Example: 32 MB = 33554432 bytes
net.core.rmem_max = 33554432
net.core.wmem_max = 33554432

# Set core default socket buffers
net.core.rmem_default = 1048576
net.core.wmem_default = 1048576

# Set maximum number of packets queued on the input side
net.core.netdev_max_backlog = 10000

# TCP Autotuning memory limits: min, default, max (in bytes)
# The max value should match or slightly exceed net.core.rmem_max / wmem_max
net.ipv4.tcp_rmem = 4096 1048576 33554432
net.ipv4.tcp_wmem = 4096 1048576 33554432

# Enable BBR congestion control for optimal performance on high-latency paths
net.core.default_qdisc = fq
net.ipv4.tcp_congestion_control = bbr

Parameter Breakdown

  • net.ipv4.tcp_window_scaling: Allows TCP window sizes to exceed the legacy 64 KB limit up to 1 GB.
  • net.core.rmem_max and net.core.wmem_max: Define the ceiling for all socket receive and transmit buffers across the kernel.
  • net.ipv4.tcp_rmem and net.ipv4.tcp_wmem: Control dynamic auto-tuning boundaries for TCP buffers specifically. The third value sets the upper boundary up to which the kernel automatically scales socket allocations based on current traffic demands.
  • net.ipv4.tcp_congestion_control = bbr: Google's BBR (Bottleneck Bandwidth and RTT) algorithm maintains high throughput over high-latency networks far more effectively than traditional loss-based algorithms like CUBIC.

Step 3: Apply and Verify Changes

Apply the new parameters without rebooting:

sudo sysctl --system

Verify that the active parameters match your newly applied values:

sysctl net.ipv4.tcp_rmem
sysctl net.core.rmem_max
sysctl net.ipv4.tcp_congestion_control

Ensure memory headroom is available on the system. The configured maximum limits represent peak allocations per socket, so systems handling thousands of concurrent connections should monitor total RAM usage under heavy load to prevent out-of-memory events.
