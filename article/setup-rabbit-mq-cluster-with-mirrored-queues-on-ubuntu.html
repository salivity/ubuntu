Setup RabbitMQ Cluster with Mirrored Queues on Ubuntu

This guide outlines the step-by-step process of building a high-availability RabbitMQ cluster across multiple Ubuntu nodes and configuring mirrored queues. By synchronizing the Erlang cookie across your instances, connecting the nodes into a unified cluster, and applying a high-availability (HA) policy, you ensure that your message queues are replicated and resilient against single-node failures.

Prerequisites

  • At least two Ubuntu 20.04 or 22.04 servers with non-root sudo users.
  • Static internal IP addresses for all servers.
  • Ports 4369 (Erlang discovery), 25672 (Erlang distribution), 5672 (AMQP), and 15672 (Management UI) open between the nodes.

For this guide, we assume two nodes:

  • Node 1 (Primary): 192.168.1.10 (node1)
  • Node 2: 192.168.1.11 (node2)

Step 1: Configure Local DNS on All Nodes

RabbitMQ relies on hostnames for node communication. Open /etc/hosts on all nodes:

sudo nano /etc/hosts

Add the IP addresses and hostnames of all cluster members:

192.168.1.10 node1
192.168.1.11 node2

Save and exit. Ensure the hostname matches on each server:

# On Node 1
sudo hostnamectl set-hostname node1

# On Node 2
sudo hostnamectl set-hostname node2

Step 2: Install RabbitMQ on All Nodes

Run the following commands on all nodes to install RabbitMQ and its Erlang runtime:

sudo apt update
sudo apt install -y rabbitmq-server

Enable and start the RabbitMQ service:

sudo systemctl enable rabbitmq-server
sudo systemctl start rabbitmq-server

Step 3: Synchronize the Erlang Cookie

Nodes in a RabbitMQ cluster must share the exact same Erlang magic cookie.

  1. Stop RabbitMQ on Node 2:

    sudo systemctl stop rabbitmq-server

  2. Copy the cookie from Node 1 to Node 2. You can view the cookie on Node 1:

    sudo cat /var/lib/rabbitmq/.erlang.cookie

  3. Replace the contents of /var/lib/rabbitmq/.erlang.cookie on Node 2 with the cookie value from Node 1:

    sudo nano /var/lib/rabbitmq/.erlang.cookie

  4. Ensure proper ownership and restrictive permissions on Node 2:

    sudo chown rabbitmq:rabbitmq /var/lib/rabbitmq/.erlang.cookie
sudo chmod 400 /var/lib/rabbitmq/.erlang.cookie

  5. Restart the RabbitMQ service on Node 2:

    sudo systemctl start rabbitmq-server

Step 4: Join Node 2 to the Cluster

On Node 2, run the following commands to connect to Node 1:

# Stop the RabbitMQ application process
sudo rabbitmqctl stop_app

# Reset the node configuration
sudo rabbitmqctl reset

# Join the cluster
sudo rabbitmqctl join_cluster rabbit@node1

# Restart the RabbitMQ application process
sudo rabbitmqctl start_app

Verify the cluster status from either node:

sudo rabbitmqctl cluster_status

The output should list both rabbit@node1 and rabbit@node2 under Running Nodes.

Step 5: Configure Mirrored Queue Policies

By default, queues in a cluster reside on the node where they were declared. To mirror queues across all nodes, apply an HA policy.

To mirror all queues whose names begin with ha. across all nodes in the cluster, run the following command on any node:

sudo rabbitmqctl set_policy ha-all "^ha\." '{"ha-mode":"all"}'

To mirror all queues regardless of their name, use the .* regex pattern:

sudo rabbitmqctl set_policy ha-all ".*" '{"ha-mode":"all"}'

To enable automatic synchronization for queues when a node rejoins the cluster, include the ha-sync-mode parameter:

sudo rabbitmqctl set_policy ha-all ".*" '{"ha-mode":"all", "ha-sync-mode":"automatic"}'

Step 6: Enable the Management Web Interface (Optional)

To inspect your cluster and queue synchronization status visually, enable the RabbitMQ web management console on any node:

sudo rabbitmq-plugins enable rabbitmq_management

Create an administrative user:

sudo rabbitmqctl add_user admin YourSecurePassword
sudo rabbitmqctl set_user_tags admin administrator
sudo rabbitmqctl set_permissions -p / admin ".*" ".*" ".*"

Access the dashboard via your browser at http://192.168.1.10:15672/. Under the Queues tab, queues matching your policy will now show an indicator such as +1 under the Node column, confirming the queue is actively mirrored across cluster nodes.
