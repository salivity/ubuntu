How to Configure Ubuntu as a Secure Bastion Host

A jump host (or bastion host) acts as a single, hardened gateway through which administrators access private network infrastructure. This guide covers how to set up an Ubuntu server as a secure jump host by creating a dedicated administrative user, hardening the OpenSSH server configuration, enforcing firewall rules, installing intrusion detection software, and using standard SSH ProxyJump commands to access isolated internal nodes safely.

Step 1: Update the System and Create a Dedicated User

Start by updating the package repositories and upgrading installed packages to their latest versions:

sudo apt update && sudo apt upgrade -y

Avoid using the root account for routine access. Create a dedicated administrative user:

sudo adduser bastionuser
sudo usermod -aG sudo bastionuser

Add your public SSH key to the new user’s authorized keys file on the bastion:

sudo mkdir -p /home/bastionuser/.ssh
sudo chmod 700 /home/bastionuser/.ssh
sudo nano /home/bastionuser/.ssh/authorized_keys
# Paste your public key here
sudo chmod 600 /home/bastionuser/.ssh/authorized_keys
sudo chown -R bastionuser:bastionuser /home/bastionuser/.ssh

Step 2: Harden SSH Configuration

The SSH daemon on a bastion host must only permit secure authentication methods and restrict administrative privileges.

Edit the SSH configuration file:

sudo nano /etc/ssh/sshd_config

Update or add the following directives:

# Disable root login
PermitRootLogin no

# Enforce public key authentication
PubkeyAuthentication yes
PasswordAuthentication no
PermitEmptyPasswords no

# Disable legacy or insecure authentication
KbdInteractiveAuthentication no
X11Forwarding no

# Set idle timeout to disconnect inactive sessions (e.g., 5 minutes)
ClientAliveInterval 300
ClientAliveCountMax 0

# Limit access exclusively to the bastion user
AllowUsers bastionuser

Test the configuration for syntax errors and restart the SSH service:

sudo sshd -t
sudo systemctl restart ssh

Note: Keep your current SSH session open until you confirm a successful login from a new terminal window.

Step 3: Configure the Firewall (UFW)

Restrict incoming traffic so that the bastion accepts connections only on the SSH port, ideally from trusted IP addresses (such as an office or VPN IP).

Reset the firewall and configure basic rules:

sudo ufw default deny incoming
sudo ufw default allow outgoing

If connecting from a static IP address, restrict SSH access specifically to that IP:

sudo ufw allow from <YOUR_TRUSTED_IP> to any port 22 proto tcp

If a static IP is not available, allow public SSH access:

sudo ufw allow 22/tcp

Enable the firewall:

sudo ufw enable
sudo ufw status

Step 4: Install and Configure Fail2ban

Fail2ban mitigates brute-force attacks by monitoring authentication logs and temporarily banning IP addresses that show malicious signs.

Install Fail2ban:

sudo apt install fail2ban -y

Create a local configuration override:

sudo cp /etc/fail2ban/jail.conf /etc/fail2ban/jail.local
sudo nano /etc/fail2ban/jail.local

Ensure the [sshd] section is enabled:

[sshd]
enabled = true
port = ssh
maxretry = 3
findtime = 600
bantime = 3600

Start and enable the Fail2ban service:

sudo systemctl enable fail2ban
sudo systemctl start fail2ban

Step 5: Configure Downstream Access

A secure jump host should route administrative traffic to target servers on the private network without storing private keys on the bastion itself.

Using the Command Line

Connect through the bastion directly to an internal target using OpenSSH's -J (ProxyJump) flag:

ssh -J bastionuser@<BASTION_IP> internaluser@<INTERNAL_SERVER_IP>

Using Local SSH Config

To simplify access, configure your local workstation's ~/.ssh/config file:

Host bastion
    HostName <BASTION_IP>
    User bastionuser
    IdentityFile ~/.ssh/id_ed25519

Host internal-server
    HostName <INTERNAL_SERVER_IP>
    User internaluser
    IdentityFile ~/.ssh/id_ed25519
    ProxyJump bastion

With this configuration in place, connect to the private target seamlessly:

ssh internal-server
