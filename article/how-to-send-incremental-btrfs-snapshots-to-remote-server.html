How to Send Incremental Btrfs Snapshots to Remote Server

Sending Btrfs snapshots incrementally to a remote Ubuntu backup server is an efficient way to back up data across a network by transferring only the differences between two points in time. The process requires creating read-only subvolume snapshots locally, transferring an initial base snapshot over SSH using btrfs send and btrfs receive, and then using the parent (-p) flag on subsequent transfers to sync only the modified data blocks to the remote filesystem.

Prerequisites

  • Both the local machine and the remote backup server must run filesystems formatted with Btrfs.
  • You need SSH access to the remote Ubuntu server with root or sudo privileges capable of running btrfs receive.
  • The target subvolumes and snapshots must be set to read-only mode, as Btrfs will not generate send streams from read-write snapshots.

Step 1: Create the Initial Read-Only Snapshot

Generate a read-only snapshot of your source subvolume on the local machine:

sudo btrfs subvolume snapshot -r /path/to/source /path/to/snapshots/snap_backup_v1

Step 2: Transfer the Base Snapshot to the Remote Server

Because incremental sends require a common ancestor on both machines, stream the full initial snapshot to the remote Ubuntu server using btrfs send, piped securely over SSH to btrfs receive:

sudo btrfs send /path/to/snapshots/snap_backup_v1 | ssh user@backup-server "sudo btrfs receive /mnt/backup_pool/"

Once completed, /mnt/backup_pool/snap_backup_v1 exists on the remote system as the baseline reference point.

Step 3: Create the Subsequent Snapshot

When you are ready to back up new changes, generate a new read-only snapshot on the local system:

sudo btrfs subvolume snapshot -r /path/to/source /path/to/snapshots/snap_backup_v2

Step 4: Stream the Incremental Difference

To send only the delta between the first snapshot and the second snapshot, use the -p (parent) flag. Point the parent parameter to the previous snapshot that already exists on both systems:

sudo btrfs send -p /path/to/snapshots/snap_backup_v1 /path/to/snapshots/snap_backup_v2 | ssh user@backup-server "sudo btrfs receive /mnt/backup_pool/"

Btrfs calculates the differences at the filesystem block level and transmits only the changes. The remote server reconstructs the exact state of snap_backup_v2 using its local copy of snap_backup_v1.

Maintenance and Snapshot Rotation

For continuous backups, repeat Steps 3 and 4 using the latest remote snapshot as the parent reference:

  1. Create snap_backup_v3.
  2. Send incrementally using -p snap_backup_v2 snap_backup_v3.
  3. Once snap_backup_v3 is verified on the remote server, older snapshots such as snap_backup_v1 can be safely deleted using btrfs subvolume delete on both the local and remote machines. Never delete the common parent snapshot until the subsequent incremental transfer has finished successfully.
