How to Query Active Directory with ldapsearch on Ubuntu

Querying a remote Microsoft Active Directory (AD) domain controller from an Ubuntu system is a routine task for system administrators and security professionals. By using the ldapsearch utility, you can authenticate against an AD server, inspect user and group attributes, and verify directory connectivity straight from the Linux command line. This guide demonstrates how to install the required tools on Ubuntu, structure the ldapsearch command for Active Directory authentication, and execute targeted queries to retrieve specific domain objects.

1. Install LDAP Utilities on Ubuntu

The ldapsearch command is provided by the ldap-utils package. Update your package lists and install it via apt:

sudo apt update
sudo apt install -y ldap-utils

2. Understand Key ldapsearch Parameters

Active Directory supports standard LDAP queries, but requires specific flags to format the connection and handle credentials:

  • -x: Use simple authentication instead of SASL.
  • -H: Specifies the LDAP URI (e.g., ldap://dc01.example.com:389 or ldaps://dc01.example.com:636).
  • -D: The Bind DN (distinguished name) or User Principal Name (UPN) to authenticate with.
  • -W: Prompts interactively for the bind password (avoids storing passwords in shell history).
  • -b: The search base (the starting point in the directory tree, e.g., dc=example,dc=com).
  • -s: Search scope (sub for entire subtree, one for one level, base for the base object).

3. Basic Active Directory Query

Active Directory allows binding using a User Principal Name (e.g., username@example.com) rather than a full Distinguished Name.

Run the following command to authenticate and search the directory:

ldapsearch -x -H ldap://dc01.example.com \
  -D "svc-query@example.com" \
  -W \
  -b "dc=example,dc=com" \
  "(objectClass=user)"

4. Practical Query Examples

Find a Specific User by Username

To retrieve details for a specific user using their sAMAccountName:

ldapsearch -x -H ldap://dc01.example.com \
  -D "svc-query@example.com" \
  -W \
  -b "dc=example,dc=com" \
  "(sAMAccountName=jdoe)" cn mail department

Note: Listing attributes (cn mail department) at the end of the command restricts the output strictly to those fields.

Find Members of a Specific Group

To locate all members belonging to a particular security group:

ldapsearch -x -H ldap://dc01.example.com \
  -D "svc-query@example.com" \
  -W \
  -b "dc=example,dc=com" \
  "(&(objectCategory=group)(cn=IT_Admins))" member

Search Within a Specific Organizational Unit (OU)

To limit search scope to a designated OU, modify the search base parameter:

ldapsearch -x -H ldap://dc01.example.com \
  -D "svc-query@example.com" \
  -W \
  -b "ou=Employees,dc=example,dc=com" \
  "(objectClass=person)" sAMAccountName mail

5. Using LDAPS (Secure LDAP)

When transmitting credentials and directory data across networks, use LDAPS (port 636) to encrypt communication:

ldapsearch -x -H ldaps://dc01.example.com:636 \
  -D "svc-query@example.com" \
  -W \
  -b "dc=example,dc=com" \
  "(sAMAccountName=jdoe)"

If your domain controller uses a self-signed certificate or an internal Certificate Authority (CA) not trusted by Ubuntu, you must append LDAPTLS_REQCERT=never before the command for temporary testing, or add the enterprise CA certificate to /usr/local/share/ca-certificates/ and run sudo update-ca-certificates.
