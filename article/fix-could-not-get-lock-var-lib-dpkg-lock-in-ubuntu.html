Fix Could Not Get Lock /var/lib/dpkg/lock in Ubuntu

The "Could not get lock /var/lib/dpkg/lock" error occurs in Ubuntu when the Advanced Package Tool (APT) or DPKG package manager is blocked by another running process, such as background system updates, or when an earlier installation terminated unexpectedly without releasing its lock file. This guide provides a safe, step-by-step process to identify active package management tasks, close them safely, clean up stale lock files if necessary, and reconfigure the package manager to restore full functionality without corrupting system packages.

Step 1: Check for Running APT Processes

Before deleting any files, check if Ubuntu is actively running an update, upgrade, or unattended background installation in the background.

Open your terminal and run:

ps aux | grep -i -E "apt|dpkg"

Alternatively, see which process holds the specific lock:

sudo lsof /var/lib/dpkg/lock
sudo lsof /var/lib/dpkg/lock-frontend

If processes such as unattended-upgr, apt, or apt-get are returned with active PIDs (Process IDs), the system is likely applying scheduled security updates.

Step 2: Allow the Process to Finish or Terminate It Safely

If a background update is actively running, the safest action is to wait several minutes for it to complete on its own.

If the process is frozen or unresponsive, terminate it gracefully using its PID:

sudo kill -SIGTERM <PID>

Replace <PID> with the process ID identified in Step 1. Wait a few moments for the process to exit. If it refuses to terminate, force it to stop:

sudo kill -SIGKILL <PID>

To stop all hung APT instances at once:

sudo killall -9 apt apt-get

Step 3: Remove the Stale Lock Files

If no APT or DPKG processes are running, but the error persists, the lock files were left behind by a system crash or improper shutdown. Remove the lock files safely:

sudo rm /var/lib/apt/lists/lock
sudo rm /var/cache/apt/archives/lock
sudo rm /var/lib/dpkg/lock
sudo rm /var/lib/dpkg/lock-frontend

Step 4: Reconfigure DPKG and Repair Packages

Removing lock files while an installation was pending can leave packages in a half-configured state. Reconfigure the package database to fix broken dependencies:

sudo dpkg --configure -a

Once the reconfiguration finishes without errors, refresh the package lists to ensure everything operates normally:

sudo apt update
