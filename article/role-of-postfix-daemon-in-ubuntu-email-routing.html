Role of Postfix Daemon in Ubuntu Email Routing

The Postfix daemon serves as the primary Mail Transfer Agent (MTA) on Ubuntu systems, responsible for routing, transferring, and delivering email messages. It acts as a central hub that accepts incoming emails from local users or remote servers, processes address rules and security checks, and routes the messages to their final destination using the Simple Mail Transfer Protocol (SMTP).

When an email is submitted to Postfix on Ubuntu, the daemon manages the message through a series of specialized internal services and message queues:

1. Message Reception

The postfix master process spawns specific worker daemons like smtpd to listen for network connections (typically on ports 25, 587, or 465) or pickup for locally generated system emails. These processes validate the sender, apply access controls, and place accepted messages into the incoming queue.

2. Address Processing and Routing Decisions

Once in the queue, the cleanup and trivial-rewrite daemons process the message headers and recipient addresses. Postfix evaluates configuration files (such as /etc/postfix/main.cf) and lookup tables to determine how the message should be routed:

  • Local Delivery: If the destination domain matches the local system hostname or configured virtual domains, Postfix routes the message internally.
  • Remote Delivery: If the domain is external, Postfix queries DNS records for the destination domain's Mail Exchanger (MX) record to locate the receiving server.
  • Relay Delivery: If configured to use a smart host or relay server, Postfix routes the email directly to the designated outbound provider.

3. Queue Management

Postfix utilizes distinct queue directories (incoming, active, deferred, and bounce) managed by the qmgr (queue manager) daemon. If a destination server is temporarily unavailable, the email is moved to the deferred queue, where Postfix automatically attempts redelivery at scheduled intervals before generating a non-delivery report (bounce).

4. Final Delivery

After determining the target destination, the queue manager hands the message off to the appropriate delivery agent:

  • smtp daemon: Handles outgoing transmission to external mail servers across the internet.
  • local or virtual daemons: Delivers incoming messages to local user mailboxes (such as Maildir or mbox formats) or passes them to a Local Delivery Agent (LDA) like Dovecot.
  • pipe daemon: Routes messages to external software, such as content filters, spam scanners, or custom scripts.
