Configure Docker Default Bridge Subnet on Ubuntu

By default, Docker assigns an automatically selected private subnet (typically in the 172.17.0.0/16 range) to its default docker0 bridge network. In many network environments, this default range can overlap with local enterprise networks, VPNs, or other host interfaces, causing routing conflicts. This article provides a clear, step-by-step guide to configuring the /etc/docker/daemon.json file to assign a custom subnet to the default bridge network on Ubuntu.

Step 1: Check the Current Bridge Configuration

Before making changes, verify the current subnet assigned to the default docker0 interface by running:

ip addr show docker0

Alternatively, inspect the Docker bridge network directly:

docker network inspect bridge | grep -A 5 "IPAM"

Step 2: Edit or Create the daemon.json File

Docker daemon settings are configured in the /etc/docker/daemon.json configuration file. Open this file using a text editor with administrative privileges:

sudo nano /etc/docker/daemon.json

If the file does not exist, creating it is safe.

Step 3: Specify the Custom Subnet

To define the IP address and subnet mask for the default bridge, use the bip (Bridge IP) parameter. The value must include an IP address for the Docker host interface along with the subnet mask in CIDR notation.

Add or update the configuration with your preferred subnet (for example, 192.168.100.1/24):

{
  "bip": "192.168.100.1/24"
}

If you already have existing configurations in daemon.json, ensure valid JSON formatting by separating entries with a comma:

{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  },
  "bip": "192.168.100.1/24"
}

Save the file and exit the editor (in nano, press CTRL + O, Enter, and then CTRL + X).

Step 4: Restart the Docker Service

Apply the new configuration by restarting the Docker daemon on Ubuntu:

sudo systemctl restart docker

If the Docker service fails to start, verify your JSON syntax using a validator or check the system logs:

sudo journalctl -u docker.service -n 20 --no-pager

Step 5: Verify the New Subnet

After restarting, confirm that the docker0 bridge has assumed the new IP address and subnet:

ip addr show docker0

You can also run a test container to confirm that containers attached to the default bridge receive IP addresses from the new range:

docker run --rm alpine ip addr show eth0

The output should show an IP address within the custom subnet range configured in daemon.json.
