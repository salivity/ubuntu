How to View Systemd Service Logs in Ubuntu

Viewing the standard output logs of a running systemd service in Ubuntu is primarily accomplished using the journalctl command. Because systemd captures both standard output (stdout) and standard error (stderr) by default, journalctl acts as the centralized query tool to view, filter, and monitor these logs in real time.

The Primary Command

To stream and follow the standard output logs of a running service in real time, use the following command:

journalctl -u <service_name> -f

Replace <service_name> with the exact name of your systemd service (for example, nginx, docker, or apache2). Adding .service at the end (such as nginx.service) is optional.

Key Flags Explained

  • -u <service_name>: Specifies the systemd unit (service) you want to filter logs for.
  • -f (follow): Continuously streams new log messages to the console as they are generated, functioning similarly to tail -f.

Useful Command Variations

Depending on how you want to view the standard output, you can combine other flags with journalctl:

  • Limit the number of lines: Display only the most recent log entries by appending -n:

    journalctl -u <service_name> -n 50 -f

    (This displays the last 50 lines and continues to follow live output.)

  • View logs from the current boot only: Prevent older logs from appearing by adding -b:

    journalctl -u <service_name> -b -f

  • Disable the interactive pager: By default, journalctl pipes output through less. To output raw text directly to the terminal standard output, use --no-pager:

    journalctl -u <service_name> --no-pager -n 100

Permission Requirements

To view system-wide service logs, your user account must either have administrative privileges or belong to the systemd-journal, adm, or wheel groups. If standard output logs do not appear or permission is denied, prepend sudo to the command:

sudo journalctl -u <service_name> -f
