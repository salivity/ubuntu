How to Convert ext4 to Btrfs in Place on Ubuntu

This guide explains how to convert an existing ext4 filesystem to a modern Btrfs filesystem in-place on Ubuntu without losing your existing data. Utilizing the native btrfs-convert utility, this process restructures the underlying filesystem metadata while keeping your files intact and creating a rollback image of the original ext4 layout.

Prerequisites

  • A full backup of all critical data before proceeding, as filesystem conversions inherently carry risks.
  • An Ubuntu Live USB environment if you are converting your root (/) partition, because the target partition must be unmounted during the conversion.
  • Sufficient free space on the partition (at least 15–20% free space is recommended) to store the new Btrfs metadata alongside the existing data.

Step 1: Install Btrfs Utilities

Ensure your Ubuntu system or live environment has the necessary tools installed:

sudo apt update
sudo apt install btrfs-progs

Step 2: Unmount and Check the ext4 Filesystem

The partition must be unmounted and verified for integrity before conversion. Replace /dev/sdXn with your specific target drive and partition (e.g., /dev/sda2 or /dev/nvme0n1p2).

Unmount the target partition:

sudo umount /dev/sdXn

Run a thorough filesystem consistency check:

sudo e2fsck -fvy /dev/sdXn

Step 3: Run the In-Place Conversion

Execute the conversion utility to transform the ext4 filesystem into Btrfs:

sudo btrfs-convert /dev/sdXn

This process creates a Btrfs filesystem tree using the existing ext4 file blocks. It also creates a subvolume named ext2_saved containing a complete image of the original ext4 metadata, allowing for a rollback if necessary.

Step 4: Retrieve the New UUID and Mount

The conversion changes the partition's UUID. Identify the new UUID:

sudo blkid /dev/sdXn

Mount the newly converted Btrfs filesystem:

sudo mount /dev/sdXn /mnt

Step 5: Update the Filesystem Table (/etc/fstab)

If you converted a secondary data drive, update /etc/fstab on your host system. If you converted your root filesystem, edit the file located at /mnt/etc/fstab:

Locate the entry for your partition and change:

  1. The UUID to the new value obtained from blkid.
  2. The filesystem type from ext4 to btrfs.
  3. The mount options to your preferred Btrfs options (such as defaults or defaults,compress=zstd).

Example entry:

UUID=your-new-uuid-here  /  btrfs  defaults,compress=zstd  0  0

Step 6: Reinstall GRUB and Update Initramfs (Root Conversions Only)

If converting the root partition, you must reconfigure the bootloader to read the Btrfs filesystem. Bind the necessary pseudo-filesystems and chroot into the installation:

sudo mount --bind /dev /mnt/dev
sudo mount --bind /proc /mnt/proc
sudo mount --bind /sys /mnt/sys

# If using EFI, mount the EFI partition as well
sudo mount /dev/sdX_efi /mnt/boot/efi

sudo chroot /mnt
update-initramfs -u -k all
update-grub
exit

Unmount the filesystems and reboot:

sudo umount -R /mnt
sudo reboot

Step 7: Finalize or Rollback

Once you have verified that the system operates correctly under Btrfs, you can choose between keeping the changes or rolling back.

To finalize and free up disk space: Deleting the saved ext4 snapshot removes the rollback capability but frees up the space occupied by the old metadata:

sudo btrfs subvolume delete /ext2_saved
sudo btrfs balance start -m /

To rollback (if issues occur): Boot back into a live USB, ensure the partition is unmounted, and revert the conversion:

sudo btrfs-convert -r /dev/sdXn
