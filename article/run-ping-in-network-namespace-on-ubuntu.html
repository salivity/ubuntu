Run Ping in Network Namespace on Ubuntu

Linux network namespaces provide isolated network stacks, complete with their own network interfaces, routing tables, and firewall rules. This guide explains how to execute network diagnostic utilities like ping directly inside an isolated network namespace using Ubuntu's ip netns command suite to test and troubleshoot connectivity.

Check Existing Network Namespaces

To verify the name of the target namespace, list all available network namespaces on your Ubuntu machine:

ip netns list

If you need to create a test namespace named test-ns, run:

sudo ip netns add test-ns

Run Ping Inside the Namespace

To execute any command inside a namespace, use the ip netns exec command followed by the namespace name and the command you wish to run. Running commands inside a network namespace requires superuser privileges.

Use the following syntax to send ICMP echo requests (ping) to an IP address or domain:

sudo ip netns exec <namespace_name> ping -c 4 <target_ip_or_host>

For example, to ping Google's public DNS (8.8.8.8) from inside test-ns:

sudo ip netns exec test-ns ping -c 4 8.8.8.8

Ensure Required Interfaces Are Up

If the ping command fails immediately with an error such as Network is unreachable, check the status of the interfaces allocated to that namespace:

sudo ip netns exec test-ns ip link

By default, even the loopback (lo) interface is disabled in a newly created namespace. Bring it up using:

sudo ip netns exec test-ns ip link set lo up

If you are using a virtual ethernet pair (veth), ensure the interface assigned to the namespace is also set to up and configured with an IP address:

sudo ip netns exec test-ns ip link set veth-ns up
sudo ip netns exec test-ns ip addr add 192.168.1.2/24 dev veth-ns

Verify Default Gateway and Routing

If you are pinging an external IP outside your local subnet, ensure that a default route exists inside the namespace:

sudo ip netns exec test-ns ip route add default via 192.168.1.1 dev veth-ns

Open an Interactive Shell in the Namespace

If you need to run multiple diagnostic commands sequentially (such as ping, traceroute, or curl), launch an interactive bash session inside the namespace:

sudo ip netns exec test-ns bash

From this shell, all networking tools run natively inside test-ns without prefixing ip netns exec:

ping -c 4 1.1.1.1
exit
