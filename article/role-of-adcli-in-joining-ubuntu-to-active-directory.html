Role of adcli in Joining Ubuntu to Active Directory

The adcli tool is a specialized command-line utility used to manage domain membership and computer accounts in an Active Directory (AD) environment. When integrating an Ubuntu server into Active Directory, adcli performs the low-level administrative operations required to establish a trusted machine identity, such as creating the computer object in AD, setting the initial machine password, and generating the local Kerberos keytab. While administrators frequently interact with higher-level abstractions like realmd, adcli acts as the underlying engine responsible for executing the actual identity provisioning and domain enrollment.

What is adcli?

The adcli tool communicates directly with Active Directory Domain Controllers using standard protocols, primarily LDAP for directory interactions and Kerberos for authentication. It eliminates the need for proprietary domain-join software or the Samba winbind stack by providing a lightweight, native mechanism for Linux systems to perform domain join operations.

Key Responsibilities During the Domain Join

When an Ubuntu system is joined to an Active Directory domain, adcli handles several essential tasks:

  • Computer Object Creation: It connects to Active Directory using administrative credentials to create the host's computer account object. Administrators can specify the exact Organizational Unit (OU) where the machine object should reside.
  • Kerberos Keytab Generation: A functional domain membership requires the client to authenticate itself to domain services. adcli negotiates the shared secret with the domain controller and writes the host's Service Principal Names (SPNs) and cryptographic keys to the local /etc/krb5.keytab file.
  • Machine Password Management: It configures the initial password for the machine account, enabling secure, unattended Kerberos ticket generation for system services.
  • Operating System Attribute Updates: During the join, adcli can populate attributes on the Active Directory computer object, such as operatingSystem and operatingSystemVersion, allowing directory administrators to identify the machine as an Ubuntu system.

Relationship with realmd and SSSD

In modern Ubuntu deployments, identity management is typically structured across three layers:

  1. realmd: A high-level front-end that simplifies configuration by orchestrating dependencies, DNS discovery, PAM modules, and configuration files.
  2. adcli: The enrollment backend invoked by realmd to handle the specific Active Directory transactions.
  3. SSSD (System Security Services Daemon): The runtime client that manages user authentication, identity caching, and access policies once the system is joined.

When you run realm join domain.example.com, realmd calls adcli join under the hood to perform the enrollment and create the keytab, before configuring SSSD to use that keytab for routine user lookups and logins.

Direct Use vs. Abstraction

While realmd is common for standard setups, using adcli directly offers finer control. Direct execution is useful in automated provisioning scripts (such as cloud-init or Ansible) where administrators need to:

  • Pre-create or reset computer accounts without altering the local authentication configuration.
  • Explicitly define specific Kerberos encryption types.
  • Specify hostnames that differ from the local machine's transient hostname.
  • Target specific domain controllers directly rather than relying on automated SRV record resolution.

Post-Join Maintenance

The role of adcli does not end after the initial join. Active Directory computer accounts require periodic password rotation to remain secure. Systems running adcli can automate this renewal using adcli update, which refreshes the machine password in Active Directory and updates the local /etc/krb5.keytab without administrative intervention or system downtime. If a system must be decommissioned, adcli delete-computer can remove the account from the directory directly from the command line.
