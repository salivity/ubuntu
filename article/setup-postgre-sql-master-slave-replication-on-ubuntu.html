Setup PostgreSQL Master Slave Replication on Ubuntu

This guide provides a step-by-step walkthrough for configuring streaming replication between two Ubuntu servers running PostgreSQL. By designating one server as the primary (master) node to handle read-write transactions and another as the standby (slave) node for read-only failover and backup, you establish a resilient, high-availability database architecture.

Prerequisites

  • Two Ubuntu servers with PostgreSQL installed (e.g., PostgreSQL 14 or 16).
  • Server A (Primary): 192.168.1.10
  • Server B (Standby): 192.168.1.20
  • Root or sudo access on both servers.

Step 1: Configure the Primary (Master) Server

1. Create a Replication User

Log into PostgreSQL on the primary server and create a dedicated user with replication privileges:

sudo -u postgres psql
CREATE ROLE replicator WITH REPLICATION LOGIN ENCRYPTED PASSWORD 'StrongReplicationPassword';
\q

2. Configure postgresql.conf

Locate and edit the main PostgreSQL configuration file (typically in /etc/postgresql/<version>/main/postgresql.conf):

sudo nano /etc/postgresql/16/main/postgresql.conf

Ensure the following parameters are set:

listen_addresses = '*'
wal_level = replica
max_wal_senders = 10
wal_keep_size = 64MB

3. Configure pg_hba.conf

Allow the standby server to authenticate for replication by editing /etc/postgresql/<version>/main/pg_hba.conf:

sudo nano /etc/postgresql/16/main/pg_hba.conf

Add this line to the end of the file:

host    replication     replicator      192.168.1.20/32         scram-sha-256

4. Restart PostgreSQL

Apply the changes on the primary server:

sudo systemctl restart postgresql

Step 2: Configure the Standby (Slave) Server

1. Stop PostgreSQL

Stop the PostgreSQL service on the standby server before copying the initial database cluster:

sudo systemctl stop postgresql

2. Clear Existing Data

Remove or back up the default data directory on the standby node:

sudo rm -rf /var/lib/postgresql/16/main/*

3. Clone the Primary Node Data

Use pg_basebackup to pull the database files from the primary server. The -R flag automatically creates the standby.signal file and appends connection settings to postgresql.auto.conf:

sudo -u postgres pg_basebackup -h 192.168.1.10 -D /var/lib/postgresql/16/main/ -U replicator -P -v -R

Enter the password for the replicator user when prompted.

4. Ensure Correct Permissions

Verify that the postgres system user owns the newly created data directory:

sudo chown -R postgres:postgres /var/lib/postgresql/16/main
sudo chmod 700 /var/lib/postgresql/16/main

5. Start PostgreSQL

Start the PostgreSQL service on the standby server:

sudo systemctl start postgresql

Step 3: Verify Replication

1. Check Replication Status on the Primary

Execute the following query on the primary server to confirm active streaming:

sudo -u postgres psql -c "SELECT client_addr, state, sync_state FROM pg_stat_replication;"

You should see an output indicating streaming state alongside the standby server's IP address.

2. Test Data Replication

  • On the primary server, create a test database or table: 
    CREATE DATABASE repl_test;
  • On the standby server, check if the database exists: 
    sudo -u postgres psql -c "\l"

If repl_test appears in the list on the standby server, master-slave streaming replication is successfully working.
