How to Clear Cached RAM in Ubuntu Using sysctl

This article explains how to safely clear cached RAM—including PageCache, dentries, and inodes—in Ubuntu using the sysctl utility. While the Linux kernel automatically manages memory efficiently by borrowing unused RAM for caching, administrators sometimes need to manually flush these caches for benchmarking, troubleshooting, or testing purposes. Following the steps below ensures that all unwritten data is safely committed to disk before the cache is emptied, preventing data loss.

Step 1: Synchronize Data to Disk

Before dropping memory caches, you must ensure that all dirty pages (data written to memory but not yet written to storage) are flushed to disk. Failing to do this can lead to data loss or corruption.

Run the sync command with root privileges:

sudo sync

Step 2: Clear the Cache Using sysctl

The Linux kernel controls cache management via the vm.drop_caches kernel parameter. You can modify this parameter on the fly using sysctl -w.

There are three options depending on what you want to clear:

  1. Clear PageCache only:

    sudo sysctl -w vm.drop_caches=1

  2. Clear dentries and inodes (directory and inode cache):

    sudo sysctl -w vm.drop_caches=2

  3. Clear PageCache, dentries, and inodes (all cached memory):

    sudo sysctl -w vm.drop_caches=3

To clear all cached memory in one safe operation, combine the sync command with sysctl:

sudo sync && sudo sysctl -w vm.drop_caches=3

Step 3: Verify the Cleared Memory

You can check your system's memory usage before and after running the command using the free utility:

free -h

Look at the buff/cache and available columns to observe the reduction in cached memory and the corresponding increase in free memory.

Important Notes on Cache Management

  • Non-Destructive Operation: Clearing caches via vm.drop_caches is completely non-destructive as long as sync is executed first. It will only release clean, inactive cached objects.
  • Temporary Effect: The kernel will immediately begin caching files and metadata again as your applications read and write data. This is normal and desired behavior for Linux performance.
  • Routine Use: You should not automate cache clearing via cron jobs in production environments. Cached RAM does not starve applications; the kernel immediately reclaims cached memory whenever an active process requests it. Constantly dropping caches forces the system to read frequently accessed files directly from storage, degrading system performance.
