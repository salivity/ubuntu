Mount iSCSI Target After Network Online in Ubuntu

Mounting an iSCSI target at system boot in Ubuntu often leads to boot delays or mounting failures if the system attempts to mount the filesystem before the network interfaces and iSCSI initiator services are fully initialized. To prevent this, the operating system must be explicitly instructed to delay the mount operation until the network stack is fully active. This guide explains how to properly configure your Ubuntu system using systemd-aware /etc/fstab options and network wait-online services to ensure reliable automatic mounting on every boot.

Step 1: Ensure Network Wait-Online Services Are Active

Before configuring the mount points, verify that systemd's network wait-online target is properly activated. This ensures systemd does not report the network as "ready" until an IP address is actually assigned.

If your Ubuntu system uses systemd-networkd (common on Ubuntu Server):

sudo systemctl enable systemd-networkd-wait-online.service

If your system uses NetworkManager (common on Ubuntu Desktop):

sudo systemctl enable NetworkManager-wait-online.service

Step 2: Identify the iSCSI Block Device UUID

Avoid using device node names like /dev/sdb because they can change between reboots. Instead, identify the filesystem's universally unique identifier (UUID):

sudo blkid

Locate your iSCSI drive in the output and copy the UUID string.

Step 3: Configure /etc/fstab with Network Dependencies

Open /etc/fstab in a text editor:

sudo nano /etc/fstab

Add an entry for your iSCSI volume utilizing systemd-specific network mount flags:

UUID=YOUR-UUID-HERE /mnt/iscsi ext4 _netdev,x-systemd.requires=iscsid.service,x-systemd.after=network-online.target 0 0

Key Mount Options Explained:

  • _netdev: Informs systemd and the init system that this device requires network access, preventing it from mounting before local network devices are initialized.
  • x-systemd.requires=iscsid.service: Instructs systemd that the mount depends on the iSCSI initiator daemon (iscsid) being running.
  • x-systemd.after=network-online.target: Enforces that the mount job runs strictly after network-online.target is reached.

Step 4: Configure Automatic Node Login

Ensure the open-iscsi service is configured to log in to your target automatically on boot:

  1. Open the iSCSI initiator node configuration file located under /etc/iscsi/nodes/<target_name>/<portal_ip>,<port>/default.
  2. Find the node.startup parameter and set it to automatic: 
    node.startup = automatic
  3. Restart and enable the initiator service: 
    sudo systemctl enable open-iscsi
sudo systemctl enable iscsid

Step 5: Reload and Test the Configuration

To confirm that systemd recognizes the updated /etc/fstab dependencies without errors, reload the systemd daemon:

sudo systemctl daemon-reload

Test mounting the target directly:

sudo mount -a

Verify that the mount is active:

df -h /mnt/iscsi

Once confirmed, reboot the machine using sudo reboot to ensure that the volume cleanly mounts automatically after the network comes online.
