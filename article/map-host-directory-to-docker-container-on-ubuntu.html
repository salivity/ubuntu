Map Host Directory to Docker Container on Ubuntu

Mapping a host directory to a Docker container allows persistent storage and seamless data sharing between an Ubuntu host and a containerized environment. While Docker natively uses the -v (or --mount) flag during container creation to bind-mount directories, native Docker commands cannot directly attach a live mount to an already running container. To achieve this on Ubuntu, administrators must either launch a new container with the mount flag, copy files using docker cp, or use advanced system tools like nsenter to inject the mount point into the container's active mount namespace.

1. The Standard Command: Mapping at Container Launch

The recommended way to map a host directory into a container is specifying the bind mount when launching it with docker run.

Using the -v Flag

docker run -d \
  -v /path/to/host/dir:/path/to/container/dir \
  --name my_container \
  my_image

Using the --mount Flag (Recommended for Clarity)

docker run -d \
  --mount type=bind,source=/path/to/host/dir,target=/path/to/container/dir \
  --name my_container \
  my_image
  • Both paths must be absolute paths on Ubuntu.
  • If /path/to/container/dir does not exist inside the container, Docker creates it automatically.

2. Managing an Already Running Container

If your container is already running and cannot easily be stopped, there are three methods to manage directory access:

Method A: Copy Data Without Stopping (docker cp)

If you only need to sync files rather than maintain a live, synchronized mount, use docker cp:

docker cp /path/to/host/dir/. my_container:/path/to/container/dir/

This immediately transfers the files from the Ubuntu host into the active container.

Method B: Stop, Recreate, and Mount (Best Practice)

To establish a persistent, synchronized link, commit the current state of the running container and recreate it with the volume mapped:

  1. Save the running state: 
    docker commit my_container my_container_backup
  2. Stop and remove the old container: 
    docker stop my_container
docker rm my_container
  3. Run the saved image with the bind mount attached: 
    docker run -d \
  -v /path/to/host/dir:/path/to/container/dir \
  --name my_container \
  my_container_backup

Method C: Dynamic Mount Using nsenter (Advanced)

For advanced users who cannot stop a running container, Ubuntu allows live mounting directly into the container's filesystem namespace using Linux utilities:

  1. Obtain the container's PID: 
    PID=$(docker inspect --format '{{.State.Pid}}' my_container)
  2. Create the target directory inside the container's namespace: 
    sudo nsenter --target $PID --mount mkdir -p /path/to/container/dir
  3. Bind-mount the host directory into the target namespace: 
    sudo nsenter --target $PID --mount mount --bind /path/to/host/dir /path/to/container/dir

The host directory is now accessible inside the running container without interruption. Note that mounts applied via nsenter will not persist across container restarts.
