How to Alias Snap Commands in Ubuntu

This guide explains how to map Snap-packaged applications to traditional system command names in Ubuntu using native Snap tools, system-wide symlinks, and shell configurations. By setting up these aliases, you can execute Snap utilities using standard command-line syntax without typing prefix names or altering your primary terminal workflow.

Using the Native Snap Alias Command

The Snap package manager includes a built-in alias system. This is the cleanest approach, as it integrates directly with the Snap daemon and preserves configurations across package updates.

To create an alias for a specific Snap command, use the following syntax:

sudo snap alias <snap-name>.<app> <desired-command>

If the package exposes a single binary directly named after the package, the syntax is:

sudo snap alias <snap-name> <desired-command>

For example, to map the microk8s.kubectl command to the standard kubectl namespace:

sudo snap alias microk8s.kubectl kubectl

Once executed, Snap automatically creates a symbolic link in /snap/bin/, which resides in the default Ubuntu $PATH.

Verifying and Removing Snap Aliases

To view all active aliases configured on your Ubuntu system, run:

snap aliases

The output will display the source Snap command, the custom alias, and whether the alias is currently active or manual.

If you want to remove an alias and return the namespace to its previous state:

sudo snap unalias <desired-command>

Using the previous example:

sudo snap unalias kubectl

Alternative: Using Symbolic Links in /usr/local/bin

If you encounter a package with strict confinement constraints or automatic alias restrictions, you can map the binary manually via /usr/local/bin. Since /usr/local/bin typically takes precedence in the shell's $PATH, this ensures the Snap version is called whenever the command is typed.

Run the following command to link the binary:

sudo ln -s /snap/bin/<snap-command> /usr/local/bin/<desired-command>

To remove this manual mapping:

sudo rm /usr/local/bin/<desired-command>

Alternative: User-Level Shell Aliases

If you only need the alias for a single user account and do not have sudo privileges, define a standard shell alias.

Open your shell configuration file (such as ~/.bashrc or ~/.zshrc):

nano ~/.bashrc

Add the alias definition at the bottom of the file:

alias <desired-command>='/snap/bin/<snap-command>'

Save the file and apply the changes to your current session:

source ~/.bashrc
