How to Configure DNS over TLS on Ubuntu

This article explains how to secure your internet requests by configuring DNS over TLS (DoT) on an Ubuntu client. Modern Ubuntu installations utilize the native systemd-resolved service, allowing you to encrypt standard plaintext DNS traffic without installing third-party software. Following the steps below will route your DNS lookups through an encrypted TLS tunnel to prevent tampering and eavesdropping.

Step 1: Open the Resolved Configuration File

systemd-resolved handles network name resolution on Ubuntu. To enable DoT, edit its configuration file with root privileges:

sudo nano /etc/systemd/resolved.conf

Step 2: Configure Upstream DNS and Enable DoT

Locate the [Resolve] section. You must specify upstream DNS providers that support DoT (such as Cloudflare or Quad9) along with their Server Name Indication (SNI) hostnames, and set DNSOverTLS to yes.

Add or update the following directives:

[Resolve]
DNS=1.1.1.1#cloudflare-dns.com 1.0.0.1#cloudflare-dns.com 2606:4700:4700::1111#cloudflare-dns.com
FallbackDNS=9.9.9.9#dns.quad9.net 149.112.112.112#dns.quad9.net
DNSOverTLS=yes
  • DNS: Specifies the primary encrypted DNS servers. The #hostname suffix is required for TLS certificate validation.
  • DNSOverTLS=yes: Strictly enforces encryption. If the encrypted connection fails, name resolution will fail rather than falling back to plaintext. You can use opportunistic instead if you want to fall back to plaintext when TLS is unavailable.

Save the file and exit the editor (in nano, press Ctrl+O, Enter, then Ctrl+X).

Step 3: Restart systemd-resolved

Apply the new configuration by restarting the resolution service:

sudo systemctl restart systemd-resolved

Ensure the service restarted without errors:

sudo systemctl status systemd-resolved

Step 4: Verify the Configuration

Verify that DNS over TLS is active using resolvectl:

resolvectl status

Check the output under the Global section. You should see:

  • DNS Servers: Listed with their IP addresses and SNI hostnames.
  • DNSOverTLS: Set to yes.

To verify encrypted resolution in real-time, test a query:

resolvectl query example.com

You can confirm that queries are traveling over port 853 (standard DoT port) rather than standard port 53 by monitoring traffic with tcpdump:

sudo tcpdump -n -i any port 853

Run a DNS lookup in a separate terminal. If packets appear in the tcpdump output, your Ubuntu system is successfully encrypting its DNS traffic over TLS.
