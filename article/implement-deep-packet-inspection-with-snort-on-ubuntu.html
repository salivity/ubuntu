Implement Deep Packet Inspection with Snort on Ubuntu

Deep packet inspection (DPI) allows network administrators to look beyond packet headers and analyze the actual data payloads crossing a network perimeter. This article provides a direct, technical walkthrough for deploying Snort as a DPI engine on an Ubuntu-based gateway router or firewall. You will learn how to configure network interfaces for boundary monitoring, install and configure Snort, write custom rules to inspect payload contents, and run the engine to actively identify and log malicious application-layer data.

1. Network Boundary Architecture

To inspect boundary traffic, the Ubuntu host must sit directly in the traffic path (as a router/bridge using Inline mode) or receive mirrored traffic from a switch's SPAN port (Passive mode). For full deep packet inspection and prevention (IPS), an inline deployment with two network interfaces is standard:

  • Interface 1 (eth0): External / WAN facing.
  • Interface 2 (eth1): Internal / LAN facing.

Disable interface offloading features to ensure Snort sees raw, intact packets without kernel-level fragmentation changes:

sudo ethtool -K eth0 gro off lro off tso off
sudo ethtool -K eth1 gro off lro off tso off

To persist these settings, add them to your /etc/netplan/*.yaml file or a systemd startup script.

2. Installing Snort

Update package lists and install Snort. Ubuntu provides Snort packages via the standard repository:

sudo apt update
sudo apt install snort -y

During installation, the package installer will prompt you for the local network address range. Specify your internal subnet (for example, 192.168.1.0/24).

3. Configuring the Boundary Parameters

The main configuration file is located at /etc/snort/snort.conf. Edit this file to establish your network topology:

sudo nano /etc/snort/snort.conf

Define the internal and external network variables:

ipvar HOME_NET [192.168.1.0/24]
ipvar EXTERNAL_NET !$HOME_NET

Set the rule path variables to ensure custom DPI signatures are loaded:

var RULE_PATH /etc/snort/rules
var SO_RULE_PATH /etc/snort/so_rules
var PREPROC_RULE_PATH /etc/snort/preproc_rules

Verify that preprocessors responsible for packet reassembly (such as frag3 for IP defragmentation and stream5 for TCP stream reassembly) are enabled. DPI requires clean stream reassembly to inspect payloads spanning multiple packets:

preprocessor frag3_global: max_frags 65536
preprocessor frag3_engine: policy first detect_anomalies

preprocessor stream5_global: track_tcp yes, track_udp yes
preprocessor stream5_tcp: policy first, require_3whs yes

4. Writing Custom Deep Packet Inspection Rules

DPI relies on matching patterns deep inside the application payload rather than just filtering source/destination ports and IPs.

Open the local rules file:

sudo nano /etc/snort/rules/local.rules

Add rules that inspect payload contents using keywords such as content, depth, offset, and nocase:

  • Detecting cleartext credentials or command sequences (e.g., unauthorized HTTP admin login):
alert tcp $EXTERNAL_NET any -> $HOME_NET 80 (msg:"DPI: Unauthorized Admin POST Attempt"; flow:to_server,established; content:"POST"; http_method; content:"/admin/login"; http_uri; content:"admin=true"; nocase; sid:1000001; rev:1;)
  • Detecting custom protocol malware signatures (hex payload matching):
alert tcp $HOME_NET any -> $EXTERNAL_NET any (msg:"DPI: Known Trojan Signature Match"; flow:to_server,established; content:"|4d 5a 90 00 03|"; depth:5; sid:1000002; rev:1;)
  • Detecting sensitive data leakage (credit card or PII strings):
alert tcp $HOME_NET any -> $EXTERNAL_NET any (msg:"DPI: Suspicious Outbound Key Transmission"; flow:established; content:"BEGIN PRIVATE KEY"; sid:1000003; rev:1;)

5. Validating and Testing the Configuration

Validate the configuration file to detect syntax errors before running the service:

sudo snort -T -c /etc/snort/snort.conf

If the validation returns Snort successfully validated the configuration!, start Snort in test mode on your monitored boundary interface:

sudo snort -A console -q -c /etc/snort/snort.conf -i eth1

Trigger a rule from a client machine inside the network using curl:

curl -X POST http://<target-ip>/admin/login -d "admin=true"

Snort will output an alert to the terminal confirming that the application payload was inspected and flagged:

[**] [1:1000001:1] DPI: Unauthorized Admin POST Attempt [**]
[Priority: 0] 
05/14-10:20:15.123456 192.168.1.50:48292 -> 192.168.1.10:80

6. Running Snort as a System Service

To keep Snort running continuously at the boundary, enable the systemd service:

sudo systemctl enable snort
sudo systemctl start snort

Alert logs will be written to /var/log/snort/alert, where they can be forwarded to a SIEM or analyzed using tools like Barnyard2 or fluentd for continuous boundary monitoring.
