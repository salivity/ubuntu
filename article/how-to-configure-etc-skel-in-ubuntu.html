How to Configure /etc/skel in Ubuntu

This article explains how to configure the /etc/skel directory on Ubuntu to define the default files, directories, and configurations for newly created users. By customizing this skeleton directory, system administrators can automatically deploy environment variables, custom shell profiles, welcome messages, and standard folder structures to every new user account created on the system.

What Is the /etc/skel Directory?

The /etc/skel (skeleton) directory serves as a blueprint for user home directories. Whenever a new user is added using tools like adduser or useradd -m, the system copies the contents of /etc/skel directly into the new user's home directory (/home/<username>) and sets the appropriate ownership permissions automatically.

Viewing the Default Skeleton Files

Most files in /etc/skel are hidden files that begin with a dot (dotfiles). To view the existing template files, open your terminal and list all directory contents:

ls -la /etc/skel

Typically, Ubuntu includes default configuration files such as:

  • .bashrc (bash configuration)
  • .bash_logout (cleanup commands executed upon exit)
  • .profile (environment and path settings)

Modifying Existing Default Files

You must have administrative (sudo) privileges to make changes inside /etc/skel.

To modify settings that apply to all new user shells—such as default aliases, shell prompts, or custom paths—edit the .bashrc file:

sudo nano /etc/skel/.bashrc

Scroll to the bottom and add custom configurations, such as:

# Custom global aliases for new users
alias ll='ls -la'
alias update='sudo apt update && sudo apt upgrade -y'

Save and exit the file.

Adding New Files and Directories

You can add standard folders or informative files directly into /etc/skel.

1. Adding Standard Directories

To ensure all new users have standard folders (e.g., bin or projects):

sudo mkdir -p /etc/skel/bin /etc/skel/projects

2. Adding Custom Files

To place a welcome document or instruction guide in every new home directory:

sudo nano /etc/skel/README.txt

Enter your instructions, then save and exit.

Setting Correct File Permissions

Files and directories within /etc/skel must have permissions that allow the user creation tools to read and duplicate them. Ensure permissions are set correctly:

  • Directories: Should be set to 755 (rwxr-xr-x)
  • Files: Should be set to 644 (rw-r--r--)

Run the following commands to normalize permissions:

sudo find /etc/skel -type d -exec chmod 755 {} +
sudo find /etc/skel -type f -exec chmod 644 {} +

Root ownership of the skeleton files themselves should be maintained:

sudo chown -R root:root /etc/skel

Testing the Configuration

Existing users are not affected by changes made to /etc/skel. To verify that your changes work, create a new test user:

sudo adduser testuser

Once created, inspect the contents of the newly created home directory:

ls -la /home/testuser

Verify that the custom directories, .bashrc modifications, and template files appear and are correctly owned by testuser. Once verified, remove the test account:

sudo deluser --remove-home testuser
