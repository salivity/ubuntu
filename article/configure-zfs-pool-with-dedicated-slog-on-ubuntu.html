Configure ZFS Pool with Dedicated SLOG on Ubuntu

This guide outlines the complete process for configuring a ZFS storage pool with a dedicated Separate ZFS Intent Log (SLOG) device on Ubuntu. A dedicated SLOG improves write performance for synchronous workloads by offloading ZFS Intent Log (ZIL) commits to high-speed, low-latency storage devices such as enterprise NVMe SSDs with Power Loss Protection (PLP). Following the steps below, you will prepare your system, install required packages, identify disk identifiers, create the primary zpool, and attach a dedicated log device.

1. Install ZFS Utilities

Update your Ubuntu package lists and install the standard OpenZFS userland utilities:

sudo apt update
sudo apt install -y zfsutils-linux

Ensure the ZFS kernel module is loaded:

sudo modprobe zfs

2. Identify Disk Identifiers

Always use /dev/disk/by-id/ paths rather than generic names like /dev/sdb to prevent pool corruption if drive letters change across reboots.

List all attached disks by their unique hardware IDs:

ls -l /dev/disk/by-id/

Identify the disk IDs for your main storage drives (e.g., standard HDDs or SSDs) and your dedicated fast write device reserved for the SLOG.

3. Create the Base ZFS Pool

If you do not already have an active pool, create one. For example, to create a mirrored pool named datapool using two storage drives:

sudo zpool create -f -o ashift=12 datapool mirror \
  /dev/disk/by-id/wwn-0x5000cca250c1234a \
  /dev/disk/by-id/wwn-0x5000cca250c1234b
  • -o ashift=12 sets the vdev block size to 4KB, standard for modern hard drives and SSDs.
  • Replace the drive IDs with the identifiers determined in Step 2.

4. Add the Dedicated SLOG Device

Attach your dedicated high-speed device to the existing pool using the log vdev type.

Option A: Single SLOG Device

For non-critical data environments or when relying on a reliable single SSD:

sudo zpool add datapool log /dev/disk/by-id/nvme-eui.002538b101a12345

Option B: Mirrored SLOG Device (Recommended)

Because an SLOG failure during a power outage can result in the loss of in-flight sync writes, production environments should mirror the SLOG devices:

sudo zpool add datapool log mirror \
  /dev/disk/by-id/nvme-eui.002538b101a12345 \
  /dev/disk/by-id/nvme-eui.002538b101a12346

5. Verify the Pool Status

Verify that the dedicated log device is attached correctly to the pool:

sudo zpool status datapool

The output will display a distinct logs section showing the attached drive or mirror:

  pool: datapool
 state: ONLINE
  scan: none requested
config:

    NAME                                                 STATE     READ WRITE CKSUM
    datapool                                             ONLINE       0     0     0
      mirror-0                                           ONLINE       0     0     0
        wwn-0x5000cca250c1234a                           ONLINE       0     0     0
        wwn-0x5000cca250c1234b                           ONLINE       0     0     0
    logs    
      mirror-1                                           ONLINE       0     0     0
        nvme-eui.002538b101a12345                        ONLINE       0     0     0
        nvme-eui.002538b101a12346                        ONLINE       0     0     0

errors: No known data errors

6. Verify Synchronous Write Behavior

An SLOG is only utilized during synchronous write operations (such as databases, NFS shares, or virtual machine disks). To force all writes to use the SLOG for testing or specific dataset requirements, set the dataset's sync property:

sudo zfs set sync=always datapool

For general workloads, keep the default setting (sync=standard), which allows applications to request synchronous or asynchronous writes dynamically:

sudo zfs set sync=standard datapool

Monitor activity on the dedicated log device in real-time while running write operations:

zpool iostat -v datapool 1
